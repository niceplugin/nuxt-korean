## 새로운 플러그인 형식 %{#new-plugins-format}%

이제 Nuxt 2와 형식이 약간 다른 Nuxt 3 플러그인 API로 마이그레이션할 수 있습니다.

이제 플러그인은 인자를 하나(`nuxtApp`)만 받습니다. 자세한 내용은 [문서](/docs/4.x/directory-structure/app/plugins)에서 확인할 수 있습니다.

```ts [app/plugins/hello.ts]
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.provide('injected', () => '내가 주입한 함수')
  // 이제 `nuxtApp.$injected`에서 사용할 수 있습니다
})
```

::note
플러그인 안에서 새로운 Nuxt 컴포저블([`useNuxtApp`](/docs/4.x/api/composables/use-nuxt-app), `useRuntimeConfig` 등)을 사용하려면 해당 플러그인에 `defineNuxtPlugin` 헬퍼를 사용해야 합니다.
::

::warning
`nuxtApp.vueApp`를 통해 호환 인터페이스가 제공되지만, 두 번 이상 설치되지 않도록 보장하는 자체 로직 없이 이 방식으로 플러그인, 디렉티브, 믹스인, 컴포넌트를 등록하는 것은 피해야 합니다. 그렇지 않으면 메모리 누수가 발생할 수 있습니다.
::

## 새로운 미들웨어 형식 %{#new-middleware-format}%

이제 Nuxt 2와 형식이 약간 다른 Nuxt 3 미들웨어 API로 마이그레이션할 수 있습니다.

이제 미들웨어는 인자를 두 개(`to`, `from`)만 받습니다. 자세한 내용은 [문서](/docs/4.x/directory-structure/app/middleware)에서 확인할 수 있습니다.

```ts twoslash
export default defineNuxtRouteMiddleware((to) => {
  if (to.path !== '/') {
    return navigateTo('/')
  }
})
```

::important
`defineNuxtRouteMiddleware`는 `app/middleware` 디렉터리 밖에서는 사용할 수 없습니다.
::

## definePageMeta %{#definepagemeta}%

Nuxt Bridge에서도 [`definePageMeta`](/docs/4.x/api/utils/define-page-meta)를 사용할 수 있습니다.

설정 파일의 `macros.pageMeta` 옵션으로 활성화할 수 있습니다

```ts [nuxt.config.ts]
import { defineNuxtConfig } from '@nuxt/bridge'

export default defineNuxtConfig({
  bridge: {
    macros: {
      pageMeta: true,
    },
  },
})
```

::note
하지만 `middleware`와 `layout`에 대해서만 가능합니다.
::
