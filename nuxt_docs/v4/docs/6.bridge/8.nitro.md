## 모듈 제거 %{#remove-modules}%

- `@nuxt/nitro` 제거: Bridge가 동일한 기능을 주입합니다

## 설정 업데이트 %{#update-config}%

```ts [nuxt.config.ts]
import { defineNuxtConfig } from '@nuxt/bridge'

export default defineNuxtConfig({
  bridge: {
    nitro: true,
  },
})
```

## 스크립트 업데이트 %{#update-your-scripts}%

이제 Nuxt가 빌드 출력으로 Nitro 서버를 생성한다는 점을 반영하도록 `package.json` 안의 스크립트도 업데이트해야 합니다.

### Nuxi 설치 %{#install-nuxi}%

개발 의존성으로 `nuxi`를 설치합니다:

::code-group{sync="pm"}

```bash [npm]
npm install -D nuxi
```

```bash [yarn]
yarn add --dev nuxi
```

```bash [pnpm]
pnpm add -D nuxi
```

```bash [bun]
bun add -D nuxi
```

```bash [deno]
deno add -D npm:nuxi
```

::

### Nuxi %{#nuxi}%

Nuxt 3에는 새로운 Nuxt CLI 명령 [`nuxi`](/docs/4.x/api/commands/add)가 도입되었습니다. Nuxt Bridge의 더 나은 지원을 활용할 수 있도록 다음과 같이 스크립트를 업데이트하세요:

```diff
{
  "scripts": {
-   "dev": "nuxt",
+   "dev": "nuxi dev",
-   "build": "nuxt build",
+   "build": "nuxi build",
-   "start": "nuxt start",
+   "start": "nuxi preview"
  }
}
```

::tip
`nitro: false`인 경우 `nuxt2` 명령을 사용하세요.
::

### 정적 타깃 %{#static-target}%

`nuxt.config`에서 `target: 'static'`을 설정했다면, 빌드 스크립트를 `nuxi generate`로 업데이트해야 합니다.

```json [package.json]
{
  "scripts": {
    "build": "nuxi generate"
  }
}
```

### 서버 타깃 %{#server-target}%

그 외 모든 경우에는 `nuxi build` 명령을 사용할 수 있습니다.

```json [package.json]
{
  "scripts": {
    "build": "nuxi build",
    "start": "nuxi preview"
  }
}
```

## 빌드된 Nitro 폴더를 Git에서 제외 %{#exclude-built-nitro-folder-from-git}%

`.gitignore` 파일에 `.output` 폴더를 추가하세요.

## 모든 것이 잘 동작하는지 확인하기 %{#ensure-everything-goes-well}%

✔️ `nuxi dev`와 `nuxi build`(또는 `nuxi generate`)로 실행해 모든 것이 잘 동작하는지 확인해 보세요.
