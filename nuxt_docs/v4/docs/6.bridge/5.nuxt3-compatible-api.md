---
title: 새로운 Composition API
description: Nuxt Bridge는 Nuxt 3와 호환되는 컴포저블을 구현합니다.
---

`@nuxtjs/composition-api`에서 Nuxt 3 호환 API로 마이그레이션하면, Nuxt 3로 옮길 때 다시 작성해야 하는 코드가 줄어듭니다.

## `ssrRef` and `shallowSsrRef` %{#ssrref-and-shallowssrref}%

이 두 함수는 내부적으로 매우 유사하게 동작하는 새로운 컴포저블 `useState`로 대체되었습니다.

핵심 차이점은 이 state에 대해 _key_를 직접 제공해야 한다는 점(기존에는 Nuxt가 `ssrRef`, `shallowSsrRef`에 대해 자동 생성했음)과, 이것이 Nuxt 3 플러그인(`defineNuxtPlugin`으로 정의됨)이나 컴포넌트 인스턴스 안에서만 호출될 수 있다는 점입니다. (즉 요청 간 상태 공유 위험 때문에 [`useState`](/docs/4.x/api/composables/use-state)를 전역/ambient 컨텍스트에서 사용할 수 없습니다.)

```diff
- import { ssrRef } from '@nuxtjs/composition-api'

- const ref1 = ssrRef('initialData')
- const ref2 = ssrRef(() => 'factory function')
+ const ref1 = useState('ref1-key', () => 'initialData')
+ const ref2 = useState('ref2-key', () => 'factory function')
  // state에 접근
  console.log(ref1.value)
```

state가 key 기반이므로 같은 key를 사용하기만 하면 여러 위치에서 동일한 state에 접근할 수 있습니다.

이 컴포저블 사용법은 [Nuxt 3 docs](/docs/4.x/api/composables/use-state)에서 더 읽어볼 수 있습니다.

## `ssrPromise` %{#ssrpromise}%

이 함수는 제거되었으며, 사용 중이었다면 대체 구현을 찾아야 합니다. `ssrPromise`에 대한 사용 사례가 있다면 discussion을 통해 알려 주세요.

## `onGlobalSetup` %{#onglobalsetup}%

이 함수는 제거되었지만, 그 사용 사례는 `defineNuxtPlugin` 안에서 [`useNuxtApp`](/docs/4.x/api/composables/use-nuxt-app) 또는 [`useState`](/docs/4.x/api/composables/use-state)를 사용해 충족할 수 있습니다. 레이아웃의 `setup()` 함수 안에서 사용자 정의 코드를 실행할 수도 있습니다.

```diff
- import { onGlobalSetup } from '@nuxtjs/composition-api'

- export default () => {
-   onGlobalSetup(() => {
+ export default defineNuxtPlugin((nuxtApp) => {
+   nuxtApp.hook('vue:setup', () => {
      // ...
    })
- }
+ })
```

## `useStore` %{#usestore}%

Vuex store 인스턴스에 접근하려면 `useNuxtApp().$store`를 사용할 수 있습니다.

```diff
- import { useStore } from '@nuxtjs/composition-api`
+ const { $store } = useNuxtApp()
```

## `useContext` and `withContext` %{#usecontext-and-withcontext}%

주입된 helper에는 `useNuxtApp`을 사용해 접근할 수 있습니다.

```diff
- import { useContext } from '@nuxtjs/composition-api`
+ const { $axios } = useNuxtApp()
```

::note
`useNuxtApp()`는 `nuxt2Context`라는 키도 제공하는데, 여기에는 보통 Nuxt 2 context에서 접근하던 동일한 속성이 모두 들어 있습니다. 하지만 이것은 Nuxt 3에 존재하지 않으므로 직접 사용하지 _않는_ 것이 좋습니다. 대신 필요한 것에 접근하는 다른 방법이 있는지 확인해 보세요. (없다면 feature request나 discussion을 열어 주세요.)
::

## `wrapProperty` %{#wrapproperty}%

이 helper 함수는 더 이상 제공되지 않지만 다음 코드로 대체할 수 있습니다:

```ts
import { computed, getCurrentInstance } from 'vue'

const wrapProperty = (property: string, makeComputed = true) => () => {
  const vm = getCurrentInstance().proxy
  return makeComputed ? computed(() => vm[property]) : vm[property]
}
```

## `useAsync` and `useFetch` %{#useasync-and-usefetch}%

이 두 컴포저블은 [Nuxt 3 docs](/docs/4.x/getting-started/data-fetching)에 문서화된 `useLazyAsyncData`와 `useLazyFetch`로 대체할 수 있습니다. 이전 `@nuxtjs/composition-api` 컴포저블과 마찬가지로, 이 컴포저블들은 클라이언트 사이드에서 라우트 탐색을 막지 않습니다 (이름에 'lazy'가 붙은 이유입니다).

::important
이름은 비슷하지만 API는 완전히 다르다는 점에 유의하세요. 특히 컴포저블 밖의 다른 변수 값을 바꾸려고 해서는 안 됩니다 (이전 `useFetch`에서는 그렇게 했을 수도 있음).
::

::warning
`useLazyFetch`는 [Nitro](/docs/4.x/bridge/nitro)에 맞게 구성되어 있어야 합니다.
::

`useAsync`에서 새 컴포저블로 마이그레이션:

```diff
<script setup>
- import { useAsync } from '@nuxtjs/composition-api'
- const posts = useAsync(() => $fetch('/api/posts'))
+ const { data: posts } = useLazyAsyncData('posts', () => $fetch('/api/posts'))
+ // 또는 더 간단하게!
+ const { data: posts } = useLazyFetch('/api/posts')
</script>
```

`useFetch`에서 새 컴포저블로 마이그레이션:

```diff
<script setup>
- import { useFetch } from '@nuxtjs/composition-api'
- const posts = ref([])
- const { fetch } = useFetch(() => { posts.value = await $fetch('/api/posts') })
+ const { data: posts, refresh } = useLazyAsyncData('posts', () => $fetch('/api/posts'))
+ // 또는 더 간단하게!
+ const { data: posts, refresh } = useLazyFetch('/api/posts')
  function updatePosts() {
-   return fetch()
+   return refresh()
  }
</script>
```

### `useMeta` %{#usemeta}%

`vue-meta`와 상호작용하려면 `useNuxt2Meta`를 사용할 수 있습니다. 이는 Nuxt Bridge에서는 동작하지만 Nuxt 3에서는 동작하지 않으며, `vue-meta`와 호환되는 방식으로 메타 태그를 조작할 수 있게 해 줍니다.

```diff
<script setup>
- import { useMeta } from '@nuxtjs/composition-api'
  useNuxt2Meta({
    title: 'My Nuxt App',
  })
</script>
```

computed 값이나 ref를 전달할 수도 있으며, 메타 값은 반응형으로 업데이트됩니다:

```vue
<script setup>
const title = ref('내 제목')
useNuxt2Meta({
  title,
})
title.value = '새 제목'
</script>
```

::note
동작이 예측 불가능해질 수 있으므로 같은 컴포넌트 안에서 `useNuxt2Meta()`와 Options API `head()`를 함께 사용하지 않도록 주의하세요.
::

Nuxt Bridge는 [`useHead`](/docs/4.x/api/composables/use-head) 컴포저블로 접근할 수 있는 Nuxt 3 호환 메타 구현도 제공합니다.

```diff
<script setup>
- import { useMeta } from '@nuxtjs/composition-api'
  useHead({
    title: 'My Nuxt App',
  })
</script>
```

You will also need to enable it explicitly in your `nuxt.config`:

```js
import { defineNuxtConfig } from '@nuxt/bridge'

export default defineNuxtConfig({
  bridge: {
    meta: true,
  },
})
```

이 [`useHead`](/docs/4.x/api/composables/use-head) 컴포저블은 내부적으로 `vue-meta`가 아니라 `@unhead/vue`를 사용해 `<head>`를 조작합니다. 따라서 충돌할 수 있으므로 기본 Nuxt 2 `head()` 속성과 [`useHead`](/docs/4.x/api/composables/use-head)를 함께 사용하지 않는 것이 좋습니다.

이 컴포저블 사용법에 대한 자세한 내용은 [Nuxt 3 docs](/docs/4.x/getting-started/seo-meta)를 참고하세요.

### 명시적 Imports %{#explicit-imports}%

Nuxt는 모든 auto-import를 `#imports` 별칭으로 노출하므로 필요할 때 import를 명시적으로 작성할 수 있습니다:

```vue
<script setup lang="ts">
import { computed, ref } from '#imports'

const count = ref(1)
const double = computed(() => count.value * 2)
</script>
```

### Auto-imports 비활성화 %{#disabling-auto-imports}%

컴포저블과 유틸리티의 auto-import를 비활성화하고 싶다면 `nuxt.config` 파일에서 `imports.autoImport`를 `false`로 설정할 수 있습니다.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  imports: {
    autoImport: false,
  },
})
```

이렇게 하면 auto-import가 완전히 비활성화되지만, 여전히 `#imports`에서 [명시적 imports](/docs/4.x/bridge/nuxt3-compatible-api#explicit-imports)를 사용할 수 있습니다.
