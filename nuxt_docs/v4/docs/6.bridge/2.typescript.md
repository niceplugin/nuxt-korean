## 모듈 제거 %{#remove-modules}%

- `@nuxt/typescript-build` 제거: Bridge가 동일한 기능을 활성화합니다
- `@nuxt/typescript-runtime`와 `nuxt-ts` 제거: Nuxt 2에는 런타임 지원이 내장되어 있습니다

### `bridge.typescript` 설정 %{#set-bridge-typescript}%

```ts
import { defineNuxtConfig } from '@nuxt/bridge'

export default defineNuxtConfig({
  bridge: {
    typescript: true,
    nitro: false, // Nitro 마이그레이션이 완료되었다면 true로 설정
  },
})
```

## `tsconfig.json` 업데이트 %{#update-tsconfig-json}%

TypeScript를 사용 중이라면 자동 생성되는 Nuxt 타입의 이점을 얻기 위해 `tsconfig.json`을 수정할 수 있습니다:

```diff [tsconfig.json]
{
+ "extends": "./.nuxt/tsconfig.json",
  "compilerOptions": {
    ...
  }
}
```

::note
`.nuxt/tsconfig.json`은 생성되는 파일이며 버전 관리에 포함되지 않으므로, 테스트를 실행하기 전에 해당 파일을 생성해야 합니다. 테스트 전에 `nuxi prepare`를 단계로 추가하세요. 그렇지 않으면 `TS5083: Cannot read file '~/.nuxt/tsconfig.json'` 오류가 표시됩니다.

현대적인 Nuxt 프로젝트에서는 `.nuxt/tsconfig.json`을 직접 확장하는 대신 [TypeScript project references](/docs/4.x/directory-structure/tsconfig)를 사용하는 것을 권장합니다.
::

::note
`./.nuxt/tsconfig.json`에서 확장된 모든 옵션은 `tsconfig.json`에 정의된 옵션으로 덮어써진다는 점을 기억하세요.
`"compilerOptions.paths"` 같은 옵션을 자체 설정으로 덮어쓰면 TypeScript가 `./.nuxt/tsconfig.json`의 모듈 해석을 반영하지 않게 됩니다. 그 결과 `#imports` 같은 모듈 해석이 인식되지 않을 수 있습니다.

`./.nuxt/tsconfig.json`이 제공하는 옵션을 더 확장해야 한다면 `nuxt.config`의 `alias` 속성을 사용할 수 있습니다. `nuxi`가 이를 읽어 `./.nuxt/tsconfig.json`을 그에 맞게 확장합니다.
::
