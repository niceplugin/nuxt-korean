---
title: 레거시 Composition API
description: 'Nuxt Bridge로 Composition API로 마이그레이션하는 방법을 알아보세요.'
---

Nuxt Bridge는 Composition API 문법에 대한 접근을 제공합니다. 이는 Nuxt 3와 정렬되도록 특별히 설계되었습니다. 이런 이유로 이전에 Composition API를 사용하고 있었다면 Nuxt Bridge를 활성화할 때 몇 가지 추가 단계가 필요합니다.

## 모듈 제거 %{#remove-modules}%

- 의존성에서 `@vue/composition-api`를 제거합니다.
- 의존성에서 `@nuxtjs/composition-api`를 제거합니다 (`nuxt.config`의 modules에서도 제거).

## `@vue/composition-api` 사용하기 %{#using-vue-composition-api}%

`@nuxtjs/composition-api`가 아니라 `@vue/composition-api`만 사용해 왔다면 매우 간단합니다.

1. 먼저 Composition API를 수동 등록하던 플러그인을 제거합니다. Nuxt Bridge가 이를 대신 처리합니다.

   ```diff
   - import Vue from 'vue'
   - import VueCompositionApi from '@vue/composition-api'
   -
   - Vue.use(VueCompositionApi)
   ```

2. 그 외에는 아무것도 할 필요가 없습니다. 원한다면 `@vue/composition-api`에서의 명시적 import를 제거하고 Nuxt Bridge의 자동 import에 맡길 수도 있습니다.

## `@nuxtjs/composition-api`에서 마이그레이션 %{#migrating-from-nuxtjs-composition-api}%

Nuxt Bridge는 `@nuxtjs/composition-api`와 약간 다르게 Composition API를 구현하며, 다른 컴포저블을 제공합니다 (Nuxt 3가 제공하는 컴포저블과 정렬되도록 설계됨).

일부 컴포저블은 제거되었고 아직 대체제가 없기 때문에 이 과정은 조금 더 복잡합니다.

### buildModules에서 `@nuxtjs/composition-api/module` 제거 %{#remove-nuxtjs-composition-api-module-from-your-buildmodules}%

아직 import를 즉시 업데이트할 필요는 없습니다. Nuxt Bridge가 현재 사용하는 대부분의 import에 대해 자동으로 'shim'을 제공하여 Nuxt 3 호환 컴포저블로 마이그레이션할 시간을 확보해 줍니다. 단, 다음 예외가 있습니다:

- `withContext`는 제거되었습니다. [아래](/docs/4.x/bridge/nuxt3-compatible-api#usecontext-and-withcontext)를 참고하세요.
- `useStatic`는 제거되었습니다. 현재 대체제는 없습니다. 이에 대한 사용 사례가 있다면 discussion을 열어 주세요.
- 더 이상 권장되지 않던 `reqRef`와 `reqSsrRef`도 이제 완전히 제거되었습니다. 이를 대체하려면 아래의 [ssrRef](/docs/4.x/bridge/nuxt3-compatible-api#ssrref-and-shallowssrref) 관련 지침을 따르세요.

### `bridge.capi` 설정 %{#set-bridge-capi}%

```ts
import { defineNuxtConfig } from '@nuxt/bridge'

export default defineNuxtConfig({
  bridge: {
    capi: true,
    nitro: false, // Nitro로의 마이그레이션이 완료되면 true로 설정
  },
})
```

`@nuxtjs/composition-api`에서 사용 중인 다른 각 컴포저블에 대해서는 아래 단계를 따르세요.

### useFetch %{#usefetch}%

`$fetchState`와 `$fetch`는 제거되었습니다.

```diff
const {
- $fetch,
- $fetchState,
+ fetch,
+ fetchState,
} = useFetch(() => { posts.value = await $fetch('/api/posts') })
```

### `defineNuxtMiddleware` %{#definenuxtmiddleware}%

이것은 타입 헬퍼 스텁 함수였으며 이제 제거되었습니다.

`defineNuxtMiddleware` 래퍼를 제거하세요:

```diff
- import { defineNuxtMiddleware } from '@nuxtjs/composition-api`
- export default defineNuxtMiddleware((ctx) => {})
+ export default (ctx) => {}
```

TypeScript 지원을 위해 `@nuxt/types`를 사용할 수 있습니다:

```ts
import type { Middleware } from '@nuxt/types'

export default <Middleware> function (ctx) { }
```

### `defineNuxtPlugin` %{#definenuxtplugin}%

이것은 타입 헬퍼 스텁 함수였으며 이제 제거되었습니다.

[defineNuxtMiddleware](/docs/4.x/bridge/bridge-composition-api#definenuxtmiddleware)와 마찬가지로 함수를 제거해 Nuxt 2 스타일 플러그인을 계속 사용할 수도 있습니다.

`defineNuxtPlugin` 래퍼를 제거하세요:

```diff
- import { defineNuxtPlugin } from '@nuxtjs/composition-api'
- export default defineNuxtPlugin((ctx, inject) => {})
+ export default (ctx, inject) => {}
```

TypeScript 지원을 위해 `@nuxt/types`를 사용할 수 있습니다:

```ts
import type { Plugin } from '@nuxt/types'

export default <Plugin> function (ctx, inject) {}
```

::warning
이 예시는 유효하지만, Nuxt 3는 시그니처가 약간 다른 새로운 defineNuxtPlugin 함수를 도입합니다.
::

:ReadMore{link="/docs/4.x/directory-structure/app/plugins#creating-plugins"}

### `useRouter` and `useRoute` %{#userouter-and-useroute}%

Nuxt Bridge는 [`useRouter`](/docs/4.x/api/composables/use-router)와 `useRoute`를 통해 이 컴포저블들에 대한 직접적인 대체제를 제공합니다.

유일한 핵심 차이점은 [`useRoute`](/docs/4.x/api/composables/use-route)가 더 이상 computed property를 반환하지 않는다는 점입니다.

```diff
- import { useRouter, useRoute } from '@nuxtjs/composition-api'

  const router = useRouter()
  const route = useRoute()

- console.log(route.value.path)
+ console.log(route.path)
```
