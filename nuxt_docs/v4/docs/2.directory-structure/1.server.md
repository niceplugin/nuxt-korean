Nuxt는 이 디렉터리 안의 파일을 자동으로 스캔하여 HMR(Hot Module Replacement) 지원과 함께 API 및 서버 핸들러를 등록합니다.

```bash [Directory structure]
-| server/
---| api/
-----| hello.ts      # /api/hello
---| routes/
-----| bonjour.ts    # /bonjour
---| middleware/
-----| log.ts        # 모든 요청 로그 기록
```

각 파일은 `defineEventHandler()` 또는 `eventHandler()`(별칭)로 정의한 기본 함수를 export해야 합니다.

핸들러는 JSON 데이터, `Promise`, 또는 `Response` 객체를 직접 반환할 수 있습니다.

```ts twoslash [server/api/hello.ts]
import { defineEventHandler } from 'nitro/h3'

export default defineEventHandler((event) => {
  return {
    hello: '세계',
  }
})
```

이제 페이지와 컴포넌트에서 이 API를 공통적으로 호출할 수 있습니다:

```vue [app/pages/index.vue]
<script setup lang="ts">
const { data } = await useFetch('/api/hello')
</script>

<template>
  <pre>{{ data }}</pre>
</template>
```

## 서버 라우트 %{#server-routes}%

`~~/server/api` 안의 파일은 라우트에서 자동으로 `/api` 접두사를 갖습니다.

:video-accordion{title="API 라우트에 대한 Vue School 영상 보기" videoId="761468863" platform="vimeo"}

`/api` 접두사 없이 서버 라우트를 추가하려면 `~~/server/routes` 디렉터리에 두세요.

**예시:**

```ts [server/routes/hello.ts]
export default defineEventHandler(() => '안녕하세요 세계!')
```

위 예시에서는 `/hello` 라우트에 <http://localhost:3000/hello>에서 접근할 수 있습니다.

::note
현재 서버 라우트는 [pages](/docs/4.x/directory-structure/app/pages#dynamic-routes)처럼 동적 라우트의 전체 기능을 지원하지 않는다는 점에 유의하세요.
::

## 서버 미들웨어 %{#server-middleware}%

Nuxt는 프로젝트용 서버 미들웨어를 만들기 위해 `~~/server/middleware` 안의 모든 파일을 자동으로 읽어들입니다.

미들웨어 핸들러는 다른 모든 서버 라우트보다 먼저 모든 요청에서 실행되며, 헤더를 추가하거나 확인하고, 요청을 기록하거나, event의 request 객체를 확장할 수 있습니다.

::note
미들웨어 핸들러는 아무것도 반환하지 않아야 하며(요청을 닫거나 응답해서도 안 됨), 요청 컨텍스트를 검사하거나 확장하거나 오류를 던지는 역할만 해야 합니다.
::

**예시:**

```ts [server/middleware/log.ts]
export default defineEventHandler((event) => {
  console.log('새 요청: ' + getRequestURL(event))
})
```

```ts [server/middleware/auth.ts]
export default defineEventHandler((event) => {
  event.context.auth = { user: 123 }
})
```

## 서버 플러그인 %{#server-plugins}%

Nuxt는 `~~/server/plugins` 디렉터리 안의 모든 파일을 자동으로 읽어 Nitro 플러그인으로 등록합니다. 이를 통해 Nitro의 런타임 동작을 확장하고 라이프사이클 이벤트에 훅을 걸 수 있습니다.

**예시:**

```ts [server/plugins/nitroPlugin.ts]
import { definePlugin } from 'nitro'

export default definePlugin((nitroApp) => {
  console.log('Nitro 플러그인', nitroApp)
})
```

:read-more{to="https://nitro.build/guide/plugins" title="Nitro Plugins" target="_blank"}

## 서버 유틸리티 %{#server-utilities}%

서버 라우트는 [h3js/h3](https://github.com/h3js/h3) 기반으로 동작하며, 편리한 헬퍼 집합을 함께 제공합니다.

:read-more{to="https://www.jsdocs.io/package/h3#package-index-functions" title="Available H3 Request Helpers" target="_blank"}

`~~/server/utils` 디렉터리 안에 직접 더 많은 헬퍼를 추가할 수도 있습니다.

예를 들어, 원래 핸들러를 감싸고 최종 응답을 반환하기 전에 추가 작업을 수행하는 사용자 정의 핸들러 유틸리티를 정의할 수 있습니다.

**예시:**

```ts [server/utils/handler.ts]
export const defineWrappedResponseHandler = <T extends EventHandlerRequest, D> (
  handler: EventHandler<T, D>,
): EventHandler<T, D> =>
  defineEventHandler<T>(async (event) => {
    try {
      // 라우트 핸들러 전에 작업 수행
      const response = await handler(event)
      // 라우트 핸들러 후에 작업 수행
      return { response }
    } catch (err) {
      // 오류 처리
      return { err }
    }
  })
```

```ts [server/api/hello.get.ts]
export default defineWrappedResponseHandler(event => '안녕하세요 세계')
```

## 서버 별칭 %{#server-alias}%

가져오는 파일의 위치와 관계없이 `server/` 디렉터리 안의 파일을 import하기 위해 `#server` 별칭을 사용할 수 있습니다.

```ts [server/api/users/[id]/profile.ts]
// 이런 상대 경로 대신:
// import { formatUser } from '../../../utils/formatUser'

// #server 별칭을 사용하세요:
import { formatUser } from '#server/utils/formatUser'
```

이 별칭은 특히 깊게 중첩된 라우트 핸들러에서 서버 코드 전반에 걸쳐 일관된 import를 보장합니다.

::note
`#server` 별칭은 `server/` 디렉터리 안에서만 사용할 수 있습니다. 클라이언트 코드에서 `#server`를 import하면 오류가 발생합니다.
::

## 서버 타입 %{#server-types}%

`server/` 디렉터리는 `app/` 디렉터리와 다른 컨텍스트에서 실행되므로 auto-import와 기타 타입도 서로 다릅니다.

기본적으로 Nuxt 4는 `server/` 폴더를 포함하는 프로젝트 참조가 들어간 [`tsconfig.json`](/docs/4.x/directory-structure/tsconfig)을 생성하며, 이를 통해 정확한 타입 정보를 보장합니다.

## 레시피 %{#recipes}%

### 라우트 파라미터 %{#route-parameters}%

서버 라우트는 `/api/hello/[name].ts`처럼 파일명에 대괄호를 사용한 동적 파라미터를 사용할 수 있으며 `event.context.params`를 통해 접근할 수 있습니다.

```ts [server/api/hello/[name\\].ts]
export default defineEventHandler((event) => {
  const name = getRouterParam(event, 'name')

  return `안녕하세요, ${name}!`
})
```

::tip{to="https://h3.dev/examples/validate-data#validate-params"}
또는 런타임 및 타입 안전성을 위해 Zod 같은 스키마 검증기와 함께 `getValidatedRouterParams`를 사용하세요.
::

이제 `/api/hello/nuxt`에서 이 API를 공통적으로 호출하면 `안녕하세요, nuxt!`를 받을 수 있습니다.

### HTTP 메서드 매칭 %{#matching-http-method}%

핸들러 파일명에는 요청의 [HTTP Method](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Methods)에 맞추기 위해 `.get`, `.post`, `.put`, `.delete` 등의 접미사를 붙일 수 있습니다.

```ts [server/api/test.get.ts]
export default defineEventHandler(() => 'GET 테스트 핸들러')
```

```ts [server/api/test.post.ts]
export default defineEventHandler(() => 'POST 테스트 핸들러')
```

위 예시에서 `/test`를 다음과 같이 요청하면:

- **GET** 메서드: `GET 테스트 핸들러` 반환
- **POST** 메서드: `POST 테스트 핸들러` 반환
- 다른 모든 메서드: 405 오류 반환

디렉터리 안에서 `index.[method].ts`를 사용해 코드를 다른 방식으로 구조화할 수도 있으며, 이는 API 네임스페이스를 만들 때 유용합니다.

::code-group
```ts [server/api/foo/index.get.ts]
export default defineEventHandler((event) => {
  // `api/foo` 엔드포인트에 대한 GET 요청 처리
})
```
```ts [server/api/foo/index.post.ts]
export default defineEventHandler((event) => {
  // `api/foo` 엔드포인트에 대한 POST 요청 처리
})
```
```ts [server/api/foo/bar.get.ts]
export default defineEventHandler((event) => {
  // `api/foo/bar` 엔드포인트에 대한 GET 요청 처리
})
```
::

### Catch-all 라우트 %{#catch-all-route}%

Catch-all 라우트는 fallback 라우트 처리에 유용합니다.

예를 들어 `~~/server/api/foo/[...].ts`라는 파일을 만들면 `/api/foo/bar/baz`처럼 어떤 라우트 핸들러와도 매칭되지 않는 모든 요청에 대한 catch-all 라우트가 등록됩니다.

```ts [server/api/foo/[...\\].ts]
export default defineEventHandler((event) => {
  // event.context.path로 라우트 경로 가져오기: '/api/foo/bar/baz'
  // event.context.params._로 라우트 세그먼트 가져오기: 'bar/baz'
  return `기본 foo 핸들러`
})
```

`~~/server/api/foo/[...slug].ts`를 사용해 catch-all 라우트에 이름을 붙일 수 있으며 `event.context.params.slug`로 접근할 수 있습니다.

```ts [server/api/foo/[...slug\\].ts]
export default defineEventHandler((event) => {
  // event.context.params.slug로 라우트 세그먼트 가져오기: 'bar/baz'
  return `기본 foo 핸들러`
})
```

### 본문 처리 %{#body-handling}%

```ts [server/api/submit.post.ts]
export default defineEventHandler(async (event) => {
  const body = await readBody(event)
  return { body }
})
```

::tip{to="https://unjs.io/blog/2023-08-15-h3-towards-the-edge-of-the-web/#runtime-type-safe-request-utils"}
또는 런타임 및 타입 안전성을 위해 Zod 같은 스키마 검증기와 함께 `readValidatedBody`를 사용하세요.
::

이제 다음과 같이 이 API를 공통적으로 호출할 수 있습니다:

```vue [app/app.vue]
<script setup lang="ts">
async function submit () {
  const { body } = await $fetch('/api/submit', {
    method: 'post',
    body: { test: 123 },
  })
}
</script>
```

::note
파일명에서 `submit.post.ts`를 사용하는 이유는 request body를 받을 수 있는 `POST` 메서드 요청에만 매칭하기 위해서입니다. GET 요청 안에서 `readBody`를 사용하면 `readBody`는 `405 Method Not Allowed` HTTP 오류를 던집니다.
::

### 오류 처리 %{#error-handling}%

오류가 전혀 발생하지 않으면 `200 OK` 상태 코드가 반환됩니다.

잡히지 않은 모든 오류는 `500 Internal Server Error` HTTP Error를 반환합니다.

다른 오류 코드를 반환하려면 [`createError`](/docs/4.x/api/utils/create-error)와 함께 예외를 던지세요:

```ts [server/api/validation/[id\\].ts]
export default defineEventHandler((event) => {
  const id = Number.parseInt(event.context.params.id) as number

  if (!Number.isInteger(id)) {
    throw createError({
      status: 400,
      statusText: 'ID는 정수여야 합니다',
    })
  }
  return '모든 것이 정상입니다'
})
```

### 상태 코드 %{#status-codes}%

다른 상태 코드를 반환하려면 [`setResponseStatus`](/docs/4.x/api/utils/set-response-status) 유틸리티를 사용하세요.

예를 들어 `202 Accepted`를 반환하려면

```ts [server/api/validation/[id\\].ts]
export default defineEventHandler((event) => {
  setResponseStatus(event, 202)
})
```

### Runtime Config %{#runtime-config}%

::code-group
```ts [server/api/foo.ts]
export default defineEventHandler(async (event) => {
  const config = useRuntimeConfig()

  const repo = await $fetch('https://api.github.com/repos/nuxt/nuxt', {
    headers: {
      Authorization: `token ${config.githubToken}`,
    },
  })

  return repo
})
```
```ts [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    githubToken: '',
  },
})
```
```ini [.env]
NUXT_GITHUB_TOKEN='<my-super-token>'
```
::

::note
`useRuntimeConfig`에 `event`를 인수로 전달하는 것은 선택 사항이지만, 서버 라우트에서 런타임에 [environment variables](/docs/4.x/guide/going-further/runtime-config#environment-variables)로 덮어쓴 런타임 설정을 얻으려면 전달하는 것을 권장합니다.
::

### 컨텍스트 및 헤더 전달 %{#forwarding-context-headers}%

기본적으로 서버 라우트에서 fetch 요청을 만들 때는 들어오는 요청의 헤더도 request context도 전달되지
않습니다. 서버 라우트에서 fetch 요청을 만들 때 request context와 헤더를 전달하려면 `event.$fetch`를 사용할 수 있습니다.

```ts [server/api/forward.ts]
export default defineEventHandler((event) => {
  return event.$fetch('/api/forwarded')
})
```

::note
**전달되면 안 되는** 헤더는 요청에 **포함되지 않습니다**. 예를 들어 다음 헤더가 여기에 포함됩니다:
`transfer-encoding`, `connection`, `keep-alive`, `upgrade`, `expect`, `host`, `accept`
::

### 응답 후 Promise 대기 %{#awaiting-promises-after-response}%

서버 요청을 처리할 때 클라이언트 응답을 막지 않아야 하는 비동기 작업(예: 캐싱, 로깅)을 수행해야 할 수 있습니다. `event.waitUntil`을 사용하면 응답을 지연시키지 않고 백그라운드에서 Promise를 기다릴 수 있습니다.

`event.waitUntil` 메서드는 핸들러가 종료되기 전에 기다릴 Promise를 받아, 서버가 응답을 보낸 직후 핸들러를 종료하더라도 작업이 완료되도록 보장합니다. 이는 런타임 프로바이더와 통합되어 응답 전송 후 비동기 작업을 처리하는 네이티브 기능을 활용할 수 있게 합니다.

```ts [server/api/background-task.ts]
const timeConsumingBackgroundTask = async () => {
  await new Promise(resolve => setTimeout(resolve, 1000))
}

export default eventHandler((event) => {
  // 응답을 막지 않고 백그라운드 작업 예약
  event.waitUntil(timeConsumingBackgroundTask())

  // 클라이언트에 즉시 응답 전송
  return '완료'
})
```

### 중첩 라우터 %{#nested-router}%

### 레거시 핸들러 또는 미들웨어 %{#legacy-handler-or-middleware}%

```ts [server/api/legacy.ts]
export default fromNodeMiddleware((req, res) => {
  res.end('레거시 핸들러')
})
```

::important
[h3js/h3](https://github.com/h3js/h3)를 사용해 레거시 지원이 가능하지만, 가능한 한 레거시 핸들러는 피하는 것이 좋습니다.
::

```ts [server/middleware/legacy.ts]
export default fromNodeMiddleware((req, res, next) => {
  console.log('레거시 미들웨어')
  next()
})
```

::warning
`async`이거나 `Promise`를 반환하는 레거시 미들웨어와 `next()` 콜백을 절대 함께 사용하지 마세요.

### 서버 스토리지 %{#server-storage}%

Nitro는 크로스플랫폼 [스토리지 레이어](https://nitro.build/guide/storage)를 제공합니다. 추가 스토리지 마운트 지점을 설정하려면 `nitro.storage` 또는 [server plugins](/docs/4.x/directory-structure/server#server-plugins)를 사용할 수 있습니다.

**Redis 스토리지를 추가하는 예시:**

`nitro.storage` 사용:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  nitro: {
    storage: {
      redis: {
        driver: 'redis',
        /* redis 커넥터 옵션 */
        port: 6379, // Redis 포트
        host: '127.0.0.1', // Redis 호스트
        username: '', // Redis >= 6 필요
        password: '',
        db: 0, // 기본값은 0
        tls: {}, // tls/ssl
      },
    },
  },
})
```

그런 다음 API 핸들러에서:

```ts [server/api/storage/test.ts]
export default defineEventHandler(async (event) => {
  // 모든 키 목록 가져오기
  const keys = await useStorage('redis').getKeys()

  // 키 설정하기
  await useStorage('redis').setItem('foo', 'bar')

  // 키 삭제하기
  await useStorage('redis').removeItem('foo')

  return {}
})
```

Nitro Storage Layer에 대해 더 알아보세요.

또는 server plugin과 runtime config를 사용해 스토리지 마운트 지점을 만들 수도 있습니다:

::code-group
```ts [server/plugins/storage.ts]
import { definePlugin } from 'nitro'
import redisDriver from 'unstorage/drivers/redis'

export default definePlugin(() => {
  const storage = useStorage()

  // 런타임 설정 또는 다른 소스에서 자격 증명을 동적으로 전달합니다
  const driver = redisDriver({
    base: 'redis',
    host: useRuntimeConfig().redis.host,
    port: useRuntimeConfig().redis.port,
    /* 다른 redis 커넥터 옵션 */
  })

  // 드라이버 마운트
  storage.mount('redis', driver)
})
```

``` ts [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    redis: { // 기본값
      host: '',
      port: 0,
      /* 다른 redis 커넥터 옵션 */
    },
  },
})
```
