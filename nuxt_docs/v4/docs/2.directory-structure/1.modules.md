애플리케이션을 구축하면서 개발하는 모든 로컬 모듈을 두기에 좋은 위치입니다.

자동 등록되는 파일 패턴은 다음과 같습니다:
- `modules/*/index.ts`
- `modules/*.ts`

이런 로컬 모듈은 [`nuxt.config.ts`](/docs/4.x/directory-structure/nuxt-config)에 따로 추가할 필요가 없습니다.

::code-group

```ts twoslash [modules/hello/index.ts]
// `nuxt/kit`은 로컬 모듈을 정의할 때 사용할 수 있는 helper subpath import입니다
// 즉, 프로젝트 의존성에 `@nuxt/kit`을 추가할 필요가 없습니다
import { addComponentsDir, addServerHandler, createResolver, defineNuxtModule } from 'nuxt/kit'

export default defineNuxtModule({
  meta: {
    name: 'hello',
  },
  setup () {
    const resolver = createResolver(import.meta.url)

    // API 라우트 추가
    addServerHandler({
      route: '/api/hello',
      handler: resolver.resolve('./runtime/api-route'),
    })

    // 컴포넌트 추가
    addComponentsDir({
      path: resolver.resolve('./runtime/app/components'),
      pathPrefix: true, // 사용자 코드나 다른 모듈과 충돌하지 않도록 export에 접두사를 붙입니다
    })
  },
})
```

```ts twoslash [modules/hello/runtime/api-route.ts]
import { defineEventHandler } from 'nitro/h3'

export default defineEventHandler(() => {
  return { hello: 'world' }
})
```

::

Nuxt를 시작하면 `hello` 모듈이 등록되고 `/api/hello` 라우트를 사용할 수 있게 됩니다.

::note
일반적으로 `app/` 디렉터리에 두는 모든 컴포넌트, 페이지, 컴포저블 및 기타 파일은 `modules/your-module/runtime/app/` 안에 있어야 한다는 점에 유의하세요. 그래야 올바르게 타입 검사할 수 있습니다.
::

모듈은 다음 순서로 실행됩니다:
- 먼저 [`nuxt.config.ts`](/docs/4.x/api/nuxt-config#modules-1)에 정의된 모듈이 로드됩니다.
- 그다음 `modules/` 디렉터리에서 찾은 모듈이 실행되며, 알파벳순으로 로드됩니다.

각 디렉터리 이름 앞에 숫자를 붙여 로컬 모듈의 순서를 바꿀 수 있습니다:

```bash [Directory structure]
modules/
  1.first-module/
    index.ts
  2.second-module.ts
```
