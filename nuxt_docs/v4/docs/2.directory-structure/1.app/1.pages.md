애플리케이션 번들 크기를 줄이기 위해 이 디렉터리는 **선택 사항**입니다. 즉 [`app.vue`](/docs/4.x/directory-structure/app/app)만 사용한다면 [`vue-router`](https://router.vuejs.org)는 포함되지 않습니다. pages 시스템을 강제로 사용하려면 `nuxt.config`에서 `pages: true`를 설정하거나 [`router.options.ts`](/docs/4.x/guide/recipes/custom-routing#using-routeroptions)를 두세요.
::

## 사용법 %{#usage}%

pages는 Vue 컴포넌트이며 Nuxt가 지원하는 모든 [유효한 확장자](/docs/4.x/api/nuxt-config#extensions)를 사용할 수 있습니다(기본값은 `.vue`, `.js`, `.jsx`, `.mjs`, `.ts`, `.tsx`).

Nuxt는 `~/pages/` 디렉터리의 각 페이지에 대해 자동으로 라우트를 만듭니다.

::code-group

```vue [app/pages/index.vue]
<template>
  <h1>인덱스 페이지</h1>
</template>
```

```ts twoslash [pages/index.ts]
// https://vuejs.org/guide/extras/render-function.html
export default defineComponent({
  render () {
    return h('h1', '인덱스 페이지')
  },
})
```

```tsx twoslash [pages/index.tsx]
// https://nuxt.com/docs/4.x/examples/advanced/jsx
// https://vuejs.org/guide/extras/render-function.html#jsx-tsx
export default defineComponent({
  render () {
    return <h1>인덱스 페이지</h1>
  },
})
```

::

`app/pages/index.vue` 파일은 애플리케이션의 `/` 라우트에 매핑됩니다.

[`app.vue`](/docs/4.x/directory-structure/app/app)를 사용한다면 현재 페이지를 표시하기 위해 [`<NuxtPage/>`](/docs/4.x/api/components/nuxt-page) 컴포넌트를 사용해야 합니다:

```vue [app/app.vue]
<template>
  <div>
    <!-- 모든 페이지에서 공유되는 마크업, 예: NavBar -->
    <NuxtPage />
  </div>
</template>
```

pages는 페이지 간 [route transitions](/docs/4.x/getting-started/transitions)를 허용하려면 **반드시 단일 루트 요소**를 가져야 합니다. HTML 주석도 요소로 간주됩니다.

즉, 라우트가 서버 렌더링되거나 정적으로 생성될 때는 내용을 정상적으로 볼 수 있지만, 클라이언트 측 내비게이션 중 해당 라우트로 이동하면 라우트 간 트랜지션이 실패하고 해당 라우트가 렌더링되지 않는 것을 보게 됩니다.

단일 루트 요소를 가진 페이지가 어떤 모습인지 보여주는 예시는 다음과 같습니다:

::code-group

```vue [app/pages/working.vue]
<template>
  <div>
    <!-- 이 페이지는 올바르게 단 하나의 루트 요소만 가집니다 -->
    페이지 콘텐츠
  </div>
</template>
```

```vue [app/pages/bad-1.vue]
<template>
  <!-- 이 페이지는 이 주석 때문에 클라이언트 측 내비게이션 중 라우트가 바뀌면 렌더링되지 않습니다 -->
  <div>페이지 콘텐츠</div>
</template>
```

```vue [app/pages/bad-2.vue]
<template>
  <div>이 페이지는</div>
  <div>루트 요소가 하나보다 많고</div>
  <div>클라이언트 측 내비게이션 중 라우트가 바뀌면 렌더링되지 않습니다</div>
</template>
```

::

## 동적 라우트 %{#dynamic-routes}%

대괄호 안에 무엇이든 넣으면 [동적 라우트](https://router.vuejs.org/guide/essentials/dynamic-matching) 파라미터로 변환됩니다. 파일명이나 디렉터리 안에서 여러 파라미터와 비동적 텍스트를 함께 조합할 수도 있습니다.

파라미터를 _선택 사항_ 으로 만들고 싶다면 이중 대괄호로 감싸야 합니다. 예를 들어 `~/pages/[[slug]]/index.vue` 또는 `~/pages/[[slug]].vue`는 `/`와 `/test` 모두에 매칭됩니다.

```bash [Directory Structure]
-| pages/
---| index.vue
---| users-[group]/
-----| [id].vue
```

위 예시에서는 컴포넌트 안에서 `$route` 객체를 통해 group/id에 접근할 수 있습니다:

```vue [app/pages/users-[group\\]/[id\\].vue]
<template>
  <p>{{ $route.params.group }} - {{ $route.params.id }}</p>
</template>
```

`/users-admins/123`으로 이동하면 다음이 렌더링됩니다:

```html
<p>admins - 123</p>
```

Composition API로 라우트에 접근하고 싶다면, Options API의 `this.$route`처럼 라우트에 접근할 수 있는 전역 [`useRoute`](/docs/4.x/api/composables/use-route) 함수가 있습니다.

```vue twoslash
<script setup lang="ts">
const route = useRoute()

if (route.params.group === 'admins' && !route.params.id) {
  console.log('경고! 사용자가 인증되었는지 확인하세요!')
}
</script>
```

::note
이름 있는 부모 라우트는 중첩된 동적 라우트보다 우선합니다. `/foo/hello` 라우트에서는 `~/pages/foo.vue`가 `~/pages/foo/[slug].vue`보다 우선합니다. :br `/foo`와 `/foo/hello`를 서로 다른 페이지로 매칭하려면 `~/pages/foo/index.vue`와 `~/pages/foo/[slug].vue`를 사용하세요.
::

## Catch-all 라우트 %{#catch-all-route}%

catch-all 라우트가 필요하다면 `[...slug].vue` 같은 이름의 파일을 사용해 만들 수 있습니다. 이 파일은 해당 경로 아래의 _모든_ 라우트와 매칭됩니다.

```vue [app/pages/[...slug\\].vue]
<template>
  <p>{{ $route.params.slug }}</p>
</template>
```

`/hello/world`로 이동하면 다음이 렌더링됩니다:

```html
<p>["hello", "world"]</p>
```

## 중첩 라우트 %{#nested-routes}%

`<NuxtPage>`로 [중첩 라우트](https://router.vuejs.org/guide/essentials/nested-routes)를 표시할 수 있습니다.

예시:

```bash [Directory Structure]
-| pages/
---| parent/
-----| child.vue
---| parent.vue
```

이 파일 트리는 다음 라우트를 생성합니다:

```js
[
  {
    path: '/parent',
    component: '~/pages/parent.vue',
    name: 'parent',
    children: [
      {
        path: 'child',
        component: '~/pages/parent/child.vue',
        name: 'parent-child',
      },
    ],
  },
]
```

`child.vue` 컴포넌트를 표시하려면 `app/pages/parent.vue` 안에 `<NuxtPage>` 컴포넌트를 삽입해야 합니다:

```vue {}[pages/parent.vue]
<template>
  <div>
    <h1>저는 부모 뷰입니다</h1>
    <NuxtPage :foobar="123" />
  </div>
</template>
```

```vue {}[pages/parent/child.vue]
<script setup lang="ts">
const props = defineProps({
  foobar: String,
})

console.log(props.foobar)
</script>
```

### 자식 라우트 키 %{#child-route-keys}%

`<NuxtPage>` 컴포넌트가 언제 다시 렌더링될지(예: 트랜지션을 위해) 더 세밀하게 제어하고 싶다면 `pageKey` prop에 문자열이나 함수를 전달하거나 `definePageMeta`를 통해 `key` 값을 정의할 수 있습니다:

```vue {}[pages/parent.vue]
<template>
  <div>
    <h1>저는 부모 뷰입니다</h1>
    <NuxtPage :page-key="route => route.fullPath" />
  </div>
</template>
```

또는 다음과 같이 할 수 있습니다:

```vue twoslash {}[pages/parent/child.vue]
<script setup lang="ts">
definePageMeta({
  key: route => route.fullPath,
})
</script>
```

## 라우트 그룹 %{#route-groups}%

경우에 따라 파일 기반 라우팅에는 영향을 주지 않으면서 라우트 집합을 함께 묶고 싶을 수 있습니다. 이를 위해 괄호 `(`, `)`로 감싼 폴더 안에 파일을 넣을 수 있습니다.

예를 들면:

```bash [Directory structure]
-| pages/
---| index.vue
---| (marketing)/
-----| about.vue
-----| contact.vue
```

이렇게 하면 앱에 `/`, `/about`, `/contact` 페이지가 생성됩니다. URL 구조에서는 `marketing` 그룹이 무시됩니다.

### 라우트 그룹 접근하기 %{#accessing-route-groups}%

라우트 그룹은 자동으로 `route.meta.groups` 형태의 라우트 메타데이터에서 사용할 수 있습니다.
이를 통해 컴포넌트에서 조건부 로직, 스타일링 또는 다른 목적으로 그룹 정보에 접근할 수 있습니다.

```vue {}[pages/(marketing)/about.vue]
<script setup lang="ts">
const route = useRoute()

console.log(route.meta.groups) // 출력: ['marketing']
</script>

<template>
  <div>
    <p v-if="route.meta.groups?.includes('marketing')">
      이것은 마케팅 페이지입니다
    </p>
  </div>
</template>
```

## 페이지 메타데이터 %{#page-metadata}%

앱의 각 라우트에 대한 메타데이터를 정의하고 싶을 수 있습니다. `<script>`와 `<script setup>` 모두에서 동작하는 `definePageMeta` 매크로를 사용해 이를 할 수 있습니다:

```vue twoslash
<script setup lang="ts">
definePageMeta({
  title: '내 홈 페이지',
})
</script>
```

이 데이터는 앱의 다른 곳에서 `route.meta` 객체를 통해 접근할 수 있습니다.

```vue twoslash
<script setup lang="ts">
const route = useRoute()

console.log(route.meta.title) // 내 홈 페이지
</script>
```

중첩 라우트를 사용한다면 이들 모든 라우트의 페이지 메타데이터는 하나의 객체로 병합됩니다. route meta에 대한 자세한 내용은 [vue-router 문서](https://router.vuejs.org/guide/advanced/meta)를 참고하세요.

`defineEmits`나 `defineProps`와 마찬가지로([Vue 문서](https://vuejs.org/api/sfc-script-setup#defineprops-defineemits) 참고) `definePageMeta`는 **컴파일러 매크로**입니다. 컴파일 과정에서 제거되므로 컴포넌트 내부에서 참조할 수 없습니다. 대신 여기에 전달된 메타데이터는 컴포넌트 밖으로 호이스팅됩니다.
따라서 page meta 객체는 컴포넌트를 참조할 수 없습니다. 하지만 import한 바인딩과 로컬에서 정의한 **순수 함수**는 참조할 수 있습니다.

::warning
반응형 데이터나 부작용을 일으키는 함수를 참조하지 않도록 주의하세요. 예기치 않은 동작으로 이어질 수 있습니다.
::

```vue
<script setup lang="ts">
import { someData } from '~/utils/example'

function validateIdParam (route) {
  return route.params.id && !Number.isNaN(Number(route.params.id))
}

const title = ref('')

definePageMeta({
  validate: validateIdParam,
  someData,
  title, // 이렇게 하면 안 됩니다. ref가 컴포넌트 밖으로 호이스팅됩니다
})
</script>
```

### 특수 메타데이터 %{#special-metadata}%

물론 앱 전반에서 사용할 목적으로 직접 메타데이터를 정의해도 됩니다. 하지만 `definePageMeta`로 정의하는 메타데이터 중 일부는 특별한 목적을 가집니다:

#### `alias` %{#alias}%

페이지 별칭을 정의할 수 있습니다. 이를 통해 서로 다른 경로에서 같은 페이지에 접근할 수 있습니다. [vue-router 문서](https://router.vuejs.org/guide/essentials/redirect-and-alias#Alias)에 정의된 것처럼 문자열 하나 또는 문자열 배열이 될 수 있습니다.

#### `keepalive` %{#keepalive}%

`definePageMeta`에 `keepalive: true`를 설정하면 Nuxt는 페이지를 자동으로 [Vue `<KeepAlive>` 컴포넌트](https://vuejs.org/guide/built-ins/keep-alive#keepalive)로 감쌉니다. 예를 들어 동적 자식 라우트가 있는 부모 라우트에서 라우트 변경 간 페이지 상태를 유지하고 싶을 때 유용할 수 있습니다.

부모 라우트의 상태를 유지하는 것이 목적이라면 `<NuxtPage keepalive />` 문법을 사용하세요. `<KeepAlive>`에 전달할 props도 설정할 수 있습니다([전체 목록](https://vuejs.org/api/built-in-components#keepalive) 참고).

이 속성의 기본값은 [`nuxt.config`](/docs/4.x/api/nuxt-config#keepalive)에서 설정할 수 있습니다.

#### `key` %{#key}%

[위에서 확인하세요](/docs/4.x/directory-structure/app/pages#child-route-keys).

#### `layout` %{#layout}%

라우트를 렌더링할 때 사용할 레이아웃을 정의할 수 있습니다. 모든 레이아웃을 비활성화하는 `false`, 문자열, 또는 어떤 방식으로든 반응형으로 만들고 싶다면 ref/computed가 될 수 있습니다. [레이아웃 더 알아보기](/docs/4.x/directory-structure/app/layouts).

#### `layoutTransition` and `pageTransition` %{#layouttransition-and-pagetransition}%

페이지와 레이아웃을 감싸는 `<transition>` 컴포넌트의 트랜지션 속성을 정의하거나, 해당 라우트에서 `<transition>` 래퍼를 비활성화하기 위해 `false`를 전달할 수 있습니다. 전달 가능한 [옵션 목록](https://vuejs.org/api/built-in-components#transition)을 보거나 [트랜지션 동작 방식](https://vuejs.org/guide/built-ins/transition#transition)을 더 읽어보세요.

이 속성들의 기본값은 [`nuxt.config`](/docs/4.x/api/nuxt-config#layouttransition)에서 설정할 수 있습니다.

#### `middleware` %{#middleware}%

이 페이지를 로드하기 전에 적용할 middleware를 정의할 수 있습니다. 이는 매칭되는 모든 부모/자식 라우트에서 사용되는 다른 middleware와 병합됩니다. 문자열, 함수([전역 before guard 패턴](https://router.vuejs.org/guide/advanced/navigation-guards#Global-Before-Guards)을 따르는 익명/인라인 middleware 함수), 또는 문자열/함수 배열이 될 수 있습니다. [이름 있는 middleware 더 알아보기](/docs/4.x/directory-structure/app/middleware).

#### `name` %{#name}%

이 페이지 라우트의 이름을 정의할 수 있습니다.

#### `path` %{#path}%

파일명으로 표현할 수 있는 것보다 더 복잡한 패턴이 있다면 path matcher를 정의할 수 있습니다. 자세한 내용은 [`vue-router` 문서](https://router.vuejs.org/guide/essentials/route-matching-syntax#Custom-regex-in-params)를 참고하세요.

#### `props` %{#props}%

라우트 `params`를 페이지 컴포넌트로 전달되는 props처럼 접근할 수 있게 합니다. 자세한 내용은 [`vue-router` 문서](https://router.vuejs.org/guide/essentials/passing-props)를 참고하세요.

### 사용자 정의 메타데이터 타입 지정 %{#typing-custom-metadata}%

페이지에 사용자 정의 메타데이터를 추가한다면 타입 안전하게 처리하고 싶을 수 있습니다. `definePageMeta`가 받는 객체의 타입을 확장할 수 있습니다:

```ts [index.d.ts]
declare module '#app' {
  interface PageMeta {
    pageType?: string
  }
}

// 타입을 확장할 때는 항상 무언가를 import/export하도록 해야 합니다
export {}
```

## 내비게이션 %{#navigation}%

앱의 페이지 사이를 이동하려면 [`<NuxtLink>`](/docs/4.x/api/components/nuxt-link) 컴포넌트를 사용해야 합니다.

이 컴포넌트는 Nuxt에 포함되어 있으므로 다른 컴포넌트처럼 import할 필요가 없습니다.

`app/pages` 폴더의 `index.vue` 페이지로 가는 간단한 링크 예시:

```vue
<template>
  <NuxtLink to="/">홈 페이지</NuxtLink>
</template>
```

`<NuxtLink>` 사용법을 더 알아보세요.

## 프로그래밍 방식 내비게이션 %{#programmatic-navigation}%

Nuxt는 `navigateTo()` 유틸리티 메서드를 통해 프로그래밍 방식 내비게이션을 허용합니다. 이 유틸리티 메서드를 사용하면 앱 안에서 사용자를 코드로 이동시킬 수 있습니다. 사용자 입력을 받아 애플리케이션 곳곳으로 동적으로 이동시키기에 적합합니다. 아래 예시에서는 사용자가 검색 폼을 제출할 때 호출되는 간단한 `navigate()` 메서드를 사용합니다.

::note
항상 `navigateTo`를 `await`하거나 함수에서 반환해 그 결과를 체이닝하도록 하세요.
::

```vue twoslash
<script setup lang="ts">
const name = ref('')

function navigate () {
  return navigateTo({
    path: '/search',
```

## 클라이언트 전용 페이지 %{#client-only-pages}%

`.client.vue` 접미사를 붙여 페이지를 [클라이언트 전용](/docs/4.x/directory-structure/app/components#client-components)으로 정의할 수 있습니다. 이 페이지의 콘텐츠는 서버에서 전혀 렌더링되지 않습니다.

## 서버 전용 페이지 %{#server-only-pages}%

`.server.vue` 접미사를 붙여 페이지를 [서버 전용](/docs/4.x/directory-structure/app/components#server-components)으로 정의할 수 있습니다. `vue-router`가 제어하는 클라이언트 측 내비게이션으로 이 페이지에 이동할 수는 있지만, 자동으로 서버 컴포넌트로 렌더링되므로 페이지 렌더링에 필요한 코드는 클라이언트 번들에 포함되지 않습니다.

::warning
서버 전용 페이지는 반드시 단일 루트 요소를 가져야 합니다. (HTML 주석도 요소로 간주됩니다.)
::

## 사용자 정의 라우팅 %{#custom-routing}%

앱이 더 커지고 복잡해질수록 라우팅에 더 많은 유연성이 필요할 수 있습니다. 이를 위해 Nuxt는 router, routes, router options를 다양한 방식으로 사용자 정의할 수 있도록 직접 노출합니다.

:read-more{to="/docs/4.x/guide/recipes/custom-routing"}

## 여러 Pages 디렉터리 %{#multiple-pages-directories}%

기본적으로 모든 페이지는 프로젝트 루트의 하나의 `app/pages` 디렉터리에 있어야 합니다.

하지만 [Nuxt Layers](/docs/4.x/getting-started/layers)를 사용하면 앱의 페이지를 여러 묶음으로 나눌 수 있습니다:

```bash [Directory Structure]
-| some-app/
---| nuxt.config.ts
---| pages/
-----| app-page.vue
-| nuxt.config.ts
```

```ts twoslash [some-app/nuxt.config.ts]
// some-app/nuxt.config.ts
export default defineNuxtConfig({
})
```

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  extends: ['./some-app'],
})
```
