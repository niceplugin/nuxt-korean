Nuxt는 이 디렉터리의 모든 컴포넌트(그리고 사용 중인 모든 모듈이 등록한 컴포넌트)를 자동으로 import합니다.

```bash [Directory Structure]
-| components/
---| AppHeader.vue
---| AppFooter.vue
```

```html [app/app.vue]
<template>
  <div>
    <AppHeader />
    <NuxtPage />
    <AppFooter />
  </div>
</template>
```

## 컴포넌트 이름 %{#component-names}%

다음과 같이 중첩 디렉터리에 컴포넌트가 있다면:

```bash [Directory Structure]
-| components/
---| base/
-----| foo/
-------| Button.vue
```

...컴포넌트 이름은 해당 경로의 디렉터리와 파일명을 기준으로 하며, 중복 구간은 제거됩니다. 따라서 컴포넌트 이름은 다음과 같습니다:

```html
<BaseFooButton />
```

::note
명확성을 위해 컴포넌트 파일명이 이름과 일치하도록 하는 것을 권장합니다. 따라서 위 예시에서는 `Button.vue`를 `BaseFooButton.vue`로 이름 바꿀 수 있습니다.
::

이름이 아니라 경로를 기준으로 하지 않고 컴포넌트를 자동 import하고 싶다면, 설정 객체의 확장형을 사용해 `pathPrefix` 옵션을 `false`로 설정해야 합니다:

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  components: [
    {
      path: '~/components',
      pathPrefix: false, // [!code ++]
    },
  ],
})
```

이렇게 하면 Nuxt 2에서 사용하던 것과 동일한 전략으로 컴포넌트가 등록됩니다. 예를 들어 `~/components/Some/MyComponent.vue`는 `<SomeMyComponent>`가 아니라 `<MyComponent>`로 사용할 수 있습니다.

## 동적 컴포넌트 %{#dynamic-components}%

Vue의 `<component :is="someComputedComponent">`{lang=vue} 문법을 사용하고 싶다면 Vue가 제공하는 `resolveComponent` 헬퍼를 사용하거나, `#components`에서 컴포넌트를 직접 import해 `is` prop에 전달해야 합니다.

예를 들면:

```vue [app/pages/index.vue]
<script setup lang="ts">
import { SomeComponent } from '#components'

const MyButton = resolveComponent('MyButton')
</script>

<template>
  <component :is="clickable ? MyButton : 'div'" />
  <component :is="SomeComponent" />
</template>
```

::important
동적 컴포넌트를 처리하기 위해 `resolveComponent`를 사용하는 경우 컴포넌트 이름 외에는 아무것도 넣지 않도록 하세요. 이름은 반드시 리터럴 문자열이어야 하며 변수 자체이거나 변수를 포함해서는 안 됩니다. 이 문자열은 컴파일 단계에서 정적으로 분석됩니다.
::

:video-accordion{title="resolveComponent()에 대한 Daniel Roe의 짧은 영상 보기" videoId="4kq8E5IUM2U"}

대안으로, 권장되지는 않지만 모든 컴포넌트를 전역 등록할 수도 있습니다. 이렇게 하면 모든 컴포넌트에 대해 async chunk가 생성되고 애플리케이션 전체에서 사용할 수 있게 됩니다.

```diff
  export default defineNuxtConfig({
    components: {
+     global: true,
+     dirs: ['~/components']
    },
  })
```

또한 일부 컴포넌트만 `~/components/global` 디렉터리에 두거나 파일명에 `.global.vue` 접미사를 사용해 선택적으로 전역 등록할 수도 있습니다. 위에서 언급했듯이 각 전역 컴포넌트는 별도의 청크로 렌더링되므로 이 기능을 과도하게 사용하지 않도록 주의하세요.

::note
`global` 옵션은 컴포넌트 디렉터리별로도 설정할 수 있습니다.
::

## 동적 Import %{#dynamic-imports}%

컴포넌트를 동적으로 import하려면(즉, 지연 로딩하려면) 컴포넌트 이름 앞에 `Lazy` 접두사만 붙이면 됩니다. 이 방식은 컴포넌트가 항상 필요하지 않을 때 특히 유용합니다.

`Lazy` 접두사를 사용하면 적절한 시점까지 컴포넌트 코드 로딩을 지연시킬 수 있어 JavaScript 번들 크기를 최적화하는 데 도움이 됩니다.

```vue [app/pages/index.vue]
<script setup lang="ts">
const show = ref(false)
</script>

<template>
  <div>
    <h1>산</h1>
    <LazyMountainsList v-if="show" />
    <button
      v-if="!show"
      @click="show = true"
    >
      목록 보기
    </button>
  </div>
</template>
```

## 지연(또는 Lazy) Hydration %{#delayed-or-lazy-hydration}%

Lazy 컴포넌트는 앱의 청크 크기를 제어하는 데 유용하지만, 조건부로 렌더링하지 않으면 여전히 eager하게 로드되므로 런타임 성능을 항상 향상시키는 것은 아닙니다. 실제 애플리케이션에서는 일부 페이지에 많은 콘텐츠와 많은 컴포넌트가 포함될 수 있고, 대부분의 경우 그 모든 것이 페이지가 로드되자마자 상호작용 가능할 필요는 없습니다. 이들을 모두 즉시 로드하면 성능에 부정적인 영향을 줄 수 있습니다.

앱을 최적화하려면 일부 컴포넌트가 화면에 보일 때까지 또는 브라우저가 더 중요한 작업을 마칠 때까지 hydration을 지연시키고 싶을 수 있습니다.

Nuxt는 lazy(또는 지연) hydration을 사용해 이를 지원하며, 컴포넌트가 언제 상호작용 가능해질지 제어할 수 있게 해줍니다.

### Hydration 전략 %{#hydration-strategies}%

Nuxt는 다양한 내장 hydration 전략을 제공합니다. lazy 컴포넌트마다 하나의 전략만 사용할 수 있습니다.

::note
지연 hydration된 컴포넌트의 prop이 변경되면 즉시 hydration이 트리거됩니다. (예: `hydrate-never`가 적용된 컴포넌트의 prop을 변경하면 hydration이 발생합니다)
::

::warning
현재 Nuxt의 내장 lazy hydration은 single-file component(SFC)에서만 동작하며, prop을 템플릿에서 직접 정의해야 합니다(`v-bind`로 props 객체를 펼치는 방식은 불가). 또한 `#components`에서 직접 import한 경우에는 동작하지 않습니다.
::

#### `hydrate-on-visible` %{#hydrate-on-visible}%

컴포넌트가 뷰포트에서 보이게 되면 hydration합니다.

```vue [app/pages/index.vue]
<template>
  <div>
    <LazyMyComponent hydrate-on-visible />
  </div>
</template>
```

::read-more{to="https://developer.mozilla.org/en-US/docs/Web/API/IntersectionObserver/IntersectionObserver" title="IntersectionObserver options"}
`hydrate-on-visible` 옵션에 대해 더 알아보세요.
::

::note
내부적으로 Vue의 내장 [`hydrateOnVisible` 전략](https://vuejs.org/guide/components/async#hydrate-on-visible)을 사용합니다.
::

#### `hydrate-on-idle` %{#hydrate-on-idle}%

브라우저가 idle 상태가 되면 컴포넌트를 hydration합니다. 컴포넌트가 가능한 한 빨리 로드되어야 하지만 중요한 렌더링 경로를 막아서는 안 될 때 적합합니다.

최대 timeout으로 동작하는 숫자를 전달할 수도 있습니다.

```vue [app/pages/index.vue]
<template>
  <div>
    <LazyMyComponent hydrate-on-idle />
  </div>
</template>
```

::note
내부적으로 Vue의 내장 [`hydrateOnIdle` 전략](https://vuejs.org/guide/components/async#hydrate-on-idle)을 사용합니다.
::

#### `hydrate-on-interaction` %{#hydrate-on-interaction}%

지정한 상호작용(예: click, mouseover) 이후에 컴포넌트를 hydration합니다.

```vue [app/pages/index.vue]
<template>
  <div>
    <LazyMyComponent hydrate-on-interaction="mouseover" />
  </div>
</template>
```

이벤트 또는 이벤트 목록을 전달하지 않으면 기본값으로 `pointerenter`, `click`, `focus`에서 hydration됩니다.

::note
내부적으로 Vue의 내장 [`hydrateOnInteraction` 전략](https://vuejs.org/guide/components/async#hydrate-on-interaction)을 사용합니다.
::

#### `hydrate-on-media-query` %{#hydrate-on-media-query}%

윈도우가 media query와 일치할 때 컴포넌트를 hydration합니다.

```vue [app/pages/index.vue]
<template>
  <div>
    <LazyMyComponent hydrate-on-media-query="(max-width: 768px)" />
  </div>
</template>
```

::note
내부적으로 Vue의 내장 [`hydrateOnMediaQuery` 전략](https://vuejs.org/guide/components/async#hydrate-on-media-query)을 사용합니다.
::

#### `hydrate-after` %{#hydrate-after}%

지정한 지연 시간(밀리초) 이후에 컴포넌트를 hydration합니다.

```vue [app/pages/index.vue]
<template>
  <div>
    <LazyMyComponent :hydrate-after="2000" />
  </div>
</template>
```

#### `hydrate-when` %{#hydrate-when}%

불리언 조건에 따라 컴포넌트를 hydration합니다.

```vue [app/pages/index.vue]
<template>
  <div>
    <LazyMyComponent :hydrate-when="isReady" />
  </div>
</template>

<script setup lang="ts">
const isReady = ref(false)
function myFunction () {
  // 사용자 정의 hydration 전략 트리거...
  isReady.value = true
}
</script>
```

#### `hydrate-never` %{#hydrate-never}%

컴포넌트를 절대 hydration하지 않습니다.

```vue [app/pages/index.vue]
<template>
  <div>
    <LazyMyComponent hydrate-never />
  </div>
</template>
```

### Hydration 이벤트 수신 %{#listening-to-hydration-events}%

모든 지연 hydration 컴포넌트는 hydration될 때 `@hydrated` 이벤트를 발생시킵니다.

```vue [app/pages/index.vue]
<template>
  <div>
    <LazyMyComponent
      hydrate-on-visible
      @hydrated="onHydrate"
    />
  </div>
</template>

<script setup lang="ts">
function onHydrate () {
  console.log('컴포넌트가 hydration되었습니다!')
}
</script>
```

### 주의사항과 모범 사례 %{#caveats-and-best-practices}%

지연 hydration은 성능상 이점을 줄 수 있지만, 올바르게 사용하는 것이 중요합니다:

1. **뷰포트 안의 콘텐츠를 우선하세요:** 중요한 첫 화면 콘텐츠에는 지연 hydration을 피하세요. 즉시 필요하지 않은 콘텐츠에 가장 적합합니다.

2. **조건부 렌더링:** lazy 컴포넌트에 `v-if="false"`를 사용하는 경우 지연 hydration이 필요 없을 수 있습니다. 일반 lazy 컴포넌트를 사용하면 됩니다.

3. **공유 상태:** 여러 컴포넌트에서 공유하는 상태(`v-model`)에 유의하세요. 한 컴포넌트에서 모델을 업데이트하면 그 모델에 바인딩된 모든 컴포넌트에서 hydration이 트리거될 수 있습니다.

4. **각 전략의 의도된 사용 사례를 따르세요:** 각 전략은 특정 목적에 맞게 최적화되어 있습니다.
    * `hydrate-when`은 항상 hydration할 필요가 없을 수 있는 컴포넌트에 가장 적합합니다.
    * `hydrate-after`는 일정 시간 기다릴 수 있는 컴포넌트를 위한 것입니다.
    * `hydrate-on-idle`은 브라우저가 한가할 때 hydration될 수 있는 컴포넌트를 위한 것입니다.

5. **상호작용이 필요한 컴포넌트에는 `hydrate-never`를 피하세요:** 사용자 상호작용이 필요한 컴포넌트는 never hydrate로 설정하면 안 됩니다.

## 직접 Import %{#direct-imports}%

Nuxt의 자동 import 기능을 우회하고 싶거나 우회해야 할 필요가 있다면 `#components`에서 컴포넌트를 명시적으로 import할 수도 있습니다.

```vue [app/pages/index.vue]
<script setup lang="ts">
import { LazyMountainsList, NuxtLink } from '#components'

const show = ref(false)
</script>

<template>
  <div>
    <h1>산</h1>
    <LazyMountainsList v-if="show" />
    <button
      v-if="!show"
      @click="show = true"
    >
      목록 보기
    </button>
    <NuxtLink to="/">홈</NuxtLink>
  </div>
</template>
```

## 사용자 정의 디렉터리 %{#custom-directories}%

기본적으로는 `~/components` 디렉터리만 스캔합니다. 다른 디렉터리를 추가하거나 이 디렉터리의 하위 폴더에서 컴포넌트를 스캔하는 방식을 바꾸고 싶다면 설정에 디렉터리를 추가할 수 있습니다:

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  components: [
    // ~/calendar-module/components/event/Update.vue => <EventUpdate />
    { path: '~/calendar-module/components' },

    // ~/user-module/components/account/UserDeleteDialog.vue => <UserDeleteDialog />
    { path: '~/user-module/components', pathPrefix: false },

    // ~/components/special-components/Btn.vue => <SpecialBtn />
    { path: '~/components/special-components', prefix: 'Special' },

    // overrides를 적용하고 싶다면 이것이 마지막에 와야 합니다
    // `~/components`의 하위 디렉터리에 대해 적용됩니다.
    //
    // ~/components/Btn.vue => <Btn />
    // ~/components/base/Btn.vue => <BaseBtn />
    '~/components',
  ],
})
```

::note
중첩 디렉터리는 순서대로 스캔되므로 먼저 추가해야 합니다.
::

## npm 패키지 %{#npm-packages}%

npm 패키지에서 컴포넌트를 자동 import하고 싶다면 [local module](/docs/4.x/directory-structure/modules)에서 [`addComponent`](/docs/4.x/api/kit/components#addcomponent)를 사용해 등록할 수 있습니다.

::code-group

```ts twoslash [~/modules/register-component.ts]
import { addComponent, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup () {
    // import { MyComponent as MyAutoImportedComponent } from 'my-npm-package'
    addComponent({
      name: 'MyAutoImportedComponent',
      export: 'MyComponent',
      filePath: 'my-npm-package',
    })
  },
})
```

```vue [app/app.vue]
<template>
  <div>
    <!--  컴포넌트는 우리가 지정한 이름을 사용하며 자동 import됩니다  -->
    <MyAutoImportedComponent />
  </div>
</template>
```

::

## 컴포넌트 확장자 %{#component-extensions}%

기본적으로 [ `nuxt.config.ts`의 extensions 키](/docs/4.x/api/nuxt-config#extensions)에 지정된 확장자를 가진 모든 파일은 컴포넌트로 취급됩니다.
컴포넌트로 등록할 파일 확장자를 제한해야 한다면 컴포넌트 디렉터리 선언의 확장형과 그 안의 `extensions` 키를 사용할 수 있습니다:

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  components: [
    {
      path: '~/components',
      extensions: ['.vue'], // [!code ++]
    },
  ],
})
```

## 클라이언트 컴포넌트 %{#client-components}%

컴포넌트를 클라이언트 측에서만 렌더링하려면 컴포넌트에 `.client` 접미사를 붙일 수 있습니다.

```bash [Directory Structure]
| components/
--| Comments.client.vue
```

```vue [app/pages/example.vue]
<template>
  <div>
    <!-- 이 컴포넌트는 클라이언트 측에서만 렌더링됩니다 -->
    <Comments />
  </div>
</template>
```

::note
이 기능은 Nuxt auto-import와 `#components` import에서만 동작합니다. 실제 경로에서 이 컴포넌트를 명시적으로 import해도 클라이언트 전용 컴포넌트로 바뀌지는 않습니다.
::

::important
`.client` 컴포넌트는 마운트된 이후에만 렌더링됩니다. `onMounted()`를 사용해 렌더링된 템플릿에 접근하려면 `onMounted()` 훅의 콜백 안에 `await nextTick()`을 추가하세요.
::

::read-more{to="/docs/4.x/api/components/client-only"}
`<ClientOnly>` 컴포넌트로도 비슷한 결과를 얻을 수 있습니다.
::

## 서버 컴포넌트 %{#server-components}%

서버 컴포넌트를 사용하면 클라이언트 측 앱 안에서 개별 컴포넌트를 서버 렌더링할 수 있습니다. 정적 사이트를 생성하는 경우에도 Nuxt 안에서 서버 컴포넌트를 사용할 수 있습니다. 이는 동적 컴포넌트, 서버 렌더링된 HTML, 정적인 마크업 조각까지 섞인 복잡한 사이트를 구축할 수 있게 해줍니다.

서버 컴포넌트는 단독으로 사용할 수도 있고 [client component](/docs/4.x/directory-structure/app/components#paired-with-a-client-component)와 짝지어 사용할 수도 있습니다.

### 독립형 서버 컴포넌트 %{#standalone-server-components}%

독립형 서버 컴포넌트는 항상 서버에서 렌더링되며, Islands 컴포넌트라고도 합니다.

props가 업데이트되면 네트워크 요청이 발생하고, 렌더링된 HTML이 제자리에서 업데이트됩니다.

서버 컴포넌트는 현재 실험적 기능이므로, 이를 사용하려면 nuxt.config에서 'component islands' 기능을 활성화해야 합니다:

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  experimental: {
    componentIslands: true,
  },
})
```

이제 `.server` 접미사로 서버 전용 컴포넌트를 등록하고 애플리케이션 어디에서나 자동으로 사용할 수 있습니다.

```bash [Directory Structure]
-| components/
---| HighlightedMarkdown.server.vue
```

```vue [app/pages/example.vue]
<template>
  <div>
    <!--
      이 컴포넌트는 자동으로 서버에서 렌더링되므로, markdown 파싱 및 highlighting
      라이브러리는 클라이언트 번들에 포함되지 않습니다.
     -->
    <HighlightedMarkdown markdown="# 헤드라인" />
  </div>
</template>
```

서버 전용 컴포넌트는 내부적으로 [`<NuxtIsland>`](/docs/4.x/api/components/nuxt-island)를 사용하므로 `lazy` prop과 `#fallback` slot이 모두 여기에 전달됩니다.

::warning
서버 컴포넌트(및 island)는 반드시 단일 루트 요소를 가져야 합니다. (HTML 주석도 요소로 간주됩니다.)
::

::warning
props는 URL 쿼리 파라미터를 통해 서버 컴포넌트에 전달되므로, URL이 가질 수 있는 길이 제한을 받습니다. 따라서 props로 서버 컴포넌트에 너무 많은 데이터를 전달하지 않도록 주의하세요.
::

::warning
island 안에 또 다른 island를 중첩할 때는 각 island가 추가 오버헤드를 더한다는 점에 주의하세요.
::

::warning
슬롯과 클라이언트 컴포넌트 같은 서버 전용 컴포넌트 및 island 컴포넌트 기능 대부분은 single file component에서만 사용할 수 있습니다.
::

#### 서버 컴포넌트 안의 클라이언트 컴포넌트 %{#client-components-within-server-components}%

::note
이 기능을 사용하려면 설정에서 `experimental.componentIslands.selectiveClient`가 true여야 합니다.
::

클라이언트 측에서 로드할 컴포넌트에 `nuxt-client` 속성을 설정해 컴포넌트를 부분적으로 hydration할 수 있습니다.

```vue [app/components/ServerWithClient.vue]
<template>
  <div>
    <HighlightedMarkdown markdown="# Headline" />
    <!-- Counter는 클라이언트 측에서 로드되고 hydration됩니다 -->
    <Counter
      nuxt-client
      :count="5"
    />
  </div>
</template>
```

::note
이 기능은 서버 컴포넌트 안에서만 동작합니다. 클라이언트 컴포넌트용 슬롯은 `experimental.componentIsland.selectiveClient`가 `'deep'`으로 설정된 경우에만 동작하며, 서버 측에서 렌더링되므로 클라이언트 측에서는 상호작용할 수 없습니다.
::

#### 서버 컴포넌트 컨텍스트 %{#server-component-context}%

서버 전용 또는 island 컴포넌트를 렌더링할 때 `<NuxtIsland>`는 `NuxtIslandResponse`를 반환하는 fetch 요청을 수행합니다. (서버에서 렌더링되면 이는 내부 요청이고, 클라이언트 측 내비게이션에서 렌더링되면 네트워크 탭에서 볼 수 있는 요청입니다.)

이는 다음을 의미합니다:

* `NuxtIslandResponse`를 만들기 위해 서버 측에서 새 Vue 앱이 생성됩니다.
* 컴포넌트를 렌더링하는 동안 새로운 'island context'가 생성됩니다.
* 앱의 나머지 부분에서 'island context'에 접근할 수 없고, island 컴포넌트에서 앱의 나머지 컨텍스트에도 접근할 수 없습니다. 즉, 서버 컴포넌트 또는 island는 앱의 나머지 부분으로부터 _격리_ 됩니다.
* 플러그인은 island를 렌더링할 때 다시 실행됩니다. 단, 객체 문법 플러그인에서 `env: { islands: false }`를 설정한 경우는 예외입니다.

::important
island 컴포넌트를 렌더링할 때 route middleware는 실행되지 않습니다. middleware는 페이지에 적용되는 라우팅 개념이지 컴포넌트 렌더링을 제어하도록 설계된 것이 아닙니다.
::

island 컴포넌트 안에서는 `nuxtApp.ssrContext.islandContext`를 통해 island context에 접근할 수 있습니다. island 컴포넌트가 아직 실험적 기능으로 표시되는 동안에는 이 컨텍스트의 형식이 바뀔 수 있다는 점에 유의하세요.

::note
슬롯은 상호작용할 수 있으며 `<div>`에 `display: contents;`가 적용된 상태로 감싸집니다
::

### 클라이언트 컴포넌트와 짝지어 사용 %{#paired-with-a-client-component}%

이 경우 `.server` + `.client` 컴포넌트는 컴포넌트의 두 '반쪽'이며, 서버와 클라이언트 측에서 컴포넌트를 별도로 구현해야 하는 고급 사용 사례에 사용할 수 있습니다.

```bash [Directory Structure]
-| components/
---| Comments.client.vue
---| Comments.server.vue
```

```vue [app/pages/example.vue]
<template>
  <div>
    <!-- 이 컴포넌트는 서버에서 Comments.server를 렌더링한 뒤 브라우저에서 마운트되면 Comments.client를 렌더링합니다 -->
    <Comments />
  </div>
</template>
```

## 라이브러리 작성자 %{#library-authors}%

자동 tree-shaking과 컴포넌트 등록이 가능한 Vue 컴포넌트 라이브러리를 만드는 일은 매우 쉽습니다. ✨

`@nuxt/kit`에서 제공하는 [`addComponentsDir`](/docs/4.x/api/kit/components#addcomponentsdir) 메서드를 사용해 Nuxt 모듈 안에 컴포넌트 디렉터리를 등록할 수 있습니다.

다음과 같은 디렉터리 구조를 상상해 봅시다:

```bash [Directory Structure]
-| node_modules/
---| awesome-ui/
-----| components/
-------| Alert.vue
-------| Button.vue
-----| nuxt.ts
-| pages/
---| index.vue
-| nuxt.config.ts
```

그런 다음 `awesome-ui/nuxt.ts`에서 `addComponentsDir` 훅을 사용할 수 있습니다:

```ts twoslash
import { addComponentsDir, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup () {
    const resolver = createResolver(import.meta.url)

    // 목록에 ./components 디렉터리 추가
    addComponentsDir({
      path: resolver.resolve('./components'),
      prefix: 'awesome',
    })
  },
})
```

이것으로 끝입니다! 이제 프로젝트에서 `nuxt.config` 파일의 Nuxt 모듈로 UI 라이브러리를 import할 수 있습니다:

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['awesome-ui/nuxt'],
})
```

...그리고 `app/pages/index.vue`에서 모듈 컴포넌트(`awesome-` 접두사 포함)를 직접 사용할 수 있습니다:

```vue
<template>
  <div>
    내 <AwesomeButton>UI 버튼</AwesomeButton>!
    <awesome-alert>여기 알림이 있습니다!</awesome-alert>
  </div>
</template>
```

컴포넌트가 실제로 사용될 때만 자동 import되며, `node_modules/awesome-ui/components/` 안의 컴포넌트를 업데이트할 때 HMR도 지원합니다.
