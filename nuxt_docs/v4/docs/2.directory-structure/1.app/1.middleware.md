Nuxt는 애플리케이션 전반에서 사용할 수 있는 커스터마이즈 가능한 **route middleware** 프레임워크를 제공하며, 특정 라우트로 이동하기 전에 실행하려는 코드를 분리해내기에 적합합니다.

route middleware에는 세 가지 종류가 있습니다:

1. 익명(또는 인라인) route middleware는 페이지 안에 직접 정의합니다.
2. 이름 있는 route middleware는 `app/middleware/`에 두며, 페이지에서 사용할 때 비동기 import를 통해 자동으로 로드됩니다.
3. 전역 route middleware는 `app/middleware/`에 `.global` 접미사로 두며, 모든 라우트 변경에서 실행됩니다.

앞의 두 종류 route middleware는 [`definePageMeta`](/docs/4.x/api/utils/define-page-meta) 안에서 정의할 수 있습니다.

::note
middleware 이름은 kebab-case로 정규화됩니다: `myMiddleware`는 `my-middleware`가 됩니다.
::

::note
route middleware는 Nuxt 앱의 Vue 부분에서 실행됩니다. 이름이 비슷하지만, 앱의 Nitro 서버 부분에서 실행되는 [server middleware](/docs/4.x/directory-structure/server#server-middleware)와는 완전히 다릅니다.
::

## 사용법 %{#usage}%

route middleware는 현재 라우트와 다음 라우트를 인수로 받는 navigation guard입니다.

```ts twoslash [middleware/my-middleware.ts]
export default defineNuxtRouteMiddleware((to, from) => {
  if (to.params.id === '1') {
    return abortNavigation()
  }
  // 실제 앱에서는 아마 모든 라우트를 `/`로 리디렉션하지는 않을 것입니다
  // 하지만 리디렉션 전에 `to.path`를 확인하는 것이 중요합니다
  // 그렇지 않으면 무한 리디렉션 루프에 빠질 수 있습니다
  if (to.path !== '/') {
    return navigateTo('/')
  }
})
```

Nuxt는 middleware에서 직접 반환할 수 있는 두 가지 전역 헬퍼를 제공합니다.

1. [`navigateTo`](/docs/4.x/api/utils/navigate-to) - 지정한 라우트로 리디렉션합니다
2. [`abortNavigation`](/docs/4.x/api/utils/abort-navigation) - 선택적 오류 메시지와 함께 내비게이션을 중단합니다.

`vue-router`의 [navigation guards](https://router.vuejs.org/guide/advanced/navigation-guards#Global-Before-Guards)와 달리 세 번째 `next()` 인수는 전달되지 않으며, **리디렉션이나 라우트 취소는 middleware에서 값을 반환하는 방식으로 처리됩니다**.

반환 가능한 값은 다음과 같습니다:

* 아무것도 반환하지 않음(단순 `return` 또는 반환 자체가 없음) - 내비게이션을 막지 않고, 다음 middleware 함수가 있으면 그쪽으로 이동하거나 라우트 내비게이션을 완료합니다
* `return navigateTo('/')` - 지정한 경로로 리디렉션하며, 서버 측에서 리디렉션이 일어나면 리디렉션 코드를 [`302` Found](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status/302)로 설정합니다
* `return navigateTo('/', { redirectCode: 301 })` - 지정한 경로로 리디렉션하며, 서버 측에서 리디렉션이 일어나면 리디렉션 코드를 [`301` Moved Permanently](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status/301)로 설정합니다
* `return abortNavigation()` - 현재 내비게이션을 중지합니다
* `return abortNavigation(error)` - 현재 내비게이션을 오류와 함께 거부합니다

:read-more{to="/docs/4.x/api/utils/navigate-to"}
:read-more{to="/docs/4.x/api/utils/abort-navigation"}

::important
리디렉션을 수행하거나 내비게이션을 중지할 때는 위 헬퍼 함수를 사용하는 것을 권장합니다. [vue-router 문서](https://router.vuejs.org/guide/advanced/navigation-guards#Global-Before-Guards)에 설명된 다른 반환값도 동작할 수 있지만, 앞으로 호환성이 깨지는 변경이 생길 수 있습니다.
::

## 미들웨어 순서 %{#middleware-order}%

middleware는 다음 순서로 실행됩니다:

1. 전역 Middleware
2. 페이지에 정의된 middleware 순서(배열 문법으로 여러 middleware를 선언한 경우)

예를 들어 다음과 같은 middleware와 컴포넌트가 있다고 가정해 봅시다:

```bash [app/middleware/ directory]
-| middleware/
---| analytics.global.ts
---| setup.global.ts
---| auth.ts
```

```vue twoslash [pages/profile.vue]
<script setup lang="ts">
definePageMeta({
  middleware: [
    function (to, from) {
      // 사용자 정의 인라인 middleware
    },
    'auth',
  ],
})
</script>
```

middleware는 다음 순서로 실행된다고 예상할 수 있습니다:

1. `analytics.global.ts`
2. `setup.global.ts`
3. 사용자 정의 인라인 middleware
4. `auth.ts`

### 전역 Middleware 순서 지정 %{#ordering-global-middleware}%

기본적으로 전역 middleware는 파일명을 기준으로 알파벳순 실행됩니다.

하지만 특정 순서를 정의하고 싶을 때도 있습니다. 예를 들어 앞선 시나리오에서는 `setup.global.ts`가 `analytics.global.ts`보다 먼저 실행되어야 할 수 있습니다. 그런 경우 전역 middleware 앞에 '알파벳순' 번호를 접두사로 붙이는 것을 권장합니다.

```bash [Directory structure]
-| middleware/
---| 01.setup.global.ts
---| 02.analytics.global.ts
---| auth.ts
```

::note
'알파벳순' 번호 매기기가 익숙하지 않다면, 파일명은 숫자값이 아니라 문자열로 정렬된다는 점을 기억하세요. 예를 들어 `10.new.global.ts`는 `2.new.global.ts`보다 앞에 옵니다. 그래서 예시에서는 한 자리 숫자 앞에 `0`을 붙입니다.
::

## 미들웨어가 실행되는 시점 %{#when-middleware-runs}%

사이트가 서버 렌더링되거나 생성된 경우, 초기 페이지용 middleware는 페이지가 렌더링될 때 한 번, 그리고 클라이언트에서 다시 한 번 실행됩니다. 생성된 사이트를 쓰거나, 응답을 강하게 캐시하거나, 로컬 스토리지 값을 읽고 싶어서 middleware에 브라우저 환경이 필요한 경우 이런 동작이 필요할 수 있습니다.

하지만 이런 동작을 피하고 싶다면 다음과 같이 할 수 있습니다:

```ts twoslash [middleware/example.ts]
export default defineNuxtRouteMiddleware((to) => {
  // 서버에서는 middleware 건너뛰기
  if (import.meta.server) {
    return
  }
  // 클라이언트 쪽에서는 middleware를 완전히 건너뛰기
  if (import.meta.client) {
    return
  }
  // 또는 초기 클라이언트 로드에서만 middleware 건너뛰기
  const nuxtApp = useNuxtApp()
  if (import.meta.client && nuxtApp.isHydrating && nuxtApp.payload.serverRendered) {
    return
  }
})
```

서버에서 middleware 안에서 오류를 던져 오류 페이지가 렌더링되는 경우에도 마찬가지입니다. middleware는 브라우저에서 다시 실행됩니다.

::note
오류 페이지 렌더링은 완전히 별도의 페이지 로드이므로, 등록된 모든 middleware가 다시 실행됩니다. middleware에서 [`useError`](/docs/4.x/getting-started/error-handling#useerror)를 사용해 오류가 처리 중인지 확인할 수 있습니다.
::

## 미들웨어에서 라우트 접근하기 %{#accessing-route-in-middleware}%

middleware에서는 항상 `to`와 `from` 매개변수를 사용해 다음 라우트와 이전 라우트에 접근하세요. 이 컨텍스트에서는 [`useRoute()`](/docs/4.x/api/composables/use-route) composable 사용을 아예 피해야 합니다.
middleware에는 **"현재 라우트"라는 개념이 없기** 때문입니다. middleware는 내비게이션을 중단하거나 다른 라우트로 리디렉션할 수 있습니다. 이 컨텍스트에서 `useRoute()` composable은 항상 부정확합니다.  

::warning
가끔 내부적으로 `useRoute()`를 사용하는 composable을 호출할 수 있는데, 그러면 middleware 안에 직접 호출이 없어도 이 경고가 발생할 수 있습니다.
이 역시 **위와 같은 문제**로 이어지므로, middleware에서 사용할 함수는 대신 라우트를 인수로 받도록 구성해야 합니다.
::

::code-group
```ts twoslash [middleware/access-route.ts]
// @errors: 2304
export default defineNuxtRouteMiddleware((to) => {
  // middleware에서 `useRoute()`를 호출하지 않도록 함수에 라우트를 전달합니다
  doSomethingWithRoute(to)

  // ❌ 경고가 출력되며 권장되지 않습니다
  callsRouteInternally()
})
```

```ts twoslash [utils/handle-route.ts]
// middleware에서 올바르게 사용할 수 있도록 라우트를 인수로 제공합니다
export function doSomethingWithRoute (route = useRoute()) {
  // ...
}
```
```ts twoslash [utils/dont-do-this.ts]
// ❌ 이 함수는 middleware에서 사용하기에 적합하지 않습니다
export function callsRouteInternally () {
  const route = useRoute()
  // ...
}
```

::

## 동적으로 미들웨어 추가하기 %{#adding-middleware-dynamically}%

플러그인 내부처럼 [`addRouteMiddleware()`](/docs/4.x/api/utils/add-route-middleware) 헬퍼 함수를 사용해 전역 또는 이름 있는 route middleware를 수동으로 추가할 수 있습니다.

```ts twoslash
export default defineNuxtPlugin(() => {
  addRouteMiddleware('global-test', () => {
    console.log('이 전역 middleware는 플러그인에서 추가되었으며 모든 라우트 변경에서 실행됩니다')
  }, { global: true })

  addRouteMiddleware('named-test', () => {
    console.log('이 이름 있는 middleware는 플러그인에서 추가되었으며 같은 이름의 기존 middleware를 덮어씁니다')
  })
})
```

## 예시 %{#example}%

```bash [Directory Structure]
-| middleware/
---| auth.ts
```

페이지 파일에서 이 route middleware를 참조할 수 있습니다:

```vue twoslash
<script setup lang="ts">
definePageMeta({
  middleware: ['auth'],
  // 또는 middleware: 'auth'
})
</script>
```

이제 해당 페이지로의 내비게이션이 완료되기 전에 `auth` route middleware가 실행됩니다.

## 빌드 시점에 미들웨어 설정하기 %{#setting-middleware-at-build-time}%

각 페이지에서 `definePageMeta`를 사용하는 대신 `pages:extend` 훅 안에서 이름 있는 route middleware를 추가할 수 있습니다.

```ts twoslash [nuxt.config.ts]
import type { NuxtPage } from 'nuxt/schema'

export default defineNuxtConfig({
  hooks: {
    'pages:extend' (pages) {
      function setMiddleware (pages: NuxtPage[]) {
        for (const page of pages) {
          if (/* some condition */ Math.random() > 0.5) {
            page.meta ||= {}
            // 이렇게 하면 페이지의 `definePageMeta`에 설정된 모든 middleware를 덮어씁니다
            page.meta.middleware = ['named']
          }
          if (page.children) {
            setMiddleware(page.children)
          }
        }
      }
      setMiddleware(pages)
    },
  },
})
```
