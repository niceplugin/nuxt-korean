Nuxt는 애플리케이션 내부에 반응형 설정을 노출할 수 있도록 `app/app.config.ts` 설정 파일을 제공합니다. 이 설정은 라이프사이클 중 런타임에 업데이트하거나 Nuxt 플러그인을 사용해 갱신할 수 있으며, HMR(hot-module-replacement)로 편집할 수도 있습니다.

`app.config.ts` 파일을 사용하면 런타임 앱 설정을 쉽게 제공할 수 있습니다. 확장자는 `.ts`, `.js`, `.mjs` 중 하나일 수 있습니다.

```ts twoslash [app/app.config.ts]
export default defineAppConfig({
  foo: 'bar',
})
```

::caution
`app.config` 파일 안에 비밀 값을 넣지 마세요. 이 파일은 사용자 클라이언트 번들에 노출됩니다.
::

::note
사용자 정의 [`srcDir`](/docs/4.x/api/nuxt-config#srcdir)를 설정할 때는 `app.config` 파일을 새 `srcDir` 경로의 루트에 두어야 합니다.
::

## 사용법 %{#usage}%

앱의 나머지 부분에 설정과 환경 변수를 노출하려면 `app.config` 파일 안에 설정을 정의해야 합니다.

```ts twoslash [app/app.config.ts]
export default defineAppConfig({
  theme: {
    primaryColor: '#ababab',
  },
})
```

이제 [`useAppConfig`](/docs/4.x/api/composables/use-app-config) 컴포저블을 사용해 페이지를 서버 렌더링할 때와 브라우저 모두에서 `theme`에 공통으로 접근할 수 있습니다.

```vue [app/pages/index.vue]
<script setup lang="ts">
const appConfig = useAppConfig()

console.log(appConfig.theme)
</script>
```

[`updateAppConfig`](/docs/4.x/api/utils/update-app-config) 유틸리티를 사용하면 런타임에 `app.config`를 업데이트할 수 있습니다.

```vue [app/pages/index.vue]
<script setup>
const appConfig = useAppConfig() // { foo: 'bar' }

const newAppConfig = { foo: 'baz' }

updateAppConfig(newAppConfig)

console.log(appConfig) // { foo: 'baz' }
</script>
```

::read-more{to="/docs/4.x/api/utils/update-app-config"}
`updateAppConfig` 유틸리티에 대해 더 알아보세요.
::

## App Config 타입 지정 %{#typing-app-config}%

Nuxt는 제공된 app config로부터 TypeScript 인터페이스를 자동 생성하려고 하므로 직접 타입을 작성하지 않아도 됩니다.

하지만 경우에 따라 직접 타입을 지정하고 싶을 수 있습니다. 타입을 지정하고 싶은 대상은 두 가지입니다.

### App Config 입력 %{#app-config-input}%

`AppConfigInput`은 app config를 설정할 때 어떤 _입력_ 옵션이 유효한지 선언하려는 모듈 작성자가 사용할 수 있습니다. 이는 `useAppConfig()`의 타입에는 영향을 주지 않습니다.

```ts [index.d.ts]
declare module 'nuxt/schema' {
  interface AppConfigInput {
    /** 테마 설정 */
    theme?: {
      /** 앱 기본 색상 */
      primaryColor?: string
    }
  }
}

// 타입을 확장할 때는 항상 무언가를 import/export하도록 해야 합니다
export {}
```

### App Config 출력 %{#app-config-output}%

[`useAppConfig()`](/docs/4.x/api/composables/use-app-config) 호출 결과의 타입을 지정하고 싶다면 `AppConfig`를 확장해야 합니다.

::warning
`AppConfig`에 타입을 지정할 때는 실제로 정의한 app config에서 Nuxt가 추론한 타입을 덮어쓰게 되므로 주의하세요.
::

```ts [index.d.ts]
declare module 'nuxt/schema' {
  interface AppConfig {
    // 기존에 추론된 `theme` 속성을 완전히 대체합니다
    theme: {
      // Nuxt가 추론할 수 있는 것보다 더 구체적인 타입을 추가하기 위해
      // 이 값의 타입을 직접 지정하고 싶을 수 있습니다. 예: 문자열 리터럴 타입
      primaryColor?: 'red' | 'blue'
    }
  }
}

// 타입을 확장할 때는 항상 무언가를 import/export하도록 해야 합니다
export {}
```

## 병합 전략 %{#merging-strategy}%

Nuxt는 애플리케이션 [레이어](/docs/4.x/getting-started/layers) 안의 `AppConfig`에 대해 사용자 정의 병합 전략을 사용합니다.

이 전략은 [Function Merger](https://github.com/unjs/defu#function-merger)를 사용해 구현되며, 이를 통해 `app.config`에서 배열 값을 가진 각 키에 대해 사용자 정의 병합 전략을 정의할 수 있습니다.

::note
함수 병합기는 확장된 레이어에서만 사용할 수 있고 프로젝트의 메인 `app.config`에서는 사용할 수 없습니다.
::

사용 예시는 다음과 같습니다:

::code-group

```ts twoslash [layer/app/app.config.ts]
export default defineAppConfig({
  // 기본 배열 값
  array: ['hello'],
})
```

```ts twoslash [app/app.config.ts]
export default defineAppConfig({
  // 병합 함수를 사용해 기본 배열 값을 덮어씁니다
  array: () => ['bonjour'],
})
```

::

## 알려진 제한 사항 %{#known-limitations}%

Nuxt v3.3 기준으로 `app.config.ts` 파일은 Nitro와 공유되며, 그 결과 다음과 같은 제한 사항이 있습니다:

1. `app.config.ts`에서 Vue 컴포넌트를 직접 import할 수 없습니다.
2. 일부 auto-import는 Nitro 컨텍스트에서 사용할 수 없습니다.

이러한 제한은 Nitro가 완전한 Vue 컴포넌트 지원 없이 app config를 처리하기 때문에 발생합니다.

우회책으로 Nitro 설정에서 Vite 플러그인을 사용하는 것은 가능하지만, 이 접근 방식은 권장되지 않습니다:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  nitro: {
    vite: {
      plugins: [vue()],
    },
  },
})
```

::warning
이 우회책을 사용하면 예기치 않은 동작과 버그가 생길 수 있습니다. Vue 플러그인은 Nitro 컨텍스트에서 사용할 수 없는 많은 항목 중 하나입니다.
::

관련 이슈:
- [Issue #19858](https://github.com/nuxt/nuxt/issues/19858)
- [Issue #19854](https://github.com/nuxt/nuxt/issues/19854)

::note
Nitro v3는 app config 지원을 제거함으로써 이러한 제한을 해소할 예정입니다.
[이 pull request](https://github.com/nitrojs/nitro/pull/2521)에서 진행 상황을 추적할 수 있습니다.
::
