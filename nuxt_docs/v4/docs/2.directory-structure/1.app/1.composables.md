## 사용법 %{#usage}%

**방법 1:** 이름 있는 export 사용

```ts [app/composables/useFoo.ts]
export const useFoo = () => {
  return useState('foo', () => 'bar')
}
```

**방법 2:** 기본 export 사용

```ts [app/composables/use-foo.ts or composables/useFoo.ts]
// 확장자를 제외한 파일 이름의 camelCase 형태인 useFoo()로 사용할 수 있습니다
export default function () {
  return useState('foo', () => 'bar')
}
```

**사용:** 이제 `.js`, `.ts`, `.vue` 파일에서 auto-import된 composable을 사용할 수 있습니다

```vue [app/app.vue]
<script setup lang="ts">
const foo = useFoo()
</script>

<template>
  <div>
    {{ foo }}
  </div>
</template>
```

::note
Nuxt의 `app/composables/` 디렉터리는 코드에 추가적인 반응성 기능을 제공하지 않습니다. 대신 composable 안의 반응성은 ref나 reactive 같은 Vue의 Composition API 메커니즘으로 구현됩니다. 또한 반응형 코드는 `app/composables/` 디렉터리 경계 안에만 제한되지 않습니다. 애플리케이션에서 필요한 곳이라면 어디서든 반응성 기능을 사용할 수 있습니다.
::

## 타입 %{#types}%

내부적으로 Nuxt는 타입 선언을 위해 `.nuxt/imports.d.ts` 파일을 자동 생성합니다.

Nuxt가 타입을 생성하게 하려면 [`nuxt prepare`](/docs/4.x/api/commands/prepare), [`nuxt dev`](/docs/4.x/api/commands/dev), [`nuxt build`](/docs/4.x/api/commands/build) 중 하나를 실행해야 한다는 점에 유의하세요.

::note
개발 서버를 실행하지 않은 상태에서 composable을 만들면 TypeScript가 `Cannot find name 'useBar'.` 같은 오류를 발생시킵니다.
::

## 예시 %{#examples}%

### 중첩된 Composable %{#nested-composables}%

auto import를 사용하면 다른 composable 안에서 composable을 사용할 수 있습니다:

```ts [app/composables/test.ts]
export const useFoo = () => {
  const nuxtApp = useNuxtApp()
  const bar = useBar()
}
```

### 플러그인 주입 접근 %{#access-plugin-injections}%

[plugin injections](/docs/4.x/directory-structure/app/plugins#providing-helpers)에 composable에서 접근할 수 있습니다:

```ts [app/composables/test.ts]
export const useHello = () => {
  const nuxtApp = useNuxtApp()
  return nuxtApp.$hello
}
```

## 파일 스캔 방식 %{#how-files-are-scanned}%

Nuxt는 [`app/composables/` 디렉터리](/docs/4.x/directory-structure/app/composables)의 최상위 파일만 스캔합니다. 예를 들면:

```bash [Directory Structure]
-| composables/
---| index.ts     // 스캔됨
---| useFoo.ts    // 스캔됨
---| nested/
-----| utils.ts   // 스캔되지 않음
```

`app/composables/index.ts`와 `app/composables/useFoo.ts`만 import 대상으로 검색됩니다.

중첩 모듈에서도 auto import가 동작하게 하려면 다시 export하는 방법(권장) 또는 스캐너가 중첩 디렉터리를 포함하도록 설정하는 방법이 있습니다:

**예시:** `app/composables/index.ts` 파일에서 필요한 composable을 다시 export합니다:

```ts [app/composables/index.ts]
// 이 export에 대해 auto import를 활성화합니다
export { utils } from './nested/utils.ts'
```

**예시:** `app/composables/` 폴더 안의 중첩 디렉터리를 스캔합니다:

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  imports: {
    dirs: [
      // 최상위 composable 스캔
      '~/composables',
      // ... 또는 특정 이름과 파일 확장자를 가진 한 단계 깊이의 composable 스캔
      '~/composables/*/index.{ts,js,mjs,mts}',
      // ... 또는 지정한 디렉터리 안의 모든 composable 스캔
      '~/composables/**',
    ],
  },
})
```
