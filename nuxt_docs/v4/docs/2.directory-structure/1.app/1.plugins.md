Nuxt는 `app/plugins/` 디렉터리의 파일을 자동으로 읽어 Vue 애플리케이션 생성 시 로드합니다.

::note
이 안의 모든 플러그인은 자동 등록되므로 `nuxt.config`에 따로 추가할 필요가 없습니다.
::

::note
파일 이름에 `.server` 또는 `.client` 접미사를 사용해 서버 또는 클라이언트에서만 플러그인을 로드할 수 있습니다.
::

## 등록된 플러그인 %{#registered-plugins}%

디렉터리 최상위 수준의 파일(또는 하위 디렉터리 안의 index 파일)만 플러그인으로 자동 등록됩니다.

```bash [Directory structure]
-| plugins/
---| foo.ts      // 스캔됨
---| bar/
-----| baz.ts    // 스캔되지 않음
-----| foz.vue   // 스캔되지 않음
-----| index.ts  // 현재는 스캔되지만 더 이상 권장되지 않음
```

`foo.ts`와 `bar/index.ts`만 등록됩니다.

하위 디렉터리의 플러그인을 추가하려면 `nuxt.config.ts`의 [`app/plugins`](/docs/4.x/api/nuxt-config#plugins-1) 옵션을 사용할 수 있습니다:

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  plugins: [
    '~/plugins/bar/baz',
    '~/plugins/bar/foz',
  ],
})
```

## 플러그인 만들기 %{#creating-plugins}%

플러그인에 전달되는 유일한 인수는 [`nuxtApp`](/docs/4.x/api/composables/use-nuxt-app)입니다.

```ts twoslash [plugins/hello.ts]
export default defineNuxtPlugin((nuxtApp) => {
  // nuxtApp으로 작업 수행
})
```

### 객체 문법 플러그인 %{#object-syntax-plugins}%

더 고급 사용 사례를 위해 객체 문법을 사용해 플러그인을 정의할 수도 있습니다. 예를 들면:

```ts twoslash [plugins/hello.ts]
export default defineNuxtPlugin({
  name: 'my-plugin',
  enforce: 'pre', // or 'post'
  async setup (nuxtApp) {
    // 일반 함수형 플러그인과 동일합니다
  },
  hooks: {
    // 여기서 Nuxt 앱 런타임 훅을 직접 등록할 수 있습니다
    'app:created' () {
      const nuxtApp = useNuxtApp()
      // 훅에서 작업 수행
    },
  },
  env: {
    // 서버 전용 또는 아일랜드 컴포넌트를 렌더링할 때 플러그인을 실행하고 싶지 않다면 이 값을 `false`로 설정합니다.
    islands: true,
  },
})
```

:video-accordion{title="Nuxt 플러그인의 객체 문법에 대한 Alexander Lichter 영상 보기" videoId="2aXZyXB1QGQ"}

::note
객체 문법을 사용하면 더 최적화된 빌드를 만들기 위해 속성이 정적으로 분석됩니다. 따라서 이를 런타임에 정의해서는 안 됩니다. :br
예를 들어 `enforce: import.meta.server ? 'pre' : 'post'`로 설정하면 Nuxt가 플러그인에 대해 수행할 수 있는 향후 최적화를 무력화하게 됩니다.
Nuxt는 객체 문법을 사용할 때 모든 훅 리스너를 정적으로 미리 로드하므로, 플러그인 등록 순서를 걱정하지 않고 훅을 정의할 수 있습니다.
::

## 등록 순서 %{#registration-order}%

파일 이름 앞에 '알파벳순' 번호를 붙여 플러그인 등록 순서를 제어할 수 있습니다.

```bash [Directory structure]
plugins/
 | - 01.myPlugin.ts
 | - 02.myOtherPlugin.ts
```

이 예시에서는 `02.myOtherPlugin.ts`가 `01.myPlugin.ts`가 주입한 모든 것에 접근할 수 있습니다.

이 방식은 다른 플러그인에 의존하는 플러그인이 있을 때 유용합니다.

::note
'알파벳순' 번호 매기기가 익숙하지 않다면, 파일명은 숫자값이 아니라 문자열로 정렬된다는 점을 기억하세요. 예를 들어 `10.myPlugin.ts`는 `2.myOtherPlugin.ts`보다 앞에 옵니다. 그래서 예시에서는 한 자리 숫자 앞에 `0`을 붙입니다.
::

## 로딩 전략 %{#loading-strategy}%

### 병렬 플러그인 %{#parallel-plugins}%

기본적으로 Nuxt는 플러그인을 순차적으로 로드합니다. 플러그인을 `parallel`로 정의하면 Nuxt는 해당 플러그인의 실행이 끝날 때까지 기다리지 않고 다음 플러그인을 로드합니다.

```ts twoslash [plugins/my-plugin.ts]
export default defineNuxtPlugin({
  name: 'my-plugin',
  parallel: true,
  async setup (nuxtApp) {
    // 다음 플러그인이 즉시 실행됩니다
  },
})
```

### 의존성이 있는 플러그인 %{#plugins-with-dependencies}%

플러그인이 실행되기 전에 다른 플러그인을 기다려야 한다면 해당 플러그인의 이름을 `dependsOn` 배열에 추가할 수 있습니다.

```ts twoslash [plugins/depending-on-my-plugin.ts]
export default defineNuxtPlugin({
  name: 'depends-on-my-plugin',
  dependsOn: ['my-plugin'],
  async setup (nuxtApp) {
    // 이 플러그인은 `my-plugin`의 실행이 끝날 때까지 기다렸다가 실행됩니다
  },
})
```

## Composable 사용하기 %{#using-composables}%

Nuxt 플러그인 안에서는 [composables](/docs/4.x/directory-structure/app/composables)와 [utils](/docs/4.x/directory-structure/app/utils)를 모두 사용할 수 있습니다:

```ts [app/plugins/hello.ts]
export default defineNuxtPlugin((nuxtApp) => {
  const foo = useFoo()
})
```

하지만 몇 가지 제한과 차이점을 염두에 두어야 합니다:

::important
**composable이 나중에 등록되는 다른 플러그인에 의존한다면 동작하지 않을 수 있습니다.** :br

플러그인은 순서대로, 그리고 다른 모든 것보다 먼저 호출됩니다. 아직 호출되지 않은 다른 플러그인에 의존하는 composable을 사용할 수 있습니다.
::

::important
**composable이 Vue.js 라이프사이클에 의존한다면 동작하지 않습니다.** :br

보통 Vue.js composable은 현재 컴포넌트 인스턴스에 바인딩되지만, 플러그인은 [`nuxtApp`](/docs/4.x/api/composables/use-nuxt-app) 인스턴스에만 바인딩됩니다.
::

## 헬퍼 제공하기 %{#providing-helpers}%

[`NuxtApp`](/docs/4.x/api/composables/use-nuxt-app) 인스턴스에 헬퍼를 제공하고 싶다면 플러그인에서 `provide` 키 아래로 반환하면 됩니다.

::code-group
```ts twoslash [plugins/hello.ts]
export default defineNuxtPlugin(() => {
  return {
    provide: {
      hello: (msg: string) => `안녕하세요 ${msg}!`,
    },
  }
})
```
```ts twoslash [plugins/hello-object-syntax.ts]
export default defineNuxtPlugin({
  name: 'hello',
  setup () {
    return {
      provide: {
        hello: (msg: string) => `안녕하세요 ${msg}!`,
      },
    }
  },
})
```
::

그런 다음 컴포넌트에서 이 헬퍼를 사용할 수 있습니다:

```vue [app/components/Hello.vue]
<script setup lang="ts">
// 또는 여기에서도 사용할 수 있습니다
const { $hello } = useNuxtApp()
</script>

<template>
  <div>
    {{ $hello('세계') }}
  </div>
</template>
```

::important
전역 네임스페이스 오염을 피하고 메인 번들 엔트리를 작게 유지하기 위해, 헬퍼를 제공하는 대신 [`composables`](/docs/4.x/directory-structure/app/composables)를 사용하는 것을 강력히 권장합니다.
::

::warning
**플러그인이 `ref`나 `computed`를 제공하면 컴포넌트 `<template>`에서는 언래핑되지 않습니다.** :br
이는 Vue가 템플릿 최상위가 아닌 ref를 처리하는 방식 때문입니다. 자세한 내용은 [Vue 문서](https://vuejs.org/guide/essentials/reactivity-fundamentals#caveat-when-unwrapping-in-templates)에서 확인할 수 있습니다.
::

## 플러그인 타입 지정 %{#typing-plugins}%

플러그인에서 헬퍼를 반환하면 자동으로 타입이 지정되며, `useNuxtApp()`의 반환값과 템플릿 안에서 타입이 적용된 것을 확인할 수 있습니다.

::note
다른 플러그인 _내부에서_ 제공된 헬퍼를 사용해야 한다면 [`useNuxtApp()`](/docs/4.x/api/composables/use-nuxt-app)을 호출해 타입이 지정된 버전을 가져올 수 있습니다. 하지만 일반적으로는 플러그인 순서를 확신할 수 있는 경우가 아니라면 피해야 합니다.
::

고급 사용 사례에서는 다음과 같이 주입된 속성의 타입을 선언할 수 있습니다:

```ts [index.d.ts]
declare module '#app' {
  interface NuxtApp {
    $hello (msg: string): string
  }
}

declare module 'vue' {
  interface ComponentCustomProperties {
    $hello (msg: string): string
  }
}

export {}
```

## Vue 플러그인 %{#vue-plugins}%

Google Analytics 태그를 추가하는 [vue-gtag](https://github.com/MatteoGabriele/vue-gtag) 같은 Vue 플러그인을 사용하고 싶다면 Nuxt 플러그인을 이용할 수 있습니다.

먼저 Vue 플러그인 의존성을 설치합니다:

::code-group{sync="pm"}
```bash [npm]
npm install --save-dev vue-gtag-next
```
```bash [yarn]
yarn add --dev vue-gtag-next
```
```bash [pnpm]
pnpm add -D vue-gtag-next
```
```bash [bun]
bun add -D vue-gtag-next
```
```bash [deno]
deno add -D npm:vue-gtag-next
```
::

그다음 플러그인 파일을 만듭니다:

```ts [app/plugins/vue-gtag.client.ts]
import VueGtag, { trackRouter } from 'vue-gtag-next'

export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.vueApp.use(VueGtag, {
    property: {
      id: 'GA_MEASUREMENT_ID',
    },
  })
  trackRouter(useRouter())
})
```

## Vue 디렉티브 %{#vue-directives}%

마찬가지로 플러그인에서 사용자 정의 Vue 디렉티브를 등록할 수 있습니다.

```ts twoslash [plugins/my-directive.ts]
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.vueApp.directive('focus', {
    mounted (el) {
      el.focus()
    },
    getSSRProps (binding, vnode) {
      // 여기서 SSR 전용 props를 제공할 수 있습니다
      return {}
    },
  })
})
```

::warning
Vue 디렉티브를 등록한다면, 한쪽 렌더링에서만 사용할 것이 아니라면 _반드시_ 클라이언트와 서버 양쪽에 등록해야 합니다. 디렉티브가 클라이언트 측에서만 의미가 있다면 `~/plugins/my-directive.client.ts`로 옮기고 서버용 'stub' 디렉티브를 `~/plugins/my-directive.server.ts`에서 제공할 수 있습니다.
::
