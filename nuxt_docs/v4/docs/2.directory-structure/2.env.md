## 개발, 빌드 및 생성 시점 %{#dev-build-and-generate-time}%

Nuxt CLI는 개발 모드와 [`nuxt build`](/docs/4.x/api/commands/build), [`nuxt generate`](/docs/4.x/api/commands/generate)를 실행할 때 내장 [dotenv](https://github.com/motdotla/dotenv) 지원을 제공합니다.

프로세스 환경 변수 외에도 프로젝트 루트 디렉터리에 `.env` 파일이 있으면 **개발, 빌드, 생성 시점에** 자동으로 로드됩니다. 그 안에 설정한 환경 변수는 `nuxt.config` 파일과 모듈에서 접근할 수 있습니다.

```ini [.env]
MY_ENV_VARIABLE=hello
```

::note
`.env`에서 변수를 제거하거나 `.env` 파일 자체를 삭제해도 이미 설정된 값이 해제되지는 않는다는 점에 유의하세요.
::

## 사용자 정의 파일 %{#custom-file}%

다른 파일(예: `.env.local` 또는 `.env.production`)을 사용하고 싶다면 Nuxt CLI를 사용할 때 `--dotenv` 플래그를 전달하면 됩니다.

```bash [Terminal]
npx nuxt dev --dotenv .env.local
```

개발 모드에서 `.env`를 업데이트하면 새 값을 `process.env`에 적용하기 위해 Nuxt 인스턴스가 자동으로 재시작됩니다.

::important
애플리케이션 코드에서는 일반 env 변수 대신 [Runtime Config](/docs/4.x/guide/going-further/runtime-config)를 사용해야 합니다.
::

## 프로덕션 %{#production}%

**서버가 빌드된 후에는** 서버를 실행할 때 환경 변수를 직접 설정해야 합니다.

이 시점에는 `.env` 파일을 읽지 않습니다. 이를 설정하는 방법은 환경마다 다릅니다.

이 설계 결정은 서버리스 플랫폼이나 Cloudflare Workers 같은 엣지 네트워크처럼 전통적인 파일 시스템이 없을 수 있는 다양한 배포 환경과의 호환성을 보장하기 위해 내려졌습니다.

프로덕션에서는 `.env` 파일을 사용하지 않으므로, 호스팅 환경이 제공하는 도구와 방법을 사용해 환경 변수를 명시적으로 설정해야 합니다. 일반적인 방법은 다음과 같습니다:

* 터미널에서 환경 변수를 인자로 전달할 수 있습니다:

   `$ DATABASE_HOST=mydatabaseconnectionstring node .output/server/index.mjs`

* `.bashrc`나 `.profile` 같은 셸 설정 파일에 환경 변수를 설정할 수 있습니다.

* Vercel, Netlify, AWS 같은 많은 클라우드 서비스 제공자는 대시보드, CLI 도구, 설정 파일을 통해 환경 변수를 설정하는 인터페이스를 제공합니다.

::important
`runtimeConfig`는 [프로덕션에서 `NUXT_`로 시작하지 않는 환경 변수를 읽지 않습니다] (https://nuxt.com/docs/4.x/guide/going-further/runtime-config#environment-variables).
::

## 프로덕션 미리 보기 %{#production-preview}%

로컬에서 프로덕션 미리 보기를 할 때는 [`nuxt preview`](/docs/4.x/api/commands/preview)를 사용하는 것을 권장합니다. 이 명령은 편의를 위해 `.env` 파일을 `process.env`로 로드합니다. 이 명령을 사용하려면 패키지 디렉터리에 의존성이 설치되어 있어야 합니다.

또는 터미널에서 환경 변수를 인자로 전달할 수도 있습니다. 예를 들어 Linux나 macOS에서는 다음과 같습니다:

```bash [Terminal]
DATABASE_HOST=mydatabaseconnectionstring node .output/server/index.mjs
```

완전히 정적인 사이트의 경우 프로젝트가 프리렌더링된 뒤에는 런타임 설정을 지정할 수 없다는 점에 유의하세요.

:read-more{to="/docs/4.x/guide/going-further/runtime-config"}

::note
빌드 시점에 설정한 환경 변수를 사용하되 이후에 이를 갱신할 필요가 없거나(또는 앱 _내부에서만_ 반응형으로 갱신하면 된다면) `appConfig`가 더 나은 선택일 수 있습니다. `appConfig`는 `nuxt.config`(환경 변수 사용) 안에서도, 프로젝트의 `~/app.config.ts` 파일 안에서도 정의할 수 있습니다.
:read-more{to="/docs/4.x/directory-structure/app/app-config"}
::
