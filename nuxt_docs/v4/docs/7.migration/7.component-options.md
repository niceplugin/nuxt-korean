## `asyncData` and `fetch` %{#asyncdata-and-fetch}%

### 동형 Fetch %{#isomorphic-fetch}%

Nuxt 2에서는 `@nuxtjs/axios`나 `@nuxt/http`로 데이터를 가져오거나, 폴리필된 전역 `fetch`를 사용했을 수 있습니다.

Nuxt 3에서는 [Fetch API](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch)와 동일한 API를 가진 전역 `fetch` 메서드나 [unjs/ofetch](https://github.com/unjs/ofetch)를 사용하는 [`$fetch`](/docs/4.x/api/utils/dollarfetch) 메서드를 사용할 수 있습니다. 여기에는 다음과 같은 여러 장점이 있습니다:

1. 서버에서 실행 중이면 [직접 API 호출](/docs/4.x/guide/concepts/server-engine#direct-api-calls)을 '똑똑하게' 처리하고, 클라이언트에서 실행 중이면 API에 대한 클라이언트 사이드 호출을 수행합니다. (서드파티 API 호출도 처리할 수 있습니다.)

2. 또한 응답 자동 파싱과 데이터 문자열화 같은 편의 기능이 포함되어 있습니다.

[직접 API 호출](/docs/4.x/guide/concepts/server-engine#direct-api-calls)이나 [데이터 가져오기](/docs/4.x/getting-started/data-fetching)에 대해 더 읽어볼 수 있습니다.

### Composables %{#composables}%

Nuxt 3는 데이터 가져오기를 위한 새로운 컴포저블 [`useAsyncData`](/docs/4.x/api/composables/use-async-data)와 `useFetch`를 제공합니다. 각각에는 클라이언트 사이드 탐색을 막지 않는 'lazy' 변형(`useLazyAsyncData`, `useLazyFetch`)도 있습니다.

Nuxt 2에서는 컴포넌트에서 다음과 비슷한 문법으로 데이터를 가져왔을 것입니다:

```ts
export default {
  async asyncData ({ params, $http }) {
    const post = await $http.$get(`https://api.nuxtjs.dev/posts/${params.id}`)
    return { post }
  },
  // or alternatively
  fetch () {
    this.post = await $http.$get(`https://api.nuxtjs.dev/posts/${params.id}`)
  },
}
```

메서드와 템플릿 안에서는 컴포넌트가 제공하는 다른 데이터처럼 `post` 변수를 사용할 수 있었습니다.

Nuxt 3에서는 `setup()` 메서드나 `<script setup>` 태그 안에서 컴포저블을 사용해 이 데이터 fetch를 수행할 수 있습니다:

```vue
<script setup lang="ts">
// `defineProps()`, `useRoute()` 등으로 필요한 곳에서 params를 정의합니다.
const { data: post, refresh } = await useAsyncData('post', () => $fetch(`https://api.nuxtjs.dev/posts/${params.id}`))
// 또는 단순한 fetch만 수행한다면 useFetch는 useAsyncData를 감싼 편의 래퍼입니다.
const { data: post, refresh } = await useFetch(`https://api.nuxtjs.dev/posts/${params.id}`)
</script>
```

이제 Nuxt 3 템플릿 안에서 `post`를 사용하거나 `refresh`를 호출해 데이터를 업데이트할 수 있습니다.

::note
이름과 달리 [`useFetch`](/docs/4.x/api/composables/use-fetch)는 `fetch()` 훅의 직접적인 대체제가 아닙니다. 오히려 [`useAsyncData`](/docs/4.x/api/composables/use-async-data)가 두 훅을 모두 대체하며 더 많은 사용자 지정을 제공합니다. 단순히 엔드포인트에서 데이터를 가져오는 것 이상의 작업을 할 수 있습니다. [`useFetch`](/docs/4.x/api/composables/use-fetch)는 엔드포인트에서 데이터를 단순히 가져오기 위한 [`useAsyncData`](/docs/4.x/api/composables/use-async-data)의 편의 래퍼입니다.
::

### Migration %{#migration}%

1. 페이지/컴포넌트에서 `asyncData` 훅을 [`useAsyncData`](/docs/4.x/api/composables/use-async-data) 또는 [`useFetch`](/docs/4.x/api/composables/use-fetch)로 교체하세요.
2. 컴포넌트에서 `fetch` 훅을 [`useAsyncData`](/docs/4.x/api/composables/use-async-data) 또는 [`useFetch`](/docs/4.x/api/composables/use-fetch)로 교체하세요.

## `key` %{#key}%

이제 [`definePageMeta`](/docs/4.x/api/utils/define-page-meta) 컴파일러 매크로 안에서 key를 정의할 수 있습니다.

```diff [app/pages/index.vue]
- <script>
- export default {
-   key: 'index'
-   // or a method
-   // key: route => route.fullPath
- }
+ <script setup>
+ definePageMeta({
+   key: 'index'
+   // or a method
+   // key: route => route.fullPath
+ })
</script>
```

## `scrollToTop` %{#scrolltotop}%

이 기능은 아직 Nuxt 3에서 지원되지 않습니다. `vue-router`의 기본 스크롤 동작을 덮어쓰고 싶다면 `~/router.options.ts`에서 처리할 수 있습니다 (자세한 내용은 [docs](/docs/4.x/guide/recipes/custom-routing#router-options) 참고).
`key`와 마찬가지로 [`definePageMeta`](/docs/4.x/api/utils/define-page-meta) 컴파일러 매크로 안에서 지정하세요.

```diff [app/pages/index.vue]
- <script>
- export default {
-   scrollToTop: false
- }
+ <script setup>
+ definePageMeta({
+   scrollToTop: false
+ })
</script>
```

## `validate` %{#validate}%

Nuxt 3의 validate 훅은 `route`라는 단일 인자만 받습니다. Nuxt 2와 마찬가지로 boolean 값을 반환할 수 있습니다. false를 반환하고 다른 일치 항목을 찾지 못하면 404가 됩니다. `status`/`statusText`를 가진 객체를 직접 반환해 즉시 오류로 응답할 수도 있습니다 (다른 일치 항목은 검사되지 않음).

```diff [app/pages/users/[id\\].vue]
- <script>
- export default {
-   async validate({ params }) {
-     return /^\d+$/.test(params.id)
-   }
- }
+ <script setup>
+ definePageMeta({
+   validate: async (route) => {
+     const nuxtApp = useNuxtApp()
+     return /^\d+$/.test(route.params.id)
+   }
+ })
  </script>
```

## `watchQuery` %{#watchquery}%

이는 Nuxt 3에서 지원되지 않습니다. 대신 watcher를 직접 사용해 데이터 재가져오기를 트리거할 수 있습니다.

```vue [app/pages/users/[id\\].vue]
<script setup lang="ts">
const route = useRoute()
const { data, refresh } = await useFetch('/api/user')
watch(() => route.query, () => refresh())
</script>
```
