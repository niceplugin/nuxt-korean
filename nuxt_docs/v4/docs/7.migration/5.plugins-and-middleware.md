## 플러그인 %{#plugins}%

이제 플러그인의 형식이 달라졌으며 인자를 하나(`nuxtApp`)만 받습니다.

::code-group

```ts [Nuxt 2]
export default (ctx, inject) => {
  inject('injected', () => '내가 주입한 함수')
}
```

```ts [Nuxt 3]
export default defineNuxtPlugin((nuxtApp) => {
  // 이제 `nuxtApp.$injected`에서 사용할 수 있습니다
  nuxtApp.provide('injected', () => '내가 주입한 함수')

  // 자동 타입 지원이 포함된 이 형식을 대신 사용할 수도 있습니다
  return {
    provide: {
      injected: () => '내가 주입한 함수',
    },
  }
})
```

::

:read-more{to="/docs/4.x/directory-structure/app/plugins"}

::read-more{to="/docs/4.x/api/composables/use-nuxt-app"}
`nuxtApp` 형식에 대해 더 알아보세요.
::

### 마이그레이션 %{#migration}%

1. 플러그인을 `defineNuxtPlugin` 헬퍼 함수를 사용하도록 마이그레이션하세요.
2. `app/plugins/` 폴더에 있는 항목은 `nuxt.config`의 plugins 배열에서 제거하세요. 이 디렉터리의 최상위 파일(및 하위 디렉터리의 모든 index 파일)은 자동 등록됩니다. `mode`를 `client`나 `server`로 설정하는 대신 파일 이름으로 이를 표시할 수 있습니다. 예를 들어 `~/plugins/my-plugin.client.ts`는 클라이언트 사이드에서만 로드됩니다.

## 라우트 미들웨어 %{#route-middleware}%

라우트 미들웨어는 형식이 다릅니다.

::code-group

```js [Nuxt 2]
export default function ({ store, redirect }) {
  // 사용자가 인증되지 않은 경우
  if (!store.state.authenticated) {
    return redirect('/login')
  }
}
```

```ts [Nuxt 3]
export default defineNuxtRouteMiddleware((to, from) => {
  const auth = useState('auth')
  if (!auth.value.authenticated) {
    return navigateTo('/login')
  }
})
```

::

Nuxt 2와 마찬가지로 `~/middleware` 폴더에 둔 route middleware는 자동 등록됩니다. 이후 컴포넌트에서 이름으로 지정할 수 있습니다. 다만 컴포넌트 옵션이 아니라 `definePageMeta`로 지정합니다.

`navigateTo`는 여러 route 헬퍼 함수 중 하나입니다.

:read-more{to="/docs/4.x/directory-structure/app/middleware"}

### 마이그레이션 %{#migration}%

1. route middleware를 `defineNuxtRouteMiddleware` 헬퍼 함수를 사용하도록 마이그레이션하세요.
1. 전역 미들웨어(`nuxt.config`에 있던 것 등)는 `~/middleware` 폴더에 `.global` 확장자를 붙여 둘 수 있습니다. 예: `~/middleware/auth.global.ts`.
