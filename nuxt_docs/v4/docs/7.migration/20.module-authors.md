## 모듈 호환성 %{#module-compatibility}%

Nuxt 3는 `@nuxt/kit` 자동 래퍼를 사용해 Nuxt 2 모듈에 대한 기본적인 하위 호환 계층을 제공합니다. 하지만 보통 모듈을 Nuxt 3와 호환되게 만들기 위해 따라야 할 단계가 있으며, 때로는 버전 간 호환성을 위해 Nuxt Bridge가 필요합니다.

우리는 `@nuxt/kit`을 사용해 Nuxt 3 준비가 된 모듈을 작성하기 위한 [전용 가이드](/docs/4.x/guide/modules)를 준비했습니다. 현재 가장 좋은 마이그레이션 경로는 이 가이드를 따라 모듈을 다시 작성하는 것입니다. 이 가이드의 나머지 부분은 전체 재작성을 피하면서도 모듈을 Nuxt 3와 호환되게 만들고 싶을 때의 준비 단계를 포함합니다.

::tip{icon="i-lucide-puzzle" to="/modules"}
Nuxt 3 호환 모듈을 살펴보세요.
::

### 플러그인 호환성 %{#plugin-compatibility}%

Nuxt 3 플러그인은 Nuxt 2와 **완전히** 하위 호환되지 않습니다.

:read-more{to="/docs/4.x/directory-structure/app/plugins"}

### Vue 호환성 %{#vue-compatibility}%

Composition API를 사용하는 플러그인이나 컴포넌트는 Vue 2 또는 Vue 3에 대한 전용 지원이 필요합니다.

[vue-demi](https://github.com/vueuse/vue-demi)를 사용하면 Nuxt 2와 3 모두와 호환되도록 만들 수 있습니다.

## 모듈 마이그레이션 %{#module-migration}%

Nuxt 3 사용자가 여러분의 모듈을 추가하면 더 이상 module container(`this.*`)에 접근할 수 없으므로 container 기능에 접근하려면 `@nuxt/kit`의 유틸리티를 사용해야 합니다.

### `@nuxt/bridge`로 테스트하기 %{#test-with-nuxt-bridge}%

Nuxt 3 지원을 위해 `@nuxt/bridge`로 마이그레이션하는 것은 첫 번째이자 가장 중요한 단계입니다.

모듈에 fixture나 예제가 있다면 해당 설정에 `@nuxt/bridge` 패키지를 추가하세요([예시](/docs/4.x/bridge/overview#update-nuxtconfig) 참고)

### CommonJS에서 ESM으로 마이그레이션 %{#migrate-from-commonjs-to-esm}%

Nuxt 3는 TypeScript와 ECMAScript Modules를 네이티브로 지원합니다. 자세한 정보와 업그레이드 방법은 [Native ES Modules](/docs/4.x/guide/concepts/esm)를 확인하세요.

### 플러그인 기본 export 보장 %{#ensure-plugins-default-export}%

`export default`가 없는 Nuxt 플러그인(예: 전역 Vue 플러그인)을 주입한다면 마지막에 `export default () => { }`를 추가해야 합니다.

::code-group

```js [Before]
// ~/plugins/vuelidate.js
import Vue from 'vue'
import Vuelidate from 'vuelidate'

Vue.use(Vuelidate)
```

```js [After]
// ~/plugins/vuelidate.js
import Vue from 'vue'
import Vuelidate from 'vuelidate'

Vue.use(Vuelidate)

export default () => { }
```

::

### 런타임 모듈 피하기 %{#avoid-runtime-modules}%

Nuxt 3에서 Nuxt는 이제 빌드 타임 전용 의존성이므로, 모듈이 Nuxt 런타임에 연결되려고 해서는 안 됩니다.

여러분의 모듈은 [`buildModules`](/docs/4.x/api/nuxt-config#runtimeconfig)에만 추가되어도(`modules` 대신) 동작해야 합니다. 예를 들면:

- Nuxt 모듈 안에서 `process.env`를 수정하고 Nuxt 플러그인에서 읽는 방식은 피하고, 대신 [`runtimeConfig`](/docs/4.x/api/nuxt-config#runtimeconfig)를 사용하세요.
- (*) 프로덕션에서는 `vue-renderer:*` 같은 런타임 훅 의존을 피하세요
- (*) `serverMiddleware`를 모듈 안에서 import해 추가하는 방식은 피하세요. 대신 파일 경로를 참조해 추가하여 모듈 컨텍스트와 독립적으로 동작하게 하세요

(*) 단, `nuxt dev` 전용 목적이고 `if (nuxt.options.dev) { }`로 보호된 경우는 예외입니다.

::tip
[Modules Author Guide](/docs/4.x/guide/modules)에서 Nuxt 3 모듈에 대해 계속 읽어보세요.
::

### TypeScript 사용하기(선택) %{#use-typescript-optional}%

필수는 아니지만 Nuxt 생태계 대부분이 TypeScript 사용으로 옮겨가고 있으므로 마이그레이션을 적극 권장합니다.

::tip
`.js` 파일을 `.ts`로 이름만 바꾸는 것부터 마이그레이션을 시작할 수 있습니다. TypeScript는 점진적 도입을 전제로 설계되었습니다!
::

::tip
별도 의존성 없이도 Nuxt 2와 3 모듈 및 플러그인에서 TypeScript 문법을 사용할 수 있습니다.
::
