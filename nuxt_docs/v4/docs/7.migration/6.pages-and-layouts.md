## `app.vue` %{#app-vue}%

Nuxt 3는 `~/app.vue`를 통해 앱의 중앙 진입점을 제공합니다.

::note
소스 디렉터리에 `app.vue` 파일이 없다면 Nuxt는 자체 기본 버전을 사용합니다.
::

이 파일은 앱이 시작될 때 한 번만 실행되어야 하는 사용자 정의 코드와 앱의 모든 페이지에 존재하는 컴포넌트를 배치하기에 좋은 위치입니다. 예를 들어 레이아웃이 하나뿐이라면 이를 대신 `app.vue`로 옮길 수 있습니다.

:read-more{to="/docs/4.x/directory-structure/app/app"}

:link-example{to="/docs/4.x/examples/hello-world"}

### 마이그레이션 %{#migration}%

`app.vue` 파일을 만들고 앱의 최상위에서 한 번만 실행되어야 하는 로직을 포함하는 것을 고려해 보세요. [여기 예제](/docs/4.x/directory-structure/app/app)를 확인할 수 있습니다.

## 레이아웃 %{#layouts}%

앱에서 여러 페이지에 레이아웃을 사용하고 있다면, 필요한 변경은 약간뿐입니다.

Nuxt 2에서는 현재 페이지를 렌더링하기 위해 레이아웃 안에서 `<Nuxt>` 컴포넌트를 사용합니다. Nuxt 3에서는 대신 슬롯을 사용하므로, 해당 컴포넌트를 `<slot />`으로 바꿔야 합니다. 이렇게 하면 이름 있는 슬롯과 스코프드 슬롯을 사용하는 고급 사례도 가능해집니다. [레이아웃에 대해 더 알아보기](/docs/4.x/directory-structure/app/layouts).

또한 `definePageMeta` 컴파일러 매크로를 사용해 페이지에서 사용할 레이아웃을 정의하는 방식도 바꿔야 합니다. 레이아웃 이름은 kebab-case가 됩니다. 따라서 `app/layouts/customLayout.vue`는 페이지에서 참조할 때 `custom-layout`이 됩니다.

### 마이그레이션 %{#migration}%

1. `<Nuxt />`를 `<slot />`으로 교체합니다
    ```diff [app/layouts/custom.vue]
      <template>
        <div id="app-layout">
          <main>
    -       <Nuxt />
    +       <slot />
          </main>
        </div>
      </template>
    ```
2. 페이지에서 사용할 레이아웃을 선택하기 위해 [`definePageMeta`](/docs/4.x/api/utils/define-page-meta)를 사용합니다.
    ```diff [app/pages/index.vue]
    + <script setup>
    + definePageMeta({
    +   layout: 'custom'
    + })
    - <script>
    - export default {
    -   layout: 'custom'
    - }
      </script>
    ```
3. `~/layouts/_error.vue`를 `~/error.vue`로 옮깁니다. [오류 처리 문서](/docs/4.x/getting-started/error-handling)를 참고하세요. 이 페이지가 레이아웃을 사용하도록 보장하고 싶다면 `error.vue` 안에서 [`<NuxtLayout>`](/docs/4.x/directory-structure/app/layouts)를 직접 사용할 수 있습니다:
    ```vue [error.vue]
    <template>
      <div>
        <NuxtLayout name="default">
          <!-- -->
        </NuxtLayout>
      </div>
    </template>
    ```

## 페이지 %{#pages}%

Nuxt 3는 소스 디렉터리에 [`app/pages/`](/docs/4.x/directory-structure/app/pages) 디렉터리가 존재하면 활성화되는 선택적 `vue-router` 통합을 제공합니다. 페이지가 하나뿐이라면 더 가벼운 빌드를 위해 이를 `app.vue`로 옮기는 것도 고려할 수 있습니다.

### 동적 라우트 %{#dynamic-routes}%

Nuxt 3에서 동적 라우트를 정의하는 형식은 Nuxt 2와 약간 다르므로, `app/pages/` 내부 파일 일부의 이름을 바꿔야 할 수 있습니다.

1. 이전에 동적 라우트 매개변수를 정의할 때 `_id`를 사용했다면 이제는 `[id]`를 사용합니다.
2. 이전에 catch-all 라우트를 정의할 때 `_.vue`를 사용했다면 이제는 `[...slug].vue`를 사용합니다.

### 중첩 라우트 %{#nested-routes}%

Nuxt 2에서는 `<Nuxt>`와 `<NuxtChild>`를 사용해 부모 및 자식 컴포넌트가 있는 중첩 라우트를 정의했을 것입니다. Nuxt 3에서는 이들이 단일 `<NuxtPage>` 컴포넌트로 대체되었습니다.

### 페이지 키와 Keep-alive Props %{#page-keys-and-keep-alive-props}%

사용자 정의 페이지 키나 keep-alive props를 `<Nuxt>`에 전달하고 있었다면, 이제 `definePageMeta`를 사용해 이 옵션들을 설정합니다.

:read-more{to="/docs/4.x/directory-structure/app/pages#special-metadata"}

### 페이지 및 레이아웃 전환 %{#page-and-layout-transitions}%

페이지나 레이아웃의 전환을 컴포넌트 옵션에서 직접 정의하고 있었다면, 이제 전환을 설정하기 위해 `definePageMeta`를 사용해야 합니다. Vue 3부터는 [-enter 및 -leave CSS 클래스 이름이 변경되었습니다](https://v3-migration.vuejs.org/breaking-changes/transition.html). `<Nuxt>`의 `style` prop은 `<slot>`에 사용할 때 더 이상 전환에 적용되지 않으므로, 스타일을 `-active` 클래스 쪽으로 옮기세요.

:read-more{to="/docs/4.x/getting-started/transitions"}

### 마이그레이션 %{#migration}%

1. 동적 매개변수가 있는 모든 페이지의 이름을 새 형식에 맞게 변경합니다.
2. `<Nuxt>`와 `<NuxtChild>`를 `<NuxtPage>`로 업데이트합니다.
3. Composition API를 사용 중이라면, `this.$route`와 `this.$router`도 [`useRoute`](/docs/4.x/api/composables/use-route) 및 [`useRouter`](/docs/4.x/api/composables/use-router) 컴포저블로 마이그레이션할 수 있습니다.

#### 예제: 동적 라우트 %{#example-dynamic-routes}%

::code-group

``` [Nuxt 2]
- URL: /users
- 페이지: /pages/users/index.vue

- URL: /users/some-user-name
- 페이지: /pages/users/_user.vue
- 사용법: params.user

- URL: /users/some-user-name/edit
- 페이지: /pages/users/_user/edit.vue
- 사용법: params.user

- URL: /users/anything-else
- 페이지: /pages/users/_.vue
- 사용법: params.pathMatch
```

``` [Nuxt 3]
- URL: /users
- 페이지: /pages/users/index.vue

- URL: /users/some-user-name
- 페이지: /pages/users/[user].vue
- 사용법: params.user

- URL: /users/some-user-name/edit
- 페이지: /pages/users/[user]/edit.vue
- 사용법: params.user

- URL: /users/anything-else
- 페이지: /pages/users/[...slug].vue
- 사용법: params.slug
```

::

#### 예제: 중첩 라우트와 `definePageMeta` %{#example-nested-routes-and-definepagemeta}%

::code-group

```vue [Nuxt 2]
<template>
  <div>
    <NuxtChild
      keep-alive
      :keep-alive-props="{ exclude: ['modal'] }"
      :nuxt-child-key="$route.slug"
    />
  </div>
</template>

<script>
export default {
  transition: 'page', // or { name: 'page' }
}
</script>
```

```vue [Nuxt 3]
<template>
  <div>
    <NuxtPage />
  </div>
</template>

<script setup lang="ts">
// 이 컴파일러 매크로는 <script>와 <script setup> 모두에서 동작합니다
definePageMeta({
  // 문자열이나 계산된 속성을 전달할 수도 있습니다
  key: route => route.slug,
  transition: {
    name: 'page',
  },
  keepalive: {
    exclude: ['modal'],
  },
})
</script>
```

::

## `<NuxtLink>` 컴포넌트 %{#component}%

전역 [NuxtLink](/docs/4.x/api/components/nuxt-link) 컴포넌트의 문법과 기능 대부분은 동일합니다. 축약형 `<NLink>`를 사용하고 있었다면 `<NuxtLink>`로 업데이트해야 합니다.

이제 `<NuxtLink>`는 외부 링크를 포함한 _모든_ 링크에 대한 드롭인 대체재입니다. 이에 대한 자세한 내용과 자체 링크 컴포넌트를 제공하도록 확장하는 방법을 더 읽어볼 수 있습니다.

:read-more{to="/docs/4.x/api/components/nuxt-link"}

## 프로그래밍 방식 내비게이션 %{#programmatic-navigation}%

Nuxt 2에서 Nuxt 3로 마이그레이션할 때는 사용자를 프로그래밍 방식으로 내비게이션하는 방법도 업데이트해야 합니다. Nuxt 2에서는 `this.$router`로 기반 Vue Router에 접근할 수 있었습니다. Nuxt 3에서는 Vue Router에 라우트와 매개변수를 전달할 수 있는 `navigateTo()` 유틸리티 메서드를 사용할 수 있습니다.

::warning
항상 [`navigateTo`](/docs/4.x/api/utils/navigate-to)에 `await`를 사용하거나 함수에서 반환해 그 결과를 체이닝해야 합니다.
::

::code-group

```vue [Nuxt 2]
<script>
export default {
  methods: {
    navigate () {
      this.$router.push({
        path: '/search',
        query: {
          name: 'first name',
          type: '1',
        },
      })
    },
  },
}
</script>
```

```vue [Nuxt 3]
<script setup lang="ts">
function navigate () {
  return navigateTo({
    path: '/search',
    query: {
      name: 'first name',
      type: '1',
    },
  })
}
</script>
```

::
