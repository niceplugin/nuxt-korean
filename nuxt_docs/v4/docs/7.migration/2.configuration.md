## `nuxt.config` %{#nuxt-config}%

Nuxt 앱의 시작점은 여전히 `nuxt.config` 파일입니다.

::note
Nuxt 설정은 [`unjs/jiti`](https://github.com/unjs/jiti)와 [`unjs/c12`](https://github.com/unjs/c12)를 사용해 로드됩니다.
::

### 마이그레이션 %{#migration}%

1. 타입이 지정된 설정 스키마를 제공하는 새로운 `defineNuxtConfig` 함수로 마이그레이션해야 합니다.

   ::code-group

   ```ts [Nuxt 2]
   export default {
     // ...
   }
   ```

   ```ts [Nuxt 3]
   export default defineNuxtConfig({
     // ...
   })
   ```

   ::

1. `router.extendRoutes`를 사용하고 있었다면 새로운 `pages:extend` 훅으로 마이그레이션할 수 있습니다:

   ::code-group

   ```ts [Nuxt 2]
   export default {
     router: {
       extendRoutes (routes) {
         //
       },
     },
   }
   ```

   ```ts [Nuxt 3]
   export default defineNuxtConfig({
     hooks: {
       'pages:extend' (routes) {
         //
       },
     },
   })
   ```

   ::

1. `router.routeNameSplitter`를 사용하고 있었다면 새로운 `pages:extend` 훅에서 라우트 이름 생성 로직을 업데이트하여 같은 결과를 얻을 수 있습니다:

   ::code-group

   ```ts [Nuxt 2]
   export default {
     router: {
       routeNameSplitter: '/',
     },
   }
   ```

   ```ts [Nuxt 3]
   import { createResolver } from '@nuxt/kit'

   export default defineNuxtConfig({
     hooks: {
       'pages:extend' (routes) {
         const routeNameSplitter = '/'
         const root = createResolver(import.meta.url).resolve('./pages')

         function updateName (routes) {
           if (!routes) {
             return
           }

           for (const route of routes) {
             const relativePath = route.file.substring(root.length + 1)
             route.name = relativePath.slice(0, -4).replace(/\/index$/, '').replace(/\//g, routeNameSplitter)

             updateName(route.children)
           }
         }
         updateName(routes)
       },
     },
   })
   ```

   ::

#### ESM 문법 %{#esm-syntax}%

Nuxt 3는 [ESM 네이티브 프레임워크](/docs/4.x/guide/concepts/esm)입니다. [`unjs/jiti`](https://github.com/unjs/jiti)가 `nuxt.config` 파일을 로드할 때 어느 정도 호환성을 제공하긴 하지만, 이 파일에서는 `require`와 `module.exports` 사용을 피하세요.

1. `module.exports`를 `export default`로 바꿉니다
1. `const lib = require('lib')`를 `import lib from 'lib'`로 바꿉니다

#### 비동기 설정 %{#async-configuration}%

Nuxt 로딩 동작을 더 예측 가능하게 만들기 위해 비동기 설정 문법은 더 이상 권장되지 않습니다. 비동기 작업에는 Nuxt 훅 사용을 고려하세요.

#### Dotenv %{#dotenv}%

Nuxt는 `.env` 파일 로드를 기본으로 지원합니다. `nuxt.config`에서 이를 직접 임포트하지 마세요.

## 모듈 %{#modules}%

이제 Nuxt와 Nuxt 모듈은 빌드 타임 전용입니다.

### 마이그레이션 %{#migration}%

1. 모든 `buildModules`를 `modules`로 옮깁니다.
2. 모듈의 Nuxt 3 호환성을 확인합니다.
3. 디렉터리를 가리키는 로컬 모듈이 있다면, 이를 엔트리 파일을 가리키도록 업데이트해야 합니다:

```diff
  export default defineNuxtConfig({
    modules: [
-     '~/modules/my-module'
+     '~/modules/my-module/index'
    ]
  })
```

::tip
모듈 작성자라면 [모듈 호환성에 대한 추가 정보](/docs/4.x/migration/module-authors)와 [모듈 작성자 가이드](/docs/4.x/guide/modules)를 확인해 보세요.
::

## 디렉터리 변경 사항 %{#directory-changes}%

정적 자산을 저장하는 `static/`은 `public/`으로 이름이 바뀌었습니다. `static` 디렉터리를 `public`으로 이름 변경하거나, `nuxt.config`에서 `dir.public`을 설정해 기존 이름을 유지할 수 있습니다.

:read-more{to="/docs/4.x/directory-structure/public"}

## TypeScript %{#typescript}%

Nuxt의 TypeScript 통합을 사용하면 애플리케이션을 훨씬 쉽게 마이그레이션할 수 있습니다. 그렇다고 애플리케이션을 TypeScript로 작성해야 한다는 뜻은 아니며, Nuxt가 편집기용 자동 타입 힌트를 제공한다는 의미입니다.

Nuxt의 TypeScript 지원에 대해서는 [문서](/docs/4.x/guide/concepts/typescript)에서 더 읽어볼 수 있습니다.

::note
Nuxt는 `nuxt typecheck` 명령으로 [`vue-tsc`](https://github.com/vuejs/language-tools/tree/master/packages/tsc)를 사용해 앱의 타입을 검사할 수 있습니다.
::

### 마이그레이션 %{#migration}%

1. 다음 내용으로 `tsconfig.json`을 만듭니다:

   ```json
   {
     "files": [],
     "references": [
       {
         "path": "./.nuxt/tsconfig.app.json"
       },
       {
         "path": "./.nuxt/tsconfig.server.json"
       },
       {
         "path": "./.nuxt/tsconfig.shared.json"
       },
       {
         "path": "./.nuxt/tsconfig.node.json"
       }
     ]
   }
   ```

1. `npx nuxt prepare`를 실행해 tsconfig 파일을 생성합니다.
1. [문서](/docs/4.x/getting-started/installation#prerequisites)의 지침에 따라 Volar를 설치합니다.

## Vue 변경 사항 %{#vue-changes}%

권장되는 Vue 모범 사례가 여러 가지 바뀌었고, Vue 2와 3 사이에는 다수의 호환성 깨짐 변경 사항도 있습니다.

[Vue 3 마이그레이션 가이드](https://v3-migration.vuejs.org)와 특히 [호환성 깨짐 변경 사항 목록](https://v3-migration.vuejs.org/breaking-changes/)을 읽어보는 것을 권장합니다.

현재는 Nuxt 3와 함께 [Vue 3 migration build](https://v3-migration.vuejs.org/migration-build.html)를 사용할 수 없습니다.

## Vuex %{#vuex}%

Nuxt는 더 이상 Vuex 통합을 제공하지 않습니다. 대신 Vue의 공식 권장 사항은 [Nuxt 모듈](https://pinia.vuejs.org/ssr/nuxt.html)을 통해 Nuxt를 기본 지원하는 `pinia`를 사용하는 것입니다. [pinia에 대해 더 알아보기](https://pinia.vuejs.org).

pinia로 전역 상태 관리를 제공하는 간단한 방법은 다음과 같습니다:

[`@pinia/nuxt`](/modules/pinia) 모듈을 설치합니다:

```bash [Terminal]
yarn add pinia @pinia/nuxt
```

Nuxt 설정에서 모듈을 활성화합니다:

```ts [nuxt.config.ts]
import { defineNuxtConfig } from 'nuxt/config'

export default defineNuxtConfig({
  modules: ['@pinia/nuxt'],
})
```

애플리케이션 루트에 `store` 폴더를 만듭니다:

```ts [store/index.ts]
import { defineStore } from 'pinia'

export const useMainStore = defineStore('main', {
  state: () => ({
    counter: 0,
  }),
  actions: {
    increment () {
      // `this`는 store 인스턴스입니다
      this.counter++
    },
  },
})
```

[플러그인](/docs/4.x/directory-structure/app/plugins) 파일을 만들어 store를 전역화합니다:

```ts [app/plugins/pinia.ts]
import { useMainStore } from '~/store'

export default defineNuxtPlugin(({ $pinia }) => {
  return {
    provide: {
      store: useMainStore($pinia),
    },
  }
})
```

Vuex를 계속 사용하고 싶다면 [이 단계](https://vuex.vuejs.org/guide/migrating-to-4-0-from-3-x.html)를 따라 Vuex 4로 수동 마이그레이션할 수 있습니다.

완료되면 Nuxt 앱에 다음 플러그인을 추가해야 합니다:

```ts [app/plugins/vuex.ts]
import store from '~/store'

export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.vueApp.use(store)
})
```

더 큰 앱에서는 이 마이그레이션에 많은 작업이 필요할 수 있습니다. Vuex 업데이트가 여전히 걸림돌이 된다면, 바로 사용할 수 있어야 하는 커뮤니티 모듈 [nuxt3-vuex-module](https://github.com/vedmant/nuxt3-vuex#nuxt3-vuex-module)을 사용해 볼 수 있습니다.
