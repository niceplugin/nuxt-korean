Nuxt의 핵심 기능 중 하나는 레이어와 확장 지원입니다. 기본 Nuxt 애플리케이션을 확장하여 컴포넌트, 유틸리티, 설정을 재사용할 수 있습니다. 레이어 구조는 표준 Nuxt 애플리케이션과 거의 동일하므로 작성과 유지 관리가 쉽습니다.

## 사용 사례 %{#use-cases}%

- `nuxt.config`와 `app.config`를 사용해 프로젝트 간 재사용 가능한 설정 프리셋 공유
- [`app/components/`](/docs/4.x/directory-structure/app/components) 디렉터리를 사용해 컴포넌트 라이브러리 생성
- [`app/composables/`](/docs/4.x/directory-structure/app/composables) 및 [`app/utils/`](/docs/4.x/directory-structure/app/utils) 디렉터리를 사용해 유틸리티와 컴포저블 라이브러리 생성
- Nuxt 모듈 프리셋 생성
- 프로젝트 전반에 표준 설정 공유
- Nuxt 테마 생성
- 대규모 프로젝트에서 모듈형 아키텍처를 구현하고 도메인 주도 설계(DDD) 패턴을 지원해 코드 구성을 개선합니다.

## 사용법 %{#usage}%

기본적으로 프로젝트의 `~~/layers` 디렉터리 안에 있는 모든 레이어는 프로젝트의 레이어로 자동 등록됩니다.

::note
레이어 자동 등록은 Nuxt v3.12.0에서 도입되었습니다.
::

또한 각 레이어의 `srcDir`에 대한 이름 있는 레이어 별칭이 자동으로 생성됩니다. 예를 들어 `~~/layers/test` 레이어에는 `#layers/test`로 접근할 수 있습니다.

::note
이름 있는 레이어 별칭은 Nuxt v3.16.0에서 도입되었습니다.
::

또한 [`nuxt.config`](/docs/4.x/directory-structure/nuxt-config) 파일에 [extends](/docs/4.x/api/nuxt-config#extends) 속성을 추가하여 레이어를 확장할 수 있습니다.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: [
    // 로컬 레이어에서 확장
    '../base',
    // 설치된 npm 패키지에서 확장
    '@my-themes/awesome',
    // Git 저장소에서 확장
    'github:my-themes/awesome#v1',
  ],
})
```

비공개 GitHub 저장소에서 확장하는 경우 인증 토큰을 전달할 수도 있습니다:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: [
    // 레이어별 설정
    ['github:my-themes/private-awesome', { auth: process.env.GITHUB_TOKEN }],
  ],
})
```

::note
브랜치를 지정하지 않으면 `main`을 클론합니다.
::

::tip
레이어 소스 옆의 옵션에 지정하여 레이어의 별칭을 재정의할 수 있습니다.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: [
    [
      'github:my-themes/awesome',
      {
        meta: {
          name: 'my-awesome-theme',
        },
      },
    ],
  ],
})
```

::

Nuxt는 원격 레이어를 확장하기 위해 [unjs/c12](https://github.com/unjs/c12)와 [unjs/giget](https://github.com/unjs/giget)을 사용합니다. 자세한 정보와 사용 가능한 모든 옵션은 해당 문서를 확인하세요.

## 레이어 우선순위 %{#layer-priority}%

여러 레이어를 사용할 때는 덮어쓰기 순서를 이해하는 것이 중요합니다. 동일한 파일이나 컴포넌트를 정의할 경우 **우선순위가 더 높은** 레이어가 더 낮은 레이어를 덮어씁니다.

### 우선순위 순서 %{#priority-order}%

우선순위가 높은 것부터 낮은 것까지:

1. **프로젝트 파일** - 항상 가장 높은 우선순위를 가집니다
2. `~~/layers` 디렉터리의 **자동 스캔된 레이어** - 알파벳순으로 정렬됩니다 (Z가 A보다 우선순위가 높음)
3. `extends` 설정의 **레이어** - 첫 번째 항목이 두 번째보다 우선순위가 높습니다

### 실용적인 예시 %{#practical-example}%

동일한 컴포넌트를 여러 레이어가 정의하는 경우를 생각해 봅시다:

```bash [Directory structure]
layers/
  1.base/
    app/components/Button.vue    # 기본 버튼 스타일
  2.theme/
    app/components/Button.vue    # 테마 버튼 (기본 스타일 덮어씀)
app/
  components/Button.vue          # 프로젝트 버튼 (모든 레이어 덮어씀)
```

이 경우:
- 레이어만 존재하면 `2.theme/Button.vue`가 사용됩니다 (알파벳순으로 더 뒤에 있음)
- 프로젝트에 `app/components/Button.vue`가 있으면 모든 레이어를 덮어씁니다

### 우선순위 제어 %{#controlling-priority}%

순서를 제어하려면 레이어 디렉터리 이름 앞에 숫자 접두사를 붙일 수 있습니다:

```bash [Directory structure]
layers/
  1.base/        # 가장 낮은 우선순위
  2.features/    # 중간 우선순위
  3.admin/       # 가장 높은 우선순위 (레이어 중)
```

::tip
이 패턴은 기본값을 가진 베이스 레이어를 만들고, 더 구체적인 레이어가 이를 점진적으로 덮어쓰도록 할 때 유용합니다.
::

### 각각 언제 사용할까 %{#when-to-use-each}%

- **`~~/layers` directory** - 프로젝트의 일부인 로컬 레이어에 사용합니다
- **`extends`** - 외부 의존성(npm 패키지, 원격 저장소)이나 프로젝트 디렉터리 밖의 레이어에 사용합니다

### extends를 사용한 전체 예시 %{#full-example-with-extends}%

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: [
    '../base', // 프로젝트 외부의 로컬 레이어
    '@my-themes/awesome', // NPM 패키지
    'github:my-themes/awesome#v1', // 원격 저장소
  ],
})
```

`~~/layers/custom`도 있다면 우선순위 순서는 다음과 같습니다:
- 프로젝트 파일 (가장 높음)
- `~~/layers/custom`
- `../base`
- `@my-themes/awesome`
- `github:my-themes/awesome#v1` (가장 낮음)
