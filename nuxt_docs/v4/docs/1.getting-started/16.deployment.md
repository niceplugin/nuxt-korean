Nuxt 애플리케이션은 Node.js 서버에 배포하거나, 정적 호스팅용으로 프리렌더링하거나, 서버리스 또는 엣지(CDN) 환경에 배포할 수 있습니다.

::tip
Nuxt를 지원하는 클라우드 제공자 목록을 찾고 있다면 [호스팅 제공자](/deploy) 섹션을 참고하세요.
::

## Node.js 서버 %{#node-js-server}%

어떤 Node 호스팅에도 배포할 수 있도록 Nitro의 Node.js 서버 프리셋을 살펴보세요.

- 지정하거나 자동 감지한 값이 없을 때 사용하는 **기본 출력 형식** <br>
- 최적의 콜드 스타트 시간을 위해 요청 렌더링에 필요한 청크만 로드 <br>
- 어떤 Node.js 호스팅에도 Nuxt 앱을 배포할 때 유용함

### 진입점 %{#entry-point}%

Node 서버 프리셋으로 `nuxt build`를 실행하면 즉시 실행 가능한 Node 서버를 시작하는 진입점이 결과물로 생성됩니다.

```bash [Terminal]
node .output/server/index.mjs
```

이렇게 하면 기본적으로 3000 포트에서 수신하는 프로덕션 Nuxt 서버가 실행됩니다.

다음 런타임 환경 변수를 따릅니다:

- `NITRO_PORT` 또는 `PORT` (`3000`이 기본값)
- `NITRO_HOST` 또는 `HOST` (`'0.0.0.0'`이 기본값)
- `NITRO_SSL_CERT`와 `NITRO_SSL_KEY` - 둘 다 존재하면 서버가 HTTPS 모드로 실행됩니다. 대부분의 경우 이는 테스트 외에는 사용하지 말아야 하며, Nitro 서버는 SSL을 종료하는 nginx나 Cloudflare 같은 리버스 프록시 뒤에서 실행해야 합니다.

### PM2 %{#pm2}%

[PM2](https://pm2.keymetrics.io/) (Process Manager 2)는 서버나 VM에서 Nuxt 애플리케이션을 호스팅하기 위한 빠르고 쉬운 솔루션입니다.

`pm2`를 사용하려면 `ecosystem.config.cjs`를 사용하세요:

```ts [ecosystem.config.cjs]
module.exports = {
  apps: [
    {
      name: 'NuxtAppName',
      port: '3000',
      exec_mode: 'cluster',
      instances: 'max',
      script: './.output/server/index.mjs',
    },
  ],
}
```

### 클러스터 모드 %{#cluster-mode}%

Node.js [cluster](https://nodejs.org/dist/latest/docs/api/cluster.html) 모듈을 사용한 멀티프로세스 성능을 활용하려면 `NITRO_PRESET=node_cluster`를 사용할 수 있습니다.

기본적으로 워크로드는 라운드 로빈 전략으로 워커에 분산됩니다.

## 정적 호스팅 %{#static-hosting}%

Nuxt 애플리케이션을 정적 호스팅 서비스에 배포하는 방법은 두 가지입니다:

- `ssr: true`를 사용하는 정적 사이트 생성(SSG)은 빌드 시 애플리케이션의 라우트를 프리렌더링합니다. (`nuxt generate`를 실행할 때의 기본 동작입니다.) 또한 클라이언트에서 동적 라우트나 404 오류를 렌더링할 수 있는 `/200.html` 및 `/404.html` 단일 페이지 앱 폴백 페이지도 생성합니다(정적 호스트에서 이를 별도로 설정해야 할 수는 있습니다).
- 또는 `ssr: false`(정적 단일 페이지 앱)로 사이트를 프리렌더링할 수 있습니다. 이 경우 일반적으로 Vue 앱이 렌더링될 위치에 비어 있는 `<div id="__nuxt"></div>`가 있는 HTML 페이지가 생성됩니다. 사이트를 프리렌더링할 때 얻는 SEO 이점을 많이 잃게 되므로, 대신 서버 렌더링할 수 없는 사이트의 일부가 있다면 이를 [`<ClientOnly>`](/docs/4.x/api/components/client-only)로 감싸는 방식을 권장합니다.

:read-more{title="Nuxt prerendering" to="/docs/4.x/getting-started/prerendering"}

### 클라이언트 전용 렌더링 %{#client-side-only-rendering}%

라우트를 프리렌더링하고 싶지 않다면 정적 호스팅을 사용하는 또 다른 방법은 `nuxt.config` 파일에서 `ssr` 속성을 `false`로 설정하는 것입니다. 그러면 `nuxt generate` 명령은 전통적인 클라이언트 사이드 Vue.js 애플리케이션처럼 `.output/public/index.html` 진입점과 JavaScript 번들을 출력합니다.

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  ssr: false,
})
```

## 프리셋 %{#presets}%

Node.js 서버와 정적 호스팅 서비스 외에도 Nuxt 프로젝트는 잘 검증된 여러 프리셋과 최소한의 설정으로 배포할 수 있습니다.

원하는 프리셋은 [`nuxt.config.ts`](/docs/4.x/directory-structure/nuxt-config) 파일에서 명시적으로 설정할 수 있습니다:

```ts twoslash [nuxt.config.ts]
// @errors: 2353
export default defineNuxtConfig({
  nitro: {
    preset: 'node-server',
  },
})
```

또는 `nuxt build`를 실행할 때 `NITRO_PRESET` 환경 변수를 사용할 수 있습니다:

```bash [Terminal]
NITRO_PRESET=node-server nuxt build
```

🔎 가능한 모든 배포 프리셋과 제공자는 [Nitro 배포 문서](https://nitro.build/deploy)에서 확인하세요.

## CDN 프록시 %{#cdn-proxy}%

대부분의 경우 Nuxt는 Nuxt 자체가 생성하거나 만든 것이 아닌 서드파티 콘텐츠와도 함께 동작할 수 있습니다. 하지만 때때로 이런 콘텐츠는 문제를 일으킬 수 있으며, 특히 Cloudflare의 "Minification and Security Options"가 그렇습니다.

따라서 Cloudflare에서 다음 옵션이 선택 해제되었거나 비활성화되어 있는지 반드시 확인해야 합니다. 그렇지 않으면 불필요한 재렌더링이나 hydration 오류가 프로덕션 애플리케이션에 영향을 줄 수 있습니다.

1. Speed > Settings > Content Optimization > Disable "Rocket Loader™"
2. Security > Settings > Disable "Email Address Obfuscation"

이 설정을 사용하면 Cloudflare가 원치 않는 부작용을 일으킬 수 있는 스크립트를 Nuxt 애플리케이션에 주입하지 않는다는 점을 확신할 수 있습니다.

::tip
Cloudflare 대시보드에서 이 위치는 때때로 바뀌므로 주위를 조금 찾아보는 것을 주저하지 마세요.
::
