Nuxt는 풀스택 프레임워크이므로 서로 다른 컨텍스트에서 발생할 수 있는, 사용자가 막을 수 없는 런타임 오류 원인이 여러 가지 있습니다:

- Vue 렌더링 라이프사이클 중 오류 (SSR & CSR)
- 서버 및 클라이언트 시작 오류 (SSR + CSR)
- Nitro 서버 라이프사이클 중 오류 ([`server/`](/docs/4.x/directory-structure/server) 디렉터리)
- JS 청크 다운로드 오류

::tip
**SSR**은 **Server-Side Rendering**, **CSR**은 **Client-Side Rendering**을 의미합니다.
::

## Vue 오류 %{#vue-errors}%

[`onErrorCaptured`](https://vuejs.org/api/composition-api-lifecycle#onerrorcaptured)를 사용해 Vue 오류에 훅을 걸 수 있습니다.

또한 Nuxt는 오류가 최상위까지 전파될 경우 호출되는 [`vue:error`](/docs/4.x/api/advanced/hooks#app-hooks-runtime) 훅을 제공합니다.

오류 보고 프레임워크를 사용 중이라면 [`vueApp.config.errorHandler`](https://vuejs.org/api/application#app-config-errorhandler)를 통해 전역 핸들러를 제공할 수 있습니다. 이 핸들러는 오류가 이미 처리된 경우에도 모든 Vue 오류를 받습니다.

```ts twoslash [plugins/error-handler.ts]
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.vueApp.config.errorHandler = (error, instance, info) => {
    // 오류를 처리합니다. 예: 서비스에 보고
  }

  // 이것도 가능합니다
  nuxtApp.hook('vue:error', (error, instance, info) => {
    // 오류를 처리합니다. 예: 서비스에 보고
  })
})
```

::note
`vue:error` 훅은 [`onErrorCaptured`](https://vuejs.org/api/composition-api-lifecycle#onerrorcaptured) 라이프사이클 훅을 기반으로 한다는 점에 유의하세요.
::

## 시작 오류 %{#startup-errors}%

Nuxt 애플리케이션 시작 중 오류가 발생하면 Nuxt는 `app:error` 훅을 호출합니다.

여기에는 다음이 포함됩니다:
- [Nuxt plugins](/docs/4.x/directory-structure/app/plugins) 실행
- `app:created` 및 `app:beforeMount` 훅 처리
- Vue 앱을 HTML로 렌더링 (SSR 중)
- 앱 마운트 (클라이언트 측), 다만 이 경우는 `onErrorCaptured` 또는 `vue:error`로 처리해야 합니다
- `app:mounted` 훅 처리

## Nitro 서버 오류 %{#nitro-server-errors}%

현재로서는 이러한 오류에 대한 서버 측 핸들러를 정의할 수는 없지만, 오류 페이지는 렌더링할 수 있습니다. [오류 페이지 렌더링](/docs/4.x/getting-started/error-handling#error-page) 섹션을 참고하세요.

## JS 청크 관련 오류 %{#errors-with-js-chunks}%

네트워크 연결 실패나 새 배포(이전 해시된 JS 청크 URL을 무효화함) 때문에 청크 로딩 오류가 발생할 수 있습니다. Nuxt는 라우트 이동 중 청크 로딩에 실패하면 하드 리로드를 수행하여 이러한 청크 로딩 오류를 처리하는 내장 지원을 제공합니다.

이 동작은 `experimental.emitRouteChunkError`를 `false`(이 오류들에 대한 훅 자체를 비활성화)로 설정하거나, 직접 처리하고 싶다면 `manual`로 설정해 변경할 수 있습니다. 청크 로딩 오류를 수동으로 처리하고 싶다면 아이디어를 얻기 위해 [자동 구현](https://github.com/nuxt/nuxt/blob/main/packages/nuxt/src/app/plugins/chunk-reload.client.ts)을 살펴볼 수 있습니다.

## 오류 페이지 %{#error-page}%

::note
Nuxt가 치명적인 오류(서버에서 처리되지 않은 모든 오류 또는 클라이언트에서 `fatal: true`로 생성한 오류)를 만나면 JSON 응답(`Accept: application/json` 헤더로 요청된 경우)을 렌더링하거나 전체 화면 오류 페이지를 트리거합니다.
::

서버 라이프사이클 중에는 다음 상황에서 오류가 발생할 수 있습니다:
- Nuxt 플러그인 처리
- Vue 앱을 HTML로 렌더링
- 서버 API 라우트에서 오류 throw

클라이언트 측에서는 다음 상황에서도 발생할 수 있습니다:
- Nuxt 플러그인 처리
- 애플리케이션 마운트 전 (`app:beforeMount` 훅)
- 오류가 `onErrorCaptured` 또는 `vue:error` 훅으로 처리되지 않은 상태에서 앱 마운트
- 브라우저에서 Vue 앱이 초기화되고 마운트될 때 (`app:mounted`)

::read-more{to="/docs/4.x/api/advanced/hooks"}
Nuxt 라이프사이클 훅 전체를 살펴보세요.
::

애플리케이션의 소스 디렉터리에서 `app.vue`와 나란히 `~/error.vue`를 추가하여 기본 오류 페이지를 사용자 정의하세요.

<!-- TODO:twoslash: Twoslash는 아직 tsconfig 경로를 지원하지 않습니다 -->

```vue [error.vue]
<script setup lang="ts">
import type { NuxtError } from '#app'

const props = defineProps({
  error: Object as () => NuxtError,
})

const handleError = () => clearError({ redirect: '/' })
</script>

<template>
  <div>
    <h2>{{ error?.status }}</h2>
    <button @click="handleError">
      오류 지우기
    </button>
  </div>
</template>
```

::read-more{to="/docs/4.x/directory-structure/app/error"}
`error.vue`와 그 용도에 대해 더 알아보세요.
::

사용자 정의 오류에는 페이지/컴포넌트 setup 함수에서 호출할 수 있는 `onErrorCaptured` 컴포저블이나 Nuxt 플러그인에서 설정할 수 있는 `vue:error` 런타임 Nuxt 훅 사용을 강력히 권장합니다.

```ts twoslash [plugins/error-handler.ts]
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.hook('vue:error', (err) => {
    //
  })
})
```

오류 페이지를 제거할 준비가 되면 [`clearError`](/docs/4.x/api/utils/clear-error) 헬퍼 함수를 호출할 수 있으며, 이 함수는 리디렉션할 선택적 경로를 받습니다(예: '안전한' 페이지로 이동하고 싶은 경우).

::important
`$route`나 `useRouter`처럼 Nuxt 플러그인에 의존하는 항목을 사용하기 전에 반드시 확인하세요. 플러그인에서 오류가 발생했다면 오류를 지우기 전까지 다시 실행되지 않기 때문입니다.
::

::note
오류 페이지 렌더링은 완전히 별개의 페이지 로드이므로 등록된 모든 미들웨어가 다시 실행됩니다. 미들웨어에서 오류가 처리 중인지 확인하려면 [`useError`](/docs/4.x/getting-started/error-handling#useerror)를 사용할 수 있습니다.
::

::note
Node 16에서 실행 중이고 오류 페이지를 렌더링할 때 쿠키를 설정하면, 그 쿠키는 [기존에 설정된 쿠키를 덮어씁니다](https://github.com/nuxt/nuxt/pull/20585). Node 16은 2023년 9월에 지원 종료되었으므로 더 최신 버전의 Node 사용을 권장합니다.
::

`useError` 컴포저블에 대해 더 알아보세요.
::

### `createError` %{#createerror}%

```ts [TS Signature]
function createError (err: string | { cause, data, message, name, stack, status, statusText, fatal }): Error
```

추가 메타데이터가 포함된 오류 객체를 생성합니다. 오류 `message`로 설정할 문자열이나 오류 속성이 포함된 객체를 전달할 수 있습니다. 이는 앱의 Vue 영역과 서버 영역 모두에서 사용할 수 있으며, throw하는 용도로 설계되었습니다.

`createError`로 생성한 오류를 throw하면:
- 서버 측에서는 전체 화면 오류 페이지가 트리거되며, [`clearError`](/docs/4.x/getting-started/error-handling#clearerror)로 이를 지울 수 있습니다.
- 클라이언트 측에서는 사용자가 처리할 수 있는 비치명적 오류가 throw됩니다. 전체 화면 오류 페이지를 트리거해야 한다면 `fatal: true`를 설정하면 됩니다.

```vue twoslash [pages/movies/[slug\\].vue]
<script setup lang="ts">
const route = useRoute()
const { data } = await useFetch(`/api/movies/${route.params.slug}`)

if (!data.value) {
  throw createError({
    status: 404,
    statusText: 'Page Not Found',
  })
}
</script>
```

::tip
`statusText` 속성은 짧고 HTTP 규격을 준수하는 상태 텍스트(예: "Not Found")를 위한 것입니다. 여기에는 가로 탭, 공백, 보이는 ASCII 문자(`[\t\u0020-\u007E]`)만 포함되어야 합니다.

자세한 설명, 여러 줄 메시지, 비 ASCII 문자가 포함된 콘텐츠에는 항상 대신 `message` 속성을 사용해야 합니다.
::

::read-more{to="/docs/4.x/api/utils/create-error"}
`createError` 유틸리티에 대해 더 알아보세요.
::

### `showError` %{#showerror}%

```ts [TS Signature]
function showError (err: string | Error | { status, statusText }): Error
```

이 함수는 클라이언트 측 어느 지점에서든 호출할 수 있고, 서버 측에서는 미들웨어, 플러그인, `setup()` 함수 안에서 직접 호출할 수 있습니다. 이 함수는 전체 화면 오류 페이지를 트리거하며, [`clearError`](/docs/4.x/getting-started/error-handling#clearerror)로 이를 지울 수 있습니다.

대신 `throw createError()`를 사용하는 것을 권장합니다.

::read-more{to="/docs/4.x/api/utils/show-error"}
`showError` 유틸리티에 대해 더 알아보세요.
::

### `clearError` %{#clearerror}%

```ts [TS Signature]
function clearError (options?: { redirect?: string }): Promise<void>
```

이 함수는 현재 처리 중인 Nuxt 오류를 지웁니다. 또한 리디렉션할 선택적 경로도 받습니다(예: '안전한' 페이지로 이동하고 싶은 경우).

::read-more{to="/docs/4.x/api/utils/clear-error"}

## 컴포넌트에서 오류 렌더링 %{#render-error-in-component}%

Nuxt는 앱 전체를 오류 페이지로 대체하지 않고도 앱 내부에서 클라이언트 측 오류를 처리할 수 있게 해주는 [`<NuxtErrorBoundary>`](/docs/4.x/api/components/nuxt-error-boundary) 컴포넌트도 제공합니다.

이 컴포넌트는 기본 슬롯 내부에서 발생한 오류를 처리합니다. 클라이언트 측에서는 오류가 최상위로 버블링되는 것을 막고, 대신 `#error` 슬롯을 렌더링합니다.

`#error` 슬롯은 `error`를 prop으로 받습니다. (`error = null`로 설정하면 기본 슬롯이 다시 렌더링되는데, 먼저 오류가 완전히 해결되었는지 확인하지 않으면 오류 슬롯이 다시 한번 렌더링될 뿐입니다.)

::tip
다른 라우트로 이동하면 오류는 자동으로 지워집니다.
::

```vue [app/pages/index.vue]
<template>
    <!-- 일부 콘텐츠 -->
  <NuxtErrorBoundary @error="someErrorLogger">
    <!-- 기본 슬롯을 사용해 콘텐츠를 렌더링합니다 -->
    <template #error="{ error, clearError }">
      여기에서 오류를 로컬로 표시할 수 있습니다: {{ error }}
      <button @click="clearError">
        이 버튼은 오류를 지웁니다.
      </button>
    </template>
  </NuxtErrorBoundary>
</template>
```
