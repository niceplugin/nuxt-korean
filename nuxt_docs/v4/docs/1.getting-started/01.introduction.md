Nuxt는 [Vue.js](https://vuejs.org)를 사용해 타입 안정성을 갖춘 고성능 프로덕션급 풀스택 웹 애플리케이션과 웹사이트를 만들 수 있도록 직관적이고 확장 가능한 방식을 제공하는 무료 [오픈 소스 프레임워크](https://github.com/nuxt/nuxt)입니다.

Nuxt는 처음부터 `.vue` 파일 작성을 시작할 수 있도록 모든 것을 갖추고 있으며, 개발 중에는 핫 모듈 교체를 누리고 기본값인 서버 사이드 렌더링으로 프로덕션에서는 고성능 애플리케이션을 제공할 수 있습니다.

Nuxt는 특정 벤더에 종속되지 않으므로 애플리케이션을 [**어디에나, 심지어 엣지에도**](/blog/nuxt-on-the-edge) 배포할 수 있습니다.

::tip
브라우저에서 Nuxt를 직접 만져보고 싶다면 [온라인 샌드박스 중 하나에서 사용해 볼 수 있습니다](/docs/4.x/getting-started/installation#play-online).
::

## 자동화와 컨벤션 %{#automation-and-conventions}%

Nuxt는 컨벤션과 의견이 반영된 디렉터리 구조를 사용해 반복 작업을 자동화하고, 개발자가 기능 구현에 집중할 수 있도록 합니다. 구성 파일을 사용하면 기본 동작을 여전히 사용자 지정하고 재정의할 수 있습니다.

- **파일 기반 라우팅:** [`app/pages/` 디렉터리](/docs/4.x/directory-structure/app/pages) 구조를 기준으로 라우트를 정의합니다. 덕분에 애플리케이션을 더 쉽게 구성할 수 있고 수동 라우트 설정이 필요하지 않을 수 있습니다.
- **코드 분할:** Nuxt는 코드를 자동으로 더 작은 청크로 분할하여 애플리케이션의 초기 로드 시간을 줄이는 데 도움을 줍니다.
- **즉시 사용 가능한 서버 사이드 렌더링:** Nuxt에는 SSR 기능이 내장되어 있어 별도의 서버를 직접 설정할 필요가 없습니다.
- **자동 임포트:** 각 디렉터리에 Vue 컴포저블과 컴포넌트를 작성하면 tree-shaking과 최적화된 JS 번들의 이점을 누리면서 import 없이 사용할 수 있습니다.
- **데이터 페칭 유틸리티:** Nuxt는 SSR 호환 데이터 페칭과 다양한 전략을 처리하는 컴포저블을 제공합니다.
- **제로 설정 TypeScript 지원:** 자동 생성되는 타입과 `tsconfig.json`을 통해 TypeScript를 따로 익히지 않고도 타입 안정성이 있는 코드를 작성할 수 있습니다.
- **미리 구성된 빌드 도구:** Nuxt는 기본적으로 [Vite](https://vite.dev)를 사용하여 개발 중 핫 모듈 교체(HMR)를 지원하고 프로덕션용 코드 번들링에 모범 사례를 내장합니다.

Nuxt는 이러한 부분을 처리하고 프런트엔드와 백엔드 기능을 모두 제공하므로, 여러분은 정말 중요한 일인 **웹 애플리케이션 만들기**에 집중할 수 있습니다.

## 서버 사이드 렌더링 %{#server-side-rendering}%

Nuxt는 서버를 직접 구성하지 않아도 기본적으로 서버 사이드 렌더링(SSR) 기능을 제공하며, 이는 웹 애플리케이션에 많은 이점을 줍니다.

- **더 빠른 초기 페이지 로드 시간:** Nuxt는 완전히 렌더링된 HTML 페이지를 브라우저에 전송하므로 즉시 표시할 수 있습니다. 이는 특히 느린 네트워크나 기기에서 체감 로드 시간을 줄이고 더 나은 사용자 경험(UX)을 제공할 수 있습니다.
- **향상된 SEO:** 클라이언트 측에서 JavaScript로 콘텐츠를 렌더링할 필요 없이 HTML 콘텐츠를 즉시 사용할 수 있으므로 검색 엔진이 SSR 페이지를 더 잘 색인할 수 있습니다.
- **저사양 기기에서 더 나은 성능:** 클라이언트 측에서 다운로드하고 실행해야 하는 JavaScript 양이 줄어들기 때문에 무거운 JavaScript 애플리케이션 처리에 어려움을 겪는 저사양 기기에 특히 유리할 수 있습니다.
- **더 나은 접근성:** 초기 페이지 로드 시 콘텐츠를 즉시 사용할 수 있으므로 스크린 리더나 기타 보조 기술에 의존하는 사용자의 접근성이 향상됩니다.
- **더 쉬운 캐싱:** 페이지를 서버 측에 캐시할 수 있어, 콘텐츠를 생성하고 클라이언트에 전송하는 데 걸리는 시간을 줄여 성능을 추가로 개선할 수 있습니다.

전반적으로 서버 사이드 렌더링은 더 빠르고 효율적인 사용자 경험을 제공할 뿐 아니라 검색 엔진 최적화와 접근성도 개선할 수 있습니다.

Nuxt는 다재다능한 프레임워크이므로 `nuxt generate`로 전체 애플리케이션을 정적 호스팅용으로 정적 렌더링할 수 있고,
`ssr: false` 옵션으로 SSR을 전역 비활성화하거나 `routeRules` 옵션을 설정해 하이브리드 렌더링을 활용할 수도 있습니다.

### 서버 엔진 %{#server-engine}%

Nuxt 서버 엔진 [Nitro](https://nitro.build/)는 새로운 풀스택 기능을 열어 줍니다.

개발 환경에서는 서버 코드와 컨텍스트 격리를 위해 Rollup과 Node.js 워커를 사용합니다. 또한 `server/api/`의 파일을 읽어 서버 API를 생성하고 `server/middleware/`에서 서버 미들웨어를 생성합니다.

프로덕션에서는 Nitro가 앱과 서버를 하나의 범용 `.output` 디렉터리로 빌드합니다. 이 출력물은 가볍습니다. 최소화되어 있으며 Node.js 모듈은 제거됩니다(폴리필 제외). 이 출력물은 Node.js, Serverless, Workers, 엣지 사이드 렌더링, 순수 정적 환경 등 JavaScript를 지원하는 모든 시스템에 배포할 수 있습니다.

:read-more{title="Nuxt 서버 엔진" to="/docs/4.x/guide/concepts/server-engine"}

### 프로덕션 준비 완료 %{#production-ready}%

Nuxt 애플리케이션은 Node 또는 Deno 서버에 배포할 수 있고, 정적 환경에 호스팅하도록 사전 렌더링할 수도 있으며, 서버리스 및 엣지 제공업체에 배포할 수도 있습니다.

:read-more{title="배포 섹션" to="/docs/4.x/getting-started/deployment"}

### 모듈형 %{#modular}%

모듈 시스템을 사용하면 사용자 정의 기능과 서드파티 서비스 통합으로 Nuxt를 확장할 수 있습니다.

:read-more{title="Nuxt Modules 개념" to="/docs/4.x/guide/concepts/modules"}

### 아키텍처 %{#architecture}%

Nuxt는 여러 [코어 패키지](https://github.com/nuxt/nuxt/tree/main/packages)로 구성됩니다.

- 코어 엔진: [nuxt](https://github.com/nuxt/nuxt/tree/main/packages/nuxt)
- 번들러: [@nuxt/vite-builder](https://github.com/nuxt/nuxt/tree/main/packages/vite), [@nuxt/rspack-builder](https://github.com/nuxt/nuxt/tree/main/packages/rspack), [@nuxt/webpack-builder](https://github.com/nuxt/nuxt/tree/main/packages/webpack)
- 명령줄 인터페이스: [@nuxt/cli](https://github.com/nuxt/cli)
- 서버 엔진: [nitro](https://github.com/nitrojs/nitro)
- 개발 키트: [@nuxt/kit](https://github.com/nuxt/nuxt/tree/main/packages/kit)

Nuxt의 기능과 각 패키지의 범위를 충분히 이해하려면 각 개념 문서를 읽어보는 것을 권장합니다.
