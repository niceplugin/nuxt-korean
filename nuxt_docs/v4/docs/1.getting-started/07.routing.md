Nuxt의 핵심 기능 중 하나는 파일 시스템 라우터입니다. [`app/pages/`](/docs/4.x/directory-structure/app/pages) 디렉터리 안의 모든 Vue 파일은 해당 파일의 내용을 표시하는 대응 URL(또는 라우트)을 생성합니다. Nuxt는 각 페이지에 동적 import를 사용하여 코드 분할을 활용하고, 요청된 라우트에 필요한 최소한의 JavaScript만 전송합니다.

## 페이지 %{#pages}%

Nuxt 라우팅은 [vue-router](https://router.vuejs.org)를 기반으로 하며, [`app/pages/` 디렉터리](/docs/4.x/directory-structure/app/pages)에 생성된 모든 컴포넌트로부터 파일명을 기준으로 라우트를 생성합니다.

이 파일 시스템 라우팅은 명명 규칙을 사용해 동적 라우트와 중첩 라우트를 생성합니다:

::code-group

```bash [Directory Structure]
-| pages/
---| about.vue
---| index.vue
---| posts/
-----| [id].vue
```

```json [Generated Router File]
{
  "routes": [
    {
      "path": "/about",
      "component": "pages/about.vue"
    },
    {
      "path": "/",
      "component": "pages/index.vue"
    },
    {
      "path": "/posts/:id",
      "component": "pages/posts/[id].vue"
    }
  ]
}
```

::

:read-more{to="/docs/4.x/directory-structure/app/pages"}

## 내비게이션 %{#navigation}%

[`<NuxtLink>`](/docs/4.x/api/components/nuxt-link) 컴포넌트는 페이지 사이를 연결합니다. 이 컴포넌트는 `href` 속성이 해당 페이지의 라우트로 설정된 `<a>` 태그를 렌더링합니다. 애플리케이션 하이드레이션이 끝나면 브라우저 URL을 갱신하는 JavaScript로 페이지 전환이 수행됩니다. 이 방식은 전체 페이지 새로고침을 막고 애니메이션 전환을 가능하게 합니다.

클라이언트 측에서 [`<NuxtLink>`](/docs/4.x/api/components/nuxt-link)가 뷰포트에 들어오면, Nuxt는 연결된 페이지의 컴포넌트와 payload(생성된 페이지)를 미리 자동으로 프리패치하여 더 빠른 내비게이션을 제공합니다.

```vue [app/pages/index.vue]
<template>
  <header>
    <nav>
      <ul>
        <li><NuxtLink to="/about">소개</NuxtLink></li>
        <li><NuxtLink to="/posts/1">게시물 1</NuxtLink></li>
        <li><NuxtLink to="/posts/2">게시물 2</NuxtLink></li>
      </ul>
    </nav>
  </header>
</template>
```

:read-more{to="/docs/4.x/api/components/nuxt-link"}

## 라우트 매개변수 %{#route-parameters}%

[`useRoute()`](/docs/4.x/api/composables/use-route) 컴포저블은 `<script setup>` 블록이나 Vue 컴포넌트의 `setup()` 메서드에서 사용하여 현재 라우트의 세부 정보에 접근할 수 있습니다.

```vue twoslash [pages/posts/[id\\].vue]
<script setup lang="ts">
const route = useRoute()

// /posts/1에 접근하면 route.params.id는 1이 됩니다
console.log(route.params.id)
</script>
```

:read-more{to="/docs/4.x/api/composables/use-route"}

## 라우트 미들웨어 %{#route-middleware}%

Nuxt는 애플리케이션 전반에서 사용할 수 있는 사용자 정의 가능한 라우트 미들웨어 프레임워크를 제공하며, 특정 라우트로 이동하기 전에 실행할 코드를 분리하는 데 적합합니다.

::note
라우트 미들웨어는 Nuxt 앱의 Vue 영역에서 실행됩니다. 이름은 비슷하지만, 앱의 Nitro 서버 영역에서 실행되는 서버 미들웨어와는 완전히 다릅니다.
::

::important
라우트 미들웨어는 서버 라우트(예: `/api/*`)나 기타 서버 요청에 대해서는 **실행되지 않습니다**. 이런 요청에 미들웨어를 적용하려면 대신 [server middleware](/docs/4.x/directory-structure/server#server-middleware)를 사용하세요.
::

라우트 미들웨어에는 세 가지 종류가 있습니다:

1. 익명(또는 인라인) 라우트 미들웨어로, 사용하는 페이지 안에 직접 정의됩니다.
2. 이름 있는 라우트 미들웨어로, [`app/middleware/`](/docs/4.x/directory-structure/app/middleware) 디렉터리에 두며 페이지에서 사용될 때 비동기 import를 통해 자동으로 로드됩니다. (**참고**: 라우트 미들웨어 이름은 kebab-case로 정규화되므로 `someMiddleware`는 `some-middleware`가 됩니다.)
3. 전역 라우트 미들웨어로, [`app/middleware/`](/docs/4.x/directory-structure/app/middleware) 디렉터리(`.global` 접미사 포함)에 두며 모든 라우트 변경 시 자동으로 실행됩니다.

`/dashboard` 페이지를 보호하는 `auth` 미들웨어 예시:

::code-group

```ts twoslash [middleware/auth.ts]
function isAuthenticated (): boolean { return false }
// ---cut---
export default defineNuxtRouteMiddleware((to, from) => {
  // isAuthenticated()는 사용자가 인증되었는지 확인하는 예시 메서드입니다
  if (isAuthenticated() === false) {
    return navigateTo('/login')
  }
})
```

```vue twoslash [pages/dashboard.vue]
<script setup lang="ts">
definePageMeta({
  middleware: 'auth',
})
</script>

<template>
  <h1>대시보드에 오신 것을 환영합니다</h1>
</template>
```

::

:read-more{to="/docs/4.x/directory-structure/app/middleware"}

## 라우트 유효성 검사 %{#route-validation}%

Nuxt는 유효성을 검사하려는 각 페이지의 [`definePageMeta()`](/docs/4.x/api/utils/define-page-meta) 안에 있는 `validate` 속성을 통해 라우트 유효성 검사를 제공합니다.

`validate` 속성은 `route`를 인자로 받습니다. 이 페이지로 렌더링할 수 있는 유효한 라우트인지 여부를 판단하기 위해 불리언 값을 반환할 수 있습니다. `false`를 반환하면 404 오류가 발생합니다. 반환되는 오류를 사용자 정의하려면 `status`/`statusText`가 포함된 객체를 직접 반환할 수도 있습니다.

더 복잡한 사용 사례가 있다면 대신 익명 라우트 미들웨어를 사용할 수 있습니다.

```vue twoslash [pages/posts/[id\\].vue]
<script setup lang="ts">
definePageMeta({
  validate (route) {
    // id가 숫자로만 이루어졌는지 확인합니다
    return typeof route.params.id === 'string' && /^\d+$/.test(route.params.id)
  },
})
</script>
```

:read-more{to="/docs/4.x/api/utils/define-page-meta"}
