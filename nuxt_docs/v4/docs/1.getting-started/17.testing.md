Nuxt는 `@nuxt/test-utils`를 통해 Nuxt 애플리케이션의 end-to-end 테스트와 단위 테스트를 일급으로 지원합니다. 이 라이브러리는 테스트 유틸리티와 설정을 제공하며, 현재 [Nuxt 자체에서 사용하는 테스트](https://github.com/nuxt/nuxt/tree/main/test)와 모듈 생태계 전반의 테스트를 뒷받침하고 있습니다.

:video-accordion{title="@nuxt/test-utils 시작하기에 대한 Alexander Lichter의 영상 보기" videoId="yGzwk9xi9gU"}

## 설치 %{#installation}%

다른 테스트 의존성을 직접 관리할 수 있도록 `@nuxt/test-utils`는 다양한 선택적 peer dependency와 함께 제공됩니다. 예를 들면:

- 런타임 Nuxt 환경용으로 `happy-dom`과 `jsdom` 중에서 선택할 수 있습니다
- end-to-end 테스트 러너로 `vitest`, `cucumber`, `jest`, `playwright` 중에서 선택할 수 있습니다
- `playwright-core`는 내장 브라우저 테스트 유틸리티를 사용하고(`@playwright/test`를 테스트 러너로 사용하지 않는 경우에만) 필요합니다

::code-group{sync="pm"}
```bash [npm]
npm i --save-dev @nuxt/test-utils vitest @vue/test-utils happy-dom playwright-core
```
```bash [yarn]
yarn add --dev @nuxt/test-utils vitest @vue/test-utils happy-dom playwright-core
```
```bash [pnpm]
pnpm add -D @nuxt/test-utils vitest @vue/test-utils happy-dom playwright-core
```
```bash [bun]
bun add --dev @nuxt/test-utils vitest @vue/test-utils happy-dom playwright-core
```
::

## 단위 테스트 %{#unit-testing}%

현재는 [Nuxt](https://nuxt.com) 런타임 환경이 필요한 코드를 단위 테스트할 수 있는 환경을 제공합니다. 현재는 _`vitest`만 지원_ 하지만(다른 런타임 추가 기여도 환영합니다).

### 설정 %{#setup}%

1. `nuxt.config` 파일에 `@nuxt/test-utils/module`을 추가합니다(선택 사항). 이 모듈은 Nuxt DevTools에 Vitest 통합을 추가하여 개발 중 단위 테스트를 실행할 수 있게 해줍니다.

   ```ts twoslash
   export default defineNuxtConfig({
     modules: [
       '@nuxt/test-utils/module',
     ],
   })
   ```

2. 다음 내용으로 `vitest.config.ts`를 만드세요:

   ```ts twoslash
   import { defineConfig } from 'vitest/config'
   import { defineVitestProject } from '@nuxt/test-utils/config'

   export default defineConfig({
     test: {
       projects: [
         {
           test: {
             name: 'unit',
             include: ['test/unit/*.{test,spec}.ts'],
             environment: 'node',
           },
         },
         {
           test: {
             name: 'e2e',
             include: ['test/e2e/*.{test,spec}.ts'],
             environment: 'node',
           },
         },
         await defineVitestProject({
           test: {
             name: 'nuxt',
             include: ['test/nuxt/*.{test,spec}.ts'],
             environment: 'nuxt',
           },
         }),
       ],
     },
   })
   ```

::tip
vitest 설정에서 `@nuxt/test-utils`를 import할 때는 `package.json`에 `"type": "module"`이 지정되어 있어야 하며, 그렇지 않다면 vitest 설정 파일 이름을 적절히 바꿔야 합니다.
> i.e., `vitest.config.m{ts,js}`.
::

::tip
`.env.test` 파일을 사용해 테스트용 환경 변수를 설정할 수 있습니다.
::

### Nuxt 런타임 환경 사용하기 %{#using-a-nuxt-runtime-environment}%

[Vitest projects](https://vitest.dev/guide/projects.html#test-projects)를 사용하면 어떤 테스트를 어떤 환경에서 실행할지 세밀하게 제어할 수 있습니다:

- **단위 테스트**: 일반 단위 테스트는 `test/unit/`에 두세요. 이 테스트는 속도를 위해 Node 환경에서 실행됩니다
- **Nuxt 테스트**: Nuxt 런타임 환경에 의존하는 테스트는 `test/nuxt/`에 두세요. 이 테스트는 Nuxt 런타임 환경 안에서 실행됩니다

#### 대안: 간단한 설정 %{#alternative-simple-setup}%

더 간단한 설정을 원하고 모든 테스트를 Nuxt 환경에서 실행하고 싶다면 기본 설정을 사용할 수 있습니다:

```ts twoslash
import { defineVitestConfig } from '@nuxt/test-utils/config'
import { fileURLToPath } from 'node:url'

export default defineVitestConfig({
  test: {
    environment: 'nuxt',
    // 선택적으로 Nuxt 전용 환경 옵션을 설정할 수 있습니다
    // environmentOptions: {
    //   nuxt: {
    //     rootDir: fileURLToPath(new URL('./playground', import.meta.url)),
    //     domEnvironment: 'happy-dom', // 'happy-dom'(기본값) 또는 'jsdom'
    //     overrides: {
    //       // 전달하고 싶은 다른 Nuxt 설정
    //     }
    //   }
    // }
  },
})
```

기본적으로 `environment: 'nuxt'`를 사용하는 간단한 설정을 쓰고 있다면 필요에 따라 테스트 파일별로 [Nuxt 환경](https://vitest.dev/guide/environment.html#test-environment)을 _opt-out_ 할 수 있습니다.

```ts twoslash
// @vitest-environment node
import { test } from 'vitest'

test('my test', () => {
  // ... Nuxt 환경 없이 테스트합니다!
})
```

::warning
이 접근 방식은 Nuxt Vite 플러그인은 실행되지만 Nuxt 엔트리와 `nuxtApp`은 초기화되지 않는 혼합 환경을 만들기 때문에 권장되지 않습니다. 이로 인해 디버깅하기 어려운 오류가 발생할 수 있습니다.
::

### 테스트 구성하기 %{#organizing-your-tests}%

프로젝트 기반 설정에서는 테스트를 다음과 같이 구성할 수 있습니다:

```bash [Directory structure]
test/
├── e2e/
│   └── ssr.test.ts
├── nuxt/
│   ├── components.test.ts
│   └── composables.test.ts
├── unit/
│   └── utils.test.ts
```

물론 어떤 테스트 구조든 선택할 수 있지만, 테스트 안정성을 위해 Nuxt 런타임 환경 테스트와 Nuxt end-to-end 테스트를 분리해 두는 것이 중요합니다.

#### 테스트에서 TypeScript 지원 %{#typescript-support-in-tests}%

기본적으로 `test/nuxt/`와 `tests/nuxt/` 디렉터리의 테스트 파일은 [Nuxt 앱 TypeScript 컨텍스트](/docs/4.x/guide/concepts/typescript#how-nuxt-uses-project-references)에 포함됩니다. 즉, 이 파일들은 Nuxt 별칭(`~/`, `@/`, `#imports` 등)을 인식하며, TypeScript는 Nuxt 앱에서 동작하는 auto-import를 이해하게 됩니다.

::tip
이 구조는 Nuxt 런타임 환경이 필요한 테스트만 이 디렉터리에 두는 권장 방식과 일치합니다. `test/unit/` 같은 다른 디렉터리의 단위 테스트는 필요하다면 수동으로 추가할 수 있습니다.
::

##### 다른 테스트 디렉터리 추가하기 %{#adding-other-test-directories}%

Nuxt Vitest 환경에서 실행할 테스트가 다른 디렉터리에 있다면 설정에 추가하여 Nuxt 앱 TypeScript 컨텍스트에 포함시킬 수 있습니다:

<!-- @case-police-ignore tsConfig -->

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  typescript: {
    tsConfig: {
      include: [
        // 이 경로는 생성된 .nuxt/tsconfig.json을 기준으로 합니다
        '../test/other-nuxt-context/**/*',
      ],
    },
  },
})
```

::important
단위 테스트는 auto-import나 composable 같은 Nuxt 런타임 기능에 의존해서는 안 됩니다. 테스트가 소스 파일(예: `~/utils/helpers`)에서 import하는 경우에만 TypeScript 경로 별칭 지원을 추가하고, Nuxt 전용 기능을 위해서는 추가하지 마세요.
::

#### 테스트 실행하기 %{#running-tests}%

프로젝트 설정을 사용하면 서로 다른 테스트 스위트를 실행할 수 있습니다:

```bash
# 모든 테스트 실행
npx vitest

# 단위 테스트만 실행
npx vitest --project unit

# Nuxt 테스트만 실행
npx vitest --project nuxt

# watch 모드로 테스트 실행
npx vitest --watch
```

::warning
Nuxt 환경에서 테스트를 실행하면 [`happy-dom`](https://github.com/capricorn86/happy-dom) 또는 [`jsdom`](https://github.com/jsdom/jsdom) 환경에서 동작하게 됩니다. 테스트가 실행되기 전에 전역 Nuxt 앱이 초기화되며(예: `app.vue`에서 정의한 플러그인이나 코드도 실행됨),

이 말은 테스트에서 전역 상태를 변경하지 않도록 특별히 주의해야 하며(필요하다면 afterwards에 반드시 초기화해야 함)를 뜻합니다.
::

### 🎭 내장 Mock %{#built-in-mocks}%

`@nuxt/test-utils`는 DOM 환경을 위한 몇 가지 내장 mock을 제공합니다.

#### `intersectionObserver` %{#intersectionobserver}%

기본값은 `true`이며, IntersectionObserver API용 기능 없는 더미 클래스를 생성합니다

#### `indexedDB` %{#indexeddb}%

기본값은 `false`이며, [`fake-indexeddb`](https://github.com/dumbmatter/fakeIndexedDB)를 사용해 IndexedDB API의 동작 가능한 mock을 만듭니다

이 항목들은 `vitest.config.ts` 파일의 `environmentOptions` 섹션에서 설정할 수 있습니다:

```ts twoslash
import { defineVitestConfig } from '@nuxt/test-utils/config'

export default defineVitestConfig({
  test: {
    environmentOptions: {
      nuxt: {
        mock: {
          intersectionObserver: true,
          indexedDb: true,
        },
      },
    },
  },
})
```

### 🛠️ 헬퍼 %{#helpers}%

`@nuxt/test-utils`는 Nuxt 앱 테스트를 더 쉽게 해주는 여러 헬퍼를 제공합니다.

#### `mountSuspended` %{#mountsuspended}%

`mountSuspended`를 사용하면 Nuxt 환경 안에서 어떤 Vue 컴포넌트든 마운트할 수 있으며, 비동기 setup과 Nuxt 플러그인에서 제공한 주입에 접근할 수 있습니다.

::note
내부적으로 `mountSuspended`는 `@vue/test-utils`의 `mount`를 감싸므로, 전달할 수 있는 옵션과 이 유틸리티 사용법에 대해서는 [Vue Test Utils 문서](https://test-utils.vuejs.org/guide/)를 참고할 수 있습니다.
::

예를 들면:

```ts twoslash
// @noErrors
import { expect, it } from 'vitest'
import type { Component } from 'vue'

declare module '#components' {
  export const SomeComponent: Component
}
// ---cut---
// tests/components/SomeComponents.nuxt.spec.ts
import { mountSuspended } from '@nuxt/test-utils/runtime'
import { SomeComponent } from '#components'

it('can mount some component', async () => {
  const component = await mountSuspended(SomeComponent)
  expect(component.text()).toMatchInlineSnapshot(
    '"이것은 자동 import된 컴포넌트입니다"',
  )
})
```

```ts twoslash
// @noErrors
import { expect, it } from 'vitest'
// ---cut---
// tests/components/SomeComponents.nuxt.spec.ts
import { mountSuspended } from '@nuxt/test-utils/runtime'
import App from '~/app.vue'

// tests/App.nuxt.spec.ts
it('can also mount an app', async () => {
  const component = await mountSuspended(App, { route: '/test' })
  expect(component.html()).toMatchInlineSnapshot(`
      "<div>이것은 자동 import된 컴포넌트입니다</div>
      <div> 나는 전역 컴포넌트입니다 </div>
      <div>/</div>
      <a href="/test"> 테스트 링크 </a>"
    `)
})
```

옵션 객체는 `@vue/test-utils`의 mount 옵션과 다음 속성을 받습니다:

  - `route`: 초기 라우트 또는 초기 라우트 변경을 건너뛰기 위한 `false`(기본값 `/`)

#### `renderSuspended` %{#rendersuspended}%

`renderSuspended`를 사용하면 `@testing-library/vue`를 이용해 Nuxt 환경 안에서 어떤 Vue 컴포넌트든 렌더링할 수 있으며, 비동기 setup과 Nuxt 플러그인에서 제공한 주입에 접근할 수 있습니다.

이 함수는 `screen`, `fireEvent` 같은 Testing Library 유틸리티와 함께 사용해야 합니다. 이를 사용하려면 프로젝트에 [@testing-library/vue](https://testing-library.com/docs/vue-testing-library/intro/)를 설치하세요.

또한 Testing Library는 정리를 위해 테스트 전역 변수에도 의존합니다. 따라서 [Vitest 설정](https://vitest.dev/config/globals)에서 이를 켜야 합니다.

전달된 컴포넌트는 `<div id="test-wrapper"></div>` 내부에 렌더링됩니다.

예시:

```ts twoslash
// @noErrors
import { expect, it } from 'vitest'
import type { Component } from 'vue'

declare module '#components' {
  export const SomeComponent: Component
}
// ---cut---
// tests/components/SomeComponents.nuxt.spec.ts
import { renderSuspended } from '@nuxt/test-utils/runtime'
import { SomeComponent } from '#components'
import { screen } from '@testing-library/vue'

it('can render some component', async () => {
  await renderSuspended(SomeComponent)
  expect(screen.getByText('이것은 자동 import된 컴포넌트입니다')).toBeDefined()
})
```

```ts twoslash
// @noErrors
import { expect, it } from 'vitest'
// ---cut---
// tests/App.nuxt.spec.ts
import { renderSuspended } from '@nuxt/test-utils/runtime'
import App from '~/app.vue'

it('can also render an app', async () => {
  const html = await renderSuspended(App, { route: '/test' })
  expect(html).toMatchInlineSnapshot(`
    "<div id="test-wrapper">
      <div>이것은 자동 import된 컴포넌트입니다</div>
      <div> 나는 전역 컴포넌트입니다 </div>
      <div>인덱스 페이지</div><a href="/test"> 테스트 링크 </a>
    </div>"
  `)
})
```

옵션 객체는 `@testing-library/vue`의 render 옵션과 다음 속성을 받습니다:

  - `route`: 초기 라우트 또는 초기 라우트 변경을 건너뛰기 위한 `false`(기본값 `/`)

#### `mockNuxtImport` %{#mocknuxtimport}%

`mockNuxtImport`를 사용하면 Nuxt의 auto import 기능을 mock할 수 있습니다. 예를 들어 `useState`를 mock하려면 다음과 같이 할 수 있습니다:

```ts twoslash
import { mockNuxtImport } from '@nuxt/test-utils/runtime'

mockNuxtImport('useState', () => {
  return () => {
    return { value: 'mock된 저장소' }
  }
})

// 여기에 테스트 작성
```

타입 안전성을 위해 mock에 명시적으로 타입을 지정할 수 있으며, 복잡한 기능을 mock할 때는 factory 함수에 전달되는 원래 구현을 사용할 수 있습니다.

```ts twoslash [test/nuxt/import.test.ts]
import { mockNuxtImport } from '@nuxt/test-utils/runtime'

mockNuxtImport<typeof useState>('useState', (original) => {
  return (...args) => {
    return { ...original('some-key'), value: 'mock된 상태' }
  }
})

// or specify the target to mock
mockNuxtImport(useState, (original) => {
  return (...args) => {
    return { ...original('some-key'), value: 'mock된 상태' }
  }
})

// 여기에 테스트 작성
```

::note
`mockNuxtImport`는 테스트 파일 하나당 mock된 import마다 한 번만 사용할 수 있습니다. 실제로는 `vi.mock`으로 변환되는 매크로이며, [Vitest 문서](https://vitest.dev/api/vi#vi-mock)에 설명된 것처럼 `vi.mock`은 호이스팅됩니다.
::

Nuxt import를 mock하면서 테스트마다 다른 구현을 제공해야 한다면 [`vi.hoisted`](https://vitest.dev/api/vi#vi-hoisted)로 mock을 생성하고 노출한 뒤, 그 mock을 `mockNuxtImport`에서 사용하면 됩니다. 이렇게 하면 mock된 import에 접근할 수 있고 테스트마다 구현을 바꿀 수 있습니다. 테스트 실행 사이에 바뀐 mock 상태를 되돌리려면 각 테스트 전후에 [restore mocks](https://vitest.dev/api/mock#mockrestore)를 주의해서 호출하세요.

```ts twoslash
import { vi } from 'vitest'
import { mockNuxtImport } from '@nuxt/test-utils/runtime'

const { useStateMock } = vi.hoisted(() => {
  return {
    useStateMock: vi.fn(() => {
      return { value: 'mock된 저장소' }
    }),
  }
})

mockNuxtImport('useState', () => {
  return useStateMock
})

// 그런 다음 테스트 내부에서
useStateMock.mockImplementation(() => {
  return { value: '다른 무언가' }
})
```

테스트 내부에서만 동작을 mock해야 한다면 다음 접근 방식도 사용할 수 있습니다.

```ts twoslash
import { beforeEach, vi } from 'vitest'
import { mockNuxtImport } from '@nuxt/test-utils/runtime'

mockNuxtImport(useRoute, original => vi.fn(original))

beforeEach(() => {
  vi.resetAllMocks()
})

// 그런 다음 테스트 내부에서
const useRouteOriginal = vi.mocked(useRoute).getMockImplementation()!
vi.mocked(useRoute).mockImplementation(
  (...args) => ({ ...useRouteOriginal(...args), path: '/mock됨' }),
)
```

#### `mockComponent` %{#mockcomponent}%

`mockComponent`를 사용하면 Nuxt 컴포넌트를 mock할 수 있습니다.
첫 번째 인자는 PascalCase 형식의 컴포넌트 이름이나 컴포넌트의 상대 경로가 될 수 있습니다.
두 번째 인자는 mock된 컴포넌트를 반환하는 factory 함수입니다.

예를 들어 `MyComponent`를 mock하려면 다음과 같이 할 수 있습니다:

```ts twoslash
import { mockComponent } from '@nuxt/test-utils/runtime'

mockComponent('MyComponent', {
  props: {
    value: String,
  },
  setup (props) {
    // ...
  },
})

// 상대 경로나 별칭도 동작합니다
mockComponent('~/components/my-component.vue', () => {
  // 또는 factory 함수
  return defineComponent({
    setup (props) {
      // ...
    },
  })
})

// 또는 SFC를 사용해 mock 컴포넌트로 리디렉션할 수 있습니다
mockComponent('MyComponent', () => import('./MockComponent.vue'))

// 여기에 테스트 작성
```

> **참고**: factory 함수는 호이스팅되므로 그 안에서 로컬 변수를 참조할 수 없습니다. Vue API나 다른 변수에 접근해야 한다면 factory 함수 안에서 import해야 합니다.

```ts twoslash
import { mockComponent } from '@nuxt/test-utils/runtime'

mockComponent('MyComponent', async () => {
  const { ref, h } = await import('vue')

  return defineComponent({
    setup (props) {
      const counter = ref(0)
      return () => h('div', null, counter.value)
    },
  })
})
```

#### `registerEndpoint` %{#registerendpoint}%

`registerEndpoint`를 사용하면 mock 데이터를 반환하는 Nitro 엔드포인트를 만들 수 있습니다. 데이터를 표시하기 위해 API에 요청을 보내는 컴포넌트를 테스트하고 싶을 때 유용합니다.

첫 번째 인자는 엔드포인트 이름입니다(예: `/test/`).
두 번째 인자는 mock 데이터를 반환하는 factory 함수입니다.

예를 들어 `/test/` 엔드포인트를 mock하려면 다음과 같이 할 수 있습니다:

```ts twoslash
import { registerEndpoint } from '@nuxt/test-utils/runtime'

registerEndpoint('/test/', () => ({
  test: '테스트 필드',
}))
```

기본적으로 요청은 `GET` 메서드로 전송됩니다. 함수 대신 객체를 두 번째 인자로 설정하면 다른 메서드를 사용할 수 있습니다.

```ts twoslash
import { registerEndpoint } from '@nuxt/test-utils/runtime'

registerEndpoint('/test/', {
  method: 'POST',
  handler: () => ({ test: '테스트 필드' }),
})
```

이 객체는 다음 속성을 받습니다:

- `handler`: 이벤트 핸들러 함수
- `method`: (선택 사항) 일치시킬 HTTP 메서드(예: 'GET', 'POST')
- `once`: (선택 사항) true이면 핸들러는 첫 번째 일치 요청에만 사용되고 이후 자동 제거됩니다

> **참고**: 컴포넌트의 요청이 외부 API로 간다면 `baseURL`을 사용한 뒤 [Nuxt Environment Override Config](/docs/4.x/getting-started/configuration#environment-overrides) (`$test`)를 이용해 비워 둘 수 있습니다. 그러면 모든 요청이 Nitro 서버로 가게 됩니다.

#### End-To-End 테스트와의 충돌 %{#conflict-with-end-to-end-testing}%

`@nuxt/test-utils/runtime`와 `@nuxt/test-utils/e2e`는 서로 다른 테스트 환경에서 실행되어야 하므로 같은 파일에서 사용할 수 없습니다.

`@nuxt/test-utils`의 end-to-end 테스트 기능과 단위 테스트 기능을 모두 사용하고 싶다면 테스트를 별도 파일로 나눌 수 있습니다. 그런 다음 특수 주석 `// @vitest-environment nuxt`로 파일별 테스트 환경을 지정하거나, 런타임 단위 테스트 파일 이름에 `.nuxt.spec.ts` 확장자를 사용하면 됩니다.

`app.nuxt.spec.ts`

```ts twoslash
import { mockNuxtImport } from '@nuxt/test-utils/runtime'

mockNuxtImport('useState', () => {
  return () => {
    return { value: 'mock된 저장소' }
  }
})
```

`app.e2e.spec.ts`

```ts twoslash
import { $fetch, setup } from '@nuxt/test-utils/e2e'

await setup({
  setupTimeout: 10000,
})

// ...
```

### `@vue/test-utils` 사용하기 %{#using-vue-test-utils}%

Nuxt에서 단위 테스트를 위해 `@vue/test-utils`만 따로 사용하고 싶고, Nuxt composable, auto-import, context에 의존하지 않는 컴포넌트만 테스트한다면 다음 단계에 따라 설정할 수 있습니다.

1. 필요한 의존성을 설치합니다

   ::code-group{sync="pm"}
   ```bash [npm]
   npm i --save-dev vitest @vue/test-utils happy-dom @vitejs/plugin-vue
   ```
   ```bash [yarn]
   yarn add --dev vitest @vue/test-utils happy-dom @vitejs/plugin-vue
   ```
   ```bash [pnpm]
   pnpm add -D vitest @vue/test-utils happy-dom @vitejs/plugin-vue
   ```
   ```bash [bun]
   bun add --dev vitest @vue/test-utils happy-dom @vitejs/plugin-vue
   ```
   ::

2. 다음 내용으로 `vitest.config.ts`를 만듭니다:

   ```ts
   import { defineConfig } from 'vitest/config'
   import vue from '@vitejs/plugin-vue'

   export default defineConfig({
     plugins: [vue()],
     test: {
       environment: 'happy-dom',
     },
   })
   ```

3. `package.json`에 테스트용 새 명령을 추가합니다

   ```json
   "scripts": {
     "build": "nuxt build",
     "dev": "nuxt dev",
     ...
     "test": "vitest"
   },
   ```

4. 다음 내용으로 간단한 `<HelloWorld>` 컴포넌트 `app/components/HelloWorld.vue`를 만듭니다:

   ```vue
   <template>
     <p>안녕하세요 세계</p>
   </template>
   ```

5. 새로 만든 컴포넌트용 간단한 단위 테스트 `~/components/HelloWorld.spec.ts`를 만듭니다

   ```ts twoslash
   import { describe, expect, it } from 'vitest'
   import { mount } from '@vue/test-utils'

   import HelloWorld from './HelloWorld.vue'

   describe('HelloWorld', () => {
    it('컴포넌트가 안녕하세요 세계를 올바르게 렌더링한다', () => {
      const wrapper = mount(HelloWorld)
      expect(wrapper.text()).toContain('안녕하세요 세계')
    })
  })
  ```

6. vitest 명령을 실행합니다

   ::code-group{sync="pm"}
   ```bash [npm]
   npm run test
   ```
   ```bash [yarn]
   yarn test
   ```
   ```bash [pnpm]
   pnpm run test
   ```
   ```bash [bun]
   bun run test
   ```
   ::

이제 Nuxt에서 `@vue/test-utils`로 단위 테스트를 시작할 준비가 끝났습니다. 즐거운 테스트 되세요!

## 엔드투엔드 테스트 %{#end-to-end-testing}%

end-to-end 테스트를 위해 [Vitest](https://github.com/vitest-dev/vitest), [Jest](https://jestjs.io), [Cucumber](https://cucumber.io/), [Playwright](https://playwright.dev/)를 테스트 러너로 지원합니다.

### 설정 %{#setup}%

`@nuxt/test-utils/e2e` 헬퍼 메서드를 사용하는 각 `describe` 블록에서는 시작 전에 테스트 컨텍스트를 설정해야 합니다.

```ts twoslash [test/my-test.spec.ts]
import { describe, test } from 'vitest'
import { $fetch, setup } from '@nuxt/test-utils/e2e'

describe('My test', async () => {
  await setup({
    // 테스트 컨텍스트 옵션
  })

  test('my test', () => {
    // ...
  })
})
```

내부적으로 `setup`은 `beforeAll`, `beforeEach`, `afterEach`, `afterAll`에서 여러 작업을 수행하여 Nuxt 테스트 환경을 올바르게 설정합니다.

`setup` 메서드에는 아래 옵션을 사용하세요.

#### Nuxt 설정 %{#nuxt-config}%

- `rootDir`: 테스트 대상 Nuxt 앱이 있는 디렉터리 경로
  - 타입: `string`
  - 기본값: `'.'`
- `configFile`: 설정 파일 이름
  - 타입: `string`
  - 기본값: `'nuxt.config'`

<!--
- `config`: Object with configuration overrides.
  - Type: `NuxtConfig`
  - Default: `{}` -->

#### 시간 설정 %{#timings}%

- `setupTimeout`: `setupTest`가 작업을 완료하도록 허용할 시간(밀리초 단위)입니다(전달된 옵션에 따라 Nuxt 애플리케이션 빌드나 파일 생성이 포함될 수 있음).
  - 타입: `number`
  - 기본값: `120000` 또는 Windows에서는 `240000`

- `teardownTimeout`: 브라우저 종료 같은 테스트 환경 정리를 허용할 시간(밀리초 단위)입니다.
  - 타입: `number`
  - 기본값: `30000`

#### 기능 %{#features}%

- `build`: 별도의 빌드 단계를 실행할지 여부
  - 타입: `boolean`
  - 기본값: `true` (`browser` 또는 `server`가 비활성화되었거나 `host`가 제공된 경우 `false`)

- `server`: 테스트 스위트의 요청에 응답할 서버를 실행할지 여부
  - 타입: `boolean`
  - 기본값: `true` (`host`가 제공된 경우 `false`)

- `port`: 제공되면 실행된 테스트 서버 포트를 이 값으로 설정합니다
  - 타입: `number | undefined`
  - 기본값: `undefined`

- `host`: 제공되면 새 서버를 빌드하고 실행하는 대신 테스트 대상으로 사용할 URL입니다. 애플리케이션의 배포 버전이나 이미 실행 중인 로컬 서버를 대상으로 "실제" end-to-end 테스트를 실행할 때 유용합니다(테스트 실행 시간을 크게 줄일 수 있음). 아래의 [대상 host end-to-end 예시](/docs/4.x/getting-started/testing#target-host-end-to-end-example)를 참고하세요.
  - 타입: `string`
  - 기본값: `undefined`

- `browser`: 내부적으로 Nuxt test utils는 브라우저 테스트 수행을 위해 [`playwright`](https://playwright.dev)를 사용합니다. 이 옵션을 설정하면 브라우저가 실행되고 이후 테스트 스위트에서 제어할 수 있습니다.
  - 타입: `boolean`
  - 기본값: `false`
- `browserOptions`
  - 타입: 다음 속성을 가진 `object`
    - `type`: 실행할 브라우저 종류 - `chromium`, `firefox`, `webkit` 중 하나
    - `launch`: 브라우저 실행 시 playwright에 전달할 옵션 객체입니다. [전체 API 참조](https://playwright.dev/docs/api/class-browsertype#browser-type-launch)를 참고하세요.
- `runner`: 테스트 스위트의 러너를 지정합니다. 현재는 [Vitest](https://vitest.dev)를 권장합니다.
  - 타입: `'vitest' | 'jest' | 'cucumber'`
  - 기본값: `'vitest'`

##### 대상 `host` end-to-end 예시 %{#target-host-end-to-end-example}%

end-to-end 테스트의 일반적인 사용 사례 중 하나는 일반적으로 프로덕션에서 사용하는 것과 같은 환경에서 실행 중인 배포 애플리케이션을 대상으로 테스트를 실행하는 것입니다.

로컬 개발이나 자동 배포 파이프라인에서는 별도의 로컬 서버를 대상으로 테스트하는 편이 더 효율적일 수 있으며, 일반적으로 테스트 사이마다 테스트 프레임워크가 다시 빌드하도록 두는 것보다 빠릅니다.

end-to-end 테스트에 별도 대상 host를 사용하려면 `setup` 함수의 `host` 속성에 원하는 URL을 제공하면 됩니다.

```ts
import { createPage, setup } from '@nuxt/test-utils/e2e'
import { describe, expect, it } from 'vitest'

describe('login page', async () => {
  await setup({
    host: 'http://localhost:8787',
  })

  it('이메일과 비밀번호 필드를 표시한다', async () => {
    const page = await createPage('/login')
    expect(await page.getByTestId('email').isVisible()).toBe(true)
    expect(await page.getByTestId('password').isVisible()).toBe(true)
  })
})
```

### API %{#apis}%

#### `$fetch(url)` %{#fetch-url}%

서버 렌더링된 페이지의 HTML을 가져옵니다.

```ts twoslash
import { $fetch } from '@nuxt/test-utils/e2e'

const html = await $fetch('/')
```

#### `fetch(url)` %{#fetch-url}%

서버 렌더링된 페이지의 응답을 가져옵니다.

```ts twoslash
import { fetch } from '@nuxt/test-utils/e2e'

const res = await fetch('/')
const { body, headers } = res
```

#### `url(path)` %{#url-path}%

주어진 페이지의 전체 URL을 가져옵니다(테스트 서버가 실행 중인 포트 포함).

```ts twoslash
import { url } from '@nuxt/test-utils/e2e'

const pageUrl = url('/page')
// 'http://localhost:6840/page'
```

### 브라우저에서 테스트하기 %{#testing-in-a-browser}%

`@nuxt/test-utils` 내부에서 Playwright를 사용한 내장 지원을 제공하며, 프로그래밍 방식 또는 Playwright 테스트 러너를 통해 사용할 수 있습니다.

#### `createPage(url)` %{#createpage-url}%

`vitest`, `jest`, `cucumber` 안에서는 `createPage`로 설정된 Playwright 브라우저 인스턴스를 만들고, 선택적으로 실행 중인 서버의 경로를 가리키게 할 수 있습니다. 사용 가능한 API 메서드는 [Playwright 문서](https://playwright.dev/docs/api/class-page)에서 더 알아볼 수 있습니다.

```ts twoslash
import { createPage } from '@nuxt/test-utils/e2e'

const page = await createPage('/page')
// `page` 변수에서 모든 Playwright API에 접근할 수 있습니다
```

#### Playwright 테스트 러너로 테스트하기 %{#testing-with-playwright-test-runner}%

[Playwright 테스트 러너](https://playwright.dev/docs/intro) 안에서 Nuxt를 테스트하는 일급 지원도 제공합니다.

::code-group{sync="pm"}
```bash [npm]
npm i --save-dev @playwright/test @nuxt/test-utils
```
```bash [yarn]
yarn add --dev @playwright/test @nuxt/test-utils
```
```bash [pnpm]
pnpm add -D @playwright/test @nuxt/test-utils
```
```bash [bun]
bun add --dev @playwright/test @nuxt/test-utils
```
```bash [deno]
deno add --dev npm:@playwright/test npm:@nuxt/test-utils
```
::

이 섹션 앞에서 설명한 `setup()` 함수와 같은 설정 항목으로 전역 Nuxt 설정을 제공할 수 있습니다.

```ts [playwright.config.ts]
import { fileURLToPath } from 'node:url'
import { defineConfig, devices } from '@playwright/test'
import type { ConfigOptions } from '@nuxt/test-utils/playwright'

export default defineConfig<ConfigOptions>({
  use: {
    nuxt: {
      rootDir: fileURLToPath(new URL('.', import.meta.url)),
    },
  },
  // ...
})
```

::read-more{title="전체 예시 설정 보기" to="https://github.com/nuxt/test-utils/blob/main/examples/app-playwright/playwright.config.ts" target="_blank"}
::

테스트 파일에서는 `@nuxt/test-utils/playwright`에서 `expect`와 `test`를 직접 사용해야 합니다:

```ts [tests/example.test.ts]
import { expect, test } from '@nuxt/test-utils/playwright'

test('test', async ({ page, goto }) => {
  await goto('/', { waitUntil: 'hydration' })
  await expect(page.getByRole('heading')).toHaveText('Playwright에 오신 것을 환영합니다!')
})
```

또는 테스트 파일 안에서 Nuxt 서버를 직접 설정할 수도 있습니다:

```ts [tests/example.test.ts]
import { expect, test } from '@nuxt/test-utils/playwright'

test.use({
  nuxt: {
    rootDir: fileURLToPath(new URL('..', import.meta.url)),
  },
})

test('test', async ({ page, goto }) => {
  await goto('/', { waitUntil: 'hydration' })
  await expect(page.getByRole('heading')).toHaveText('Playwright에 오신 것을 환영합니다!')
})
```
