Nuxt에는 브라우저나 서버 환경에서 데이터 가져오기를 수행하기 위한 두 개의 컴포저블과 내장 라이브러리가 포함되어 있습니다: `useFetch`, [`useAsyncData`](/docs/4.x/api/composables/use-async-data), `$fetch`.

간단히 말하면:

- [`$fetch`](/docs/4.x/api/utils/dollarfetch)는 네트워크 요청을 보내는 가장 간단한 방법입니다.
- [`useFetch`](/docs/4.x/api/composables/use-fetch)는 [유니버설 렌더링](/docs/4.x/guide/concepts/rendering#universal-rendering)에서 데이터를 한 번만 가져오도록 하는 `$fetch` 래퍼입니다.
- [`useAsyncData`](/docs/4.x/api/composables/use-async-data)는 `useFetch`와 비슷하지만 더 세밀한 제어를 제공합니다.

`useFetch`와 `useAsyncData`는 공통 옵션과 패턴 집합을 공유하며, 이는 마지막 섹션에서 자세히 설명합니다.

## `useFetch`와 `useAsyncData`가 필요한 이유 %{#the-need-for-usefetch-and-useasyncdata}%

Nuxt는 서버와 클라이언트 환경 모두에서 동형(isomorphic) 코드(또는 유니버설 코드)를 실행할 수 있는 프레임워크입니다. Vue 컴포넌트의 setup 함수에서 데이터를 가져오기 위해 [`$fetch` 함수](/docs/4.x/api/utils/dollarfetch)를 사용하면, 서버에서 한 번(HTML 렌더링용), 클라이언트에서 다시 한 번(HTML hydration 시) 데이터를 두 번 가져오게 될 수 있습니다. 이는 hydration 문제를 일으키고, 상호작용 가능 시간(time to interactivity)을 늘리며, 예측할 수 없는 동작을 초래할 수 있습니다.

[`useFetch`](/docs/4.x/api/composables/use-fetch)와 [`useAsyncData`](/docs/4.x/api/composables/use-async-data) 컴포저블은 서버에서 API 호출이 이루어졌다면 해당 데이터가 payload 안에 담겨 클라이언트로 전달되도록 보장함으로써 이 문제를 해결합니다.

payload는 [`useNuxtApp().payload`](/docs/4.x/api/composables/use-nuxt-app#payload)를 통해 접근할 수 있는 JavaScript 객체입니다. 이 객체는 브라우저에서 코드가 [hydration 중](/docs/4.x/guide/concepts/rendering#universal-rendering)에 실행될 때 같은 데이터를 다시 가져오지 않도록 클라이언트 측에서 사용됩니다.

::tip
[Nuxt DevTools](https://devtools.nuxt.com)를 사용해 **Payload 탭**에서 이 데이터를 확인하세요.
::

```vue [app/app.vue]
<script setup lang="ts">
const { data } = await useFetch('/api/data')

async function handleFormSubmit () {
  const res = await $fetch('/api/submit', {
    method: 'POST',
    body: {
      // 내 폼 데이터
    },
  })
}
</script>

<template>
  <div v-if="data == undefined">
    데이터 없음
  </div>
  <div v-else>
    <form @submit="handleFormSubmit">
      <!-- 폼 입력 태그 -->
    </form>
  </div>
</template>
```

위 예시에서 `useFetch`는 요청이 서버에서 발생하고 브라우저로 올바르게 전달되도록 보장합니다. `$fetch`에는 이런 메커니즘이 없으며, 요청이 브라우저에서만 수행될 때 사용하는 편이 더 적합합니다.

### Suspense %{#suspense}%

Nuxt는 내부적으로 Vue의 [`<Suspense>`](https://vuejs.org/guide/built-ins/suspense) 컴포넌트를 사용하여 모든 비동기 데이터가 뷰에서 사용 가능해지기 전에 내비게이션이 일어나지 않도록 합니다. 데이터 가져오기 컴포저블은 이 기능을 활용하고 호출별로 가장 적합한 방식을 사용할 수 있게 도와줍니다.

::note
[`<NuxtLoadingIndicator>`](/docs/4.x/api/components/nuxt-loading-indicator)를 추가해 페이지 이동 사이에 진행 표시줄을 넣을 수 있습니다.
::

## `$fetch` %{#fetch}%

Nuxt에는 [ofetch](https://github.com/unjs/ofetch) 라이브러리가 포함되어 있으며, 애플리케이션 전역에서 `$fetch` 별칭으로 자동 import됩니다.

```vue twoslash [pages/todos.vue]
<script setup lang="ts">
async function addTodo () {
  const todo = await $fetch('/api/todos', {
    method: 'POST',
    body: {
      // 내 할 일 데이터
    },
  })
}
</script>
```

::warning
`$fetch`만 사용할 경우 [네트워크 호출 중복 제거와 내비게이션 방지](/docs/4.x/getting-started/data-fetching#the-need-for-usefetch-and-useasyncdata)가 제공되지 않는다는 점에 주의하세요. :br
`$fetch`는 클라이언트 측 상호작용(이벤트 기반)에 사용하거나, 초기 컴포넌트 데이터를 가져올 때 [`useAsyncData`](/docs/4.x/getting-started/data-fetching#useasyncdata)와 함께 사용하는 것을 권장합니다.
::

::read-more{to="/docs/4.x/api/utils/dollarfetch"}
`$fetch`에 대해 더 알아보세요.
::

### 클라이언트 헤더를 API에 전달하기 %{#pass-client-headers-to-the-api}%

서버에서 `useFetch`를 호출하면, Nuxt는 [`useRequestFetch`](/docs/4.x/api/composables/use-request-fetch)를 사용해 클라이언트 헤더와 쿠키를 프록시합니다(`host`처럼 전달되지 않아야 하는 헤더는 제외).

```vue
<script setup lang="ts">
const { data } = await useFetch('/api/echo')
</script>
```

```ts
// /api/echo.ts
export default defineEventHandler(event => parseCookies(event))
```

또는 아래 예시는 [`useRequestHeaders`](/docs/4.x/api/composables/use-request-headers)를 사용해 서버 측 요청(클라이언트에서 시작된 요청)에서 API로 쿠키에 접근하고 전달하는 방법을 보여줍니다. 동형 `$fetch` 호출을 사용하면 API 엔드포인트가 원래 사용자의 브라우저가 보낸 것과 같은 `cookie` 헤더에 접근할 수 있습니다. 이는 `useFetch`를 사용하지 않는 경우에만 필요합니다.

```vue
<script setup lang="ts">
const headers = useRequestHeaders(['cookie'])

async function getCurrentUser () {
  return await $fetch('/api/me', { headers })
}
</script>
```

::tip
[`useRequestFetch`](/docs/4.x/api/composables/use-request-fetch)를 사용해 호출에 헤더를 자동 프록시할 수도 있습니다.
::

::caution
외부 API로 헤더를 프록시하기 전에 매우 신중해야 하며, 필요한 헤더만 포함하세요. 모든 헤더가 그대로 우회 전달해도 안전한 것은 아니며 원치 않는 동작을 유발할 수 있습니다. 다음은 프록시하지 말아야 할 일반적인 헤더 목록입니다:

- `host`, `accept`
- `content-length`, `content-md5`, `content-type`
- `x-forwarded-host`, `x-forwarded-port`, `x-forwarded-proto`
- `cf-connecting-ip`, `cf-ray`
::

## `useFetch` %{#usefetch}%

[`useFetch`](/docs/4.x/api/composables/use-fetch) 컴포저블은 내부적으로 `$fetch`를 사용해 setup 함수 안에서 SSR 안전한 네트워크 호출을 수행합니다.

```vue twoslash [app/app.vue]
<script setup lang="ts">
const { data: count } = await useFetch('/api/count')
</script>

<template>
  <p>페이지 방문 수: {{ count }}</p>
</template>
```

이 컴포저블은 [`useAsyncData`](/docs/4.x/api/composables/use-async-data) 컴포저블과 `$fetch` 유틸리티를 감싼 래퍼입니다.

## `useAsyncData` %{#useasyncdata}%

`useAsyncData` 컴포저블은 비동기 로직을 감싸고 resolve된 뒤 결과를 반환하는 역할을 합니다.

::tip
`useFetch(url)`는 거의 `useAsyncData(url, () => event.$fetch(url))`와 같습니다. :br
가장 흔한 사용 사례를 위한 개발자 경험 개선용 문법 설탕입니다. (`event.fetch`에 대해서는 [`useRequestFetch`](/docs/4.x/api/composables/use-request-fetch)에서 더 알아볼 수 있습니다.)
::

:video-accordion{title="useFetch와 useAsyncData의 차이를 더 깊이 파고드는 Alexander Lichter의 영상 보기" videoId="0X-aOpSGabA"}

[`useFetch`](/docs/4.x/api/composables/use-fetch) 컴포저블을 사용하는 것이 적절하지 않은 경우도 있습니다. 예를 들어 CMS나 서드파티가 자체 쿼리 레이어를 제공하는 경우가 그렇습니다. 이럴 때는 [`useAsyncData`](/docs/4.x/api/composables/use-async-data)를 사용해 호출을 감싸면서도 컴포저블이 제공하는 장점을 유지할 수 있습니다.

```vue [app/pages/users.vue]
<script setup lang="ts">
const { data, error } = await useAsyncData('users', () => myGetFunction('users'))

// 이것도 가능합니다:
const { data, error } = await useAsyncData(() => myGetFunction('users'))
</script>
```

::note
[`useAsyncData`](/docs/4.x/api/composables/use-async-data)의 첫 번째 인자는 두 번째 인자인 조회 함수의 응답을 캐시하기 위해 사용되는 고유 키입니다. 조회 함수를 직접 전달하면 이 키는 생략할 수 있으며, 키는 자동 생성됩니다.
:br :br
자동 생성 키는 `useAsyncData`가 호출된 파일과 줄만 고려하므로, `useAsyncData`를 감싸는 사용자 정의 컴포저블을 만드는 경우와 같은 원치 않는 동작을 피하려면 항상 직접 키를 만드는 것이 좋습니다.
:br :br
키를 설정하면 [`useNuxtData`](/docs/4.x/api/composables/use-nuxt-data)를 사용해 컴포넌트 간에 같은 데이터를 공유하거나 [특정 데이터만 새로고침](/docs/4.x/api/utils/refresh-nuxt-data#refresh-specific-data)하는 데 유용합니다.
::

```vue [app/pages/users/[id\\].vue]
<script setup lang="ts">
const { id } = useRoute().params

const { data, error } = await useAsyncData(`user:${id}`, () => {
  return myGetFunction('users', { id })
})
</script>
```

`useAsyncData` 컴포저블은 여러 `$fetch` 요청을 감싸고 모두 완료될 때까지 기다린 뒤 결과를 처리하는 훌륭한 방법입니다.

```vue
<script setup lang="ts">
const { data: discounts, status } = await useAsyncData('cart-discount', async (_nuxtApp, { signal }) => {
  const [coupons, offers] = await Promise.all([
    $fetch('/cart/coupons', { signal }),
    $fetch('/cart/offers', { signal }),
  ])

  return { coupons, offers }
})
// discounts.value.coupons
// discounts.value.offers
</script>
```

::note
`useAsyncData`는 데이터 가져오기와 캐싱을 위한 것이지 Pinia action 호출 같은 부수 효과를 트리거하기 위한 것이 아닙니다. 이런 방식은 nullish 값으로 반복 실행되는 것과 같은 의도치 않은 동작을 일으킬 수 있습니다. 부수 효과를 트리거해야 한다면 [`callOnce`](/docs/4.x/api/utils/call-once) 유틸리티를 사용하세요.

```vue
<script setup lang="ts">
const offersStore = useOffersStore()

// 이렇게 하면 안 됩니다
await useAsyncData(() => offersStore.getOffer(route.params.slug))
</script>
```
::

## 반환값 %{#return-values}%

`useFetch`와 `useAsyncData`는 아래와 같은 동일한 반환값을 가집니다.

- `data`: 전달된 비동기 함수의 결과입니다.
- `refresh`/`execute`: `handler` 함수가 반환한 데이터를 새로고침하는 데 사용할 수 있는 함수입니다.
- `clear`: `data`를 `undefined`로(또는 `options.default()`가 제공된 경우 그 값으로) 설정하고, `error`를 `undefined`로, `status`를 `idle`로 설정하며, 현재 대기 중인 요청을 취소된 것으로 표시하는 데 사용할 수 있는 함수입니다.
- `error`: 데이터 가져오기에 실패했을 때의 오류 객체입니다.
- `status`: 데이터 요청 상태를 나타내는 문자열입니다 (`"idle"`, `"pending"`, `"success"`, `"error"`).

::note
`data`, `error`, `status`는 `<script setup>`에서 `.value`로 접근할 수 있는 Vue ref입니다
::

기본적으로 Nuxt는 `refresh`가 완료될 때까지 기다렸다가 다시 실행할 수 있게 합니다.

::note
서버에서 데이터를 가져오지 않았다면(예: `server: false`), hydration이 완료될 때까지 데이터는 _가져와지지 않습니다_. 즉, 클라이언트 측에서 `useFetch`를 await하더라도 `<script setup>` 안의 `data`는 null로 남습니다.
::

## 옵션 %{#options}%

[`useAsyncData`](/docs/4.x/api/composables/use-async-data)와 [`useFetch`](/docs/4.x/api/composables/use-fetch)는 같은 객체 타입을 반환하고 마지막 인자로 공통 옵션 집합을 받습니다. 이를 통해 내비게이션 차단, 캐싱, 실행 방식 같은 컴포저블 동작을 제어할 수 있습니다.

### 지연 로딩 %{#lazy}%

기본적으로 데이터 가져오기 컴포저블은 Vue의 Suspense를 사용해 비동기 함수가 resolve될 때까지 기다린 뒤 새 페이지로 이동합니다. 이 기능은 클라이언트 측 내비게이션에서 `lazy` 옵션으로 무시할 수 있습니다. 이 경우 `status` 값을 사용해 로딩 상태를 수동으로 처리해야 합니다.

```vue twoslash [app/app.vue]
<script setup lang="ts">
const { status, data: posts } = useFetch('/api/posts', {
  lazy: true,
})
</script>

<template>
  <!-- 로딩 상태를 직접 처리해야 합니다 -->
  <div v-if="status === 'pending'">
    로딩 중 ...
  </div>
  <div v-else>
    <div v-for="post in posts">
      <!-- 무언가를 수행 -->
    </div>
  </div>
</template>
```

같은 작업을 수행하는 더 간편한 방법으로 [`useLazyFetch`](/docs/4.x/api/composables/use-lazy-fetch)와 `useLazyAsyncData`를 사용할 수도 있습니다.

```vue twoslash
<script setup lang="ts">
const { status, data: posts } = useLazyFetch('/api/posts')
</script>
```

### 클라이언트 전용 가져오기 %{#client-only-fetching}%

기본적으로 데이터 가져오기 컴포저블은 클라이언트와 서버 환경 모두에서 비동기 함수를 수행합니다. 클라이언트 측에서만 호출을 수행하려면 `server` 옵션을 `false`로 설정하세요. 초기 로드에서는 hydration이 완료되기 전까지 데이터를 가져오지 않으므로 pending 상태를 처리해야 하지만, 이후 클라이언트 측 내비게이션에서는 페이지 로드 전에 데이터를 기다립니다.

이 옵션을 `lazy`와 함께 사용하면 첫 렌더링에 필요하지 않은 데이터(예: SEO에 민감하지 않은 데이터)에 유용할 수 있습니다.

```ts twoslash
/* 이 호출은 hydration 전에 수행됩니다 */
const articles = await useFetch('/api/article')

/* 이 호출은 클라이언트에서만 수행됩니다 */
const { status, data: comments } = useFetch('/api/comments', {
  lazy: true,
  server: false,
})
```

`useFetch` 컴포저블은 setup 메서드에서 호출하거나 라이프사이클 훅 내부 함수의 최상위에서 직접 호출하도록 설계되었습니다. 그렇지 않다면 [`$fetch` 메서드](/docs/4.x/getting-started/data-fetching#fetch)를 사용해야 합니다.

### payload 크기 최소화 %{#minimize-payload-size}%

`pick` 옵션은 컴포저블에서 반환받고 싶은 필드만 선택하여 HTML 문서에 저장되는 payload 크기를 최소화하는 데 도움을 줍니다.

```vue
<script setup lang="ts">
/* 템플릿에서 사용하는 필드만 선택합니다 */
const { data: mountain } = await useFetch('/api/mountains/everest', {
  pick: ['title', 'description'],
})
</script>

<template>
  <h1>{{ mountain.title }}</h1>
  <p>{{ mountain.description }}</p>
</template>
```

더 많은 제어가 필요하거나 여러 객체를 매핑해야 한다면 `transform` 함수를 사용해 쿼리 결과를 변경할 수 있습니다.

```ts
const { data: mountains } = await useFetch('/api/mountains', {
  transform: (mountains) => {
    return mountains.map(mountain => ({ title: mountain.title, description: mountain.description }))
  },
})
```

::note
`pick`과 `transform` 모두 처음부터 원치 않는 데이터가 가져와지는 것을 막지는 못합니다. 하지만 서버에서 클라이언트로 전달되는 payload에 원치 않는 데이터가 추가되는 것은 막아줍니다.
::

### 캐싱과 재조회 %{#caching-and-refetching}%

#### 키 %{#keys}%

[`useFetch`](/docs/4.x/api/composables/use-fetch)와 [`useAsyncData`](/docs/4.x/api/composables/use-async-data)는 같은 데이터를 다시 가져오지 않도록 키를 사용합니다.

- [`useFetch`](/docs/4.x/api/composables/use-fetch)는 제공된 URL을 키로 사용합니다. 또는 마지막 인자로 전달하는 `options` 객체에 `key` 값을 지정할 수도 있습니다.
- [`useAsyncData`](/docs/4.x/api/composables/use-async-data)는 첫 번째 인자가 문자열일 경우 그것을 키로 사용합니다. 첫 번째 인자가 쿼리를 수행하는 handler 함수라면, `useAsyncData` 인스턴스의 파일명과 줄 번호를 기준으로 고유 키가 자동 생성됩니다.

::tip
키를 통해 캐시된 데이터를 가져오려면 [`useNuxtData`](/docs/4.x/api/composables/use-nuxt-data)를 사용할 수 있습니다
::

:video-accordion{title="key 옵션으로 데이터를 캐싱하는 방법에 대한 Vue School 영상 보기" videoId="1026410044" platform="vimeo"}

#### 공유 상태와 옵션 일관성 %{#shared-state-and-option-consistency}%

여러 컴포넌트가 `useAsyncData`나 `useFetch`에서 같은 키를 사용하면 동일한 `data`, `error`, `status` ref를 공유합니다. 이는 컴포넌트 간 일관성을 보장하지만 일부 옵션도 일관되어야 한다는 의미입니다.

다음 옵션은 같은 키를 사용하는 모든 호출에서 **반드시 일관되어야 합니다**:
- `handler` 함수
- `deep` 옵션
- `transform` 함수
- `pick` 배열
- `getCachedData` 함수
- `default` 값

```ts
// ❌ 이 코드는 개발 경고를 발생시킵니다
const { data: users1 } = useAsyncData('users', (_nuxtApp, { signal }) => $fetch('/api/users', { signal }), { deep: false })
const { data: users2 } = useAsyncData('users', (_nuxtApp, { signal }) => $fetch('/api/users', { signal }), { deep: true })
```

다음 옵션은 경고를 발생시키지 않고 **안전하게 달라도 됩니다**:
- `server`
- `lazy`
- `immediate`
- `dedupe`
- `watch`

```ts
// ✅ 이것은 허용됩니다
const { data: users1 } = useAsyncData('users', (_nuxtApp, { signal }) => $fetch('/api/users', { signal }), { immediate: true })
const { data: users2 } = useAsyncData('users', (_nuxtApp, { signal }) => $fetch('/api/users', { signal }), { immediate: false })
```

독립적인 인스턴스가 필요하다면 다른 키를 사용하세요:

```ts
// 이들은 완전히 독립적인 인스턴스입니다
const { data: users1 } = useAsyncData('users-1', (_nuxtApp, { signal }) => $fetch('/api/users', { signal }))
const { data: users2 } = useAsyncData('users-2', (_nuxtApp, { signal }) => $fetch('/api/users', { signal }))
```

#### 반응형 키 %{#reactive-keys}%

computed ref, 일반 ref, getter 함수를 키로 사용할 수 있으며, 이를 통해 의존성이 바뀔 때 자동으로 업데이트되는 동적 데이터 가져오기가 가능합니다:

```ts
// computed 속성을 키로 사용
const userId = ref('123')
const { data: user } = useAsyncData(
  computed(() => `user-${userId.value}`),
  () => fetchUser(userId.value),
)

// userId가 바뀌면 데이터가 자동으로 다시 가져와지고
// 다른 컴포넌트가 사용하지 않으면 이전 데이터는 정리됩니다
userId.value = '456'
```

#### refresh와 execute %{#refresh-and-execute}%

데이터를 수동으로 가져오거나 새로고침하고 싶다면 컴포저블이 제공하는 `execute` 또는 `refresh` 함수를 사용하세요.

```vue twoslash
<script setup lang="ts">
const { data, error, execute, refresh } = await useFetch('/api/users')
</script>

<template>
  <div>
    <p>{{ data }}</p>
    <button @click="() => refresh()">
      데이터 새로고침
    </button>
  </div>
</template>
```

`execute` 함수는 `refresh`의 별칭이며 정확히 같은 방식으로 동작하지만, 가져오기가 [즉시 실행되지 않는](/docs/4.x/getting-started/data-fetching#not-immediate) 경우에 더 의미상 적합합니다.

::tip
캐시된 데이터를 전역으로 다시 가져오거나 무효화하려면 [`clearNuxtData`](/docs/4.x/api/utils/clear-nuxt-data)와 [`refreshNuxtData`](/docs/4.x/api/utils/refresh-nuxt-data)를 참고하세요.
::

#### 지우기 %{#clear}%

어떤 이유로든 `clearNuxtData`에 전달할 구체적인 키를 알 필요 없이 제공된 데이터를 지우고 싶다면, 컴포저블이 제공하는 `clear` 함수를 사용할 수 있습니다.

```vue twoslash
<script setup lang="ts">
const { data, clear } = await useFetch('/api/users')

const route = useRoute()
watch(() => route.path, (path) => {
  if (path === '/') {
    clear()
  }
})
</script>
```

#### 감시 %{#watch}%

애플리케이션의 다른 반응형 값이 변경될 때마다 가져오기 함수를 다시 실행하려면 `watch` 옵션을 사용하세요. 하나 또는 여러 _watchable_ 요소에 사용할 수 있습니다.

```vue twoslash
<script setup lang="ts">
const id = ref(1)

const { data, error, refresh } = await useFetch('/api/users', {
  /* id가 바뀌면 다시 가져오기가 트리거됩니다 */
  watch: [id],
})
</script>
```

**반응형 값을 감시한다고 해서 가져오는 URL이 바뀌지는 않는다**는 점에 유의하세요. 예를 들어 아래 코드는 함수가 호출되는 시점에 URL이 구성되므로 사용자의 초기 ID만 계속 가져오게 됩니다.

```vue
<script setup lang="ts">
const id = ref(1)

const { data, error, refresh } = await useFetch(`/api/users/${id.value}`, {
  watch: [id],
})
</script>
```

반응형 값을 기준으로 URL을 변경해야 한다면 대신 [계산된 URL](/docs/4.x/getting-started/data-fetching#computed-url)을 사용하는 편이 좋습니다.

반응형 fetch 옵션이 제공되면 자동으로 감시되어 다시 가져오기를 트리거합니다. 경우에 따라 `watch: false`를 지정해 이 동작을 끄는 것이 유용할 수 있습니다.

```ts
const id = ref(1)

// id가 바뀌어도 자동으로 다시 가져오지 않습니다
const { data, execute } = await useFetch('/api/users', {
  query: { id }, // id is watched by default
  watch: false, // disables automatic watching of id
})

// 다시 가져오기가 트리거되지 않습니다
id.value = 2
```

#### 계산된 URL %{#computed-url}%

때로는 반응형 값으로부터 URL을 계산하고, 값이 바뀔 때마다 데이터를 새로고침해야 할 수 있습니다. 복잡하게 우회하는 대신 각 파라미터를 반응형 값으로 연결할 수 있습니다. Nuxt는 반응형 값을 자동으로 사용하고, 값이 바뀔 때마다 다시 가져옵니다.

```vue
<script setup lang="ts">
const id = ref(null)

const { data, status } = useLazyFetch('/api/user', {
  query: {
    user_id: id,
  },
})
</script>
```

더 복잡한 URL 구성이 필요한 경우에는 URL 문자열을 반환하는 [computed getter](https://vuejs.org/guide/essentials/computed)로 콜백을 사용할 수 있습니다.

의존성이 바뀔 때마다 새로 구성된 URL을 사용해 데이터를 가져옵니다. 이를 [즉시 실행하지 않기](/docs/4.x/getting-started/data-fetching#not-immediate)와 결합하면 반응형 요소가 변경될 때까지 기다렸다가 가져올 수 있습니다.

```vue
<script setup lang="ts">
const id = ref(null)

const { data, status } = useLazyFetch(() => `/api/users/${id.value}`, {
  immediate: false,
})

const pending = computed(() => status.value === 'pending')
</script>

<template>
  <div>
    <!-- 가져오는 동안 입력 비활성화 -->
    <input
      v-model="id"
      type="number"
      :disabled="pending"
    >

    <div v-if="status === 'idle'">
      사용자 ID를 입력하세요
    </div>

    <div v-else-if="pending">
      로딩 중 ...
    </div>

    <div v-else>
      {{ data }}
    </div>
  </div>
</template>
```

다른 반응형 값이 바뀔 때 강제로 새로고침해야 한다면 [다른 값 감시하기](/docs/4.x/getting-started/data-fetching#watch)도 사용할 수 있습니다.

### 즉시 실행하지 않기 %{#not-immediate}%

`useFetch` 컴포저블은 호출되는 즉시 데이터 가져오기를 시작합니다. 예를 들어 사용자 상호작용을 기다리고 싶다면 `immediate: false`를 설정해 이를 막을 수 있습니다.

이 경우 가져오기 라이프사이클을 처리하기 위한 `status`와 데이터 가져오기를 시작하기 위한 `execute`가 모두 필요합니다.

```vue
<script setup lang="ts">
const { data, error, execute, status } = await useLazyFetch('/api/comments', {
  immediate: false,
})
</script>

<template>
  <div v-if="status === 'idle'">
    <button @click="execute">
      데이터 가져오기
    </button>
  </div>

  <div v-else-if="status === 'pending'">
    댓글 로딩 중...
  </div>

  <div v-else>
    {{ data }}
  </div>
</template>
```

더 세밀하게 제어하려면 `status` 변수는 다음 값이 될 수 있습니다:

- `idle`: 가져오기가 시작되지 않았을 때
- `pending`: 가져오기가 시작되었지만 아직 완료되지 않았을 때
- `error`: 가져오기에 실패했을 때
- `success`: 가져오기가 성공적으로 완료되었을 때

## 헤더와 쿠키 전달하기 %{#passing-headers-and-cookies}%

브라우저에서 `$fetch`를 호출하면 `cookie` 같은 사용자 헤더가 API로 직접 전송됩니다.

일반적으로 서버 사이드 렌더링 중에는 보안상의 이유로 `$fetch`가 사용자의 브라우저 쿠키를 포함하지 않으며, fetch 응답에서 쿠키를 전달하지도 않습니다.

하지만 서버에서 상대 URL로 `useFetch`를 호출할 때는 Nuxt가 [`useRequestFetch`](/docs/4.x/api/composables/use-request-fetch)를 사용해 헤더와 쿠키를 프록시합니다(`host`처럼 전달되지 않아야 하는 헤더는 제외).

### SSR 응답에서 서버 측 API 호출의 쿠키 전달하기 %{#pass-cookies-from-server-side-api-calls-on-ssr-response}%

 내부 요청에서 다시 클라이언트로 쿠키를 반대 방향으로 전달/프록시하고 싶다면, 이를 직접 처리해야 합니다.

```ts [app/composables/fetch.ts]
import type { H3Event } from 'h3'

export const fetchWithCookie = async (event: H3Event, url: string) => {
  /* 서버 엔드포인트에서 응답을 가져옵니다 */
  const res = await $fetch.raw(url)
  /* 응답에서 쿠키를 가져옵니다 */
  const cookies = res.headers.getSetCookie()
  /* 각 쿠키를 들어오는 Request에 붙입니다 */
  for (const cookie of cookies) {
    event.res.headers.append('set-cookie', cookie)
  }
  /* 응답 데이터를 반환합니다 */
  return res._data
}
```

```vue
<script setup lang="ts">
// 이 컴포저블은 자동으로 쿠키를 클라이언트에 전달합니다
const event = useRequestEvent()

const { data: result } = await useAsyncData(() => fetchWithCookie(event!, '/api/with-cookie'))

onMounted(() => console.log(document.cookie))
</script>
```

## Options API 지원 %{#options-api-support}%

Nuxt는 Options API 안에서 `asyncData` 가져오기를 수행할 수 있는 방법을 제공합니다. 이를 사용하려면 컴포넌트 정의를 `defineNuxtComponent`로 감싸야 합니다.

```vue
<script>
export default defineNuxtComponent({
  /* fetchKey 옵션으로 고유 키를 제공합니다 */
  fetchKey: 'hello',
  async asyncData () {
    return {
      hello: await $fetch('/api/hello'),
    }
  },
})
</script>
```

::note
Nuxt에서는 `<script setup>` 또는 `<script setup lang="ts">`를 사용해 Vue 컴포넌트를 선언하는 것을 권장합니다.
::

## 서버에서 클라이언트로 데이터 직렬화 %{#serializing-data-from-server-to-client}%

서버에서 가져온 데이터를 클라이언트로 전달하기 위해 `useAsyncData`와 `useLazyAsyncData`를 사용할 때(또는 [Nuxt payload](/docs/4.x/api/composables/use-nuxt-app#payload)를 활용하는 그 밖의 모든 경우에도), payload는 [`devalue`](https://github.com/sveltejs/devalue)로 직렬화됩니다. 이를 통해 단순한 JSON뿐 아니라 정규식, Date, Map, Set, `ref`, `reactive`, `shallowRef`, `shallowReactive`, `NuxtError` 등 더 고급 데이터 유형도 직렬화하고 복원/역직렬화할 수 있습니다.

Nuxt가 지원하지 않는 타입에 대해 직접 serializer/deserializer를 정의하는 것도 가능합니다. 자세한 내용은 [`useNuxtApp`](/docs/4.x/api/composables/use-nuxt-app#payload) 문서에서 확인할 수 있습니다.

::note
이 내용은 서버 라우트에서 `$fetch` 또는 `useFetch`로 가져온 데이터에는 _적용되지 않는다_ 는 점에 유의하세요. 자세한 내용은 다음 섹션을 참고하세요.
::

## API 라우트에서 데이터 직렬화 %{#serializing-data-from-api-routes}%

`server` 디렉터리에서 데이터를 가져올 때 응답은 `JSON.stringify`를 사용해 직렬화됩니다. 하지만 직렬화는 JavaScript 원시 타입으로 제한되므로, Nuxt는 `$fetch`와 [`useFetch`](/docs/4.x/api/composables/use-fetch)의 반환 타입이 실제 값과 최대한 일치하도록 변환을 시도합니다.

::read-more{icon="i-simple-icons-mdnwebdocs" to="https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/JSON/stringify#description" target="_blank"}
`JSON.stringify`의 한계에 대해 더 알아보세요.
::

### 예시 %{#example}%

```ts [server/api/foo.ts]
export default defineEventHandler(() => {
  return new Date()
})
```

```vue [app/app.vue]
<script setup lang="ts">
// Date 객체를 반환했더라도 `data`의 타입은 string으로 추론됩니다
const { data } = await useFetch('/api/foo')
</script>
```

### 사용자 정의 serializer 함수 %{#custom-serializer-function}%

직렬화 동작을 사용자 정의하려면 반환 객체에 `toJSON` 함수를 정의할 수 있습니다. `toJSON` 메서드를 정의하면 Nuxt는 그 함수의 반환 타입을 존중하며 타입을 변환하려고 하지 않습니다.

```ts [server/api/bar.ts]
export default defineEventHandler(() => {
  const data = {
    createdAt: new Date(),

    toJSON () {
      return {
        createdAt: {
          year: this.createdAt.getFullYear(),
          month: this.createdAt.getMonth(),
          day: this.createdAt.getDate(),
        },
      }
    },
  }
  return data
})
```

```vue [app/app.vue]
<script setup lang="ts">
// Type of `data` is inferred as
// {
//   createdAt: {
//     year: number
//     month: number
//     day: number
//   }
// }
const { data } = await useFetch('/api/bar')
</script>
```

### 대체 serializer 사용 %{#using-an-alternative-serializer}%

현재 Nuxt는 `JSON.stringify`를 대체하는 serializer를 지원하지 않습니다. 하지만 payload를 일반 문자열로 반환하고 `toJSON` 메서드를 활용해 타입 안전성을 유지할 수 있습니다.

아래 예시에서는 [superjson](https://github.com/flightcontrolhq/superjson)을 serializer로 사용합니다.

```ts [server/api/superjson.ts]
import superjson from 'superjson'

export default defineEventHandler(() => {
  const data = {
    createdAt: new Date(),

    // 타입 변환을 우회합니다
    toJSON () {
      return this
    },
  }

  // superjson을 사용해 출력을 문자열로 직렬화합니다
  return superjson.stringify(data) as unknown as typeof data
})
```

```vue [app/app.vue]
<script setup lang="ts">
import superjson from 'superjson'
```

### POST 요청으로 SSE(Server-Sent Events) 소비하기 %{#consuming-sse-server-sent-events-via-post-request}%

::tip
GET 요청으로 SSE를 소비하는 경우 [`EventSource`](https://developer.mozilla.org/en-US/docs/Web/API/EventSource) 또는 VueUse 컴포저블 [`useEventSource`](https://vueuse.org/core/useeventsource/)를 사용할 수 있습니다.
::

POST 요청으로 SSE를 소비할 때는 연결을 수동으로 처리해야 합니다. 다음과 같이 할 수 있습니다:

```ts
// SSE 엔드포인트에 POST 요청을 보냅니다
const response = await $fetch<ReadableStream>('/chats/ask-ai', {
  method: 'POST',
  body: {
    query: '안녕 AI, 잘 지내?',
  },
  responseType: 'stream',
})

// 데이터를 텍스트로 받기 위해 응답에서 TextDecoderStream을 사용해 새 ReadableStream을 생성합니다
const reader = response.pipeThrough(new TextDecoderStream()).getReader()

// 데이터 청크를 받는 즉시 읽습니다
while (true) {
  const { value, done } = await reader.read()

  if (done) { break }

  console.log('수신:', value)
}
```

### 병렬 요청 만들기 %{#making-parallel-requests}%

요청끼리 서로 의존하지 않는다면 `Promise.all()`로 병렬 실행해 성능을 높일 수 있습니다.

```ts
const { data } = await useAsyncData((_nuxtApp, { signal }) => {
  return Promise.all([
    $fetch('/api/comments/', { signal }),
    $fetch('/api/author/12', { signal }),
  ])
})

const comments = computed(() => data.value?.[0])
const author = computed(() => data.value?.[1])
```
