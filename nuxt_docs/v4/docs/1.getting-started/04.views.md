## `app.vue` %{#app-vue}%

![app.vue 파일은 애플리케이션의 진입점입니다](/assets/docs/getting-started/views/app.svg)

기본적으로 Nuxt는 이 파일을 **진입점**으로 간주하고 애플리케이션의 모든 라우트에 대해 그 내용을 렌더링합니다.

```vue [app/app.vue]
<template>
  <div>
    <h1>Welcome to the homepage</h1>
  </div>
</template>
```

::tip
Vue에 익숙하다면 `main.js`(보통 Vue 앱을 생성하는 파일)가 어디 있는지 궁금할 수 있습니다. Nuxt가 이 작업을 내부에서 처리합니다.
::

## 컴포넌트 %{#components}%

![컴포넌트는 재사용 가능한 UI 조각입니다](/assets/docs/getting-started/views/components.svg)

대부분의 컴포넌트는 버튼과 메뉴처럼 재사용 가능한 사용자 인터페이스 조각입니다. Nuxt에서는 이런 컴포넌트를 [`app/components/`](/docs/4.x/directory-structure/app/components) 디렉터리에 만들 수 있으며, 명시적으로 import하지 않아도 애플리케이션 전반에서 자동으로 사용할 수 있습니다.

::code-group

```vue [app/app.vue]
<template>
  <div>
    <h1>Welcome to the homepage</h1>
    <AppAlert>
      이것은 자동 import된 컴포넌트입니다.
    </AppAlert>
  </div>
</template>
```

```vue [app/components/AppAlert.vue]
<template>
  <span>
    <slot />
  </span>
</template>
```

::

## 페이지 %{#pages}%

![페이지는 특정 라우트에 연결된 뷰입니다](/assets/docs/getting-started/views/pages.svg)

페이지는 각각의 특정 라우트 패턴에 대한 뷰를 나타냅니다. [`app/pages/`](/docs/4.x/directory-structure/app/pages) 디렉터리의 각 파일은 자신의 콘텐츠를 표시하는 서로 다른 라우트를 나타냅니다.

페이지를 사용하려면 `app/pages/index.vue` 파일을 만들고 [`app/app.vue`](/docs/4.x/directory-structure/app/app)에 `<NuxtPage />` 컴포넌트를 추가하세요(또는 기본 진입점을 사용하려면 `app/app.vue`를 제거하세요). 이제 [`app/pages/`](/docs/4.x/directory-structure/app/pages) 디렉터리에 새 파일을 추가해 더 많은 페이지와 해당 라우트를 만들 수 있습니다.

::code-group

```vue [app/pages/index.vue]
<template>
  <div>
    <h1>Welcome to the homepage</h1>
    <AppAlert>
      이것은 자동 import된 컴포넌트입니다
    </AppAlert>
  </div>
</template>
```

```vue [app/pages/about.vue]
<template>
  <section>
    <p>이 페이지는 /about 라우트에서 표시됩니다.</p>
  </section>
</template>
```

::

## 레이아웃 %{#layouts}%

![레이아웃은 페이지를 감싸는 래퍼입니다](/assets/docs/getting-started/views/layouts.svg)

레이아웃은 헤더와 푸터 표시처럼 여러 페이지에서 공통으로 사용하는 사용자 인터페이스를 담고 있는 페이지 래퍼입니다. 레이아웃은 `<slot />` 컴포넌트를 사용해 **페이지** 콘텐츠를 표시하는 Vue 파일입니다. 기본적으로는 `app/layouts/default.vue` 파일이 사용됩니다. 사용자 정의 레이아웃은 페이지 메타데이터의 일부로 지정할 수 있습니다.

::note
애플리케이션에 레이아웃이 하나뿐이라면 [`<NuxtPage />`](/docs/4.x/api/components/nuxt-page)와 함께 [`app/app.vue`](/docs/4.x/directory-structure/app/app)를 사용하는 것을 권장합니다.
::

::code-group

```vue [app/app.vue]
<template>
  <div>
    <NuxtLayout>
      <NuxtPage />
    </NuxtLayout>
  </div>
</template>
```

```vue [app/layouts/default.vue]
<template>
  <div>
    <AppHeader />
    <slot />
    <AppFooter />
  </div>
</template>
```

```vue [app/pages/index.vue]
<template>
  <div>
    <h1>Welcome to the homepage</h1>
    <AppAlert>
      이것은 자동 import된 컴포넌트입니다
    </AppAlert>
  </div>
</template>
```

```vue [app/pages/about.vue]
<template>
  <section>
    <p>이 페이지는 /about 라우트에서 표시됩니다.</p>
  </section>
</template>
```

::

더 많은 레이아웃을 만들고 페이지에서 사용하는 방법을 배우고 싶다면 [레이아웃 섹션](/docs/4.x/directory-structure/app/layouts)에서 더 많은 정보를 확인하세요.

## 고급: HTML 템플릿 확장 %{#advanced-extending-the-html-template}%

::note
`<head>`만 수정하면 된다면 [SEO 및 메타 섹션](/docs/4.x/getting-started/seo-meta)을 참고하세요.
::

훅을 등록하는 Nitro 플러그인을 추가하면 HTML 템플릿을 완전히 제어할 수 있습니다.
`render:html` 훅의 콜백 함수는 HTML이 클라이언트에 전송되기 전에 이를 수정할 수 있게 해줍니다.

<!-- TODO: 다른 컨텍스트에 타입을 주입하도록 twoslash를 사용하는 방법 파악 -->

```ts [server/plugins/extend-html.ts]
import { definePlugin } from 'nitro'

export default definePlugin((nitroApp) => {
  nitroApp.hooks.hook('render:html', (html, { event }) => {
    // 이것은 html 템플릿의 객체 표현입니다.
    console.log(html)
    html.head.push(`<meta name="description" content="My custom description" />`)
  })
  // 여기에서 응답을 가로챌 수도 있습니다.
  nitroApp.hooks.hook('render:response', (response, { event }) => { console.log(response) })
})
```
