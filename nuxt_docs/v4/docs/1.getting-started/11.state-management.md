Nuxt는 [`useState`](/docs/4.x/api/composables/use-state) 컴포저블을 제공하여 컴포넌트 전반에 걸쳐 반응형이며 SSR에 친화적인 공유 상태를 생성할 수 있게 합니다.

[`useState`](/docs/4.x/api/composables/use-state)는 SSR에 친화적인 [`ref`](https://vuejs.org/api/reactivity-core#ref) 대체제입니다. 이 값은 서버 사이드 렌더링 이후(클라이언트 사이드 하이드레이션 동안)에도 보존되며, 고유한 키를 사용하는 모든 컴포넌트 간에 공유됩니다.

:video-accordion{title="Alexander Lichter가 useState를 왜, 언제 사용해야 하는지에 대해 설명하는 영상 보기" videoId="mv0WcBABcIk"}

::important
[`useState`](/docs/4.x/api/composables/use-state) 안의 데이터는 JSON으로 직렬화되므로, 클래스, 함수, 심볼과 같이 직렬화할 수 없는 것이 포함되지 않도록 하는 것이 중요합니다.
::

::read-more{to="/docs/4.x/api/composables/use-state"}
`useState` 컴포저블에 대해 더 읽어보세요.
::

## 모범 사례 %{best-practices}%

::warning
`<script setup>` 또는 `setup()` 함수 바깥에서 `const state = ref()`를 절대 정의하지 마세요.<br>
예를 들어, `export myState = ref({})`와 같이 하면 서버에서 요청 간에 상태가 공유되어 메모리 누수로 이어질 수 있습니다.
::

::tip{icon="i-lucide-circle-check"}
대신 `const useX = () => useState('x')`를 사용하세요.
::

## 예시 %{examples}%

### 기본 사용법 %{basic-usage}%

이 예시에서는 컴포넌트 로컬 카운터 상태를 사용합니다. `useState('counter')`를 사용하는 다른 모든 컴포넌트는 동일한 반응형 상태를 공유합니다.

```vue twoslash [app/app.vue]
<script setup lang="ts">
const counter = useState('counter', () => Math.round(Math.random() * 1000))
</script>

<template>
  <div>
    Counter: {{ counter }}
    <button @click="counter++">
      +
    </button>
    <button @click="counter--">
      -
    </button>
  </div>
</template>
```

:link-example{to="/docs/4.x/examples/features/state-management"}

::note
전역적으로 캐시된 상태를 무효화하려면 [`clearNuxtState`](/docs/4.x/api/utils/clear-nuxt-state) 유틸을 참고하세요.
::

### 상태 초기화 %{initializing-state}%

대부분의 경우, 비동기적으로 해결되는 데이터로 상태를 초기화하고 싶을 것입니다. 이를 위해 [`app.vue`](/docs/4.x/directory-structure/app/app) 컴포넌트와 [`callOnce`](/docs/4.x/api/utils/call-once) 유틸을 사용할 수 있습니다.

```vue twoslash [app/app.vue]
<script setup lang="ts">
const websiteConfig = useState('config')

await callOnce(async () => {
  websiteConfig.value = await $fetch('https://my-cms.com/api/website-config')
})
</script>
```

::tip
이는 Nuxt 2의 [`nuxtServerInit` 액션](https://v2.nuxt.com/docs/directory-structure/store/#the-nuxtserverinit-action)과 유사하며, 페이지를 렌더링하기 전에 서버 사이드에서 스토어의 초기 상태를 채울 수 있게 해줍니다.
::

:read-more{to="/docs/4.x/api/utils/call-once"}

### Pinia와 함께 사용하기 %{usage-with-pinia}%

이 예시에서는 [Pinia 모듈](/modules/pinia)을 활용하여 전역 스토어를 생성하고 앱 전반에서 이를 사용합니다.

::important
`npx nuxt module add pinia`로 Pinia 모듈을 설치했는지 확인하거나, [모듈 설치 단계](https://pinia.vuejs.org/ssr/nuxt.html#Installation)를 따르세요.
::

::code-group
```ts [app/stores/website.ts]
export const useWebsiteStore = defineStore('websiteStore', {
  state: () => ({
    name: '',
    description: '',
  }),
  actions: {
    async fetch () {
      const infos = await $fetch('https://api.nuxt.com/modules/pinia')

      this.name = infos.name
      this.description = infos.description
    },
  },
})
```
```vue [app/app.vue]
<script setup lang="ts">
const website = useWebsiteStore()

await callOnce(website.fetch)
</script>

<template>
  <main>
    <h1>{{ website.name }}</h1>
    <p>{{ website.description }}</p>
  </main>
</template>
```
::

## 고급 사용법 %{advanced-usage}%

::code-group
```ts [app/composables/locale.ts]
import type { Ref } from 'vue'

export const useLocale = () => {
  return useState<string>('locale', () => useDefaultLocale().value)
}

export const useDefaultLocale = (fallback = 'en-US') => {
  const locale = ref(fallback)
  if (import.meta.server) {
    const reqLocale = useRequestHeaders()['accept-language']?.split(',')[0]
    if (reqLocale) {
      locale.value = reqLocale
    }
  } else if (import.meta.client) {
    const navLang = navigator.language
    if (navLang) {
      locale.value = navLang
    }
  }
  return locale
}

export const useLocales = () => {
  const locale = useLocale()
  const locales = ref([
    'en-US',
    'en-GB',
    // ...,
    'ja-JP-u-ca-japanese',
  ])
  if (!locales.value.includes(locale.value)) {
    locales.value.unshift(locale.value)
  }
  return locales
}

export const useLocaleDate = (date: Ref<Date> | Date, locale = useLocale()) => {
  return computed(() => new Intl.DateTimeFormat(locale.value, { dateStyle: 'full' }).format(unref(date)))
}
```

```vue [app/app.vue]
<script setup lang="ts">
const locales = useLocales()
const locale = useLocale()
const date = useLocaleDate(new Date('2016-10-26'))
</script>

<template>
  <div>
    <h1>Nuxt birthday</h1>
    <p>{{ date }}</p>
    <label for="locale-chooser">Preview a different locale</label>
    <select
      id="locale-chooser"
      v-model="locale"
    >
      <option
        v-for="loc of locales"
        :key="loc"
        :value="loc"
      >
        {{ loc }}
      </option>
    </select>
  </div>
</template>
```
::

## 공유 상태 %{shared-state}%

[자동 임포트되는 컴포저블](/docs/4.x/directory-structure/app/composables)을 사용하면 전역 타입 안전 상태를 정의하고 앱 전반에서 이를 임포트하여 사용할 수 있습니다.

```ts twoslash [composables/states.ts]
export const useColor = () => useState<string>('color', () => 'pink')
```

```vue [app/app.vue]
<script setup lang="ts">
// ---cut-start---
const useColor = () => useState<string>('color', () => 'pink')
// ---cut-end---
const color = useColor() // useState('color')와 동일
</script>

<template>
  <p>Current color: {{ color }}</p>
</template>
```

## 서드파티 라이브러리 사용하기 %{using-third-party-libraries}%

Nuxt는 전역 상태 관리를 제공하기 위해 **과거에는** Vuex 라이브러리에 의존했습니다. Nuxt 2에서 마이그레이션하는 경우, [마이그레이션 가이드](/docs/4.x/migration/configuration#vuex)를 참고하세요.

Nuxt는 상태 관리에 대해 의견을 강하게 두지 않으므로, 필요에 맞는 적절한 솔루션을 자유롭게 선택할 수 있습니다. 가장 인기 있는 상태 관리 라이브러리와의 여러 통합이 제공되며, 여기에는 다음이 포함됩니다.

- [Pinia](/modules/pinia) - 공식 Vue 권장 사항
- [Harlem](/modules/harlem) - 불변 전역 상태 관리
- [XState](/modules/xstate) - 상태 로직을 시각화하고 테스트하기 위한 도구를 제공하는 상태 머신 접근 방식
