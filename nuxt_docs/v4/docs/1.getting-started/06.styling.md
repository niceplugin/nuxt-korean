Nuxt는 스타일링 측면에서 매우 유연합니다. 직접 스타일을 작성하거나 로컬 및 외부 스타일시트를 참조할 수 있습니다.
CSS 전처리기, CSS 프레임워크, UI 라이브러리, Nuxt 모듈을 사용해 애플리케이션을 스타일링할 수 있습니다.

## 로컬 스타일시트 %{#local-stylesheets}%

로컬 스타일시트를 작성한다면 자연스러운 위치는 [`app/assets/` 디렉터리](/docs/4.x/directory-structure/app/assets)입니다.

### 컴포넌트 내부에서 가져오기 %{#importing-within-components}%

페이지, 레이아웃, 컴포넌트에서 스타일시트를 직접 가져올 수 있습니다.
JavaScript import나 CSS [`@import` 구문](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@import)을 사용할 수 있습니다.

```vue [app/pages/index.vue]
<script>
// 서버 사이드 호환성을 위해 정적 import를 사용합니다
import '~/assets/css/first.css'

// 주의: 동적 import는 서버 사이드와 호환되지 않습니다
import('~/assets/css/first.css')
</script>

<style>
@import url("~/assets/css/second.css");
</style>
```

::tip
스타일시트는 Nuxt가 렌더링한 HTML에 인라인으로 포함됩니다.
::

### CSS 속성 %{#the-css-property}%

Nuxt 설정의 `css` 속성도 사용할 수 있습니다.
스타일시트를 두기 좋은 위치는 [`app/assets/` 디렉터리](/docs/4.x/directory-structure/app/assets)입니다. 그런 다음 해당 경로를 참조하면 Nuxt가 애플리케이션의 모든 페이지에 이를 포함합니다.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  css: ['~/assets/css/main.css'],
})
```

::tip
스타일시트는 Nuxt가 렌더링한 HTML에 인라인으로 포함되고, 전역으로 주입되며, 모든 페이지에 적용됩니다.
::

### 폰트 다루기 %{#working-with-fonts}%

로컬 폰트 파일은 `public/` 디렉터리(예: `public/fonts`)에 두세요. 그런 다음 스타일시트에서 `url()`을 사용해 이를 참조할 수 있습니다.

```css [assets/css/main.css]
@font-face {
  font-family: 'FarAwayGalaxy';
  src: url('/fonts/FarAwayGalaxy.woff') format('woff');
  font-weight: normal;
  font-style: normal;
  font-display: swap;
}
```

그런 다음 스타일시트, 페이지, 컴포넌트에서 이름으로 폰트를 참조하세요:

```vue
<style>
h1 {
  font-family: 'FarAwayGalaxy', sans-serif;
}
</style>
```

### NPM으로 배포되는 스타일시트 %{#stylesheets-distributed-through-npm}%

npm을 통해 배포되는 스타일시트도 참조할 수 있습니다. 인기 있는 `animate.css` 라이브러리를 예로 들어 보겠습니다.

::code-group{sync="pm"}

```bash [npm]
npm install animate.css
```

```bash [yarn]
yarn add animate.css
```

```bash [pnpm]
pnpm install animate.css
```

```bash [bun]
bun install animate.css
```

```bash [deno]
deno install npm:animate.css
```

::

그런 다음 페이지, 레이아웃, 컴포넌트에서 직접 참조할 수 있습니다:

```vue [app/app.vue]
<script>
import 'animate.css'
</script>

<style>
@import url("animate.css");
</style>
```

이 패키지는 Nuxt 설정의 css 속성에서 문자열로도 참조할 수 있습니다.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  css: ['animate.css'],
})
```

## 외부 스타일시트 %{#external-stylesheets}%

nuxt.config 파일의 head 섹션에 link 요소를 추가하면 애플리케이션에 외부 스타일시트를 포함할 수 있습니다. 이 결과는 여러 방법으로 얻을 수 있습니다. 로컬 스타일시트도 같은 방식으로 포함할 수 있다는 점에 유의하세요.

Nuxt 설정의 [`app.head`](/docs/4.x/api/nuxt-config#head) 속성으로 head를 조작할 수 있습니다:

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  app: {
    head: {
      link: [{ rel: 'stylesheet', href: 'https://cdnjs.cloudflare.com/ajax/libs/animate.css/4.1.1/animate.min.css' }],
    },
  },
})
```

### 동적으로 스타일시트 추가하기 %{#dynamically-adding-stylesheets}%

코드에서 useHead 컴포저블을 사용해 head 값을 동적으로 설정할 수 있습니다.

:read-more{to="/docs/4.x/api/composables/use-head"}

```ts twoslash
useHead({
  link: [{ rel: 'stylesheet', href: 'https://cdnjs.cloudflare.com/ajax/libs/animate.css/4.1.1/animate.min.css' }],
})
```

Nuxt는 내부적으로 `unhead`를 사용하며, 자세한 내용은 [공식 문서](https://unhead.unjs.io)를 참고할 수 있습니다.

### Nitro 플러그인으로 렌더링된 Head 수정하기 %{#modifying-the-rendered-head-with-a-nitro-plugin}%

더 고급 제어가 필요하다면 훅으로 렌더링된 html을 가로채고 head를 프로그래밍 방식으로 수정할 수 있습니다.

다음과 같이 `~~/server/plugins/my-plugin.ts`에 플러그인을 만드세요:

<!-- TODO: 다른 컨텍스트에 타입을 주입하기 위해 twoslash를 사용하는 방법 확인 -->

```ts [server/plugins/my-plugin.ts]
import { definePlugin } from 'nitro'

export default definePlugin((nitro) => {
  nitro.hooks.hook('render:html', (html) => {
    html.head.push('<link rel="stylesheet" href="https://cdnjs.cloudflare.com/ajax/libs/animate.css/4.1.1/animate.min.css">')
  })
})
```

외부 스타일시트는 렌더링 차단 리소스입니다. 브라우저가 페이지를 렌더링하기 전에 반드시 로드되고 처리되어야 합니다. 불필요하게 큰 스타일을 포함한 웹 페이지는 렌더링 시간이 더 오래 걸립니다. 자세한 내용은 [web.dev](https://web.dev/articles/defer-non-critical-css)에서 확인할 수 있습니다.

## 전처리기 사용하기 %{#using-preprocessors}%

SCSS, Sass, Less, Stylus 같은 전처리기를 사용하려면 먼저 설치하세요.

::code-group

```bash [Sass & SCSS]
npm install -D sass
```

```bash [Less]
npm install -D less
```

```bash [Stylus]
npm install -D stylus
```

::

스타일시트를 작성하기 좋은 위치는 `app/assets` 디렉터리입니다.
그런 다음 전처리기 문법을 사용해 `app.vue`(또는 레이아웃 파일)에서 소스 파일을 가져올 수 있습니다.

```vue [app/pages/app.vue]
<style lang="scss">
@use "~/assets/scss/main.scss";
</style>
```

또는 Nuxt 설정의 `css` 속성을 사용할 수 있습니다.

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  css: ['~/assets/scss/main.scss'],
})
```

::tip
두 경우 모두 컴파일된 스타일시트는 Nuxt가 렌더링한 HTML에 인라인으로 포함됩니다.
::

색상 변수가 들어 있는 [Sass partial](https://sass-lang.com/documentation/at-rules/use/#partials)처럼 전처리된 파일에 코드를 주입해야 한다면, Vite의 [preprocessors options](https://vite.dev/config/shared-options#css-preprocessoroptions)로 처리할 수 있습니다.

`app/assets` 디렉터리에 partial 파일을 몇 개 만드세요:

::code-group{sync="preprocessor"}

```scss [assets/_colors.scss]
$primary: #49240F;
$secondary: #E4A79D;
```

```sass [assets/_colors.sass]
$primary: #49240F
$secondary: #E4A79D
```

::

그런 다음 `nuxt.config`에서:

::code-group

```ts twoslash [SCSS]
export default defineNuxtConfig({
  vite: {
    css: {
      preprocessorOptions: {
        scss: {
          additionalData: '@use "~/assets/_colors.scss" as *;',
        },
      },
    },
  },
})
```

```ts twoslash [SASS]
export default defineNuxtConfig({
  vite: {
    css: {
      preprocessorOptions: {
        sass: {
          additionalData: '@use "~/assets/_colors.sass" as *\n',
        },
      },
    },
  },
})
```

::

Nuxt는 기본적으로 Vite를 사용합니다. 대신 webpack을 사용하려면 각 전처리기 로더의 [문서](https://webpack.js.org/loaders/sass-loader/)를 참고하세요.

### 전처리기 워커(실험적) %{#preprocessor-workers-experimental}%

Vite는 전처리기 사용 속도를 높일 수 있는 [실험적 옵션](https://vite.dev/config/shared-options#css-preprocessormaxworkers)을 제공합니다.

`nuxt.config`에서 이를 활성화할 수 있습니다:

```ts
export default defineNuxtConfig({
  vite: {
    css: {
      preprocessorMaxWorkers: true, // CPU 개수에서 1을 뺀 값
    },
  },
})
```

::note
이 옵션은 실험적 기능이므로 Vite 문서를 참고하고 [피드백을 제공](https://github.com/vitejs/vite/discussions/15835)해야 합니다.
::

## 단일 파일 컴포넌트(SFC) 스타일링 %{#single-file-components-sfc-styling}%

Vue와 SFC의 가장 큰 장점 중 하나는 스타일링을 자연스럽게 다룬다는 점입니다. 컴포넌트 파일의 style 블록에 CSS나 전처리기 코드를 직접 작성할 수 있으므로 CSS-in-JS 같은 것을 사용하지 않아도 훌륭한 개발 경험을 얻을 수 있습니다. 물론 CSS-in-JS를 사용하고 싶다면 [pinceau](https://github.com/Tahul/pinceau)처럼 이를 지원하는 서드파티 라이브러리와 모듈을 찾을 수 있습니다.

SFC에서 컴포넌트를 스타일링하는 포괄적인 참고 자료는 [Vue 문서](https://vuejs.org/api/sfc-css-features)를 확인하세요.

### 클래스와 스타일 바인딩 %{#class-and-style-bindings}%

Vue SFC 기능을 활용하면 class와 style 속성으로 컴포넌트를 스타일링할 수 있습니다.

::code-group

```vue [Ref and Reactive]
<script setup lang="ts">
const isActive = ref(true)
const hasError = ref(false)
const classObject = reactive({
  'active': true,
  'text-danger': false,
})
</script>

<template>
  <div
    class="static"
    :class="{ 'active': isActive, 'text-danger': hasError }"
  />
  <div :class="classObject" />
</template>
```

```vue [Computed]
<script setup lang="ts">
const isActive = ref(true)
const error = ref(null)

const classObject = computed(() => ({
  'active': isActive.value && !error.value,
  'text-danger': error.value && error.value.type === 'fatal',
}))
</script>

<template>
  <div :class="classObject" />
</template>
```

```vue [Array]
<script setup lang="ts">
const isActive = ref(true)
const errorClass = ref('text-danger')
</script>

<template>
  <div :class="[{ active: isActive }, errorClass]" />
</template>
```

```vue [Style]
<script setup lang="ts">
const activeColor = ref('red')
const fontSize = ref(30)
const styleObject = reactive({ color: 'red', fontSize: '13px' })
</script>

<template>
  <div :style="{ color: activeColor, fontSize: fontSize + 'px' }" />
  <div :style="[baseStyles, overridingStyles]" />
  <div :style="styleObject" />
</template>
```

::

자세한 내용은 [Vue 문서](https://vuejs.org/guide/essentials/class-and-style)를 참고하세요.

### `v-bind`로 동적 스타일링 %{#dynamic-styles-with-v-bind}%

v-bind 함수를 사용하면 style 블록 안에서 JavaScript 변수와 표현식을 참조할 수 있습니다.
이 바인딩은 동적으로 동작하므로 변수 값이 바뀌면 스타일도 함께 업데이트됩니다.

```vue
<script setup lang="ts">
const color = ref('red')
</script>

<template>
  <div class="text">
    안녕하세요
  </div>
</template>

<style>
.text {
  color: v-bind(color);
}
</style>
```

### 스코프 스타일 %{#scoped-styles}%

scoped 속성을 사용하면 컴포넌트를 독립적으로 스타일링할 수 있습니다. 이 속성으로 선언한 스타일은 해당 컴포넌트에만 적용됩니다.

```vue
<template>
  <div class="example">
    안녕
  </div>
</template>

<style scoped>
.example {
  color: red;
}
</style>
```

### CSS 모듈 %{#css-modules}%

module 속성과 함께 [CSS Modules](https://github.com/css-modules/css-modules)를 사용할 수 있습니다. 주입된 `$style` 변수로 접근하세요.

```vue
<template>
  <p :class="$style.red">
    이 텍스트는 빨간색이어야 합니다
  </p>
</template>

<style module>
.red {
  color: red;
}
</style>
```

### 전처리기 지원 %{#preprocessors-support}%

SFC style 블록은 전처리기 문법을 지원합니다. Vite는 별도 설정 없이 .scss, .sass, .less, .styl, .stylus 파일을 기본 지원합니다. 먼저 설치만 하면 lang 속성으로 SFC에서 바로 사용할 수 있습니다.

::code-group

```vue [SCSS]
<style lang="scss">
  /* 여기에 scss를 작성하세요 */
</style>
```

```vue [Sass]
<style lang="sass">
  /* 여기에 sass를 작성하세요 */
</style>
```

```vue [LESS]
<style lang="less">
  /* 여기에 less를 작성하세요 */
</style>
```

```vue [Stylus]
<style lang="stylus">
  /* 여기에 stylus를 작성하세요 */
</style>
```

::

자세한 내용은 [Vite CSS 문서](https://vite.dev/guide/features#css)와 [@vitejs/plugin-vue 문서](https://github.com/vitejs/vite-plugin-vue/tree/main/packages/plugin-vue)를 참고하세요.
webpack 사용자는 [vue loader 문서](https://vue-loader.vuejs.org)를 참고하세요.

## PostCSS 사용하기 %{#using-postcss}%

Nuxt에는 postcss가 기본 내장되어 있습니다. `nuxt.config` 파일에서 이를 설정할 수 있습니다.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  postcss: {
    plugins: {
      'postcss-nested': {},
      'postcss-custom-media': {},
    },
  },
})
```

SFC에서 올바른 구문 강조를 위해 postcss lang 속성을 사용할 수 있습니다.

```vue
<style lang="postcss">
  /* 여기에 postcss를 작성하세요 */
</style>
```

기본적으로 Nuxt에는 다음 플러그인이 이미 사전 설정되어 있습니다:

- [postcss-import](https://github.com/postcss/postcss-import): `@import` 규칙을 개선합니다
- [postcss-url](https://github.com/postcss/postcss-url): `url()` 구문을 변환합니다
- [autoprefixer](https://github.com/postcss/autoprefixer): 벤더 프리픽스를 자동으로 추가합니다
- [cssnano](https://cssnano.github.io/cssnano/): 최소화 및 제거를 수행합니다

## 여러 스타일에 레이아웃 활용하기 %{#leveraging-layouts-for-multiple-styles}%

애플리케이션의 서로 다른 부분을 완전히 다르게 스타일링해야 한다면 레이아웃을 사용할 수 있습니다.
레이아웃마다 다른 스타일을 적용하세요.

```vue
<template>
  <div class="default-layout">
    <h1>기본 레이아웃</h1>
    <slot />
  </div>
</template>

<style>
.default-layout {
  color: red;
}
</style>
```

:read-more{to="/docs/4.x/directory-structure/app/layouts"}

## 서드파티 라이브러리와 모듈 %{#third-party-libraries-and-modules}%

Nuxt는 스타일링 방식에 대해 특정한 견해를 강요하지 않으며, 매우 다양한 선택지를 제공합니다. [UnoCSS](https://unocss.dev)나 [Tailwind CSS](https://tailwindcss.com) 같은 인기 라이브러리를 포함해 원하는 어떤 스타일링 도구든 사용할 수 있습니다.

커뮤니티와 Nuxt 팀은 통합을 더 쉽게 만들기 위해 많은 Nuxt 모듈을 개발했습니다.
웹사이트의 [modules 섹션](/modules)에서 이를 찾아볼 수 있습니다.
시작에 도움이 되는 몇 가지 모듈은 다음과 같습니다:

- [UnoCSS](/modules/unocss): 즉시 사용 가능한 온디맨드 원자적 CSS 엔진
- [Tailwind CSS](/modules/tailwindcss): 유틸리티 우선 CSS 프레임워크
- [Fontaine](https://github.com/nuxt-modules/fontaine): 폰트 메트릭 폴백
- [Pinceau](https://github.com/Tahul/pinceau): 유연한 스타일링 프레임워크
- [Nuxt UI](https://ui.nuxt.com): 현대적인 웹 앱을 위한 UI 라이브러리
- [Panda CSS](https://panda-css.com/docs/installation/nuxt): 빌드 시 원자적 CSS를 생성하는 CSS-in-JS 엔진

Nuxt 모듈은 별도 작업 없이도 좋은 개발 경험을 제공하지만, 좋아하는 도구에 전용 모듈이 없다고 해서 Nuxt와 함께 사용할 수 없는 것은 아닙니다. 자신의 프로젝트에 맞게 직접 설정할 수 있습니다. 도구에 따라 [Nuxt 플러그인](/docs/4.x/directory-structure/app/plugins)을 사용하거나 [직접 모듈을 만들어야](/docs/4.x/guide/modules) 할 수도 있습니다. 그렇게 했다면 [커뮤니티](/modules)와 공유해 보세요.

### 웹폰트 손쉽게 불러오기 %{#easily-load-webfonts}%

[Nuxt Google Fonts 모듈](https://github.com/nuxt-modules/google-fonts)을 사용해 Google Fonts를 불러올 수 있습니다.

[UnoCSS](https://unocss.dev/integrations/nuxt)를 사용 중이라면, Google Fonts를 포함한 일반적인 공급자의 폰트를 편리하게 불러올 수 있는 [web fonts presets](https://unocss.dev/presets/web-fonts)가 함께 제공된다는 점을 참고하세요.

### LCP 고급 최적화 %{#lcp-advanced-optimizations}%

전역 CSS 파일의 다운로드 속도를 높이려면 다음을 수행할 수 있습니다:

- CDN을 사용해 파일을 사용자와 물리적으로 더 가깝게 배치합니다
- 가능하면 Brotli를 사용해 에셋을 압축합니다
- 전송에 HTTP2/HTTP3를 사용합니다
- 에셋을 동일한 도메인에서 호스팅합니다(다른 서브도메인을 사용하지 않음)

Cloudflare, Netlify, Vercel 같은 최신 플랫폼을 사용한다면 이 대부분은 자동으로 처리됩니다.
[web.dev](https://web.dev/articles/optimize-lcp)에서 LCP 최적화 가이드를 확인할 수 있습니다.

모든 CSS가 Nuxt에 의해 인라인 처리된다면, 실험적으로 렌더링된 HTML에서 외부 CSS 파일 참조를 완전히 중지할 수 있습니다.
이 작업은 모듈이나 Nuxt 설정 파일에 둘 수 있는 훅으로 구현할 수 있습니다.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  hooks: {
    'build:manifest': (manifest) => {
      // 앱 엔트리와 css 목록 찾기
      const css = Object.values(manifest).find(options => options.isEntry)?.css
      if (css) {
        // 배열 끝에서 시작해 앞으로 이동합니다
        for (let i = css.length - 1; i >= 0; i--) {
          // 'entry'로 시작하면 목록에서 제거합니다
          if (css[i].startsWith('entry')) {
            css.splice(i, 1)
          }
        }
      }
    },
  },
})
```
