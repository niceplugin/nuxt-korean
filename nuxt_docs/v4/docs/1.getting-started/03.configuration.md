기본적으로 Nuxt는 대부분의 사용 사례를 포괄하도록 구성되어 있습니다. [`nuxt.config.ts`](/docs/4.x/directory-structure/nuxt-config) 파일로 이 기본 구성을 재정의하거나 확장할 수 있습니다.

## Nuxt 구성 %{#nuxt-configuration}%

[`nuxt.config.ts`](/docs/4.x/directory-structure/nuxt-config) 파일은 Nuxt 프로젝트의 루트에 위치하며, 애플리케이션 동작을 재정의하거나 확장할 수 있습니다.

최소 구성 파일은 설정 객체를 담은 `defineNuxtConfig` 함수를 export합니다. `defineNuxtConfig` 헬퍼는 import 없이 전역에서 사용할 수 있습니다.

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  // 내 Nuxt 구성
})
```

이 파일은 사용자 정의 스크립트 추가, 모듈 등록, 렌더링 모드 변경 등과 관련해 문서에서 자주 언급됩니다.

::read-more{to="/docs/4.x/api/configuration/nuxt-config"}
모든 옵션은 **구성 레퍼런스**에 설명되어 있습니다.
::

::note
Nuxt로 애플리케이션을 만들 때 TypeScript를 반드시 사용할 필요는 없습니다. 하지만 `nuxt.config` 파일에는 `.ts` 확장자를 사용하는 것을 강력히 권장합니다. 이렇게 하면 IDE의 힌트를 활용해 구성 편집 중 오타와 실수를 줄일 수 있습니다.
::

### 환경별 재정의 %{#environment-overrides}%

`nuxt.config`에서 완전히 타입이 지정된 환경별 재정의를 구성할 수 있습니다.

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  $production: {
    routeRules: {
      '/**': { isr: true },
    },
  },
  $development: {
    //
  },
  $env: {
    staging: {
      //
    },
  },
})
```

Nuxt CLI 명령을 실행할 때 환경을 선택하려면 `--envName` 플래그에 이름을 전달하면 됩니다. 예: `nuxt build --envName staging`.

이 재정의가 동작하는 메커니즘을 더 알고 싶다면, `c12` 문서의 [환경별 구성](https://github.com/unjs/c12?tab=readme-ov-file#environment-specific-configuration)을 참고하세요.

:video-accordion{title="Alexander Lichter의 env-aware nuxt.config.ts 영상 보기" videoId="DFZI2iVCrNc"}

::note
레이어를 작성하고 있다면, 본인이나 레이어 사용자가 활용할 수 있는 메타데이터를 제공하기 위해 `$meta` 키도 사용할 수 있습니다.
::

### 환경 변수와 비공개 토큰 %{#environment-variables-and-private-tokens}%

`runtimeConfig` API는 환경 변수와 같은 값을 애플리케이션의 다른 부분에 노출합니다. 기본적으로 이 키는 서버 측에서만 사용할 수 있습니다. `runtimeConfig.public`과 `runtimeConfig.app`(Nuxt 내부에서 사용됨) 안의 키는 클라이언트 측에서도 사용할 수 있습니다.

이 값들은 `nuxt.config`에 정의해야 하며 환경 변수로 재정의할 수 있습니다.

::code-group

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    // 서버 측에서만 사용할 수 있는 비공개 키
    apiSecret: '123',
    // public 내부의 키는 클라이언트 측에도 노출됩니다
    public: {
      apiBase: '/api',
    },
  },
})
```

```ini [.env]
# apiSecret 값을 재정의합니다
NUXT_API_SECRET=api_secret_token
```

::

이 변수들은 [`useRuntimeConfig()`](/docs/4.x/api/composables/use-runtime-config) 컴포저블을 통해 애플리케이션의 다른 부분에 노출됩니다.

```vue [app/pages/index.vue]
<script setup lang="ts">
const runtimeConfig = useRuntimeConfig()
</script>
```

:read-more{to="/docs/4.x/guide/going-further/runtime-config"}

## 앱 구성 %{#app-configuration}%

소스 디렉터리(기본값은 `app/`)에 있는 `app.config.ts` 파일은 빌드 시점에 결정할 수 있는 공개 변수를 노출하는 데 사용됩니다. `runtimeConfig` 옵션과 달리, 이 값들은 환경 변수로 재정의할 수 없습니다.

최소 구성 파일은 설정 객체를 담은 `defineAppConfig` 함수를 export합니다. `defineAppConfig` 헬퍼는 import 없이 전역에서 사용할 수 있습니다.

```ts [app/app.config.ts]
export default defineAppConfig({
  title: 'Hello Nuxt',
  theme: {
    dark: true,
    colors: {
      primary: '#ff0000',
    },
  },
})
```

이 변수들은 [`useAppConfig`](/docs/4.x/api/composables/use-app-config) 컴포저블을 통해 애플리케이션의 다른 부분에 노출됩니다.

```vue [app/pages/index.vue]
<script setup lang="ts">
const appConfig = useAppConfig()
</script>
```

:read-more{to="/docs/4.x/directory-structure/app/app-config"}

## `runtimeConfig` 대 `app.config` %{#runtimeconfig-vs-app-config}%

위에서 설명했듯이 `runtimeConfig`와 `app.config`는 모두 애플리케이션의 다른 부분에 변수를 노출하는 데 사용됩니다. 어느 쪽을 사용해야 할지 판단하는 데 도움이 되는 가이드는 다음과 같습니다.

- `runtimeConfig`: 빌드 후 환경 변수로 지정해야 하는 비공개 또는 공개 토큰
- `app.config`: 빌드 시점에 결정되는 공개 토큰, 테마 변형이나 제목 같은 웹사이트 설정, 그리고 민감하지 않은 프로젝트 구성

| Feature                   | `runtimeConfig` | `app.config` |
|---------------------------|-----------------|--------------|
| 클라이언트 측             | Hydrated        | Bundled      |
| 환경 변수                 | ✅ Yes           | ❌ No         |
| 반응성                    | ✅ Yes           | ✅ Yes        |
| 타입 지원                 | ✅ Partial       | ✅ Yes        |
| 요청별 구성               | ❌ No            | ✅ Yes        |
| 핫 모듈 교체              | ❌ No            | ✅ Yes        |
| 원시형이 아닌 JS 타입     | ❌ No            | ✅ Yes        |

## 외부 구성 파일 %{#external-configuration-files}%

Nuxt는 [`nuxt.config.ts`](/docs/4.x/directory-structure/nuxt-config) 파일을 구성의 단일 진실 공급원으로 사용하며 외부 구성 파일은 읽지 않습니다. 프로젝트를 구축하는 과정에서 이런 구성들을 설정해야 할 수 있습니다. 아래 표는 일반적인 구성과, 가능할 경우 Nuxt에서 이를 어떻게 설정할 수 있는지를 보여줍니다.

| Name                              | Config File             | How To Configure                                                          |
|-----------------------------------|-------------------------|---------------------------------------------------------------------------|
| [Nitro](https://nitro.build)      | ~~`nitro.config.ts`~~   | `nuxt.config`의 [`nitro`](/docs/4.x/api/nuxt-config#nitro) 키 사용       |
| [PostCSS](https://postcss.org)    | ~~`postcss.config.js`~~ | `nuxt.config`의 [`postcss`](/docs/4.x/api/nuxt-config#postcss) 키 사용   |
| [Vite](https://vite.dev)          | ~~`vite.config.ts`~~    | `nuxt.config`의 [`vite`](/docs/4.x/api/nuxt-config#vite) 키 사용         |
| [webpack](https://webpack.js.org) | ~~`webpack.config.ts`~~ | `nuxt.config`의 [`webpack`](/docs/4.x/api/nuxt-config#webpack-1) 키 사용 |

## Vue 구성 %{#vue-configuration}%

### Vite와 함께 사용 %{#with-vite}%

`@vitejs/plugin-vue` 또는 `@vitejs/plugin-vue-jsx`에 옵션을 전달해야 한다면 `nuxt.config` 파일에서 설정할 수 있습니다.

- `@vitejs/plugin-vue`에는 `vite.vue`를 사용합니다. [사용 가능한 옵션](https://github.com/vitejs/vite-plugin-vue/tree/main/packages/plugin-vue)을 확인하세요.
- `@vitejs/plugin-vue-jsx`에는 `vite.vueJsx`를 사용합니다. [사용 가능한 옵션](https://github.com/vitejs/vite-plugin-vue/tree/main/packages/plugin-vue-jsx)을 확인하세요.

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  vite: {
    vue: {
      customElement: true,
    },
    vueJsx: {
      mergeProps: true,
    },
  },
})
```

:read-more{to="/docs/4.x/api/configuration/nuxt-config#vue"}

### webpack과 함께 사용 %{#with-webpack}%

webpack을 사용하고 `vue-loader`를 구성해야 한다면 `nuxt.config` 파일 안의 `webpack.loaders.vue` 키를 사용하면 됩니다. 사용 가능한 옵션은 [여기](https://github.com/vuejs/vue-loader/blob/main/src/index.ts#L32-L62)에 정의되어 있습니다.

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  webpack: {
    loaders: {
      vue: {
        hotReload: true,
      },
    },
  },
})
```

:read-more{to="/docs/4.x/api/configuration/nuxt-config#loaders"}

### 실험적 Vue 기능 활성화 %{#enabling-experimental-vue-features}%

`propsDestructure` 같은 실험적 Vue 기능을 활성화해야 할 수 있습니다. 어떤 빌더를 사용하든 Nuxt는 `nuxt.config.ts`에서 이를 쉽게 설정할 수 있게 해줍니다.

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  vue: {
    propsDestructure: true,
  },
})
```
