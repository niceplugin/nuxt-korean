[일반 기여 가이드](/docs/4.x/community/contribution)를 읽었다면, 이제 [`nuxt/nuxt`](https://github.com/nuxt/nuxt) 저장소 기여에 관한 몇 가지 구체적인 사항을 살펴보세요.

## 모노레포 가이드 %{#monorepo-guide}%

- `packages/kit`: Nuxt 모듈 작성을 위한 툴킷이며 [`@nuxt/kit`](https://www.npmjs.com/package/@nuxt/kit)으로 배포됩니다.
- `packages/nuxt`: Nuxt의 핵심이며 [`nuxt`](https://www.npmjs.com/package/nuxt)로 배포됩니다.
- `packages/schema`: 버전 간 Nuxt 타입 정의와 기본값이며 [`@nuxt/schema`](https://www.npmjs.com/package/@nuxt/schema)로 배포됩니다.
- `packages/rspack`: Nuxt용 [Rspack](https://rspack.rs) 번들러이며 [`@nuxt/rspack-builder`](https://www.npmjs.com/package/@nuxt/rspack-builder)로 배포됩니다.
- `packages/vite`: Nuxt용 [Vite](https://vite.dev) 번들러이며 [`@nuxt/vite-builder`](https://www.npmjs.com/package/@nuxt/vite-builder)로 배포됩니다.
- `packages/webpack`: Nuxt용 [webpack](https://webpack.js.org) 번들러이며 [`@nuxt/webpack-builder`](https://www.npmjs.com/package/@nuxt/webpack-builder)로 배포됩니다.

## Setup %{#setup}%

Nuxt에 기여하려면 로컬 환경을 설정해야 합니다.

1. [`nuxt/nuxt`](https://github.com/nuxt/nuxt) 저장소를 자신의 GitHub 계정으로 [fork](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/working-with-forks/fork-a-repo)한 다음 로컬 장치에 [clone](https://docs.github.com/en/repositories/creating-and-managing-repositories/cloning-a-repository)하세요.
2. 최신 [Node.js](https://nodejs.org/en)를 사용하고 있는지 확인하세요
3. `pnpm`과 `yarn`을 사용하기 위해 [Corepack](https://github.com/nodejs/corepack)을 활성화하세요
    ```bash [Terminal]
    corepack enable
    ```
4. `pnpm install --frozen-lockfile`을 실행해 pnpm으로 의존성을 설치하세요:
    ```bash [Terminal]
    pnpm install --frozen-lockfile
    ```
    ::note
    의존성을 추가하는 경우 `pnpm add`를 사용하세요. :br
    `pnpm-lock.yaml` 파일은 모든 Nuxt 의존성의 기준 정보입니다.
    ::
5. passive development system을 활성화하세요
    ```bash [Terminal]
    pnpm dev:prepare
    ```
6. 작업하고 변경 사항을 커밋할 브랜치를 체크아웃하세요:
    ```bash [Terminal]
    git checkout -b my-new-branch
    ```

그런 다음 pull request를 제출하기 전에 [playground](/docs/4.x/community/framework-contribution#playground)에서 변경 사항을 확인하고 [테스트](/docs/4.x/community/framework-contribution#testing)하세요.

### Playground %{#playground}%

pull request 작업 중에는 변경 사항이 올바르게 동작하는지 확인하고 싶을 가능성이 높습니다.

`playground/`의 예제 앱을 수정한 뒤 다음을 실행할 수 있습니다:

```bash [Terminal]
pnpm dev
```

::important
이를 브랜치에 커밋하지 않도록 주의하세요. 다만 PR 설명에 예제 코드를 추가하면 도움이 될 수 있습니다. 이렇게 하면 리뷰어와 다른 Nuxt 사용자가 여러분이 만든 기능을 더 깊이 이해하는 데 도움이 됩니다.
::

### Testing %{#testing}%

모든 새 기능에는 가능하면 대응하는 단위 테스트가 있어야 합니다. 이 저장소의 `test/` 디렉터리는 현재도 작업 중이지만, 이미 있는 예시를 따라 새 테스트를 만들기 위해 최선을 다해 주세요.

PR을 만들거나 ready-to-review로 표시하기 전에 다음을 실행해 모든 테스트가 통과하는지 확인하세요:

```bash [Terminal]
pnpm test
```

### Linting %{#linting}%

이미 눈치챘겠지만 우리는 코딩 표준을 강제하기 위해 ESLint를 사용합니다.

변경 사항을 커밋하기 전에 코드 스타일이 올바른지 확인하려면 다음을 실행하세요:

```bash [Terminal]
pnpm lint
```

::note
`pnpm lint --fix`를 사용해 대부분의 스타일 변경 사항을 수정할 수 있습니다. :br
그래도 오류가 남아 있다면 수동으로 수정해야 합니다.
::

### Documentation %{#documentation}%

새 기능을 추가하거나 리팩터링하거나, 그 밖의 방식으로 Nuxt의 동작을 변경하고 있다면 변경 사항을 문서화하고 싶을 가능성이 높습니다. 문서 변경 사항도 같은 PR에 포함해 주세요. 첫 번째 커밋에서 문서를 작성할 필요는 없지만, pull request가 충분히 성숙해지면 가능한 한 빨리 작성해 주세요.

::important
[Documentation Style Guide](/docs/4.x/community/contribution#documentation-style-guide)에 따라 변경해 주세요.
::

### Final Checklist %{#final-checklist}%

PR을 제출할 때는 작성해야 하는 간단한 템플릿이 있습니다. 체크리스트에서 해당하는 "답변"을 모두 체크해 주세요.

## 문서화 가이드 %{#documentation-guide}%

문서나 오류 메시지를 개선할 수 있는 부분을 발견했다면, 단순한 오타 수정이라도 PR을 열어 주세요!

::important
[Documentation Style Guide](/docs/4.x/community/contribution#documentation-style-guide)에 따라 변경해 주세요.
::

### 빠른 수정 %{#quick-edits}%

오타를 발견하거나 문장을 다시 표현하고 싶다면 **Community** 섹션 오른쪽 사이드에 있는 **Edit this page** 링크를 클릭할 수 있습니다.

GitHub 인터페이스에서 직접 변경한 뒤 Pull Request를 여세요.

### 더 긴 수정 %{#longer-edits}%

문서 콘텐츠는 [nuxt/nuxt](https://github.com/nuxt/nuxt) 저장소의 `docs/` 디렉터리 안에 있으며 markdown으로 작성되어 있습니다.

::note
문서를 로컬에서 미리 보려면 [nuxt/nuxt.com](https://github.com/nuxt/nuxt.com) 저장소의 단계를 따르세요.
::

::note
VS Code용 [MDC extension](https://marketplace.visualstudio.com/items?itemName=Nuxt.mdc) 설치를 권장합니다.
::

### 문서 린트 %{#linting-docs}%

문서는 일관성을 유지하기 위해 [MarkdownLint](https://github.com/DavidAnson/markdownlint)와 [case police](https://github.com/antfu/case-police)로 린트됩니다.

```bash [Terminal]
pnpm lint:docs
```

::note
`pnpm lint:docs:fix`를 실행해 린트 문제를 강조 표시하고 해결할 수도 있습니다.
::

### PR 열기 %{#open-a-pr}%

PR 제목이 [conventional commits](https://www.conventionalcommits.org) 가이드라인을 따르는지 확인해 주세요.

```bash [PR 제목 예시]
docs: update the section about the nuxt.config.ts file
```
