아무리 노력해도 버그를 완전히 없앨 수는 없습니다.

기저 코드를 직접 고칠 수 없더라도, 버그를 잘 보고하면 코드베이스에 조금 더 익숙한 다른 사람이 패턴을 찾아내거나 빠르게 수정할 수 있게 됩니다.

다음은 몇 가지 핵심 단계입니다.

## 정말 버그인가요? %{#is-it-really-a-bug}%

무언가에 대한 도움을 받고 싶은 것인지, 아니면 Nuxt 자체에 버그가 있다고 생각하는 것인지 먼저 생각해 보세요. 전자라면 기꺼이 도와드리고 싶지만, 그럴 때 가장 좋은 방법은 버그를 보고하는 대신 [도움 요청하기](/docs/4.x/community/getting-help)를 이용하는 것입니다.

## 이슈 검색 %{#search-the-issues}%

먼저 [open issues](https://github.com/nuxt/nuxt/issues)와 [discussions](https://github.com/nuxt/nuxt/discussions)를 검색해 보세요. 같은 버그로 보이는 항목을 찾았다면, 중복 이슈를 만드는 것보다 기존 스레드에 댓글을 다는 편이 훨씬 좋습니다.

## 최소 재현 만들기 %{#create-a-minimal-reproduction}%

버그를 안정적으로 재현할 수 있어야 하며, 그것도 프로젝트의 나머지 부분과 분리된 최소한의 형태여야 합니다. 이렇게 하면 무엇이 원인일 수 있는지 범위를 좁힐 수 있고, 누군가가 원인을 찾는 것뿐 아니라 잠재적 해결책을 테스트하는 것도 가능해집니다.

Nuxt sandbox로 시작해서 여러분이 겪는 버그를 재현하는 데 필요한 **최소한**의 코드만 추가하세요.

::note
이슈가 Vue 또는 Vite와 관련 있다면 먼저 Vue SSR starter로 재현해 보세요.
::

이슈를 재현했다면, 버그가 계속 재현되는 범위 안에서 가능한 한 많은 코드를 재현 예제에서 제거하세요. 재현 예제를 최대한 작게 만드는 데 들인 시간은 문제를 해결하려는 사람에게 엄청난 차이를 만들어 줍니다.

## 원인이 무엇일지 파악하기 %{#figure-out-what-the-cause-might-be}%

Nuxt 프로젝트에는 [Nuxt modules](/modules)부터 [기타 JavaScript 라이브러리](https://www.npmjs.com)까지 많은 요소가 얽혀 있습니다. 버그는 가장 관련성이 높고 구체적인 위치에 보고하도록 하세요. 대개는 문제를 일으키는 Nuxt 모듈이거나, Nuxt가 의존하는 업스트림 라이브러리일 가능성이 높습니다.
