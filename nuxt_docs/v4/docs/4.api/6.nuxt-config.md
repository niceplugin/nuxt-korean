## alias %{#alias}%

JavaScript와 CSS에서 사용자 정의 디렉터리에 접근할 수 있도록 추가 alias를 정의해 DX를 향상시킬 수 있습니다.

- **Type**: `object`
- **Default**
```json
{
  "~": "/<rootDir>/app",
  "@": "/<rootDir>/app",
  "~~": "/<rootDir>",
  "@@": "/<rootDir>",
  "#shared": "/<rootDir>/shared",
  "#server": "/<rootDir>/server",
  "assets": "/<rootDir>/app/assets",
  "public": "/<rootDir>/public",
  "#build": "/<rootDir>/.nuxt",
  "#internal/nuxt/paths": "/<rootDir>/.nuxt/paths.mjs"
}
```

::callout
**Note**: webpack 컨텍스트에서는(이미지 소스, CSS - 단 JavaScript는 제외) alias에 접근할 때
반드시 `~` 접두사를 붙여야 합니다.
::

::callout
<!-- @case-police-ignore tsConfig -->
**Note**: 이 alias들은 생성된 TypeScript 구성(`.nuxt/tsconfig.app.json`, `.nuxt/tsconfig.server.json` 등)에 자동으로 추가되므로 전체 타입 지원과 경로 자동 완성을 받을 수 있습니다. 생성된 구성에서 제공하는 옵션을 더 확장해야 한다면, 여기 또는 `nuxt.config`의 `typescript.tsConfig` 속성 안에 추가하세요.
::

**예시**:
```ts
import { fileURLToPath } from 'node:url'

export default defineNuxtConfig({
  alias: {
    'images': fileURLToPath(new URL('./assets/images', import.meta.url)),
    'style': fileURLToPath(new URL('./assets/style', import.meta.url)),
    'data': fileURLToPath(new URL('./assets/other/data', import.meta.url)),
  },
})
```

```html
<template>
  <img src="~images/main-bg.jpg">
</template>

<script>
import data from 'data/test.json'
</script>

<style>
// 아래 주석을 해제하세요
//@import '~style/variables.scss';
//@import '~style/utils.scss';
//@import '~style/base.scss';
body {
  background-image: url('~images/main-bg.jpg');
}
</style>
```

## analyzeDir %{#analyzedir}%

`nuxt analyze`를 실행할 때 Nuxt가 생성된 파일을 저장할 디렉터리입니다.

상대 경로가 지정되면 `rootDir`를 기준으로 해석됩니다.

- **Type**: `string`
- **Default:** `"/<rootDir>/.nuxt/analyze"`

## app %{#app}%

Nuxt App 구성입니다.

### `baseURL` %{#baseurl}%

Nuxt 애플리케이션의 기본 경로입니다.

예를 들면 다음과 같습니다:

- **Type**: `string`
- **Default:** `"/"`

**예시**:
```ts
export default defineNuxtConfig({
  app: {
    baseURL: '/prefix/',
  },
})
```

이 값은 `NUXT_APP_BASE_URL` 환경 변수를 설정해 런타임에도 지정할 수 있습니다.

**예시**:
```bash
NUXT_APP_BASE_URL=/prefix/ node .output/server/index.mjs
```

### `buildAssetsDir` %{#buildassetsdir}%

빌드된 사이트 자산의 폴더 이름으로, `baseURL`(또는 설정된 경우 `cdnURL`)을 기준으로 합니다. 이 값은 빌드 시점에 설정되며 런타임에 사용자 정의해서는 안 됩니다.

- **Type**: `string`
- **Default:** `"/_nuxt/"`

### `cdnURL` %{#cdnurl}%

public 폴더를 제공할 절대 URL입니다(프로덕션 전용).

예를 들면 다음과 같습니다:

- **Type**: `string`
- **Default:** `""`

**예시**:
```ts
export default defineNuxtConfig({
  app: {
    cdnURL: 'https://mycdn.org/',
  },
})
```

이 값은 `NUXT_APP_CDN_URL` 환경 변수를 설정해 런타임에 다른 값으로 지정할 수 있습니다.

**예시**:
```bash
NUXT_APP_CDN_URL=https://mycdn.org/ node .output/server/index.mjs
```

### `head` %{#head}%

모든 페이지의 `<head>`에 대한 기본 구성을 설정합니다.

- **Type**: `object`
- **Default**
```json
{
  "meta": [
    {
      "name": "viewport",
      "content": "width=device-width, initial-scale=1"
    },
    {
      "charset": "utf-8"
    }
  ],
  "link": [],
  "style": [],
  "script": [],
  "noscript": []
}
```

**예시**:
```ts
export default defineNuxtConfig({
  app: {
    head: {
      meta: [
      // <meta name="viewport" content="width=device-width, initial-scale=1">
        { name: 'viewport', content: 'width=device-width, initial-scale=1' },
      ],
      script: [
      // <script src="https://myawesome-lib.js"></script>
        { src: 'https://awesome-lib.js' },
      ],
      link: [
      // <link rel="stylesheet" href="https://myawesome-lib.css">
        { rel: 'stylesheet', href: 'https://awesome-lib.css' },
      ],
      // 이 부분은 변경될 가능성이 높다는 점에 유의하세요
      style: [
      // <style>:root { color: red }</style>
        { textContent: ':root { color: red }' },
      ],
      noscript: [
      // <noscript>JavaScript is required</noscript>
        { textContent: 'JavaScript is required' },
      ],
    },
  },
})
```

페이지 간 KeepAlive 구성의 기본값입니다.

개별 페이지에서 `definePageMeta`로 재정의할 수 있습니다. JSON으로 직렬화 가능한 값만 허용됩니다.

- **Default:** `false`

- **Type**: `boolean | TransitionProps`
- **Default:** `false`

**참고**: [Vue Transition 문서](https://vuejs.org/api/built-in-components#transition)

### `pageTransition` %{#pagetransition}%

페이지 전환의 기본값입니다.

개별 페이지에서 `definePageMeta`로 재정의할 수 있습니다. JSON으로 직렬화 가능한 값만 허용됩니다.

- **Type**: `boolean | TransitionProps`
- **Default:** `false`

**참고**: [Vue Transition 문서](https://vuejs.org/api/built-in-components#transition)

## appConfig %{#appconfig}%

추가 앱 구성입니다

프로그래밍 방식 사용과 타입 지원을 위해 이 옵션으로 app config를 직접 제공할 수 있습니다. 이 값은 기본값으로 `app.config` 파일과 병합됩니다.

### `nuxt` %{#nuxt}%

## appId %{#appid}%

멀티 앱 프로젝트에서 Nuxt 애플리케이션의 고유 id입니다.

기본값은 `nuxt-app`입니다.

- **Type**: `string`
- **Default:** `"nuxt-app"`

## build %{#build}%

공유 빌드 구성입니다.

### `analyze` %{#analyze}%

Nuxt는 번들을 시각화하고 최적화 방법을 확인할 수 있게 해줍니다.

`true`로 설정하면 번들 분석을 활성화하고, 또는 옵션 객체를 전달할 수 있습니다: [webpack용](https://github.com/webpack/webpack-bundle-analyzer#options-for-plugin) 또는 [vite용](https://github.com/btd/rollup-plugin-visualizer#options).

- **Type**: `object`
- **Default**
```json
{
  "template": "treemap",
  "projectRoot": "/<rootDir>",
  "filename": "/<rootDir>/.nuxt/analyze/{name}.html"
}
```

**예시**:
```ts
export default defineNuxtConfig({
  analyze: {
    analyzerMode: 'static',
  },
})
```

### `templates` %{#templates}%

이 옵션 대신 `@nuxt/kit`의 `addTemplate`를 사용하는 것을 권장합니다.

- **Type**: `array`

**예시**:
```ts
export default defineNuxtConfig({
  build: {
    templates: [
      {
        src: '~~/modules/support/plugin.js', // `src`는 절대 경로이거나 상대 경로일 수 있습니다
        dst: 'support.js', // `dst`는 프로젝트 `.nuxt` 디렉터리를 기준으로 하는 상대 경로입니다
      },
    ],
  },
})
```

### `transpile` %{#transpile}%

특정 의존성을 Babel로 트랜스파일하고 싶다면 여기에 추가할 수 있습니다. transpile의 각 항목은 패키지 이름, 함수, 문자열 또는 의존성 파일명과 일치하는 정규식 객체가 될 수 있습니다.

함수를 사용해 조건부로 트랜스파일할 수도 있습니다. 함수는 객체({ isDev, isServer, isClient, isModern, isLegacy })를 받습니다.

- **Type**: `array`

**예시**:
```ts
export default defineNuxtConfig({
  build: {
    transpile: [({ isLegacy }) => isLegacy && 'ky'],
  },
})
```

## buildDir %{#builddir}%

빌드된 Nuxt 파일이 배치될 디렉터리를 정의합니다.

많은 도구는 `.nuxt`가 숨김 디렉터리라고 가정합니다(`.`로 시작하기 때문입니다). 이것이 문제라면 이 옵션으로 이를 피할 수 있습니다.

- **Type**: `string`
- **Default:** `"/<rootDir>/.nuxt"`

**예시**:
```ts
export default defineNuxtConfig({
  buildDir: 'nuxt-build',
})
```

## buildId %{#buildid}%

빌드와 일치하는 고유 식별자입니다. 프로젝트의 현재 상태를 나타내는 해시를 포함할 수 있습니다.

- **Type**: `string`
- **Default:** `"4a2e2d30-418f-41df-8e58-ed5df06de7fd"`

## builder %{#builder}%

애플리케이션의 Vue 부분을 번들링할 때 사용할 builder입니다.

Nuxt는 클라이언트 사이드 애플리케이션을 위해 여러 builder를 지원합니다. 기본값은 Vite이지만 webpack, Rspack으로 전환하거나 사용자 정의 builder 구현을 제공할 수도 있습니다.

- **Type**: `'vite' | 'webpack' | 'rspack' | string | { bundle: (nuxt: Nuxt) => Promise<void> }`
- **Default:** `"@nuxt/vite-builder"`

**지원되는 builder 사용하기:**

```ts
export default defineNuxtConfig({
  // 기본값 - @nuxt/vite-builder 사용
  // builder: 'vite',

  // @nuxt/webpack-builder 사용
  // builder: 'webpack',

  // @nuxt/rspack-builder 사용
  builder: 'rspack',
})
```

`webpack` 또는 `rspack`을 사용하는 경우, 프로젝트에 `@nuxt/webpack-builder` 또는 `@nuxt/rspack-builder`가 명시적으로 설치되어 있어야 합니다.

**사용자 정의 builder 객체 사용하기:**

`bundle` 함수를 가진 객체를 전달해 사용자 정의 builder를 제공할 수 있습니다:

```ts
export default defineNuxtConfig({
  builder: {
    async bundle (nuxt) {
      const entry = await resolvePath(resolve(nuxt.options.appDir, 'entry'))

      // 클라이언트와 서버 번들 빌드
      await buildClient(nuxt, entry)
      if (nuxt.options.ssr) {
        await buildServer(nuxt, entry)
      }

      // ... 물론 실제로는 이보다 조금 더 복잡합니다!
    },
  },
})
```

**사용자 정의 builder 패키지 만들기:**

별도 패키지로 사용자 정의 builder를 만들려면 `bundle` 함수를 export해야 합니다. 그런 다음 `nuxt.config.ts`에서 패키지 이름을 지정할 수 있습니다:

```ts
export default defineNuxtConfig({
  builder: 'my-custom-builder',
})
```

## compatibilityDate %{#compatibilitydate}%

앱의 호환성 날짜를 지정합니다.

이는 메이저 버전 증가 없이 동작이 바뀔 수 있는 Nitro, Nuxt Image 및 다른 모듈의 preset 동작을 제어하는 데 사용됩니다.
향후 이 기능을 둘러싼 도구를 개선할 계획입니다.

## components %{#components}%

Nuxt 컴포넌트 자동 등록을 구성합니다.

여기서 구성한 디렉터리의 모든 컴포넌트는 명시적으로 import하지 않아도 페이지, 레이아웃(및 다른 컴포넌트) 전반에서 사용할 수 있습니다.

- **Type**: `object`
- **Default**
```json
{
  "dirs": [
    {
      "path": "~/components/global",
      "global": true
    },
    "~/components"
  ]
}
```

**참고**: [`app/components/` 디렉터리 문서](https://nuxt.com/docs/4.x/directory-structure/app/components)

## css %{#css}%

전역으로 설정할 CSS 파일/모듈/라이브러리(모든 페이지에 포함됨)를 정의할 수 있습니다.

Nuxt는 확장자를 기준으로 파일 유형을 자동으로 추정하고 적절한 프리프로세서를 사용합니다. 다만 사용하려면 필요한 loader는 여전히 설치해야 합니다.

- **Type**: `array`

**예시**:
```ts
export default defineNuxtConfig({
  css: [
  // Node.js 모듈을 직접 로드합니다(여기서는 Sass 파일)
    'bulma',
    // 프로젝트의 CSS 파일
    '~/assets/css/main.css',
    // 프로젝트의 SCSS 파일
    '~/assets/css/main.scss',
  ],
})
```

## debug %{#debug}%

특정 디버그 옵션을 활성화하려면 객체로 설정할 수도 있습니다.

- **Type**: `boolean`
- **Default:** `false`

## hooks %{#hooks}%

훅은 보통 모듈에서 사용되는 Nuxt 이벤트 리스너이지만 `nuxt.config`에서도 사용할 수 있습니다.

구성을 더 쉽게 하기 위해 `nuxt.config`에서 계층형 객체로 구성할 수도 있습니다(아래 예시).

**예시**:
```ts
import fs from 'node:fs'
import path from 'node:path'

export default defineNuxtConfig({
  hooks: {
    build: {
      done (builder) {
        const extraFilePath = path.join(
          builder.nuxt.options.buildDir,
          'extra-file',
        )
        fs.writeFileSync(extraFilePath, 'Something extra')
      },
    },
  },
})
```

## modules %{#modules}%

모듈은 Nuxt의 핵심 기능을 확장하고 무한한 통합을 추가할 수 있는 Nuxt 확장 기능입니다.

각 모듈은 문자열(패키지를 가리키거나 파일 경로일 수 있음), 첫 번째 값이 모듈이고 두 번째 값이 옵션 객체인 튜플, 또는 인라인 모듈 함수 중 하나입니다.
Nuxt는 modules 배열의 각 항목을 먼저 node require 경로(`node_modules`)로 해석하려고 시도하고, `~~` alias가 사용되면 프로젝트 `rootDir` 기준으로 해석합니다.

- **Type**: `array`

::callout
**Note**: 모듈은 순차적으로 실행되므로 순서가 중요합니다. 먼저 `nuxt.config.ts`에 정의된 모듈이 로드됩니다. 그다음 `modules/`
디렉터리에서 찾은 모듈이 실행되며, 알파벳순으로 로드됩니다.
::

**예시**:
```ts
export default defineNuxtConfig({
  modules: [
  // 패키지 이름 사용
    '@nuxt/scripts',
    // 프로젝트 rootDir 기준 상대 경로
    '~~/custom-modules/awesome.js',
    // 옵션 제공
    ['@nuxtjs/google-analytics', { ua: 'X1234567' }],
    // 인라인 정의
    function () {},
  ],
})
```

## plugins %{#plugins}%

각 플러그인은 문자열일 수 있으며(파일의 절대 경로 또는 상대 경로), `.client` 또는 `.server`로 끝나면 해당 컨텍스트에서만 자동으로 로드됩니다.
또는 `src`와 `mode` 키를 가진 객체일 수도 있습니다.

- **Type**: `array`

::callout
**Note**: 플러그인은 `~/plugins` 디렉터리에서도 자동 등록되며

**참고**: [`app/plugins/` 디렉터리 문서](https://nuxt.com/docs/4.x/directory-structure/app/plugins)

**예시**:
```ts
export default defineNuxtConfig({
  plugins: [
    '~/custom-plugins/foo.client.js', // 클라이언트 사이드에서만
    '~/custom-plugins/bar.server.js', // 서버 사이드에서만
    '~/custom-plugins/baz.js', // 클라이언트와 서버 모두
    { src: '~/custom-plugins/both-sides.js' },
    { src: '~/custom-plugins/client-only.js', mode: 'client' }, // 클라이언트 사이드에서만
    { src: '~/custom-plugins/server-only.js', mode: 'server' }, // 서버 사이드에서만
  ],
})
```

## runtimeConfig %{#runtimeconfig}%

이 객체의 값은 서버에서만 `useRuntimeConfig`를 사용해 접근할 수 있습니다.

값은 런타임에 일치하는 환경 변수로 자동 대체됩니다. 예를 들어 `NUXT_API_KEY=my-api-key NUXT_PUBLIC_BASE_URL=/foo/` 환경 변수를 설정하면 아래 예시의 두 값을 덮어씁니다.

- **Type**: `object`
- **Default**
```json
{
  "public": {},
  "app": {
    "buildId": "4a2e2d30-418f-41df-8e58-ed5df06de7fd",
    "baseURL": "/",
    "buildAssetsDir": "/_nuxt/",
    "cdnURL": ""
  }
}
```

**예시**:
```ts
export default defineNuxtConfig({
```

## serverHandlers %{#serverhandlers}%

Nitro server handler입니다.

각 handler는 다음 옵션을 받습니다:
- handler: handler를 정의한 파일 경로입니다. - route: handler가 제공될 라우트입니다. 이는 [rou3](https://github.com/h3js/rou3)의 규칙을 따릅니다. - method: 처리할 요청의 HTTP 메서드입니다. - middleware: 미들웨어 handler인지 여부를 지정합니다. - lazy: handler import에 lazy loading을 사용할지 지정합니다.

- **Type**: `array`

**참고**: [`server/` 디렉터리 문서](https://nuxt.com/docs/4.x/directory-structure/server)

::callout
**Note**: `server/api`, `server/middleware`, `server/routes`의 파일은 Nuxt가 자동으로 등록합니다.
::

**예시**:
```ts
export default defineNuxtConfig({
  serverHandlers: [
    { route: '/path/foo/**:name', handler: '#server/foohandler.ts' },
  ],
})
```

## sourcemap %{#sourcemap}%

server 및/또는 client 번들에 대해 sourcemap을 생성할지와 생성 방식을 구성합니다.

단일 boolean으로 설정하면 그 값이 server와 client 모두에 적용됩니다. 추가로 `'hidden'` 옵션도 server와 client 모두에서 사용할 수 있습니다.
client와 server 모두에 사용할 수 있는 옵션: - `true`: sourcemap을 생성하고 최종 번들에 소스 참조를 포함합니다. - `false`: sourcemap을 생성하지 않습니다. - `'hidden'`: sourcemap은 생성하지만 최종 번들에 참조는 포함하지 않습니다.

- **Type**: `object`
- **Default**
```json
{
  "server": true,
  "client": false
}
```

### `extractCSS` %{#extractcss}%

Common CSS Extraction을 활성화합니다.

[mini-css-extract-plugin](https://github.com/webpack/mini-css-extract-plugin)을 내부적으로 사용해 CSS를 보통 컴포넌트별로 하나씩 별도 파일로 추출합니다. 이를 통해 CSS와 JavaScript를 각각 따로 캐시할 수 있습니다.

- **Type**: `boolean`
- **Default:** `true`

**예시**:
```ts
export default defineNuxtConfig({
  webpack: {
    extractCSS: true,
    // 또는
    extractCSS: {
      ignoreOrder: true,
    },
  },
})
```

모든 CSS를 하나의 파일로 추출하고 싶다면 이를 위한 우회 방법이 있습니다.
하지만 모든 것을 단일 파일로 추출하는 것은 권장되지 않는다는 점에 유의하세요.
여러 CSS 파일로 추출하는 편이 캐싱과 preload 격리에 더 유리합니다. 또한
필요한 리소스만 다운로드하고 해석하게 되므로 페이지 성능을
개선할 수도 있습니다.

**예시**:
```ts
export default defineNuxtConfig({
  webpack: {
    extractCSS: true,
    optimization: {
      splitChunks: {
        cacheGroups: {
          styles: {
            name: 'styles',
            test: /\.(css|vue)$/,
            chunks: 'all',
            enforce: true,
          },
        },
      },
    },
  },
})
```

### `filenames` %{#filenames}%

번들 파일명을 사용자 정의합니다.

manifest 사용 방식에 대해 조금 더 이해하려면 [webpack 문서](https://webpack.js.org/guides/code-splitting/)를 참고하세요.

::callout
**Note**: 프로덕션에서 해시 기반이 아닌 파일명을 사용할 때는 주의하세요
대부분의 브라우저가 자산을 캐시하므로 첫 로드에서 변경 사항을 감지하지 못할 수 있습니다.
::

이 예시는 보기 좋은 청크 이름을 숫자 id로 변경합니다:

**예시**:
```ts
export default defineNuxtConfig({
  webpack: {
    filenames: {
      chunk: ({ isDev }) => (isDev ? '[name].js' : '[id].[contenthash].js'),
    },
  },
})
```

## workspaceDir %{#workspacedir}%

애플리케이션의 워크스페이스 디렉터리를 정의합니다.

이는 모노레포 구성에서 자주 사용됩니다. Nuxt는 워크스페이스 디렉터리를 자동으로 감지하려고 시도하지만, 여기에서 이를 덮어쓸 수 있습니다.
보통은 이 옵션을 구성할 필요가 없습니다.

- **Type**: `string`
- **Default:** `"/<workspaceDir>"`
