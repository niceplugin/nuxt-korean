모듈은 Nuxt의 구성 요소입니다. Kit은 모듈을 만들고 사용하는 데 도움이 되는 유틸리티 집합을 제공합니다. 이 유틸리티를 사용해 직접 모듈을 만들거나 기존 모듈을 재사용할 수 있습니다. 예를 들어 `defineNuxtModule` 함수를 사용해 모듈을 정의하고 `moduleDependencies` 옵션으로 의존성을 지정할 수 있습니다.

## `defineNuxtModule` %{#definenuxtmodule}%

Nuxt 모듈을 정의합니다. 기본값과 사용자가 제공한 옵션을 자동으로 병합하고, 제공된 훅이 있다면 설치하며, 전체 제어를 위한 선택적 setup 함수를 호출합니다.

### 사용법 %{#usage}%

```ts twoslash
import { defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: {
    name: 'my-module',
    configKey: 'myModule',
  },
  defaults: {
    enabled: true,
  },
  setup (options) {
    if (options.enabled) {
      console.log('My Nuxt module is enabled!')
    }
  },
})
```

### 타입 %{#type}%

```ts twoslash
// @errors: 2391
import type { ModuleDefinition, ModuleOptions, NuxtModule } from '@nuxt/schema'
// ---cut---
export function defineNuxtModule<TOptions extends ModuleOptions> (
  definition?: ModuleDefinition<TOptions, Partial<TOptions>, false> | NuxtModule<TOptions, Partial<TOptions>, false>,
): NuxtModule<TOptions, TOptions, false>

export function defineNuxtModule<TOptions extends ModuleOptions> (): {
  with: <TOptionsDefaults extends Partial<TOptions>> (
    definition: ModuleDefinition<TOptions, TOptionsDefaults, true> | NuxtModule<TOptions, TOptionsDefaults, true>,
  ) => NuxtModule<TOptions, TOptionsDefaults, true>
}
```

### 매개변수 %{#parameters}%

**definition**: 모듈 정의 객체 또는 모듈 함수입니다. 모듈 정의 객체에는 다음 속성을 포함해야 합니다:

| Property             | Type                                                                                                              | Required | Description                                                                                                                                                                                                        |
|----------------------|-------------------------------------------------------------------------------------------------------------------|----------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `meta`               | `ModuleMeta`                                                                                                      | `false`  | 모듈의 메타데이터입니다. 모듈 이름, 버전, config key, 호환성을 정의합니다.                                                                                                                                         |
| `defaults`           | `T \| ((nuxt: Nuxt) => T)`{lang="ts"}                                                                             | `false`  | 모듈의 기본 옵션입니다. 함수가 제공되면 첫 번째 인수로 Nuxt 인스턴스를 받아 호출됩니다.                                                                                                                            |
| `schema`             | `T`                                                                                                               | `false`  | 모듈 옵션의 스키마입니다. 제공되면 옵션이 스키마에 적용됩니다.                                                                                                                                                      |
| `hooks`              | `Partial<NuxtHooks>`{lang="ts"}                                                                                   | `false`  | 모듈에 설치할 훅입니다. 제공되면 모듈이 훅을 설치합니다.                                                                                                                                                            |
| `moduleDependencies` | `Record<string, ModuleDependency> \| ((nuxt: Nuxt) => Record<string, ModuleDependency>)`{lang="ts"}               | `false`  | 버전 제약과 구성을 포함한 다른 모듈에 대한 의존성입니다. 객체이거나 Nuxt 인스턴스를 받는 함수일 수 있습니다. [예시](/docs/4.x/api/kit/modules#specifying-module-dependencies)를 참고하세요.                      |
| `onInstall`          | `(nuxt: Nuxt) => Awaitable<void>`{lang="ts"}                                                                      | `false`  | 모듈이 처음 설치될 때 호출되는 라이프사이클 훅입니다. `meta.name`과 `meta.version`이 정의되어 있어야 합니다.                                                                                                       |
| `onUpgrade`          | `(nuxt: Nuxt, options: T, previousVersion: string) => Awaitable<void>`{lang="ts"}                                 | `false`  | 모듈이 더 새로운 버전으로 업그레이드될 때 호출되는 라이프사이클 훅입니다. `meta.name`과 `meta.version`이 정의되어 있어야 합니다.                                                                                |
| `setup`              | `(this: void, resolvedOptions: T, nuxt: Nuxt) => Awaitable<void \| false \| ModuleSetupInstallResult>`{lang="ts"} | `false`  | 모듈의 setup 함수입니다. 제공되면 모듈이 setup 함수를 호출합니다.                                                                                                                                                   |

### 예제 %{#examples}%

#### `configKey`를 사용해 모듈을 구성 가능하게 만들기 %{#using-configkey-to-make-your-module-configurable}%

Nuxt 모듈을 정의할 때 `configKey`를 설정하면 사용자가 `nuxt.config`에서 모듈을 어떻게 구성해야 하는지 지정할 수 있습니다.

```ts
import { defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: {
    name: 'my-module',
    configKey: 'myModule',
  },
  defaults: {
    // 모듈 옵션
    enabled: true,
  },
  setup (options) {
    if (options.enabled) {
      console.log('My Nuxt module is enabled!')
    }
  },
})
```

사용자는 `nuxt.config`에서 해당 키 아래에 이 모듈의 옵션을 제공할 수 있습니다.

```ts
export default defineNuxtConfig({
  myModule: {
    enabled: false,
  },
})
```

사용자는 config key를 `false`로 설정해 모듈 전체를 비활성화할 수도 있습니다. 이렇게 하면 모듈 옵션 타입은 생성되면서도 모듈의 setup 함수는 실행되지 않습니다.

```ts
export default defineNuxtConfig({
  // 모듈 전체 비활성화
  myModule: false,
})
```

::tip
이것은 특히 [Nuxt layers](/docs/4.x/guide/going-further/layers#disabling-modules-from-layers)에서 상속한 모듈을 비활성화하고 싶을 때 유용합니다.
::

#### 모듈 호환성 요구 사항 정의하기 %{#defining-module-compatibility-requirements}%

Nuxt 모듈을 개발하면서 특정 Nuxt 버전에서만 지원되는 API를 사용한다면 `compatibility.nuxt`를 포함하는 것을 강력히 권장합니다.

```ts
export default defineNuxtModule({
  meta: {
    name: '@nuxt/icon',
    configKey: 'icon',
    compatibility: {
      // semver 형식의 필요한 nuxt 버전
      nuxt: '>=3.0.0', // 또는 '^3.0.0' 사용
    },
  },
  setup () {
    const resolver = createResolver(import.meta.url)
    // 구현
  },
})
```

사용자가 호환되지 않는 Nuxt 버전으로 모듈을 사용하려고 하면 콘솔에 경고가 표시됩니다.

```terminal
 WARN  Module @nuxt/icon is disabled due to incompatibility issues:
 - [nuxt] Nuxt version ^3.1.0 is required but currently using 3.0.0
```

#### `.with()`로 해결된 옵션의 타입 안정성 확보하기 %{#type-safety-for-resolved-options-with-with}%

해결되거나 병합된 모듈 옵션에 대한 타입 안정성이 필요하다면 `.with()` 메서드를 사용할 수 있습니다. 이렇게 하면 TypeScript가 모듈 기본값과 setup 함수가 받는 최종 해결 옵션 사이의 관계를 올바르게 추론할 수 있습니다.

```ts
import { defineNuxtModule } from '@nuxt/kit'

// 모듈 옵션 인터페이스 정의
interface ModuleOptions {
  apiKey: string
  baseURL: string
  timeout?: number
  retries?: number
}

export default defineNuxtModule<ModuleOptions>().with({
  meta: {
    name: '@nuxtjs/my-api',
    configKey: 'myApi',
  },
  defaults: {
    baseURL: 'https://api.example.com',
    timeout: 5000,
    retries: 3,
  },
  setup (resolvedOptions, nuxt) {
    // resolvedOptions는 다음과 같이 올바르게 타입 지정됩니다:
    // {
    //   apiKey: string          // 필수, 기본값 없음
    //   baseURL: string         // 필수, 기본값 있음
    //   timeout: number         // 선택적, 기본값 있음
    //   retries: number         // 선택적, 기본값 있음
    // }

    console.log(resolvedOptions.baseURL) // ✅ TypeScript는 이것이 항상 정의되어 있음을 압니다
    console.log(resolvedOptions.timeout) // ✅ TypeScript는 이것이 항상 정의되어 있음을 압니다
    console.log(resolvedOptions.retries) // ✅ TypeScript는 이것이 항상 정의되어 있음을 압니다
  },
})
```

`.with()`를 사용하지 않으면 `resolvedOptions` 매개변수는 기본값이 제공되었더라도 `timeout`과 `retries`가 `undefined`일 수 있는 원본 `ModuleOptions` 인터페이스로 타입 지정됩니다. `.with()` 메서드는 기본값이 해결된 옵션에서 해당 속성을 필수가 아닌 값으로 만들지 않는다는 점을 TypeScript가 이해하도록 해줍니다.

#### 모듈 설치 및 업그레이드를 위한 라이프사이클 훅 사용하기 %{#using-lifecycle-hooks-for-module-installation-and-upgrade}%

모듈이 처음 설치되거나 새 버전으로 업그레이드될 때 실행되는 라이프사이클 훅을 정의할 수 있습니다. 이러한 훅은 일회성 설정 작업, 데이터베이스 마이그레이션, 정리 작업 등을 수행할 때 유용합니다.

::important
라이프사이클 훅이 동작하려면 모듈 정의에 `meta.name`과 `meta.version`을 **반드시** 모두 제공해야 합니다. 훅은 이 값을 사용해 프로젝트의 `.nuxtrc` 파일에서 모듈의 설치 상태를 추적합니다.
::

라이프사이클 훅은 주 `setup` 함수보다 먼저 실행되며, 훅에서 오류가 발생해도 로그에 기록될 뿐 빌드 프로세스는 중단되지 않습니다.

**`onInstall`**은 모듈이 프로젝트에 처음 추가될 때 한 번만 실행됩니다.

**`onUpgrade`**는 모듈 버전이 올라갈 때마다 실행되며(semver 비교 사용) &mdash; 각 버전 증가마다 한 번만 실행됩니다.

##### 예시 %{#example}%

```ts
import { defineNuxtModule } from '@nuxt/kit'
import semver from 'semver'

export default defineNuxtModule({
  meta: {
    name: 'my-awesome-module',
    version: '1.2.0', // 라이프사이클 훅에 필요
    configKey: 'myAwesomeModule',
  },
  defaults: {
    apiKey: '',
    enabled: true,
  },

  onInstall (nuxt) {
    // 모듈이 처음 설치될 때만 실행됩니다
    console.log('Setting up my-awesome-module for the first time!')

    // 다음과 같은 작업을 수행할 수 있습니다:
    // - 초기 구성 파일 생성
    // - 데이터베이스 스키마 설정
    // - 환영 메시지 표시
    // - 초기 데이터 마이그레이션 수행
  },

  onUpgrade (nuxt, options, previousVersion) {
    // 모듈이 더 새로운 버전으로 업그레이드될 때 실행됩니다
    console.log(`Upgrading my-awesome-module from ${previousVersion} to 1.2.0`)

    // 다음과 같은 작업을 수행할 수 있습니다:
    // - 구성 파일 마이그레이션
    // - 데이터베이스 스키마 업데이트
    // - 더 이상 사용되지 않는 파일 정리
    // - 업그레이드 참고 사항 표시

    if (semver.lt(previousVersion, '1.1.0')) {
      console.log('⚠️  Breaking changes in 1.1.0 - please check the migration guide')
    }
  },

  setup (options, nuxt) {
    // 일반 setup 로직은 모든 빌드에서 실행됩니다
    if (options.enabled) {
      // 모듈 구성
    }
  },
})
```

#### 모듈 의존성 지정하기 %{#specifying-module-dependencies}%

`moduleDependencies` 옵션을 사용해 다른 모듈에 대한 의존성을 선언할 수 있습니다. 이렇게 하면 올바른 설정 순서, 버전 호환성, 구성 관리를 보장하는 견고한 방법을 제공합니다.

`moduleDependencies` 옵션은 객체이거나 Nuxt 인스턴스를 받는 함수일 수 있습니다:

##### 예시 %{#example}%

```ts
import { defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: {
    name: 'my-module',
  },
  moduleDependencies: {
    '@nuxtjs/tailwindcss': {
      // 버전 제약 지정 (semver 형식)
      version: '>=6.0.0',
      // 사용자 설정을 덮어쓰는 구성
      overrides: {
        exposeConfig: true,
      },
      // 사용자 설정을 존중하면서 기본값을 설정하는 구성
      defaults: {
        config: {
          darkMode: 'class',
        },
      },
    },
    '@nuxtjs/fontaine': {
      // 선택적 의존성은 설치되지는 않지만, 설치되어 있는 경우
      // 옵션을 설정할 수 있도록 보장합니다
      optional: true,
      defaults: {
        fonts: [
          {
            family: 'Roboto',
            fallbacks: ['Impact'],
          },
        ],
      },
    },
  },
  setup (options, nuxt) {

  },
})
```

함수를 사용해 Nuxt 구성에 따라 의존성을 동적으로 결정할 수도 있습니다:

```ts
import { defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: {
    name: 'my-module',
  },
  moduleDependencies (nuxt) {
    const dependencies: Record<string, any> = {
      '@nuxtjs/tailwindcss': {
        version: '>=6.0.0',
      },
    }

    // Nuxt 구성에 따라 조건부로 의존성 추가
    if (nuxt.options.experimental?.someFeature) {
      dependencies['@nuxtjs/fontaine'] = {
        optional: true,
      }
    }

    return dependencies
  },
  setup (options, nuxt) {
    // 모든 의존성이 초기화된 후 setup 로직이 실행됩니다
  },
})
```

## `installModule` %{#installmodule}%

::callout{type="warning"}
**Deprecated:** 대신 `defineNuxtModule`의 [`moduleDependencies`](/docs/4.x/api/kit/modules#specifying-module-dependencies) 옵션을 사용하세요. `installModule` 함수는 향후 버전에서 제거되거나(또는 non-blocking이 될 수 있습니다) 제거될 예정입니다.
::

지정한 Nuxt 모듈을 프로그래밍 방식으로 설치합니다. 이 기능은 모듈이 다른 모듈에 의존할 때 유용합니다. 모듈 옵션을 객체로 `inlineOptions`에 전달하면 해당 옵션이 모듈의 `setup` 함수로 전달됩니다.

### 사용법 %{#usage}%

```ts twoslash
import { defineNuxtModule, installModule } from '@nuxt/kit'

export default defineNuxtModule({
  async setup () {
    // Roboto 글꼴과 Impact 대체 글꼴로 @nuxtjs/fontaine을 설치합니다
    await installModule('@nuxtjs/fontaine', {
      // 모듈 구성
      fonts: [
        {
          family: 'Roboto',
          fallbacks: ['Impact'],
          fallbackName: 'fallback-a',
        },
      ],
    })
  },
})
```

### 타입 %{#type}%

```ts
async function installModule (moduleToInstall: string | NuxtModule, inlineOptions?: any, nuxt?: Nuxt)
```

### 매개변수 %{#parameters}%

| Property          | Type                              | Required | Description                                                                                   |
|-------------------|-----------------------------------|----------|-----------------------------------------------------------------------------------------------|
| `moduleToInstall` | `string \| NuxtModule`{lang="ts"} | `true`   | 설치할 모듈입니다. 모듈 이름 문자열이거나 모듈 객체 자체일 수 있습니다.                       |
| `inlineOptions`   | `any`                             | `false`  | 모듈의 `setup` 함수로 전달할 모듈 옵션 객체입니다.                                            |
| `nuxt`            | `Nuxt`                            | `false`  | Nuxt 인스턴스입니다. 제공되지 않으면 `useNuxt()` 호출을 통해 컨텍스트에서 가져옵니다.         |

### 예제 %{#examples}%

```ts
import { defineNuxtModule, installModule } from '@nuxt/kit'

export default defineNuxtModule({
  async setup (options, nuxt) {
    // Roboto 글꼴과 Impact 대체 글꼴로 @nuxtjs/fontaine을 설치합니다
    await installModule('@nuxtjs/fontaine', {
      // 모듈 구성
      fonts: [
        {
          family: 'Roboto',
          fallbacks: ['Impact'],
          fallbackName: 'fallback-a',
        },
      ],
    })
  },
})
```
