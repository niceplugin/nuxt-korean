Nitro는 초고속 웹 서버를 만들기 위한 오픈 소스 TypeScript 프레임워크입니다. Nuxt는 Nitro를 서버 엔진으로 사용합니다. `useNitro`를 사용해 Nitro 인스턴스에 접근할 수 있고, `addServerHandler`로 서버 핸들러를 추가할 수 있으며, `addDevServerHandler`로 개발 모드에서만 사용할 서버 핸들러를 추가할 수 있습니다. 또한 `addServerPlugin`으로 Nitro의 런타임 동작을 확장하는 플러그인을 추가하고, `addPrerenderRoutes`로 Nitro가 프리렌더할 라우트를 추가할 수 있습니다.

## `addServerHandler` %{#addserverhandler}%

Nitro 서버 핸들러를 추가합니다. 서버 미들웨어나 커스텀 라우트를 만들고 싶을 때 사용하세요.

### 사용법 %{#usage}%

```ts twoslash
import { addServerHandler, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options) {
    const { resolve } = createResolver(import.meta.url)

    addServerHandler({
      route: '/robots.txt',
      handler: resolve('./runtime/robots.get'),
    })
  },
})
```

### 타입 %{#type}%

```ts
function addServerHandler (handler: NitroEventHandler): void
```

### 매개변수 %{#parameters}%

**handler**: 다음 속성을 가진 핸들러 객체입니다:

| Property     | Type      | Required | Description                                                                                                                                   |
|--------------|-----------|----------|-----------------------------------------------------------------------------------------------------------------------------------------------|
| `handler`    | `string`  | `true`   | 이벤트 핸들러의 경로입니다.                                                                                                                   |
| `route`      | `string`  | `false`  | 경로 prefix 또는 route입니다. 빈 문자열을 사용하면 미들웨어로 사용됩니다.                                                                       |
| `middleware` | `boolean` | `false`  | 이것이 미들웨어 핸들러임을 지정합니다. 미들웨어는 모든 라우트에서 호출되며, 일반적으로 다음 핸들러로 넘기기 위해 아무것도 반환하지 않아야 합니다. |
| `lazy`       | `boolean` | `false`  | 핸들러를 import할 때 지연 로딩을 사용합니다. 필요할 때만 핸들러를 로드하고 싶을 때 유용합니다.                                                 |
| `method`     | `string`  | `false`  | 라우터 메서드 매처입니다. 핸들러 이름에 메서드 이름이 포함되어 있으면 기본값으로 사용됩니다.                                                   |

### 예제 %{#examples}%

#### 기본 사용법 %{#basic-usage}%

모듈에서 `addServerHandler`를 사용해 서버 핸들러를 추가할 수 있습니다.

::code-group

```ts twoslash [module.ts]
import { addServerHandler, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options) {
    const { resolve } = createResolver(import.meta.url)

    addServerHandler({
      route: '/robots.txt',
      handler: resolve('./runtime/robots.get'),
    })
  },
})
```

```ts twoslash [runtime/robots.get.ts]
import { defineEventHandler } from 'nitro/h3'

export default defineEventHandler(() => {
  return {
    body: `User-agent: *\nDisallow: /`,
  }
})
```

::

`/robots.txt`에 접근하면 다음 응답이 반환됩니다:

```txt
User-agent: *
Disallow: /
```

## `addDevServerHandler` %{#adddevserverhandler}%

개발 모드에서만 사용되는 Nitro 서버 핸들러를 추가합니다. 이 핸들러는 프로덕션 빌드에서 제외됩니다.

### 사용법 %{#usage}%

```ts twoslash
import { defineEventHandler } from 'nitro/h3'
import { addDevServerHandler, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup () {
    addDevServerHandler({
      handler: defineEventHandler(() => {
        return {
          body: `Response generated at ${new Date().toISOString()}`,
        }
      }),
      route: '/_handler',
    })
  },
})
```

### 타입 %{#type}%

```ts twoslash
// @errors: 2391
import type { NitroDevEventHandler } from 'nitro/types'
// ---cut---
function addDevServerHandler (handler: NitroDevEventHandler): void
```

### 매개변수 %{#parameters}%

**handler**: 다음 속성을 가진 핸들러 객체입니다:

| Property  | Type           | Required | Description                                                                  |
|-----------|----------------|----------|------------------------------------------------------------------------------|
| `handler` | `EventHandler` | `true`   | 이벤트 핸들러입니다.                                                          |
| `route`   | `string`       | `false`  | 경로 prefix 또는 route입니다. 빈 문자열을 사용하면 미들웨어로 사용됩니다.      |

### 예제 %{#examples}%

#### 기본 사용법 %{#basic-usage}%

경우에 따라 Tailwind config 뷰어처럼 개발 목적에 특화된 서버 핸들러를 만들고 싶을 수 있습니다.

```ts
import { joinURL } from 'ufo'
import { addDevServerHandler, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  async setup (options, nuxt) {
    const route = joinURL(nuxt.options.app?.baseURL, '/_tailwind')

    // @ts-expect-error - tailwind-config-viewer는 올바른 타입을 제공하지 않습니다
    const createServer = await import('tailwind-config-viewer/server/index.js').then(r => r.default || r) as any
    const viewerDevMiddleware = createServer({ tailwindConfigProvider: () => options, routerPrefix: route }).asMiddleware()

    addDevServerHandler({ route, handler: viewerDevMiddleware })
  },
})
```

## `useNitro` %{#usenitro}%

Nitro 인스턴스를 반환합니다.

::warning
`useNitro()`는 `ready` 훅 이후에만 호출할 수 있습니다.
::

::note
Nitro 인스턴스 설정에 대한 변경 사항은 적용되지 않습니다.
::

### 사용법 %{#usage}%

```ts
import { defineNuxtModule, useNitro } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    const resolver = createResolver(import.meta.url)

    nuxt.hook('ready', () => {
      const nitro = useNitro()
      // Nitro 인스턴스로 무언가를 수행합니다
    })
  },
})
```

### 타입 %{#type}%

```ts
function useNitro (): Nitro
```

## `addServerPlugin` %{#addserverplugin}%

Nitro의 런타임 동작을 확장하는 플러그인을 추가합니다.

::tip
[Nitro 문서](https://nitro.build/guide/plugins)에서 Nitro 플러그인에 대해 더 읽어볼 수 있습니다.
::

::warning
플러그인 파일 안에서 반드시 ``에서 `definePlugin`을 명시적으로 import해야 합니다. 같은 요구 사항은 `useRuntimeConfig` 같은 유틸리티에도 적용됩니다.
::

### 사용법 %{#usage}%

```ts twoslash
import { addServerPlugin, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup () {
    const { resolve } = createResolver(import.meta.url)
    addServerPlugin(resolve('./runtime/plugin.ts'))
  },
})
```

### 타입 %{#type}%

```ts
function addServerPlugin (plugin: string): void
```

### 매개변수 %{#parameters}%

| Property | Type     | Required | Description                                                                                                   |
|----------|----------|----------|---------------------------------------------------------------------------------------------------------------|
| `plugin` | `string` | `true`   | 플러그인의 경로입니다. 플러그인은 Nitro 인스턴스를 인자로 받는 기본 함수를 export해야 합니다.                 |

### 예제 %{#examples}%

::code-group

```ts [module.ts]
import { addServerPlugin, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup () {
    const { resolve } = createResolver(import.meta.url)
    addServerPlugin(resolve('./runtime/plugin.ts'))
  },
})
```

```ts [runtime/plugin.ts]
import { definePlugin } from 'nitro'

export default definePlugin((nitroApp) => {
  nitroApp.hooks.hook('request', (event) => {
    console.log('on request', event.req.url)
  })

  nitroApp.hooks.hook('response', async (res) => {
    console.log('on response', await res.text())
  })
})
```

::

## `addPrerenderRoutes` %{#addprerenderroutes}%

Nitro에 프리렌더할 라우트를 추가합니다.

### 사용법 %{#usage}%

```ts
import { addPrerenderRoutes, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: {
    name: 'nuxt-sitemap',
    configKey: 'sitemap',
  },
  defaults: {
    sitemapUrl: '/sitemap.xml',
    prerender: true,
  },
  setup (options) {
    if (options.prerender) {
      addPrerenderRoutes(options.sitemapUrl)
    }
  },
})
```

### 타입 %{#type}%

```ts
function addPrerenderRoutes (routes: string | string[]): void
```

### 매개변수 %{#parameters}%

| Property | Type                            | Required | Description                                 |
|----------|---------------------------------|----------|---------------------------------------------|
| `routes` | `string \| string[]`{lang="ts"} | `true`   | 프리렌더할 route 또는 route 배열입니다.      |

## `addServerImports` %{#addserverimports}%

서버에 imports를 추가합니다. 수동으로 import하지 않아도 Nitro에서 해당 imports를 사용할 수 있게 해줍니다.

::warning
서버와 클라이언트 컨텍스트 모두에서 동작하고 [`shared/`](/docs/4.x/directory-structure/shared) 디렉터리에서도 사용할 수 있는 유틸리티를 제공하려면, 해당 함수는 [`addImports`](/docs/4.x/api/kit/autoimports#addimports)와 `addServerImports` 모두에서 같은 소스 파일로부터 import되어야 하며 동일한 시그니처를 가져야 합니다. 그 소스 파일은 컨텍스트에 특화된 것(Nitro 컨텍스트, Nuxt 앱 컨텍스트 등)을 import해서는 안 되며, 그렇지 않으면 타입 검사 중 오류가 발생할 수 있습니다.
::

### 사용법 %{#usage}%

```ts twoslash
import { addServerImports, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options) {
    const names = [
      'useStoryblok',
      'useStoryblokApi',
      'useStoryblokBridge',
      'renderRichText',
      'RichTextSchema',
    ]

    names.forEach(name =>
      addServerImports({ name, as: name, from: '@storyblok/vue' }),
    )
  },
})
```

### 타입 %{#type}%

```ts
function addServerImports (dirs: Import | Import[]): void
```

### 매개변수 %{#parameters}%

`imports`: 다음 속성을 가진 객체 또는 객체 배열입니다:

| Property   | Type                  | Required | Description                                                                                                     |
|------------|-----------------------|----------|-----------------------------------------------------------------------------------------------------------------|
| `name`     | `string`              | `true`   | 감지할 import 이름입니다.                                                                                        |
| `from`     | `string`              | `true`   | import할 모듈 지정자입니다.                                                                                      |
| `priority` | `number`              | `false`  | import의 우선순위입니다. 같은 이름의 import가 여러 개라면 가장 높은 우선순위를 가진 것이 사용됩니다.               |
| `disabled` | `boolean`             | `false`  | 이 import를 비활성화할지 여부입니다.                                                                             |
| `meta`     | `Record<string, any>` | `false`  | import의 메타데이터입니다.                                                                                       |
| `type`     | `boolean`             | `false`  | 이 import가 순수 타입 import인지 여부입니다.                                                                     |
| `typeFrom` | `string`              | `false`  | 타입 선언을 생성할 때 `from` 값으로 이것을 사용합니다.                                                           |
| `as`       | `string`              | `false`  | 이 이름으로 import합니다.                                                                                        |

## `addServerImportsDir` %{#addserverimportsdir}%

Nitro가 자동 import를 위해 스캔할 디렉터리를 추가합니다.

### 사용법 %{#usage}%

```ts twoslash
import { addServerImportsDir, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: {
    name: 'my-module',
    configKey: 'myModule',
  },
  setup (options) {
    const { resolve } = createResolver(import.meta.url)
    addServerImportsDir(resolve('./runtime/server/composables'))
  },
})
```

### 타입 %{#type}%

```ts
function addServerImportsDir (dirs: string | string[], opts: { prepend?: boolean }): void
```

### 매개변수 %{#parameters}%

| Property | Type                            | Required | Description                                                                                                         |
|----------|---------------------------------|----------|---------------------------------------------------------------------------------------------------------------------|
| `dirs`   | `string \| string[]`{lang="ts"} | `true`   | Nitro가 스캔하도록 등록할 디렉터리 또는 디렉터리 배열입니다.                                                         |
| `opts`   | `{ prepend?: boolean }`         | `false`  | import 디렉터리 옵션입니다. `prepend`가 `true`이면 디렉터리가 스캔 목록의 앞부분에 추가됩니다.                      |

### 예제 %{#examples}%

`addServerImportsDir`를 사용해 Nitro가 스캔할 디렉터리를 추가할 수 있습니다. 커스텀 서버 디렉터리에서 함수를 자동 import하게 만들고 싶을 때 유용합니다.

::code-group

```ts twoslash [module.ts]
import { addServerImportsDir, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: {
    name: 'my-module',
    configKey: 'myModule',
  },
  setup (options) {
    const { resolve } = createResolver(import.meta.url)
    addServerImportsDir(resolve('./runtime/server/composables'))
  },
})
```

```ts twoslash [runtime/server/composables/index.ts]
export function useApiSecret () {
  const { apiSecret } = useRuntimeConfig()
  return apiSecret
}
```

::

이후 서버 코드에서 `useApiSecret` 함수를 사용할 수 있습니다:

```ts twoslash [runtime/server/api/hello.ts]
import { defineEventHandler } from 'nitro/h3'

const useApiSecret = (): string => ''
// ---cut---
export default defineEventHandler(() => {
  const apiSecret = useApiSecret()
  // apiSecret으로 무언가를 수행합니다
})
```

## `addServerScanDir` %{#addserverscandir}%

Nitro가 스캔할 디렉터리를 추가합니다. 하위 디렉터리를 확인하여 등록하며,
이는 `~~/server` 폴더와 동일한 방식으로 처리됩니다.

::note
오직 `~~/server/api`, `~~/server/routes`, `~~/server/middleware`, `~~/server/utils`만 스캔됩니다.
::

### 사용법 %{#usage}%

```ts twoslash
import { addServerScanDir, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: {
    name: 'my-module',
    configKey: 'myModule',
  },
  setup (options) {
    const { resolve } = createResolver(import.meta.url)
    addServerScanDir(resolve('./runtime/server'))
  },
})
```

### 타입 %{#type}%

```ts
function addServerScanDir (dirs: string | string[], opts: { prepend?: boolean }): void
```

### 매개변수 %{#parameters}%

| Property | Type                            | Required | Description                                                                                                         |
|----------|---------------------------------|----------|---------------------------------------------------------------------------------------------------------------------|
| `dirs`   | `string \| string[]`{lang="ts"} | `true`   | Nitro가 서버 디렉터리로 스캔하도록 등록할 디렉터리 또는 디렉터리 배열입니다.                                         |
| `opts`   | `{ prepend?: boolean }`         | `false`  | import 디렉터리 옵션입니다. `prepend`가 `true`이면 디렉터리가 스캔 목록의 앞부분에 추가됩니다.                      |

### 예제 %{#examples}%

`addServerScanDir`를 사용해 Nitro가 스캔할 디렉터리를 추가할 수 있습니다. 커스텀 서버 디렉터리를 추가하고 싶을 때 유용합니다.

::code-group

```ts twoslash [module.ts]
import { addServerScanDir, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: {
    name: 'my-module',
    configKey: 'myModule',
  },
  setup (options) {
    const { resolve } = createResolver(import.meta.url)
    addServerScanDir(resolve('./runtime/server'))
  },
})
```

```ts twoslash [runtime/server/utils/index.ts]
export function hello () {
  return 'Hello from server utils!'
}
```
::

이후 서버 코드에서 `hello` 함수를 사용할 수 있습니다.

```ts twoslash [runtime/server/api/hello.ts]

}
// ---cut---

  return hello() // Hello from server utils!
})
```
