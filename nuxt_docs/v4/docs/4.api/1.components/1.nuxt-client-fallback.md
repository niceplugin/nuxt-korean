Nuxt는 자식 중 하나라도 SSR에서 오류를 발생시키면 클라이언트에서 콘텐츠를 렌더링하는 `<NuxtClientFallback>` 컴포넌트를 제공합니다.

::note{to="/docs/4.x/guide/going-further/experimental-features#clientfallback"}
이 컴포넌트는 실험적 기능이며, 사용하려면 `nuxt.config`에서 `experimental.clientFallback` 옵션을 활성화해야 합니다.
::

```vue [app/pages/example.vue]
<template>
  <div>
    <Sidebar />
    <!-- 이 컴포넌트는 클라이언트 사이드에서 렌더링됩니다 -->
    <NuxtClientFallback fallback-tag="span">
      <Comments />
      <BrokeInSSR />
    </NuxtClientFallback>
  </div>
</template>
```

## Events %{#events}%

- `@ssr-error`: 자식이 SSR에서 오류를 발생시킬 때 emit되는 이벤트입니다. 이 이벤트는 서버에서만 트리거된다는 점에 유의하세요.

  ```vue
  <template>
    <NuxtClientFallback @ssr-error="logSomeError">
      <!-- ... -->
    </NuxtClientFallback>
  </template>
  ```

## Props %{#props}%

- `placeholderTag` | `fallbackTag`: 슬롯이 서버에서 렌더링되지 못할 경우 렌더링할 fallback 태그를 지정합니다.
  - **type**: `string`
  - **default**: `div`
- `placeholder` | `fallback`: 슬롯 렌더링에 실패할 경우 렌더링할 fallback 콘텐츠를 지정합니다.
  - **type**: `string`
- `keepFallback`: 서버 사이드 렌더링에 실패한 경우 fallback 콘텐츠를 유지합니다.
  - **type**: `boolean`
  - **default**: `false`

::warning{icon="i-ph-warning-duotone"}
`placeholder`와 `fallback` props는 콘텐츠를 raw HTML로 렌더링합니다. XSS 취약점으로 이어질 수 있으므로 신뢰할 수 없는 사용자 입력을 이 props에 전달하지 마세요. 올바른 이스케이프가 필요한 동적 콘텐츠에는 대신 `#fallback` 또는 `#placeholder` 슬롯을 사용하세요.
::

```vue
<template>
  <!-- 기본 슬롯 렌더링에 실패하면 서버 사이드에서 <span>안녕하세요</span>를 렌더링합니다 -->
  <NuxtClientFallback
    fallback-tag="span"
    fallback="안녕하세요"
  >
    <BrokeInSSR />
  </NuxtClientFallback>
</template>
```

## Slots %{#slots}%

- `#fallback`: 슬롯 렌더링에 실패할 경우 서버 사이드에 표시할 콘텐츠를 지정합니다.

```vue
<template>
  <NuxtClientFallback>
    <!-- ... -->
    <template #fallback>
      <!-- 기본 슬롯이 SSR에서 렌더링되지 못하면 이것이 서버 사이드에서 렌더링됩니다 -->
      <p>안녕하세요</p>
    </template>
  </NuxtClientFallback>
</template>
```
