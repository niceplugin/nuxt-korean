`app.vue` 또는 `error.vue`에서 `<NuxtLayout />` 컴포넌트를 사용해 `default` 레이아웃을 활성화할 수 있습니다.

```vue [app/app.vue]
<template>
  <NuxtLayout>
    일부 페이지 콘텐츠
  </NuxtLayout>
</template>
```

:read-more{to="/docs/4.x/directory-structure/app/layouts"}

## Props %{#props}%

- `name`: 렌더링할 레이아웃 이름을 지정합니다. 문자열, 반응형 참조 또는 계산된 속성을 사용할 수 있습니다. [`app/layouts/`](/docs/4.x/directory-structure/app/layouts) 디렉터리의 해당 레이아웃 파일 이름과 **반드시** 일치해야 하며, 레이아웃을 비활성화하려면 `false`를 지정합니다.
  - **type**: `string | false`
  - **default**: `default`

```vue [app/pages/index.vue]
<script setup lang="ts">
// layouts/custom.vue
const layout = 'custom'
</script>

<template>
  <NuxtLayout :name="layout">
    <NuxtPage />
  </NuxtLayout>
</template>
```

::note
레이아웃 이름은 kebab-case로 정규화된다는 점에 유의하세요. 따라서 레이아웃 파일 이름이 `errorLayout.vue`라면 `<NuxtLayout />`에 `name` 속성으로 전달할 때 `error-layout`이 됩니다.
::

```vue [error.vue]
<template>
  <NuxtLayout name="error-layout">
    <NuxtPage />
  </NuxtLayout>
</template>
```

::read-more{to="/docs/4.x/directory-structure/app/layouts"}
동적 레이아웃에 대해 더 알아보세요.
::

- `fallback`: `name` prop에 잘못된 레이아웃이 전달되면 어떤 레이아웃도 렌더링되지 않습니다. 이 경우 렌더링할 `fallback` 레이아웃을 지정합니다. [`app/layouts/`](/docs/4.x/directory-structure/app/layouts) 디렉터리의 해당 레이아웃 파일 이름과 **반드시** 일치해야 합니다.
  - **type**: `string`
  - **default**: `null`

## 추가 Props %{#additional-props}%

`NuxtLayout`는 레이아웃에 전달해야 할 수 있는 추가 props도 받을 수 있습니다. 이러한 커스텀 props는 속성으로 접근할 수 있게 됩니다.

```vue [app/pages/some-page.vue]
<template>
  <div>
    <NuxtLayout
      name="custom"
      title="나는 커스텀 레이아웃입니다"
    >
      <!-- ... -->
    </NuxtLayout>
  </div>
</template>
```

위 예제에서 `title` 값은 custom.vue의 템플릿에서는 `$attrs.title`로, `<script setup>`에서는 `useAttrs().title`로 사용할 수 있습니다.

```vue [app/layouts/custom.vue]
<script setup lang="ts">
const layoutCustomProps = useAttrs()

console.log(layoutCustomProps.title) // 나는 커스텀 레이아웃입니다
</script>
```

## Page Meta에서 전달되는 Layout Props %{#layout-props-from-page-meta}%

`layout`에 객체 문법으로 [`definePageMeta`](/docs/4.x/api/utils/define-page-meta)를 사용하면 props가 레이아웃 컴포넌트로 자동 전달됩니다. 레이아웃은 `defineProps`로 이를 받을 수 있습니다:

```vue [app/pages/dashboard.vue]
<script setup lang="ts">
definePageMeta({
  layout: {
    name: 'admin',
    props: {
      sidebar: true,
    },
  },
})
</script>
```

```vue [app/layouts/admin.vue]
<script setup lang="ts">
const props = defineProps<{
  sidebar?: boolean
}>()
</script>
```

::read-more{to="/docs/4.x/directory-structure/app/layouts#passing-props-to-layouts"}
레이아웃에 props를 전달하는 방법을 더 알아보세요.
::

## Transitions %{#transitions}%

`<NuxtLayout />`는 들어오는 콘텐츠를 `<slot />`으로 렌더링하며, 이는 다시 Vue의 `<Transition />` 컴포넌트로 감싸져 레이아웃 전환을 활성화합니다. 이것이 기대한 대로 동작하려면 `<NuxtLayout />`가 페이지 컴포넌트의 루트 요소가 **아니어야** 합니다.

::code-group

```vue [app/pages/index.vue]
<template>
  <div>
    <NuxtLayout name="custom">
      <template #header>
        일부 헤더 템플릿 콘텐츠
      </template>
    </NuxtLayout>
  </div>
</template>
```

```vue [app/layouts/custom.vue]
<template>
  <div>
    <!-- 이름 있는 슬롯 -->
    <slot name="header" />
    <slot />
  </div>
</template>
```

::

:read-more{to="/docs/4.x/getting-started/transitions"}

## Layout의 Ref %{#layout-s-ref}%

레이아웃 컴포넌트의 ref를 얻으려면 `ref.value.layoutRef`를 통해 접근하세요.

::code-group

```vue [app/app.vue]
<script setup lang="ts">
const layout = ref()

function logFoo () {
  layout.value.layoutRef.foo()
}
</script>

<template>
  <NuxtLayout ref="layout">
    기본 레이아웃
  </NuxtLayout>
</template>
```

```vue [app/layouts/default.vue]
<script setup lang="ts">
const foo = () => console.log('foo')
defineExpose({
  foo,
})
</script>

<template>
  <div>
    기본 레이아웃
    <slot />
  </div>
</template>
```

::
