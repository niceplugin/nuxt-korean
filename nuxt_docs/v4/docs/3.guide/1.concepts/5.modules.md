## Nuxt Modules 살펴보기 %{#exploring-nuxt-modules}%

Nuxt로 프로덕션 수준의 애플리케이션을 개발하다 보면 프레임워크의 핵심 기능만으로는 충분하지 않다고 느낄 수 있습니다. Nuxt는 설정 옵션과 플러그인으로 확장할 수 있지만, 이런 커스터마이징을 여러 프로젝트에 걸쳐 유지하는 일은 번거롭고 반복적이며 시간이 많이 듭니다. 반대로 모든 프로젝트의 요구를 기본으로 지원하려 하면 Nuxt는 매우 복잡해지고 사용하기 어려워질 것입니다.

이것이 Nuxt가 코어를 확장할 수 있도록 모듈 시스템을 제공하는 이유 중 하나입니다. Nuxt 모듈은 [`nuxt dev`](/docs/4.x/api/commands/dev)로 개발 모드에서 Nuxt를 시작하거나 [`nuxt build`](/docs/4.x/api/commands/build)로 프로덕션 빌드를 할 때 순차적으로 실행되는 async 함수입니다. 템플릿을 재정의하고, webpack 로더를 설정하고, CSS 라이브러리를 추가하는 등 다양한 유용한 작업을 수행할 수 있습니다.

무엇보다 Nuxt 모듈은 npm 패키지로 배포할 수 있습니다. 덕분에 여러 프로젝트에서 재사용하고 커뮤니티와 공유할 수 있어, 고품질 애드온 생태계를 만드는 데 도움이 됩니다.

## Nuxt Modules 추가하기 %{#add-nuxt-modules}%

모듈을 설치한 뒤에는 [`nuxt.config.ts`](/docs/4.x/directory-structure/nuxt-config) 파일의 `modules` 속성 아래에 추가할 수 있습니다. 보통 모듈 개발자는 사용을 위한 추가 단계와 세부 사항도 함께 제공합니다.

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  modules: [
    // 패키지 이름 사용(권장 방식)
    '@nuxtjs/example',

    // 로컬 모듈 불러오기
    './modules/example',

    // 인라인 옵션과 함께 모듈 추가
    ['./modules/example', { token: '123' }],

    // 인라인 모듈 정의
    async (inlineOptions, nuxt) => { },
  ],
})
```

::warning
Nuxt 모듈은 이제 빌드 타임 전용이며, Nuxt 2에서 사용하던 `buildModules` 속성은 `modules`로 대체되어 deprecated 되었습니다.
::

## 모듈 비활성화 %{#disabling-modules}%

Nuxt config에서 모듈의 config key를 `false`로 설정하면 해당 모듈을 비활성화할 수 있습니다. 이는 특히 레이어에서 상속된 모듈을 끄고 싶을 때 유용합니다.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  // `@nuxt/image` 모듈 비활성화
  image: false,
})
```
