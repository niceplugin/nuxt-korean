Nuxt는 Nuxt 사용자에게 새로운 패턴을 가능하게 하는 Vue의 새 메이저 릴리스인 Vue 3를 통합합니다.

::note
Nuxt를 사용하기 위해 Vue에 대한 깊은 지식이 필수는 아니지만, [vuejs.org](https://vuejs.org)의 문서를 읽고 예제를 몇 개 살펴보는 것을 권장합니다.
::

Nuxt는 항상 프런트엔드 프레임워크로 Vue를 사용해 왔습니다.

우리가 Vue 위에 Nuxt를 구축한 이유는 다음과 같습니다:

- 데이터 변경이 인터페이스 변경을 자동으로 트리거하는 Vue의 반응성 모델.
- HTML을 웹의 공통 언어로 유지하면서도, 컴포넌트 기반 템플릿은 인터페이스를 일관되면서도 강력하게 유지할 수 있는 직관적인 패턴을 가능하게 합니다.
- 작은 프로젝트부터 대규모 웹 애플리케이션까지 Vue는 규모가 커져도 좋은 성능을 유지하여 애플리케이션이 계속 사용자에게 가치를 전달할 수 있게 합니다.

## Nuxt와 함께하는 Vue %{#vue-with-nuxt}%

### Single File Components %{#single-file-components}%

[Vue의 single-file components](https://vuejs.org/guide/scaling-up/sfc)(SFC 또는 `*.vue` 파일)는 Vue 컴포넌트의 마크업(`<template>`), 로직(`<script>`), 스타일(`<style>`)을 캡슐화합니다. Nuxt는 [Hot Module Replacement](https://vite.dev/guide/features#hot-module-replacement)와 함께 SFC에 대한 zero-config 경험을 제공하여 매끄러운 개발자 경험을 제공합니다.

### 자동 import %{#auto-imports}%

Nuxt 프로젝트의 [`app/components/`](/docs/4.x/directory-structure/app/components) 디렉터리에 만든 모든 Vue 컴포넌트는 별도로 import하지 않아도 프로젝트에서 사용할 수 있습니다. 어떤 컴포넌트도 사용되지 않으면 프로덕션 코드에 포함되지 않습니다.

:read-more{to="/docs/4.x/guide/concepts/auto-imports"}

### Vue Router %{#vue-router}%

대부분의 애플리케이션은 여러 페이지와 그 사이를 이동하는 방법이 필요합니다. 이를 **routing**이라고 합니다. Nuxt는 공식 [Vue Router library](https://router.vuejs.org)를 사용해 [`app/pages/`](/docs/4.x/directory-structure/app/pages) 디렉터리와 파일 명명 규칙을 기준으로 파일에 매핑된 route를 직접 생성합니다.

:read-more{to="/docs/4.x/getting-started/routing"}

:link-example{to="/docs/4.x/examples/features/auto-imports"}

## Nuxt 2 / Vue 2와의 차이 %{#differences-with-nuxt-2-vue-2}%

Nuxt 3+는 Vue 3를 기반으로 합니다. 새 메이저 Vue 버전은 Nuxt가 활용하는 여러 변화를 도입했습니다:

- 더 나은 성능
- Composition API
- TypeScript 지원

### 더 빠른 렌더링 %{#faster-rendering}%

Vue Virtual DOM(VDOM)은 처음부터 다시 작성되어 더 나은 렌더링 성능을 제공합니다. 여기에 더해, 컴파일된 Single-File Components로 작업할 때 Vue 컴파일러는 정적 마크업과 동적 마크업을 분리해 빌드 타임에 추가 최적화를 수행할 수 있습니다.

그 결과 첫 렌더링(컴포넌트 생성)과 업데이트가 더 빨라지고 메모리 사용량도 줄어듭니다. Nuxt 3에서는 더 빠른 서버 사이드 렌더링도 가능하게 합니다.

### 더 작은 번들 %{#smaller-bundle}%

Vue 3와 Nuxt 3에서는 번들 크기 감소에 많은 중점을 두었습니다. 버전 3에서는 템플릿 디렉티브와 내장 컴포넌트를 포함한 Vue 기능 대부분이 tree-shakable합니다. 사용하지 않으면 프로덕션 번들에 포함되지 않습니다.

이렇게 하면 최소한의 Vue 3 애플리케이션은 gzip 기준 12kb까지 줄일 수 있습니다.

### Composition API %{#composition-api}%

Vue 2에서 컴포넌트에 데이터와 로직을 제공하는 유일한 방법은 Options API였으며, 이는 `data`와 `methods` 같은 미리 정의된 속성으로 템플릿에 데이터와 메서드를 반환할 수 있게 했습니다:

```vue twoslash
<script>
export default {
  data () {
    return {
      count: 0,
    }
  },
  methods: {
    increment () {
      this.count++
    },
  },
}
</script>
```

Vue 3에 도입된 [Composition API](https://vuejs.org/guide/extras/composition-api-faq)는 Options API를 대체하는 것이 아니라, 애플리케이션 전반에서 로직 재사용을 더 잘 가능하게 하고 복잡한 컴포넌트에서 관심사별로 코드를 묶는 더 자연스러운 방법을 제공합니다.

`<script>` 정의에서 `setup` 키워드와 함께 사용하면, 위 컴포넌트는 Composition API와 Nuxt 3의 자동 import된 Reactivity API로 다음과 같이 다시 작성할 수 있습니다:

```vue twoslash [components/Counter.vue]
<script setup lang="ts">
const count = ref(0)
const increment = () => count.value++
</script>
```

Nuxt의 목표는 Composition API를 중심으로 뛰어난 개발자 경험을 제공하는 것입니다.

- Vue의 자동 import된 [Reactivity functions](https://vuejs.org/api/reactivity-core)과 Nuxt의 [built-in composables](/docs/4.x/api/composables/use-async-data)를 사용합니다.
- [`app/composables/` 디렉터리](/docs/4.x/directory-structure/app/composables)에 자동 import되는 재사용 가능한 함수를 직접 작성합니다.

### TypeScript 지원 %{#typescript-support}%

Vue 3와 Nuxt 3+는 모두 TypeScript로 작성되었습니다. 완전히 타입이 지정된 코드베이스는 실수를 줄이고 API 사용법을 문서화합니다. 그렇다고 이 이점을 누리기 위해 애플리케이션 전체를 TypeScript로 작성해야 하는 것은 아닙니다. Nuxt 3에서는 파일 확장자를 `.js`에서 `.ts`로 바꾸거나 컴포넌트에 `<script setup lang="ts">`를 추가해 선택적으로 도입할 수 있습니다.
