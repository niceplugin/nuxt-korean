Nuxt는 Nuxt 사용자를 위한 새로운 패턴을 가능하게 하는 Vue의 새로운 메이저 릴리스인 Vue 3를 통합합니다.

::note
Nuxt를 사용하는 데 Vue에 대한 심층적인 지식이 필수는 아니지만, [vuejs.org](https://vuejs.org)의 문서를 읽고 몇 가지 예제를 따라 해 보기를 권장합니다.
::

Nuxt는 항상 프론트엔드 프레임워크로 Vue를 사용해 왔습니다.

우리가 Nuxt를 Vue 위에 구축하기로 선택한 이유는 다음과 같습니다:

- 데이터의 변경이 자동으로 인터페이스의 변경을 트리거하는 Vue의 반응성 모델.
- 웹의 공통 언어로 HTML을 유지하면서도 컴포넌트 기반 템플릿을 사용하여, 직관적인 패턴으로 인터페이스를 일관되면서도 강력하게 유지할 수 있습니다.
- 작은 프로젝트부터 대규모 웹 애플리케이션까지, Vue는 규모가 커져도 성능을 잘 유지하여 애플리케이션이 사용자에게 지속적으로 가치를 제공할 수 있도록 합니다.

## Nuxt와 함께하는 Vue %{vue-with-nuxt}%

### 단일 파일 컴포넌트 %{single-file-components}%

[Vue의 단일 파일 컴포넌트](https://vuejs.org/guide/scaling-up/sfc) (SFC 또는 `*.vue` 파일)는 Vue 컴포넌트의 마크업(`<template>`), 로직(`<script>`), 스타일링(`<style>`)을 캡슐화합니다. Nuxt는 [Hot Module Replacement](https://vite.dev/guide/features#hot-module-replacement)를 통해 SFC에 대해 제로 설정 경험을 제공하여 매끄러운 개발자 경험을 제공합니다.

### 자동 임포트 %{auto-imports}%

Nuxt 프로젝트의 [`app/components/`](/docs/4.x/directory-structure/app/components) 디렉터리에서 생성된 모든 Vue 컴포넌트는 임포트할 필요 없이 프로젝트 내에서 사용할 수 있습니다. 컴포넌트가 어디에서도 사용되지 않는다면, 프로덕션 코드에는 포함되지 않습니다.

:read-more{to="/docs/4.x/guide/concepts/auto-imports"}

### Vue Router %{vue-router}%

대부분의 애플리케이션은 여러 페이지와 그 사이를 이동하는 방법이 필요합니다. 이를 **라우팅**이라고 합니다. Nuxt는 [`app/pages/`](/docs/4.x/directory-structure/app/pages) 디렉터리와 네이밍 규칙을 사용하여, 공식 [Vue Router 라이브러리](https://router.vuejs.org)를 통해 파일에 매핑된 라우트를 직접 생성합니다.

:read-more{to="/docs/4.x/getting-started/routing"}

:link-example{to="/docs/4.x/examples/features/auto-imports"}

## Nuxt 2 / Vue 2와의 차이점 %{differences-with-nuxt-2-vue-2}%

Nuxt 3+는 Vue 3를 기반으로 합니다. 새로운 메이저 Vue 버전은 Nuxt가 활용하는 여러 변경 사항을 도입합니다:

- 더 나은 성능
- Composition API
- TypeScript 지원

### 더 빠른 렌더링 %{faster-rendering}%

Vue Virtual DOM(VDOM)은 처음부터 다시 작성되어 더 나은 렌더링 성능을 제공합니다. 더 나아가, 컴파일된 단일 파일 컴포넌트와 함께 작업할 때 Vue 컴파일러는 정적 마크업과 동적 마크업을 분리하여 빌드 시점에 추가 최적화를 수행할 수 있습니다.

이로 인해 첫 렌더링(컴포넌트 생성)과 업데이트가 더 빨라지고, 메모리 사용량이 줄어듭니다. Nuxt 3에서는 서버 사이드 렌더링 또한 더 빨라집니다.

### 더 작은 번들 %{smaller-bundle}%

Vue 3와 Nuxt 3에서는 번들 크기 감소에 중점을 두었습니다. 버전 3에서는 템플릿 디렉티브와 내장 컴포넌트를 포함한 대부분의 Vue 기능이 트리 셰이킹이 가능합니다. 사용하지 않는 경우 프로덕션 번들에 포함되지 않습니다.

이 방식으로, 최소한의 Vue 3 애플리케이션은 gzip 기준 12kb까지 줄일 수 있습니다.

### Composition API %{composition-api}%

Vue 2에서 컴포넌트에 데이터와 로직을 제공하는 유일한 방법은 Options API였습니다. Options API는 `data`와 `methods`와 같은 미리 정의된 속성을 사용하여 템플릿에 데이터와 메서드를 반환할 수 있게 해줍니다:

```vue twoslash
<script>
export default {
  data () {
    return {
      count: 0,
    }
  },
  methods: {
    increment () {
      this.count++
    },
  },
}
</script>
```

Vue 3에서 도입된 [Composition API](https://vuejs.org/guide/extras/composition-api-faq)는 Options API를 대체하는 것이 아니라, 애플리케이션 전반에서 로직 재사용을 더 잘 할 수 있게 해 주며, 복잡한 컴포넌트에서 관심사별로 코드를 그룹화하는 보다 자연스러운 방법을 제공합니다.

`<script>` 정의에서 `setup` 키워드와 함께 사용하면, 위 컴포넌트를 Composition API와 Nuxt 3의 자동 임포트된 반응성 API를 사용해 다음과 같이 다시 작성할 수 있습니다:

```vue twoslash [components/Counter.vue]
<script setup lang="ts">
const count = ref(0)
const increment = () => count.value++
</script>
```

Nuxt의 목표는 Composition API를 중심으로 훌륭한 개발자 경험을 제공하는 것입니다.

- Vue의 자동 임포트된 [반응성 함수](https://vuejs.org/api/reactivity-core)와 Nuxt의 [내장 composable](/docs/4.x/api/composables/use-async-data)을 사용합니다.
- [`app/composables/` 디렉터리](/docs/4.x/directory-structure/app/composables)에 자동 임포트되는 재사용 가능한 함수를 직접 작성합니다.

### TypeScript 지원 %{typescript-support}%

Vue 3와 Nuxt 3+는 모두 TypeScript로 작성되었습니다. 완전히 타입이 지정된 코드베이스는 실수를 방지하고 API 사용법을 문서화합니다. 이는 이러한 이점을 누리기 위해 애플리케이션을 반드시 TypeScript로 작성해야 한다는 의미는 아닙니다. Nuxt 3에서는 파일 이름을 `.js`에서 `.ts`로 변경하거나, 컴포넌트에 `<script setup lang="ts">`를 추가하는 방식으로 선택적으로 사용할 수 있습니다.
