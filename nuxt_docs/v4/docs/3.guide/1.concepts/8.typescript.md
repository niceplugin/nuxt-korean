## 타입 검사 %{#type-checking}%

기본적으로 Nuxt는 성능상의 이유로 [`nuxt dev`](/docs/4.x/api/commands/dev) 또는 [`nuxt build`](/docs/4.x/api/commands/build)를 실행할 때 타입을 검사하지 않습니다.

빌드 또는 개발 시 타입 검사를 활성화하려면 `vue-tsc`와 `typescript`를 개발 의존성으로 설치하세요:

::code-group{sync="pm"}

  ```bash [npm]
  npm install --save-dev vue-tsc typescript
  ```

  ```bash [yarn]
  yarn add --dev vue-tsc typescript
  ```

  ```bash [pnpm]
  pnpm add -D vue-tsc typescript
  ```

  ```bash [bun]
  bun add -D vue-tsc typescript
  ```

  ```bash [deno]
  deno add -D npm:vue-tsc npm:typescript
  ```

::

그런 다음 [`nuxt typecheck`](/docs/4.x/api/commands/typecheck) 명령을 실행해 타입을 검사하세요:

```bash [Terminal]
npx nuxt typecheck
```

빌드 또는 개발 시 타입 검사를 활성화하려면 `nuxt.config` 파일에서 [`typescript.typeCheck`](/docs/4.x/api/nuxt-config#typecheck) 옵션을 사용할 수도 있습니다:

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  typescript: {
    typeCheck: true,
  },
})
```

## 자동 생성 타입 %{#auto-generated-types}%

Nuxt 프로젝트는 올바르게 동작하기 위해 자동 생성 타입에 의존합니다. 이 타입들은 [`.nuxt`](/docs/4.x/directory-structure/nuxt) 디렉터리에 저장되며, 개발 서버를 실행하거나 애플리케이션을 빌드할 때 생성됩니다. `nuxt prepare`를 실행해 이 파일들을 수동으로 생성할 수도 있습니다.

[`.nuxt`](/docs/4.x/directory-structure/nuxt) 디렉터리 내부에 생성되는 `tsconfig.json` 파일에는 프로젝트를 위한 **권장 기본 TypeScript 설정**, [auto-imports](/docs/4.x/guide/concepts/auto-imports)에 대한 참조, [API route types](/docs/4.x/guide/concepts/server-engine#typed-api-routes), `#imports`, `~/file`, `#build/file` 같은 경로 별칭 등이 포함됩니다.

::warning
Nuxt는 이 구성에 의존하며, [Nuxt modules](/docs/4.x/guide/modules)도 이를 확장할 수 있습니다. 이런 이유로 `tsconfig.json` 파일을 직접 수정하는 것은 권장되지 않습니다. 그렇게 하면 중요한 설정을 덮어쓸 수 있기 때문입니다. 대신 `nuxt.config.ts`를 통해 확장하세요. [여기에서 구성 확장에 대해 자세히 알아보세요](/docs/4.x/directory-structure/tsconfig).
::

::tip{icon="i-lucide-video" to="https://youtu.be/umLI7SlPygY" target="_blank"}
Daniel Roe가 Nuxt 내장 별칭을 설명하는 영상을 시청하세요.
::

## 프로젝트 참조 %{#project-references}%

Nuxt는 타입 검사 성능을 개선하고 더 나은 IDE 지원을 제공하기 위해 [TypeScript project references](https://www.typescriptlang.org/docs/handbook/project-references.html)를 사용합니다. 이 기능은 TypeScript가 코드베이스를 더 작고 관리하기 쉬운 조각으로 나눌 수 있게 합니다.

### Nuxt가 프로젝트 참조를 사용하는 방식 %{#how-nuxt-uses-project-references}%

`nuxt dev`, `nuxt build`, `nuxt prepare`를 실행하면 Nuxt는 애플리케이션의 서로 다른 부분을 위한 여러 `tsconfig.json` 파일을 생성합니다.

- **`.nuxt/tsconfig.app.json`** - `app/` 디렉터리 내부 애플리케이션 코드용 구성
- **`.nuxt/tsconfig.node.json`** - `nuxt.config.ts` 및 다른 컨텍스트 밖의 파일용 구성
- **`.nuxt/tsconfig.server.json`** - 서버 사이드 코드용 구성 (해당되는 경우)
- **`.nuxt/tsconfig.shared.json`** - 앱과 서버 컨텍스트 사이에서 공유되는 코드용 구성 (타입 및 환경 비특정 유틸리티 등)

이 파일들은 각각 적절한 의존성을 참조하고 해당 컨텍스트에 최적화된 타입 검사를 제공하도록 구성됩니다.

::note
하위 호환성을 위해 Nuxt는 여전히 `.nuxt/tsconfig.json`을 생성합니다. 하지만 더 나은 타입 안정성과 성능을 위해 새 구성 파일(`.nuxt/tsconfig.app.json`, `.nuxt/tsconfig.server.json` 등)과 함께 [TypeScript project references](/docs/4.x/directory-structure/tsconfig)를 사용하는 것을 권장합니다. 이 레거시 파일은 향후 Nuxt 버전에서 제거될 예정입니다.
::

### 프로젝트 참조의 장점 %{#benefits-of-project-references}%

- **더 빠른 빌드**: TypeScript가 변경되지 않은 프로젝트의 재빌드를 건너뛸 수 있습니다
- **더 나은 IDE 성능**: IDE가 더 빠른 IntelliSense와 오류 검사를 제공할 수 있습니다
- **격리된 컴파일**: 애플리케이션 한 부분의 오류가 다른 부분의 컴파일을 막지 않습니다
- **더 명확한 의존성 관리**: 각 프로젝트가 의존성을 명시적으로 선언합니다

### 프로젝트 참조로 타입 보강하기 %{#augmenting-types-with-project-references}%

프로젝트가 **여러 타입 컨텍스트**로 나뉘어 있으므로, 올바르게 인식되도록 하려면 **올바른 컨텍스트 안에서 타입을 보강하는 것**이 중요합니다. 적절한 컨텍스트에 명시적으로 포함되지 않으면 TypeScript는 이러한 디렉터리 밖에 배치된 보강을 인식하지 못합니다.

예를 들어 `app` 컨텍스트의 타입을 보강하고 싶다면 보강 파일을 `app/` 디렉터리에 두어야 합니다.

마찬가지로:
- `server` 컨텍스트용이라면 보강 파일을 `server/` 디렉터리에 둡니다.
- **앱과 서버 사이에서 공유되는** 타입이라면 파일을 `shared/` 디렉터리에 둡니다.

::read-more{to="/docs/4.x/guide/modules/recipes-advanced#extend-typescript-config"}
모듈 작성자 가이드에서 **해당 컨텍스트 밖의 파일**로 특정 타입 컨텍스트를 보강하는 방법을 더 알아보세요.
::

## 엄격한 검사 %{#strict-checks}%

TypeScript에는 프로그램에 더 높은 안전성과 분석 기능을 제공하는 여러 검사가 포함되어 있습니다.

Nuxt에서는 더 높은 타입 안정성을 제공하기 위해 [`typescript.typeCheck`](/docs/4.x/guide/concepts/typescript#type-checking) 옵션이 활성화되면 [엄격한 검사](https://www.typescriptlang.org/docs/handbook/migrating-from-javascript.html#getting-stricter-checks)가 기본적으로 활성화됩니다.

현재 코드베이스를 TypeScript로 전환 중이라면 `nuxt.config`에서 `strict`를 `false`로 설정해 엄격한 검사를 일시적으로 비활성화하고 싶을 수 있습니다:

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  typescript: {
    strict: false,
  },
})
```
