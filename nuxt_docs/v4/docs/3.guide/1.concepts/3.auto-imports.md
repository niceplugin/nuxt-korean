---
title: Auto-imports
description: "Nuxt는 컴포넌트, 컴포저블, 헬퍼 함수, Vue API를 auto-import합니다."
---

Nuxt는 컴포넌트, 컴포저블, [Vue.js API](https://vuejs.org/api/)를 명시적으로 import하지 않아도 애플리케이션 전반에서 사용할 수 있도록 auto-import합니다.

```vue twoslash [app/app.vue]
<script setup lang="ts">
const count = ref(1) // ref는 auto-import됩니다
</script>
```

정해진 관례가 있는 디렉터리 구조 덕분에 Nuxt는 [`app/components/`](/docs/4.x/directory-structure/app/components), [`app/composables/`](/docs/4.x/directory-structure/app/composables), [`app/utils/`](/docs/4.x/directory-structure/app/utils)를 auto-import할 수 있습니다.

고전적인 전역 선언과 달리, Nuxt는 타입 정보, IDE 자동 완성 및 힌트를 유지하면서 **프로덕션 코드에서 사용되는 것만 포함합니다**.

::note
문서에서 명시적으로 import되지 않은 모든 함수는 Nuxt가 auto-import하며 코드에서 그대로 사용할 수 있습니다. auto-import되는 컴포넌트, 컴포저블, 유틸리티에 대한 참조는 [API section](/docs/4.x/api)에서 확인할 수 있습니다.
::

::note
[`server`](/docs/4.x/directory-structure/server) 디렉터리에서는 Nuxt가 `server/utils/`에서 export된 함수와 변수를 auto-import합니다.
::

::note
`nuxt.config` 파일의 [`imports`](/docs/4.x/api/nuxt-config#imports) 섹션을 구성하면 사용자 정의 폴더나 서드파티 패키지에서 export된 함수도 auto-import할 수 있습니다.
::

## 내장 Auto-imports %{#built-in-auto-imports}%

Nuxt는 [데이터 가져오기](/docs/4.x/getting-started/data-fetching), [앱 컨텍스트](/docs/4.x/api/composables/use-nuxt-app)와 [런타임 설정](/docs/4.x/guide/going-further/runtime-config)에 대한 접근, [상태](/docs/4.x/getting-started/state-management) 관리, 컴포넌트와 플러그인 정의를 수행하기 위한 함수와 컴포저블을 auto-import합니다.

```vue twoslash
<script setup lang="ts">
/* useFetch()는 auto-import됩니다 */
const { data, refresh, status } = await useFetch('/api/hello')
</script>
```

Vue는 `ref`, `computed` 같은 반응성 API와 더불어 Nuxt가 auto-import하는 라이프사이클 훅과 헬퍼도 제공합니다.

```vue twoslash
<script setup lang="ts">
/* ref()와 computed()는 auto-import됩니다 */
const count = ref(1)
const double = computed(() => count.value * 2)
</script>
```

### Vue와 Nuxt 컴포저블 %{#vue-and-nuxt-composables}%

<!-- TODO: https://github.com/nuxt/nuxt/issues/14723와 함께 별도 페이지로 이동하고 더 많은 정보 추가 -->

Vue와 Nuxt가 제공하는 내장 Composition API 컴포저블을 사용할 때는, 그중 많은 것들이 올바른 _컨텍스트_에서 호출되어야 한다는 점에 유의해야 합니다.

컴포넌트 라이프사이클 동안 Vue는 전역 변수를 통해 현재 컴포넌트의 임시 인스턴스를 추적하고(마찬가지로 Nuxt는 `nuxtApp`의 임시 인스턴스를 추적함), 같은 tick 안에서 이를 해제합니다. 이는 서버 렌더링 시 필수적인데, 요청 간 상태 오염(두 사용자 사이에 공유 참조가 새는 문제)을 피하고 서로 다른 컴포넌트 간 누수도 방지하기 위해서입니다.

즉 (아주 드문 예외를 제외하면) Nuxt 플러그인, Nuxt 라우트 미들웨어, Vue setup 함수 밖에서는 이것들을 사용할 수 없습니다. 게다가 동기적으로 사용해야 합니다. 즉 `<script setup>` 블록 안, `defineNuxtComponent`로 선언된 컴포넌트의 setup 함수 안, `defineNuxtPlugin` 안, `defineNuxtRouteMiddleware` 안을 제외하면 컴포저블을 호출하기 전에 `await`를 사용할 수 없습니다. 이 위치들에서는 `await` 이후에도 동기 컨텍스트를 유지하도록 변환을 수행합니다.

`Nuxt instance is unavailable` 같은 오류 메시지가 나온다면, 아마도 Vue 또는 Nuxt 라이프사이클에서 잘못된 위치에서 Nuxt 컴포저블을 호출하고 있다는 뜻일 가능성이 높습니다.

:video-accordion{title="'Nuxt instance is unavailable' 오류를 피하는 방법에 대한 Alexander Lichter 영상 보기" videoId="ofuKRZLtOdY"}

::tip
SFC가 아닌 컴포넌트 안에서 Nuxt 컨텍스트가 필요한 컴포저블을 사용할 때는 `defineComponent` 대신 `defineNuxtComponent`로 컴포넌트를 감싸야 합니다
::

::read-more{to="/docs/4.x/guide/going-further/experimental-features#asynccontext" icon="i-lucide-star"}
비동기 함수에서 Nuxt 컴포저블을 사용하려면 `asyncContext` 실험적 기능을 확인해 보세요.
::

::read-more{to="https://github.com/nuxt/nuxt/issues/14269#issuecomment-1397352832" target="_blank"}
전체 설명은 이 GitHub 댓글에서 확인할 수 있습니다.
::

**깨지는 코드 예시:**

```ts twoslash [composables/example.ts]
// 컴포저블 밖에서 런타임 설정에 접근하려고 함
const config = useRuntimeConfig()

export const useMyComposable = () => {
  // 여기에서 런타임 설정에 접근
}
```

**동작하는 코드 예시:**

```ts twoslash [composables/example.ts]
export const useMyComposable = () => {
  // 컴포저블이 라이프사이클의 올바른 위치에서 호출되므로
  // 여기에서는 useRuntimeConfig가 동작합니다
  const config = useRuntimeConfig()

  // ...
}
```

## 디렉터리 기반 Auto-imports %{#directory-based-auto-imports}%

Nuxt는 정의된 디렉터리에 생성된 파일을 직접 auto-import합니다:

- `app/components/`: [Vue components](/docs/4.x/directory-structure/app/components)용.
- `app/composables/`: [Vue composables](/docs/4.x/directory-structure/app/composables)용.
- `app/utils/`: helper 함수 및 기타 유틸리티용.

:link-example{to="/docs/4.x/examples/features/auto-imports"}

::warning
**Auto-import된 `ref`와 `computed`는 컴포넌트 `<template>`에서 언래핑되지 않습니다.** :br
이는 Vue가 템플릿의 최상위가 아닌 ref를 다루는 방식 때문입니다. 자세한 내용은 [Vue 문서](https://vuejs.org/guide/essentials/reactivity-fundamentals#caveat-when-unwrapping-in-templates)에서 읽어볼 수 있습니다.
::

### 명시적 Imports %{#explicit-imports}%

Nuxt는 모든 auto-import를 `#imports` 별칭으로 노출하므로 필요할 때 import를 명시적으로 작성할 수 있습니다:

<!-- TODO:twoslash: Twoslash는 아직 tsconfig 경로를 지원하지 않음 -->

```vue
<script setup lang="ts">
import { computed, ref } from '#imports'

const count = ref(1)
const double = computed(() => count.value * 2)
</script>
```

### Auto-imports 비활성화 %{#disabling-auto-imports}%

컴포저블과 유틸리티의 auto-import를 비활성화하고 싶다면 `nuxt.config` 파일에서 `imports.autoImport`를 `false`로 설정할 수 있습니다.

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  imports: {
    autoImport: false,
  },
})
```

이렇게 하면 auto-import가 완전히 비활성화되지만, 여전히 `#imports`에서 [명시적 imports](/docs/4.x/guide/concepts/auto-imports#explicit-imports)를 사용할 수 있습니다.

### Auto-imports 부분 비활성화 %{#partially-disabling-auto-imports}%

`ref` 같은 프레임워크 전용 함수는 계속 auto-import되도록 유지하면서 자신의 코드(예: 사용자 정의 컴포저블)에 대한 auto-import만 비활성화하고 싶다면 `nuxt.config.ts` 파일에서 `imports.scan` 옵션을 `false`로 설정할 수 있습니다:

```ts
export default defineNuxtConfig({
  imports: {
    scan: false,
  },
})
```

이 구성에서는:
- `ref`, `computed`, `watch` 같은 프레임워크 함수는 여전히 수동 import 없이 동작합니다.
- 컴포저블 같은 사용자 정의 코드는 파일 안에서 수동으로 import해야 합니다.

::warning
**주의:** 이 설정에는 몇 가지 제한이 있습니다:
- 프로젝트를 layers 구조로 구성했다면 auto-import에 의존하는 대신 각 레이어의 컴포저블을 명시적으로 import해야 합니다.
- 이는 레이어 시스템의 override 기능을 깨뜨립니다. `imports.scan: false`를 사용한다면 이 부작용을 이해하고 그에 맞게 아키텍처를 조정해야 합니다.
::

## Auto-import된 컴포넌트 %{#auto-imported-components}%

Nuxt는 `~/components` 디렉터리의 컴포넌트도 자동으로 import하지만, 이는 컴포저블과 유틸리티 함수의 auto-import와는 별도로 구성됩니다.

:read-more{to="/docs/4.x/directory-structure/app/components"}

자신의 `~/components` 디렉터리에서 컴포넌트 auto-import를 비활성화하려면 `components.dirs`를 빈 배열로 설정할 수 있습니다 (단, 이는 모듈이 추가한 컴포넌트에는 영향을 주지 않습니다).

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  components: {
    dirs: [],
  },
})
```

## 서드파티 패키지에서 Auto-import %{#auto-import-from-third-party-packages}%

Nuxt는 서드파티 패키지에서의 auto-import도 허용합니다.

::tip
해당 패키지용 Nuxt 모듈을 사용하고 있다면, 그 모듈이 이미 해당 패키지에 대한 auto-import를 구성했을 가능성이 높습니다.
::

예를 들어 `vue-i18n` 패키지의 `useI18n` 컴포저블 auto-import를 다음과 같이 활성화할 수 있습니다:

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  imports: {
    presets: [
      {
        from: 'vue-i18n',
        imports: ['useI18n'],
      },
    ],
  },
})
```
