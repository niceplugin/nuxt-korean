## 소개 %{#introduction}%

이 레시피에서는 클라이언트 측과 서버 측 세션 데이터를 관리하기 위한 편리한 유틸리티를 제공하는 [Nuxt Auth Utils](https://github.com/Atinux/nuxt-auth-utils)를 사용해 풀스택 Nuxt 앱에서 인증을 설정합니다.

이 모듈은 보안 처리되고 봉인된 쿠키를 사용해 세션 데이터를 저장하므로, 세션 데이터를 저장하기 위한 데이터베이스를 설정할 필요가 없습니다.

## nuxt-auth-utils 설치 %{#install-nuxt-auth-utils}%

`nuxt` CLI를 사용해 `nuxt-auth-utils` 모듈을 설치합니다.

```bash [Terminal]
npx nuxt module add auth-utils
```

::callout
이 명령은 `nuxt-auth-utils`를 의존성으로 설치하고 `nuxt.config.ts`의 `modules` 섹션에 추가합니다
::

## 쿠키 암호화 키 %{#cookie-encryption-key}%

`nuxt-auth-utils`는 봉인된 쿠키를 사용해 세션 데이터를 저장하므로, 세션 쿠키는 `NUXT_SESSION_PASSWORD` 환경 변수의 비밀 키를 사용해 암호화됩니다.

::note
설정되어 있지 않으면 개발 모드에서 실행할 때 이 환경 변수가 `.env`에 자동으로 추가됩니다.
::

```ini [.env]
NUXT_SESSION_PASSWORD=a-random-password-with-at-least-32-characters
```

::important
배포하기 전에 이 환경 변수를 프로덕션 환경에 추가해야 합니다.
::

## 로그인 API 라우트 %{#login-api-route}%

이 레시피에서는 정적 데이터를 기반으로 사용자를 로그인시키는 간단한 API 라우트를 만듭니다.

요청 본문에 이메일과 비밀번호를 담은 POST 요청을 받는 `/api/login` API 라우트를 만들어 보겠습니다.

```ts [server/api/login.post.ts]
import { z } from 'zod'

const bodySchema = z.object({
  email: z.email(),
  password: z.string().min(8),
})

export default defineEventHandler(async (event) => {
  const { email, password } = await readValidatedBody(event, bodySchema.parse)

  if (email === 'admin@admin.com' && password === 'iamtheadmin') {
    // 쿠키에 사용자 세션을 설정합니다
    // 이 서버 유틸은 auth-utils 모듈에 의해 자동으로 임포트됩니다
    await setUserSession(event, {
      user: {
        name: 'John Doe',
      },
    })
    return {}
  }
  throw createError({
    status: 401,
    message: '잘못된 자격 증명입니다',
  })
})
```

::callout
프로젝트에 `zod` 의존성을 설치했는지 확인하세요 (`npm i zod`).
::

::tip{to="https://github.com/atinux/nuxt-auth-utils#server-utils"}
`nuxt-auth-utils`가 제공하는 `setUserSession` 서버 헬퍼에 대해 더 알아보세요.
::

## 로그인 페이지 %{#login-page}%

이 모듈은 애플리케이션에서 사용자가 인증되었는지 알 수 있는 Vue 컴포저블을 제공합니다:

```vue
<script setup>
const { loggedIn, session, user, clear, fetch } = useUserSession()
</script>
```

`/api/login` 라우트로 로그인 데이터를 제출하는 폼이 있는 로그인 페이지를 만들어 보겠습니다.

```vue [app/pages/login.vue]
<script setup lang="ts">
const { loggedIn, user, fetch: refreshSession } = useUserSession()
const credentials = reactive({
  email: '',
  password: '',
})
async function login () {
  try {
    await $fetch('/api/login', {
      method: 'POST',
      body: credentials,
    })

    // 클라이언트 측에서 세션을 새로고침하고 홈 페이지로 리디렉션합니다
    await refreshSession()
    await navigateTo('/')
  } catch {
    alert('잘못된 자격 증명입니다')
  }
}
</script>

<template>
  <form @submit.prevent="login">
    <input
      v-model="credentials.email"
      type="email"
      placeholder="이메일"
    >
    <input
      v-model="credentials.password"
      type="password"
      placeholder="비밀번호"
    >
    <button type="submit">
      로그인
    </button>
  </form>
</template>
```

## API 라우트 보호 %{#protect-api-routes}%

데이터를 안전하게 지키려면 서버 라우트를 보호하는 것이 핵심입니다. 클라이언트 측 미들웨어는 사용자에게 도움이 되지만, 서버 측 보호가 없으면 데이터에 여전히 접근할 수 있습니다. 민감한 데이터가 있는 모든 라우트는 반드시 보호해야 하며, 사용자가 로그인하지 않은 경우 401 오류를 반환해야 합니다.

`auth-utils` 모듈은 사용자가 로그인되어 있고 활성 세션을 가지고 있는지 확인할 수 있도록 `requireUserSession` 유틸리티 함수를 제공합니다.

인증된 사용자만 접근할 수 있는 `/api/user/stats` 라우트 예제를 만들어 보겠습니다.

```ts [server/api/user/stats.get.ts]
export default defineEventHandler(async (event) => {
  // 사용자가 로그인되어 있는지 확인합니다
  // 요청이 유효한 사용자 세션에서 오지 않으면 401 오류를 발생시킵니다
  const { user } = await requireUserSession(event)

  // TODO: 사용자를 기반으로 일부 통계를 가져옵니다

  return {}
})
```

## 앱 라우트 보호 %{#protect-app-routes}%

서버 측 라우트가 있으므로 데이터는 안전하지만, 아무 조치도 하지 않으면 인증되지 않은 사용자가 `/users` 페이지에 접근하려 할 때 이상한 데이터를 받게 될 수 있습니다. 클라이언트 측에서 라우트를 보호하고 사용자를 로그인 페이지로 리디렉션하기 위해 [클라이언트 측 미들웨어](https://nuxt.com/docs/4.x/directory-structure/app/middleware)를 만들어야 합니다.

`nuxt-auth-utils`는 편리한 `useUserSession` 컴포저블을 제공하며, 이를 사용해 사용자가 로그인되어 있는지 확인하고 로그인되지 않았다면 리디렉션합니다.

`/middleware` 디렉터리에 미들웨어를 만듭니다. 서버와 달리 클라이언트 측 미들웨어는 모든 엔드포인트에 자동으로 적용되지 않으므로, 적용할 위치를 직접 지정해야 합니다.

```typescript [app/middleware/authenticated.ts]
export default defineNuxtRouteMiddleware(() => {
  const { loggedIn } = useUserSession()

  // 인증되지 않은 경우 사용자를 로그인 화면으로 리디렉션합니다
  if (!loggedIn.value) {
    return navigateTo('/login')
  }
})
```

## 홈 페이지 %{#home-page}%

이제 라우트를 보호하는 앱 미들웨어가 있으므로, 인증된 사용자 정보를 표시하는 홈 페이지에 이를 사용할 수 있습니다. 사용자가 인증되지 않은 경우 로그인 페이지로 리디렉션됩니다.

보호하려는 라우트에 미들웨어를 적용하기 위해 [`definePageMeta`](/docs/4.x/api/utils/define-page-meta)를 사용합니다.

```vue [app/pages/index.vue]
<script setup lang="ts">
definePageMeta({
  middleware: ['authenticated'],
})

const { user, clear: clearSession } = useUserSession()

async function logout () {
  await clearSession()
  await navigateTo('/login')
}
</script>

<template>
  <div>
    <h1>{{ user.name }}님, 환영합니다</h1>
    <button @click="logout">
      로그아웃
    </button>
  </div>
</template>
```

세션을 지우고 사용자를 로그인 페이지로 리디렉션하는 로그아웃 버튼도 추가했습니다.

## 결론 %{#conclusion}%

Nuxt 앱에서 아주 기본적인 사용자 인증과 세션 관리를 성공적으로 설정했습니다. 또한 인증된 사용자만 접근할 수 있도록 서버와 클라이언트 측에서 민감한 라우트를 보호했습니다.

다음 단계로는 다음을 할 수 있습니다:
- [20개 이상의 지원되는 OAuth 공급자](https://github.com/atinux/nuxt-auth-utils?tab=readme-ov-file#supported-oauth-providers)를 사용한 인증 추가
- 사용자를 저장할 데이터베이스 추가, [Nitro SQL Database](https://nitro.build/guide/database) 또는 [NuxtHub SQL Database](https://hub.nuxt.com/docs/database) 참고
- [비밀번호 해싱](https://github.com/atinux/nuxt-auth-utils?tab=readme-ov-file#password-hashing)을 사용해 이메일과 비밀번호로 사용자가 가입할 수 있게 하기
- [WebAuthn / 패스키](https://github.com/atinux/nuxt-auth-utils?tab=readme-ov-file#webauthn-passkey) 지원 추가

OAuth 인증, 데이터베이스, CRUD 작업이 포함된 Nuxt 앱의 전체 예제를 보려면 오픈 소스 [atidone 저장소](https://github.com/atinux/atidone)를 확인해 보세요.
