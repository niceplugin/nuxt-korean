Nuxt의 일부 기능은 옵트인 방식으로 제공되거나 필요에 따라 비활성화할 수 있습니다.

## `features` %{#features}%

### devLogs %{#devlogs}%

개발하는 동안 서버 로그를 클라이언트로 스트리밍합니다. 이러한 로그는 `dev:ssr-logs` 훅에서 처리할 수 있습니다.

기본적으로 이는 개발 환경에서 활성화됩니다 (테스트 모드가 활성화되지 않은 경우).

`silent`로 설정하면 로그가 브라우저 콘솔에 출력되지 않습니다.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  features: {
    devLogs: true,
  },
})
```

### inlineStyles %{#inlinestyles}%

HTML을 렌더링할 때 스타일을 인라인으로 삽입합니다. 현재는 Vite를 사용할 때만 지원됩니다.

Vue 컴포넌트의 경로를 받아 해당 컴포넌트의 스타일을 인라인으로 넣을지 여부를 나타내는 boolean을 반환하는 함수를 전달할 수도 있습니다.

기본값은 `(id) => id.includes('.vue')`입니다.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  features: {
    inlineStyles: false, // or a function to determine inlining
  },
})
```

### noScripts %{#noscripts}%

Nuxt 스크립트와 JavaScript 리소스 힌트의 렌더링을 끕니다. `routeRules` 안에서도 세밀하게 구성할 수 있습니다.

`routeRules` 안에서 스크립트를 더 세밀하게 비활성화할 수도 있습니다.

`'production'` 또는 `true`로 설정하면 JavaScript는 프로덕션 모드에서만 비활성화됩니다. `'all'`로 설정하면 개발 및 프로덕션 모드 모두에서 JavaScript가 비활성화됩니다.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  features: {
    noScripts: true, // or 'production' | 'all' | false
  },
})
```

## `future` %{#future}%

프레임워크의 향후 버전(주 버전일 수도 있음)에서 기본값이 될 새 기능에 미리 opt-in할 수 있는 `future` 네임스페이스도 있습니다.

### compatibilityVersion %{#compatibilityversion}%

이 옵션은 Nuxt 기능이나 플래그에 대한 조기 접근을 활성화합니다.

`compatibilityVersion`을 `5`로 설정하면 [Vite Environment API](/docs/4.x/guide/going-further/experimental-features#viteenvironmentapi) 활성화를 포함해 Nuxt 구성 전반의 기본값이 Nuxt v5 동작에 opt-in하도록 변경됩니다.

```ts
export default defineNuxtConfig({
  future: {
    compatibilityVersion: 5,
  },
})
```

::read-more{to="/docs/4.x/getting-started/upgrade#testing-nuxt-5"}
Nuxt 5 테스트에 대해 자세히 알아보세요.
::

### multiApp %{#multiapp}%

이 옵션은 실험적인 멀티 앱 지원에 대한 조기 접근을 활성화합니다. [추적 이슈 #21635](https://github.com/nuxt/nuxt/issues/21635)를 통해 Nuxt의 멀티 앱 지원 진행 상황을 확인할 수 있습니다.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  future: {
    multiApp: true,
  },
})
```

### typescriptBundlerResolution %{#typescriptbundlerresolution}%

이 옵션은 TypeScript에 'Bundler' 모듈 해석 모드를 활성화하며, 이는 Nuxt나 [Vite](https://vite.dev/guide/performance#reduce-resolve-operations) 같은 프레임워크에 권장되는 설정입니다.

`exports`를 사용하는 최신 라이브러리를 사용할 때 타입 지원을 개선합니다.

[원래 TypeScript pull request](https://github.com/microsoft/TypeScript/pull/51669)를 참고하세요.

이를 false로 설정하면 TypeScript의 기본값인 레거시 'Node' 모드를 사용할 수 있습니다.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  future: {
    typescriptBundlerResolution: false,
  },
})
```
