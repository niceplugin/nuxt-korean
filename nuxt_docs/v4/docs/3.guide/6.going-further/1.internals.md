이 가이드는 Nuxt 내부 구조를 더 잘 이해해 Nuxt 위에서 새로운 솔루션과 모듈 통합을 개발하는 데 도움을 줍니다.

## Nuxt 인터페이스 %{#the-nuxt-interface}%

[`nuxt dev`](/docs/4.x/api/commands/dev)로 개발 모드에서 Nuxt를 시작하거나 [`nuxt build`](/docs/4.x/api/commands/build)로 프로덕션 애플리케이션을 빌드할 때,
공통 컨텍스트가 생성되며 내부적으로는 이를 `nuxt`라고 부릅니다. 여기에는 `nuxt.config` 파일과 병합된 정규화 옵션,
일부 내부 상태, 그리고 [unjs/hookable](https://github.com/unjs/hookable) 기반의 강력한 [hooking system](/docs/4.x/api/advanced/hooks)이 포함되어
서로 다른 컴포넌트가 서로 통신할 수 있게 합니다. 이를 **Builder Core**라고 생각할 수 있습니다.

이 컨텍스트는 [Nuxt Kit](/docs/4.x/guide/going-further/kit) 컴포저블과 함께 사용할 수 있도록 전역에서 사용 가능합니다.
따라서 프로세스당 하나의 Nuxt 인스턴스만 실행할 수 있습니다.

Nuxt 인터페이스를 확장하고 빌드 프로세스의 여러 단계에 연결하려면 [Nuxt modules](/docs/4.x/guide/modules)를 사용할 수 있습니다.

더 자세한 내용은 [소스 코드](https://github.com/nuxt/nuxt/blob/main/packages/nuxt/src/core/nuxt.ts)를 확인하세요.

## NuxtApp 인터페이스 %{#the-nuxtapp-interface}%

브라우저나 서버에서 페이지를 렌더링할 때는 공유 컨텍스트가 생성되며 이를 `nuxtApp`이라고 부릅니다.
이 컨텍스트는 vue 인스턴스, 런타임 hooks, 그리고 hydration을 위한 ssrContext와 payload 같은 내부 상태를 보관합니다.
이를 **Runtime Core**라고 생각할 수 있습니다.

이 컨텍스트는 Nuxt plugins, `<script setup>`, vue composables 안에서 [`useNuxtApp()`](/docs/4.x/api/composables/use-nuxt-app) 컴포저블로 접근할 수 있습니다.
브라우저에서는 전역 사용이 가능하지만, 사용자 간 컨텍스트 공유를 막기 위해 서버에서는 불가능합니다.

[`useNuxtApp`](/docs/4.x/api/composables/use-nuxt-app)은 현재 컨텍스트를 사용할 수 없으면 예외를 발생시키므로, composable이 항상 `nuxtApp`을 필요로 하지 않는다면 대신 [`tryUseNuxtApp`](/docs/4.x/api/composables/use-nuxt-app#tryusenuxtapp)을 사용할 수 있으며 이 경우 예외 대신 `null`을 반환합니다.

`nuxtApp` 인터페이스를 확장하고 여러 단계에 연결하거나 컨텍스트에 접근하려면 [Nuxt Plugins](/docs/4.x/directory-structure/app/plugins)를 사용할 수 있습니다.

[Nuxt App](/docs/4.x/api/composables/use-nuxt-app)에서 이 인터페이스에 대한 더 많은 정보를 확인하세요.

`nuxtApp`에는 다음과 같은 속성이 있습니다:

```ts
interface NuxtApp {
  vueApp // 전역 Vue 애플리케이션: https://vuejs.org/api/application.html#application-api

  versions // Nuxt와 Vue 버전이 담긴 객체

  // 런타임 NuxtApp hooks를 호출하고 추가할 수 있습니다
  // https://github.com/nuxt/nuxt/blob/main/packages/nuxt/src/app/nuxt.ts#L18
  hooks
  hook
  callHook

  // 서버 사이드에서만 접근 가능
  ssrContext: {
    url
    req
    res
    runtimeConfig
    noSSR
  }

  // 이것은 문자열화되어 서버에서 클라이언트로 전달됩니다
  payload: {
    serverRendered: true
    data: {}
    state: {}
  }

  provide: (name: string, value: any) => void
}
```

더 자세한 내용은 [소스 코드](https://github.com/nuxt/nuxt/blob/main/packages/nuxt/src/app/nuxt.ts)를 확인하세요.

## 런타임 컨텍스트 vs. 빌드 컨텍스트 %{#runtime-context-vs-build-context}%

Nuxt는 Node.js를 사용해 프로젝트를 빌드하고 번들링하지만 런타임 측면도 함께 가지고 있습니다.

두 영역 모두 확장할 수 있지만 런타임 컨텍스트는 빌드 타임과 분리되어 있습니다. 따라서 런타임 설정을 제외한 상태, 코드, 컨텍스트를 서로 공유해서는 안 됩니다!

`nuxt.config`와 [Nuxt modules](/docs/4.x/guide/modules)는 빌드 컨텍스트를 확장하는 데 사용할 수 있고, [Nuxt Plugins](/docs/4.x/directory-structure/app/plugins)는 런타임을 확장하는 데 사용할 수 있습니다.

프로덕션용 애플리케이션을 빌드하면 `nuxt build`는 `nuxt.config`와 [Nuxt modules](/docs/4.x/guide/modules)와 독립적인 standalone build를 `.output` 디렉터리에 생성합니다.
