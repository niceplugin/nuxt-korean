---
title: Nuxt 레이어 작성하기
description: Nuxt는 기본 파일, 설정 등을 확장할 수 있게 해주는 강력한 시스템을 제공합니다.
---

Nuxt 레이어는 모노레포 안에서, 또는 git 저장소나 npm 패키지로부터 부분적인 Nuxt 애플리케이션을 공유하고 재사용할 수 있게 해주는 강력한 기능입니다. 레이어 구조는 표준 Nuxt 애플리케이션과 거의 동일하므로 작성하고 유지보수하기 쉽습니다.

:read-more{to="/docs/4.x/getting-started/layers"}

최소한의 Nuxt 레이어 디렉터리에는 이것이 레이어임을 나타내는 [`nuxt.config.ts`](/docs/4.x/directory-structure/nuxt-config) 파일이 있어야 합니다.

```ts [base/nuxt.config.ts]
export default defineNuxtConfig({})
```

또한 레이어 디렉터리의 특정 파일들은 자동으로 스캔되어, 이 레이어를 확장하는 프로젝트에서 Nuxt가 사용하게 됩니다.

- [`app/components/*`](/docs/4.x/directory-structure/app/components)   - 기본 컴포넌트를 확장합니다
- [`app/composables/*`](/docs/4.x/directory-structure/app/composables)  - 기본 컴포저블을 확장합니다
- [`app/layouts/*`](/docs/4.x/directory-structure/app/layouts)  - 기본 레이아웃을 확장합니다
- [`app/middleware/*`](/docs/4.x/directory-structure/app/middleware)  - 기본 미들웨어를 확장합니다
- [`app/pages/*`](/docs/4.x/directory-structure/app/pages)        - 기본 페이지를 확장합니다
- [`app/plugins/*`](/docs/4.x/directory-structure/app/plugins)        - 기본 플러그인을 확장합니다
- [`app/utils/*`](/docs/4.x/directory-structure/app/utils)   - 기본 utils를 확장합니다
- [`app/app.config.ts`](/docs/4.x/directory-structure/app/app-config)  - 기본 app config를 확장합니다
- [`server/*`](/docs/4.x/directory-structure/server)       - 기본 서버 엔드포인트와 미들웨어를 확장합니다
- [`nuxt.config.ts`](/docs/4.x/directory-structure/nuxt-config)- 기본 nuxt config를 확장합니다

## 기본 예제 %{#basic-example}%

::code-tree{defaultValue="nuxt.config.ts" expandAll}

  ```ts [nuxt.config.ts]
  export default defineNuxtConfig({
    extends: [
      './base',
    ],
  })
  ```

  ```vue [app/app.vue]
  <template>
    <BaseComponent />
  </template>
  ```

  ```ts [base/nuxt.config.ts]
  export default defineNuxtConfig({
    // base nuxt.config.ts를 확장합니다!
    app: {
      head: {
        title: 'Extending Configs is Fun!',
        meta: [
          { name: 'description', content: 'I am using the extends feature in Nuxt!' },
        ],
      },
    },
  })
  ```

  ```vue [base/app/components/BaseComponent.vue]
  <template>
    <h1>Extending Components is Fun!</h1>
  </template>
  ```

::

## 레이어 우선순위 %{#layer-priority}%

여러 레이어를 확장할 때는 override 순서를 이해하는 것이 중요합니다. 같은 파일이나 컴포넌트를 정의한 경우 **우선순위가 더 높은** 레이어가 더 낮은 레이어를 덮어씁니다.

우선순위는 높은 것부터 낮은 것 순으로 다음과 같습니다:

1. **프로젝트 파일** - 항상 가장 높은 우선순위를 가집니다
2. `~~/layers` 디렉터리의 **자동 스캔 레이어** - 알파벳순으로 정렬됩니다(Z가 A보다 우선순위가 높음)
3. `extends` 설정의 **레이어들** - 첫 번째 항목이 두 번째 항목보다 우선순위가 높습니다

### 각각 언제 사용할까 %{#when-to-use-each}%

- **`extends`** - 외부 의존성(npm 패키지, 원격 저장소)이나 프로젝트 디렉터리 밖의 레이어에 사용합니다
- **`~~/layers` directory** - 프로젝트 일부인 로컬 레이어에 사용합니다

::tip
자동 스캔 레이어의 순서를 제어해야 한다면 앞에 숫자 접두사를 붙일 수 있습니다: `~/layers/1.z-layer`, `~/layers/2.a-layer`. 이렇게 하면 `2.a-layer`가 `1.z-layer`보다 더 높은 우선순위를 갖습니다.
::

### 예제 %{#example}%

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: [
    // 프로젝트 외부의 로컬 레이어
    '../base',
    // NPM 패키지
    '@my-themes/awesome',
    // 원격 저장소
    'github:my-themes/awesome#v1',
  ],
})
```

`~~/layers/custom`도 있다면 우선순위는 다음과 같습니다:
- 프로젝트 파일(가장 높음)
- `~~/layers/custom`
- `../base`
- `@my-themes/awesome`
- `github:my-themes/awesome#v1` (가장 낮음)

즉, 프로젝트 파일은 어떤 레이어보다도 우선하며, `~~/layers/custom`은 `extends`에 있는 어떤 항목보다도 우선합니다.

## 스타터 템플릿 %{#starter-template}%

시작하려면 [nuxt/starter/layer template](https://github.com/nuxt/starter/tree/layer)로 레이어를 초기화할 수 있습니다. 그러면 그 위에 확장해 나갈 수 있는 기본 구조가 생성됩니다. 시작하려면 터미널에서 다음 명령어를 실행하세요:

```bash [Terminal]
npm create nuxt -- --template layer nuxt-layer
```

다음 단계는 README 지침을 따라 진행하세요.

## 레이어 배포 %{#publishing-layers}%

원격 소스나 npm 패키지를 사용해 레이어를 배포하고 공유할 수 있습니다.

### Git 저장소 %{#git-repository}%

git 저장소를 사용해 Nuxt 레이어를 공유할 수 있습니다. 몇 가지 예시는 다음과 같습니다:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: [
    // GitHub 원격 소스
    'github:username/repoName',
    // /base 디렉터리 안의 GitHub 원격 소스
    'github:username/repoName/base',
    // dev 브랜치의 GitHub 원격 소스
    'github:username/repoName#dev',
    // v1.0.0 태그의 GitHub 원격 소스
    'github:username/repoName#v1.0.0',
    // GitLab 원격 소스 예시
    'gitlab:username/repoName',
    // Bitbucket 원격 소스 예시
    'bitbucket:username/repoName',
  ],
})
```

::tip
비공개 원격 소스를 확장하려면 토큰을 제공하기 위해 `GIGET_AUTH=<token>` 환경 변수를 추가해야 합니다.
::

::tip
셀프 호스팅 GitHub 또는 GitLab 인스턴스의 원격 소스를 확장하려면 `GIGET_GITHUB_URL=<url>` 또는 `GIGET_GITLAB_URL=<url>` 환경 변수로 해당 URL을 제공해야 합니다. 또는 `nuxt.config`에서 [`auth` 옵션](https://github.com/unjs/c12#extending-config-layer-from-remote-sources)으로 직접 설정할 수도 있습니다.
::

::warning
원격 소스를 레이어로 확장하는 경우, Nuxt 바깥에서는 그 의존성에 접근할 수 없다는 점에 유의하세요. 예를 들어 원격 레이어가 eslint 플러그인에 의존하더라도, 그것은 여러분의 eslint config에서 사용할 수 없습니다. 이러한 의존성은 패키지 매니저가 접근할 수 없는 특별한 위치(`node_modules/.c12/layer_name/node_modules/`)에 놓이기 때문입니다.
::

::note
git 원격 소스를 사용할 때 레이어에 npm 의존성이 있고 이를 설치하고 싶다면, 레이어 옵션에서 `install: true`를 지정하면 됩니다.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: [
    ['github:username/repoName', { install: true }],
  ],
})
```
::

### npm 패키지 %{#npm-package}%

Nuxt 레이어를 원하는 파일과 의존성을 포함한 npm 패키지로 배포할 수 있습니다. 이를 통해 설정을 다른 사람과 공유하거나, 여러 프로젝트에서 사용하거나, 비공개로 활용할 수 있습니다.

npm 패키지에서 확장하려면 해당 모듈이 npm에 배포되어 있고 사용자의 프로젝트에 devDependency로 설치되어 있어야 합니다. 그런 다음 모듈 이름을 사용해 현재 nuxt config를 확장할 수 있습니다:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: [
    // scope가 있는 Node 모듈
    '@scope/moduleName',
    // 또는 모듈 이름만
    'moduleName',
  ],
})
```

레이어 디렉터리를 npm 패키지로 배포하려면 `package.json`에 올바른 속성이 채워져 있는지 확인해야 합니다. 이렇게 해야 패키지를 배포할 때 필요한 파일이 포함됩니다.

```json [package.json]
{
  "name": "my-theme",
  "version": "1.0.0",
  "type": "module",
  "main": "./nuxt.config.ts",
  "dependencies": {},
  "devDependencies": {
    "nuxt": "^3.0.0"
  }
}
```

::important
레이어에서 import하는 모든 의존성은 `dependencies`에 **명시적으로 추가**되어 있어야 합니다. `nuxt` 의존성과, 배포 전에 레이어를 테스트할 때만 사용하는 항목은 `devDependencies` 필드에 남겨 두어야 합니다.
::

이제 모듈을 npm에 공개 또는 비공개로 배포할 수 있습니다.

::important
레이어를 비공개 npm 패키지로 배포할 때는 node 모듈을 다운로드하기 위해 npm에 인증할 수 있도록 로그인되어 있어야 합니다.
::

## 팁 %{#tips}%

### 이름 있는 레이어 별칭 %{#named-layer-aliases}%

자동 스캔 레이어(`~~/layers` 디렉터리의 레이어)는 자동으로 별칭을 생성합니다. 예를 들어 `~~/layers/test` 레이어는 `#layers/test`로 접근할 수 있습니다.

다른 레이어에 대해서도 이름 있는 레이어 별칭을 만들고 싶다면, 레이어 설정에서 이름을 지정할 수 있습니다.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  $meta: {
    name: 'example',
  },
})
```

그러면 여러분의 레이어를 가리키는 `#layers/example` 별칭이 생성됩니다.

### 상대 경로와 별칭 %{#relative-paths-and-aliases}%

레이어의 컴포넌트와 컴포저블에서 `~/`, `@/` 같은 전역 별칭으로 import할 때는, 이 별칭들이 사용자의 프로젝트 경로를 기준으로 해석된다는 점에 유의하세요. 우회 방법으로는 **상대 경로를 사용해** import하거나 이름 있는 레이어 별칭을 사용할 수 있습니다.

또한 레이어의 `nuxt.config` 파일에서 상대 경로를 사용할 때도(중첩된 `extends`는 제외) 레이어가 아니라 사용자의 프로젝트를 기준으로 해석됩니다. 이를 피하려면 `nuxt.config`에서 완전히 해석된 경로를 사용하세요:

```ts [nuxt.config.ts]
import { fileURLToPath } from 'node:url'
import { dirname, join } from 'node:path'

const currentDir = dirname(fileURLToPath(import.meta.url))

export default defineNuxtConfig({
  css: [
    join(currentDir, './app/assets/main.css'),
  ],
})
```

## 레이어의 모듈 비활성화 %{#disabling-modules-from-layers}%

레이어를 확장할 때, 그 레이어가 포함한 특정 모듈을 비활성화하고 싶을 수 있습니다. Nuxt config에서 해당 모듈의 config key를 `false`로 설정하면 됩니다.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: ['./base-layer'],
  // config key를 false로 설정해 레이어의 모듈을 비활성화합니다
  image: false, // @nuxt/image 비활성화
  pinia: false, // @pinia/nuxt 비활성화
})
```

::note
config key는 각 모듈이 정의합니다. 일반적인 예로는 `@nuxt/image`의 `image`, `@pinia/nuxt`의 `pinia`, `@nuxt/content`의 `content`가 있습니다. 정확한 config key는 해당 모듈 문서를 확인하세요.
::

다음과 같은 경우에 유용합니다:
- 레이어에 프로젝트에서 필요하지 않은 모듈이 포함된 경우
- 레이어가 제공하는 것과 다른 구현을 사용하고 싶은 경우
- 특정 환경에서 analytics나 기타 모듈을 비활성화해야 하는 경우

::tip
이 접근 방식은 레이어의 모듈뿐 아니라 여러분의 프로젝트 자체의 모듈을 비활성화할 때도 사용할 수 있습니다. 모듈의 config key를 `false`로 설정하면 타입은 계속 생성되지만 setup 함수는 실행되지 않습니다.
::

## Nuxt 모듈을 위한 멀티 레이어 지원 %{#multi-layer-support-for-nuxt-modules}%

Nuxt Kit의 [`getLayerDirectories`](/docs/4.x/api/kit/layers#getlayerdirectories) 유틸리티를 사용해 모듈에 대한 커스텀 멀티 레이어 처리를 지원할 수 있습니다.

```ts [modules/my-module.ts]
import { defineNuxtModule, getLayerDirectories } from 'nuxt/kit'

export default defineNuxtModule({
  setup (_options, nuxt) {
    const layerDirs = getLayerDirectories()

    for (const [index, layer] of layerDirs.entries()) {
      console.log(`Layer ${index}:`)
      console.log(`  Root: ${layer.root}`)
      console.log(`  App: ${layer.app}`)
      console.log(`  Server: ${layer.server}`)
      console.log(`  Pages: ${layer.appPages}`)
      // ... 다른 디렉터리들
    }
  },
})
```

**참고:**
- 배열에서 앞에 있는 항목일수록 우선순위가 높고 뒤의 항목을 덮어씁니다
- 사용자의 프로젝트는 배열의 첫 번째 항목입니다
