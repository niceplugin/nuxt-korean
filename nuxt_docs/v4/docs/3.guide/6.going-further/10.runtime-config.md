## 노출 %{#exposing}%

앱의 나머지 부분에 설정과 환경 변수를 노출하려면 [`nuxt.config`](/docs/4.x/directory-structure/nuxt-config) 파일에서 [`runtimeConfig`](/docs/4.x/api/nuxt-config#runtimeconfig) 옵션을 사용해 런타임 구성을 정의해야 합니다.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    // 서버 사이드에서만 사용할 수 있는 비공개 키
    apiSecret: '123',
    // public 내부 키는 클라이언트 사이드에도 노출됩니다
    public: {
      apiBase: '/api',
    },
  },
})
```

`apiBase`를 `runtimeConfig.public`에 추가하면 Nuxt는 이를 각 페이지 payload에 추가합니다. 서버와 브라우저 양쪽에서 `apiBase`에 공통적으로 접근할 수 있습니다.

```ts
const runtimeConfig = useRuntimeConfig()

console.log(runtimeConfig.apiSecret)
console.log(runtimeConfig.public.apiBase)
```

::tip
공개 런타임 설정은 Vue 템플릿에서 `$config.public`으로 접근할 수 있습니다.
::

### 직렬화 %{#serialization}%

런타임 설정은 Nitro로 전달되기 전에 직렬화됩니다. 즉 직렬화 후 역직렬화할 수 없는 모든 것(함수, Set, Map 등)은 `nuxt.config`에 설정하면 안 됩니다.

직렬화할 수 없는 객체나 함수를 `nuxt.config`에서 애플리케이션으로 전달하는 대신, 해당 코드를 Nuxt 또는 Nitro 플러그인이나 미들웨어에 배치할 수 있습니다.

### 환경 변수 %{#environment-variables}%

구성을 제공하는 가장 일반적인 방법은 환경 변수를 사용하는 것입니다.

::note
Nuxt CLI는 development, build, generate 시 `.env` 파일을 읽는 기능을 내장하고 있습니다. 하지만 빌드된 서버를 실행할 때는 **`.env` 파일이 읽히지 않습니다**.
:read-more{to="/docs/4.x/directory-structure/env"}
::

런타임 설정 값은 **런타임에 일치하는 환경 변수로 자동 대체됩니다**.

두 가지 핵심 요구 사항이 있습니다:

1. 원하는 변수는 `nuxt.config`에 정의되어 있어야 합니다. 이렇게 해야 임의의 환경 변수가 애플리케이션 코드에 노출되지 않습니다.

1. 특별한 이름 형식을 가진 환경 변수만 런타임 설정 속성을 덮어쓸 수 있습니다. 즉 `NUXT_`로 시작하고 `_`를 사용해 키와 대소문자 변화를 구분하는 대문자 환경 변수여야 합니다.

::warning
`runtimeConfig` 값의 기본값을 *이름이 다른 환경 변수*로 설정하는 것(예: `myVar`를 `process.env.OTHER_VARIABLE`로 설정)은 빌드 시에만 동작하고 런타임에서는 깨집니다.
`runtimeConfig` 객체 구조와 일치하는 환경 변수를 사용하는 것이 좋습니다.
::

::tip{icon="i-lucide-video" to="https://youtu.be/_FYV5WfiWvs" target="_blank"}
Alexander Lichter가 runtimeConfig 사용 시 개발자가 가장 자주 하는 실수를 설명하는 영상을 시청하세요.
::

#### Example %{#example}%

```ini [.env]
NUXT_API_SECRET=api_secret_token
NUXT_PUBLIC_API_BASE=https://nuxtjs.org
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    apiSecret: '', // can be overridden by NUXT_API_SECRET environment variable
    public: {
      apiBase: '', // can be overridden by NUXT_PUBLIC_API_BASE environment variable
    },
  },
})
```

## 읽기 %{#reading}%

### Vue 앱 %{#vue-app}%

Nuxt 앱의 Vue 부분에서는 런타임 설정에 접근하기 위해 [`useRuntimeConfig()`](/docs/4.x/api/composables/use-runtime-config)를 호출해야 합니다.

::important
클라이언트 사이드와 서버 사이드의 동작은 다릅니다:

- 클라이언트 사이드에서는 `runtimeConfig.public`과 `runtimeConfig.app`(Nuxt 내부에서 사용)의 키만 사용할 수 있으며, 객체는 쓰기 가능하고 반응형입니다.

- 서버 사이드에서는 전체 런타임 설정을 사용할 수 있지만, 컨텍스트 공유를 피하기 위해 읽기 전용입니다.
::

```vue [app/pages/index.vue]
<script setup lang="ts">
const config = useRuntimeConfig()

  console.log('런타임 설정:', config)
if (import.meta.server) {
  console.log('API 비밀값:', config.apiSecret)
}
</script>

<template>
  <div>
    <div>개발자 콘솔을 확인하세요!</div>
  </div>
</template>
```

::caution
**보안 참고:** 런타임 설정 키를 렌더링하거나 `useState`에 전달하는 방식으로 클라이언트 사이드에 노출하지 않도록 주의하세요.
::

### 플러그인 %{#plugins}%

런타임 설정을 (사용자 정의) 플러그인 안에서 사용하고 싶다면 `defineNuxtPlugin` 함수 내부에서 [`useRuntimeConfig()`](/docs/4.x/api/composables/use-runtime-config)를 사용할 수 있습니다.

```ts [app/plugins/config.ts]
export default defineNuxtPlugin((nuxtApp) => {
  const config = useRuntimeConfig()

  console.log('API 기본 URL:', config.public.apiBase)
})
```

### 서버 라우트 %{#server-routes}%

서버 라우트에서도 `useRuntimeConfig`를 사용해 런타임 설정에 접근할 수 있습니다.

```ts [server/api/test.ts]
export default defineEventHandler(async (event) => {
  const { apiSecret } = useRuntimeConfig()
  const result = await $fetch('https://my.api.com/test', {
    headers: {
      Authorization: `Bearer ${apiSecret}`,
    },
  })
  return result
})
```

::note
`event`를 `useRuntimeConfig`의 인자로 넘기는 것은 선택 사항이지만, 서버 라우트에서 런타임 시 [환경 변수](/docs/4.x/guide/going-further/runtime-config#environment-variables)로 덮어써진 런타임 설정을 얻으려면 전달하는 것을 권장합니다.
::

## 런타임 설정 타입 지정 %{#typing-runtime-config}%

Nuxt는 [unjs/untyped](https://github.com/unjs/untyped)를 사용해 제공된 런타임 설정으로부터 TypeScript 인터페이스를 자동 생성하려고 시도합니다.

하지만 런타임 설정에 수동으로 타입을 지정하는 것도 가능합니다:

```ts [index.d.ts]
declare module 'nuxt/schema' {
  interface RuntimeConfig {
    apiSecret: string
  }
  interface PublicRuntimeConfig {
    apiBase: string
  }
}
// 타입을 보강할 때는 항상 무언가를 import/export하고 있는지 확인하는 것이 중요합니다
export {}
```

::note
`nuxt/schema`는 최종 사용자가 프로젝트에서 Nuxt가 사용하는 스키마 버전에 접근할 수 있도록 편의를 위해 제공됩니다. 모듈 작성자는 대신 `@nuxt/schema`를 보강해야 합니다.
::
