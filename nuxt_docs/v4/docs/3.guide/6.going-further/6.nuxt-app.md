## Nuxt 컨텍스트 %{#the-nuxt-context}%

내장된 것과 직접 만든 것을 포함해 많은 composables와 utilities는 Nuxt 인스턴스에 대한 접근이 필요할 수 있습니다. 이 인스턴스는 요청마다 새로 생성되므로 애플리케이션 어디에서나 존재하는 것은 아닙니다.

현재 Nuxt 컨텍스트는 [plugins](/docs/4.x/directory-structure/app/plugins), [Nuxt hooks](/docs/4.x/guide/going-further/hooks), [Nuxt middleware](/docs/4.x/directory-structure/app/middleware) (`defineNuxtRouteMiddleware`로 감싼 경우), [setup functions](https://vuejs.org/api/composition-api-setup)(페이지와 컴포넌트 안)에서만 접근할 수 있습니다.

컨텍스트에 접근할 수 없는 상태에서 composable이 호출되면 'A composable that requires access to the Nuxt instance was called outside of a plugin, Nuxt hook, Nuxt middleware, or Vue setup function.'와 같은 오류가 발생할 수 있습니다. 이 경우 [`nuxtApp.runWithContext`](/docs/4.x/api/composables/use-nuxt-app#runwithcontext)를 사용해 이 컨텍스트 안에서 함수를 명시적으로 호출할 수도 있습니다.

## NuxtApp에 접근하기 %{#accessing-nuxtapp}%

composables, plugins, components 안에서는 [`useNuxtApp()`](/docs/4.x/api/composables/use-nuxt-app)으로 `nuxtApp`에 접근할 수 있습니다:

```ts [app/composables/useMyComposable.ts]
export function useMyComposable () {
  const nuxtApp = useNuxtApp()
  // 런타임 nuxt 앱 인스턴스에 접근
}
```

composable이 항상 `nuxtApp`을 필요로 하지 않거나 단순히 존재 여부만 확인하고 싶다면, [`useNuxtApp`](/docs/4.x/api/composables/use-nuxt-app)이 예외를 발생시키므로 대신 [`tryUseNuxtApp`](/docs/4.x/api/composables/use-nuxt-app#tryusenuxtapp)을 사용할 수 있습니다.

편의를 위해 plugins는 첫 번째 인자로 `nuxtApp`도 전달받습니다.

:read-more{to="/docs/4.x/directory-structure/app/plugins"}

## 헬퍼 제공하기 %{#providing-helpers}%

모든 composables와 애플리케이션 전반에서 사용할 수 있는 헬퍼를 제공할 수 있습니다. 보통 이는 Nuxt plugin 안에서 이루어집니다.

```ts
const nuxtApp = useNuxtApp()
nuxtApp.provide('hello', name => `Hello ${name}!`)

console.log(nuxtApp.$hello('name')) // "Hello name!"을 출력합니다
```

::read-more{to="/docs/4.x/directory-structure/app/plugins#providing-helpers"}
plugins에서 `provide` 키가 있는 객체를 반환해 헬퍼를 주입할 수도 있습니다.
::

::read-more{to="https://v2.nuxt.com/docs/directory-structure/plugins/#inject-in-root--context" target="_blank"}
Nuxt 2 plugins에서는 이를 **inject function**이라고 불렀습니다.
::
