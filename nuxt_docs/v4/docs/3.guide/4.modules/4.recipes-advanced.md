여기에는 hooks, templates, 타입 보강을 포함해 모듈을 작성할 때 사용할 수 있는 몇 가지 고급 패턴이 있습니다.

## 라이프사이클 훅 사용 %{#use-lifecycle-hooks}%

[라이프사이클 훅](/docs/4.x/guide/going-further/hooks)을 사용하면 Nuxt의 거의 모든 측면을 확장할 수 있습니다. 모듈은 프로그래밍 방식으로 또는 정의의 `hooks` 맵을 통해 여기에 연결할 수 있습니다.

```js
import { addPlugin, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  // `hooks` 맵을 통해 `app:error` 훅에 연결합니다
  hooks: {
    'app:error': (err) => {
      console.info(`다음 오류가 발생했습니다: ${err}`)
    },
  },
  setup (options, nuxt) {
    // 프로그래밍 방식으로 `pages:extend` 훅에 연결합니다
    nuxt.hook('pages:extend', (pages) => {
      console.info(`${pages.length}개의 페이지를 찾았습니다`)
    })
  },
})
```

::note
**모듈 정리**
:br
:br
모듈이 watcher를 열거나, 처리하거나, 시작한다면 Nuxt 라이프사이클이 끝날 때 이를 닫아야 합니다. 이를 위해 `close` 훅을 사용할 수 있습니다.

```ts
import { defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    nuxt.hook('close', async (nuxt) => {
      // 여기에 사용자 정의 코드를 작성합니다
    })
  },
})
```
::

### 사용자 정의 훅 만들기 %{#create-custom-hooks}%

모듈은 자체 훅을 정의하고 호출할 수도 있으며, 이는 모듈을 확장 가능하게 만드는 강력한 패턴입니다.

다른 모듈이 여러분의 모듈 훅을 구독할 수 있기를 기대한다면, `modules:done` 훅에서 이를 호출해야 합니다. 이렇게 하면 다른 모든 모듈이 자체 `setup` 함수 동안 설정되고 여러분의 훅에 리스너를 등록할 기회를 갖게 됩니다.

```ts
// my-module/module.ts
import { defineNuxtModule } from '@nuxt/kit'

export interface ModuleHooks {
  'my-module:custom-hook': (payload: { foo: string }) => void
}

export default defineNuxtModule({
  setup (options, nuxt) {
    // `modules:done`에서 훅을 호출합니다
    nuxt.hook('modules:done', async () => {
      const payload = { foo: 'bar' }
      await nuxt.callHook('my-module:custom-hook', payload)
    })
  },
})
```

## 가상 파일 추가 %{#add-virtual-files}%

사용자 앱에서 임포트할 수 있는 가상 파일을 추가해야 한다면 `addTemplate` 유틸리티를 사용할 수 있습니다.

```ts
import { addTemplate, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    // 파일은 Nuxt의 내부 가상 파일 시스템에 추가되며 '#build/my-module-feature.mjs'에서 임포트할 수 있습니다
    addTemplate({
      filename: 'my-module-feature.mjs',
      getContents: () => 'export const myModuleFeature = () => "안녕하세요 세계 !"',
    })
  },
})
```

서버의 경우에는 대신 `addServerTemplate` 유틸리티를 사용해야 합니다.

```ts
import { addServerTemplate, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    // 파일은 Nitro의 가상 파일 시스템에 추가되며 서버 코드에서 'my-server-module.mjs'로 임포트할 수 있습니다
    addServerTemplate({
      filename: 'my-server-module.mjs',
      getContents: () => 'export const myServerModule = () => "안녕하세요 세계 !"',
    })
  },
})
```

## 가상 파일 업데이트 %{#update-virtual-files}%

템플릿이나 가상 파일을 업데이트해야 한다면 다음과 같이 `updateTemplates` 유틸리티를 활용할 수 있습니다:

```ts
nuxt.hook('builder:watch', (event, path) => {
  if (path.includes('my-module-feature.config')) {
    // 등록한 템플릿을 다시 로드합니다
    updateTemplates({ filter: t => t.filename === 'my-module-feature.mjs' })
  }
})
```

## 타입 선언 추가 %{#add-type-declarations}%

사용자 프로젝트에 타입 선언을 추가하고 싶을 수도 있습니다(예를 들어 Nuxt 인터페이스를 보강하거나
자체 전역 타입을 제공할 때). 이를 위해 Nuxt는 템플릿을 디스크에 기록하고 생성된 `nuxt.d.ts` 파일에
그 참조를 추가하는 `addTypeTemplate` 유틸리티를 제공합니다.

모듈이 Nuxt가 처리하는 타입을 보강해야 한다면 `addTypeTemplate`을 사용해 이 작업을 수행할 수 있습니다:

```js
import { addTemplate, addTypeTemplate, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    addTypeTemplate({
      filename: 'types/my-module.d.ts',
      getContents: () => `// my-module에 의해 생성됨
        interface MyModuleNitroRules {
          myModule?: { foo: 'bar' }
        }
        declare module 'nitro/types' {
          interface NitroRouteRules extends MyModuleNitroRules {}
          interface NitroRouteConfig extends MyModuleNitroRules {}
        }
        export {}`,
    })
  },
})
```

더 세밀한 제어가 필요하다면 `prepare:types` 훅을 사용해 여러분의 타입을 주입할 콜백을 등록할 수 있습니다.

```ts
const template = addTemplate({ /* template options */ })
nuxt.hook('prepare:types', ({ references }) => {
  references.push({ path: template.dst })
})
```

## TypeScript 설정 확장 %{#extend-typescript-config}%

모듈에서 사용자 프로젝트의 TypeScript 설정을 확장하는 방법은 여러 가지가 있습니다.

가장 간단한 방법은 다음과 같이 Nuxt 설정을 직접 수정하는 것입니다:

<!-- @case-police-ignore tsConfig -->
```ts
// tsconfig.app.json 확장
nuxt.options.typescript.tsConfig.include ??= []
nuxt.options.typescript.tsConfig.include.push(resolve('./augments.d.ts'))

// tsconfig.shared.json 확장
nuxt.options.typescript.sharedTsConfig.include ??= []
nuxt.options.typescript.sharedTsConfig.include.push(resolve('./augments.d.ts'))

// tsconfig.node.json 확장
nuxt.options.typescript.nodeTsConfig.include ??= []
nuxt.options.typescript.nodeTsConfig.include.push(resolve('./augments.d.ts'))

// tsconfig.server.json 확장
nuxt.options.nitro.typescript ??= {}
nuxt.options.nitro.typescript.tsConfig ??= {}
nuxt.options.nitro.typescript.tsConfig.include ??= []
nuxt.options.nitro.typescript.tsConfig.include.push(resolve('./augments.d.ts'))
```

또는 `prepare:types`와 `nitro:prepare:types` 훅을 사용해 특정 타입 컨텍스트에 대한 TypeScript 참조를 확장하거나, 위 예제와 비슷하게 TypeScript 설정을 수정할 수 있습니다.

```ts
nuxt.hook('prepare:types', ({ references, sharedReferences, nodeReferences }) => {
  // 앱 컨텍스트 확장
  references.push({ path: resolve('./augments.d.ts') })
  // shared 컨텍스트 확장
  sharedReferences.push({ path: resolve('./augments.d.ts') })
  // node 컨텍스트 확장
  nodeReferences.push({ path: resolve('./augments.d.ts') })
})

nuxt.hook('nitro:prepare:types', ({ references }) => {
  // 서버 컨텍스트 확장
  references.push({ path: resolve('./augments.d.ts') })
})
```

::note
TypeScript 참조는 [`tsconfig.json`의 `exclude` 옵션에 영향을 받지 않고](https://www.typescriptlang.org/tsconfig/#exclude) 파일을 타입 컨텍스트에 추가합니다.
::

## 타입 보강 %{#augment-types}%

Nuxt는 모듈의 디렉터리를 적절한 타입 컨텍스트에 자동으로 포함합니다. 모듈의 타입을 보강하려면 보강할 타입 컨텍스트에 맞는 적절한 디렉터리에 타입 선언 파일을 두기만 하면 됩니다. 또는 [TypeScript 설정을 확장](#extend-typescript-config)해 임의의 위치에서 보강할 수도 있습니다.

- `my-module/runtime/` - 앱 타입 컨텍스트 (`runtime/server` 디렉터리 제외)
- `my-module/runtime/server/` - 서버 타입 컨텍스트
- `my-module/` - node 타입 컨텍스트 (`runtime/` 및 `runtime/server` 디렉터리 제외)

```bash [Directory Structure]
-| my-module/   # node 타입 컨텍스트
---| runtime/   # 앱 타입 컨텍스트
------| augments.app.d.ts
------| server/ # 서버 타입 컨텍스트
---------| augments.server.d.ts
---| module.ts
---| augments.node.d.ts
```

### 알려진 제한 사항 %{#known-limitations}%

#### 앱 컨텍스트에서 서버 라우트 타입 검사 %{#type-checking-server-routes-in-app-context}%

서버 라우트는 `tsconfig.server.json`에 더해 `tsconfig.app.json`을 사용해서도 타입 검사를 받습니다.

이는 Nuxt가 [`$fetch`](/docs/4.x/api/utils/dollarfetch)와 [`useFetch`](/docs/4.x/api/composables/use-fetch)에서 응답 타입을 제공하기 위해 서버 엔드포인트의 반환 타입을 추론하기 때문에 필요합니다.

::warning
이로 인해 라우트 파일에서 **서버 전용 타입**을 사용할 때 문제가 생길 수 있습니다. 예를 들어 모듈이 [`addServerTemplate`](/docs/api/kit/templates#addservertemplate)을 사용해 서버 전용 가상 파일을 만들고, 그 타입을 `tsconfig.server.json`에 선언했다면 해당 타입 선언은 서버 컨텍스트에서만 사용할 수 있습니다. 앱 컨텍스트가 서버 라우트를 타입 검사할 때는 이러한 서버 전용 타입을 인식하지 못해 오류를 보고합니다. 이를 해결하려면 아쉽지만 그러한 타입도 앱 컨텍스트에 함께 선언해야 합니다.
::
