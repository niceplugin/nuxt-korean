## 모듈 만들기 %{#create-a-module}%

Nuxt 모듈은 우리의 [starter template](https://github.com/nuxt/starter/tree/module)으로 시작하는 것을 권장합니다:

::code-group{sync="pm"}

```bash [npm]
npm create nuxt -- -t module my-module
```

```bash [yarn]
yarn create nuxt -t module my-module
```

```bash [pnpm]
pnpm create nuxt -t module my-module
```

```bash [bun]
bun create nuxt --template=module my-module
```
::

이렇게 하면 모듈을 개발하고 배포하는 데 필요한 모든 보일러플레이트가 포함된 `my-module` 프로젝트가 생성됩니다.

**다음 단계:**

1. 원하는 IDE에서 `my-module`을 엽니다
2. 선호하는 패키지 매니저로 의존성을 설치합니다
3. `npm run dev:prepare`로 개발용 로컬 파일을 준비합니다
4. 이 문서를 따라 Nuxt 모듈에 대해 더 알아봅니다

### 모듈 개발하기 %{#develop-your-module}%

모듈 소스 코드는 `src` 디렉터리에 있지만, 모듈을 개발할 때는 이를 시험해 볼 Nuxt 애플리케이션이 필요한 경우가 많습니다. 이를 위한 것이 `playground` 디렉터리입니다. 이곳은 모듈과 함께 실행되도록 이미 설정된, 자유롭게 실험할 수 있는 Nuxt 애플리케이션입니다.

playground는 일반 Nuxt 애플리케이션처럼 다룰 수 있습니다.

- `npm run dev`로 개발 서버를 실행하면 `src` 디렉터리의 모듈을 수정할 때 자동으로 다시 로드됩니다
- `npm run dev:build`로 빌드할 수 있습니다

::note
다른 모든 `nuxt` 명령도 `playground` 디렉터리에 대해 사용할 수 있습니다(예: `nuxt <COMMAND> playground`). 편의를 위해 이를 참조하는 추가 `dev:*` 스크립트를 `package.json`에 자유롭게 선언하세요.
::

### 테스트 실행하기 %{#run-tests}%

module starter에는 기본 테스트 스위트가 포함되어 있습니다:

- [ESLint](https://eslint.org) 기반의 린터, `npm run lint`로 실행
- [Vitest](https://vitest.dev) 기반의 테스트 러너, `npm run test` 또는 `npm run test:watch`로 실행

::tip
필요에 더 잘 맞도록 이 기본 테스트 전략을 자유롭게 확장하세요.
::

### 모듈 빌드하기 %{#build-your-module}%

Nuxt 모듈은 [`@nuxt/module-builder`](https://github.com/nuxt/module-builder#readme)가 제공하는 자체 빌더를 사용합니다. 이 빌더는 별도 설정이 필요 없고 TypeScript를 지원하며, 다른 Nuxt 애플리케이션에 배포할 수 있도록 에셋이 올바르게 번들링되게 해줍니다.

`npm run prepack`으로 모듈을 빌드할 수 있습니다.

::tip
모듈 빌드가 경우에 따라 유용할 수는 있지만, 대부분은 직접 빌드할 필요가 없습니다. 개발 중에는 `playground`가 이를 처리하고, 배포 시에는 release 스크립트가 이를 맡아줍니다.
::

### npm에 배포하기 %{#publish-to-npm}%

::important
npm에 모듈을 배포하기 전에 [npmjs.com](https://www.npmjs.com) 계정이 있고, 로컬에서 `npm login`으로 인증되어 있는지 확인하세요.
::

버전을 올리고 `npm publish` 명령으로 모듈을 배포할 수도 있지만, module starter에는 npm에 정상 동작하는 버전을 배포하도록 도와주는 release 스크립트가 포함되어 있습니다.

release 스크립트를 사용하려면 먼저 모든 변경 사항을 커밋하고([Conventional Commits](https://www.conventionalcommits.org)를 따르면 자동 버전 증가와 changelog 업데이트도 활용할 수 있어 권장합니다), 그다음 `npm run release`로 release 스크립트를 실행하세요.

release 스크립트를 실행하면 다음 작업이 수행됩니다:

- 먼저 다음과 같이 테스트 스위트를 실행합니다:
  - 린터 실행 (`npm run lint`)
  - 단위, 통합, e2e 테스트 실행 (`npm run test`)
  - 모듈 빌드 (`npm run prepack`)
- 이후 테스트 스위트가 잘 통과하면 다음과 같이 모듈 배포를 진행합니다:
  - Conventional Commits에 따라 모듈 버전을 올리고 changelog 생성
  - 모듈을 npm에 배포(이 과정에서 게시 산출물에 최신 버전 번호가 반영되도록 모듈을 다시 빌드)
  - 새로 배포된 버전을 나타내는 git 태그를 원격 origin에 푸시

::tip
다른 스크립트와 마찬가지로 기본 `release` 스크립트도 필요에 더 잘 맞도록 `package.json`에서 자유롭게 조정하세요.
::
