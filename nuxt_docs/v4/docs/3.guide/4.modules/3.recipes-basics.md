다음은 모듈 작성자가 자주 사용하는 일반적인 패턴입니다.

## Nuxt 구성 수정하기 %{#modify-nuxt-configuration}%

Nuxt 구성은 모듈에서 읽고 변경할 수 있습니다. 다음은 모듈이 실험적 기능을 활성화하는 예시입니다.

```js
import { defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    // 아직 존재하지 않는다면 `experimental` 객체를 생성합니다
    nuxt.options.experimental ||= {}
    nuxt.options.experimental.componentIslands = true
  },
})
```

더 복잡한 구성 변경을 처리해야 한다면 [defu](https://github.com/unjs/defu) 사용을 고려해야 합니다.

::tip{icon="i-lucide-video" to="https://vueschool.io/lessons/extending-and-altering-nuxt-configuration-and-options?friend=nuxt" target="_blank"}
Nuxt 구성을 변경하는 방법에 대한 Vue School 영상을 시청하세요.
::

## 런타임에 옵션 노출하기 %{#expose-options-to-runtime}%

모듈은 애플리케이션 런타임의 일부가 아니므로, 모듈 옵션도 마찬가지입니다. 하지만 많은 경우 런타임 코드 안에서 이러한 모듈 옵션 일부에 접근해야 할 수 있습니다. 필요한 구성은 Nuxt의 [`runtimeConfig`](/docs/4.x/api/nuxt-config#runtimeconfig)를 사용해 노출하는 것을 권장합니다.

<!-- TODO: Update after #18466 (or equivalent) -->

```js
import { defineNuxtModule } from '@nuxt/kit'
import { defu } from 'defu'

export default defineNuxtModule({
  setup (options, nuxt) {
    nuxt.options.runtimeConfig.public.myModule = defu(nuxt.options.runtimeConfig.public.myModule, {
      foo: options.foo,
    })
  },
})
```

덮어쓰는 대신 사용자가 제공한 public runtime 구성을 확장하기 위해 [`defu`](https://github.com/unjs/defu)를 사용한다는 점에 유의하세요.

그런 다음 다른 runtime 구성과 마찬가지로 플러그인, 컴포넌트, 애플리케이션에서 모듈 옵션에 접근할 수 있습니다:

```js
import { useRuntimeConfig } from '@nuxt/kit'

const options = useRuntimeConfig().public.myModule
```

::warning
private API key와 같은 민감한 모듈 구성을 public runtime config에 노출하지 않도록 주의하세요. 이런 값은 공개 번들에 포함되기 때문입니다.
::

:read-more{to="/docs/4.x/guide/going-further/runtime-config"}

::tip{icon="i-lucide-video" to="https://vueschool.io/lessons/passing-and-exposing-module-options?friend=nuxt" target="_blank"}
Nuxt 모듈 옵션을 전달하고 노출하는 방법에 대한 Vue School 영상을 시청하세요.
::

## 플러그인 추가하기 %{#add-plugins}%

플러그인은 모듈이 런타임 로직을 추가하는 일반적인 방법입니다. `addPlugin` 유틸리티를 사용해 모듈에서 등록할 수 있습니다.

```js
import { addPlugin, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    // 상대 경로를 해석할 resolver 생성
    const resolver = createResolver(import.meta.url)

    addPlugin(resolver.resolve('./runtime/plugin'))
  },
})
```

:read-more{to="/docs/4.x/guide/going-further/kit"}

## 컴포넌트 추가하기 %{#add-components}%

모듈이 Vue 컴포넌트를 제공해야 한다면 `addComponent` 유틸리티를 사용해 Nuxt가 해석할 auto-import로 추가할 수 있습니다.

```ts twoslash
import { addComponent, createResolver, defineNuxtModule, useRuntimeConfig } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    const resolver = createResolver(import.meta.url)

    // runtime 디렉터리에서 가져오기
    addComponent({
      name: 'MySuperComponent', // vue 템플릿에서 사용할 컴포넌트 이름
      export: 'MySuperComponent', // (선택 사항) 컴포넌트가 default export가 아닌 named export인 경우
      filePath: resolver.resolve('runtime/app/components/MySuperComponent.vue'),
    })

    // 라이브러리에서 가져오기
    addComponent({
      name: 'MyAwesomeComponent', // vue 템플릿에서 사용할 컴포넌트 이름
      export: 'MyAwesomeComponent', // (선택 사항) 컴포넌트가 default export가 아닌 named export인 경우
      filePath: '@vue/awesome-components',
    })
  },
})
```

또는 `addComponentsDir`를 사용해 전체 디렉터리를 추가할 수 있습니다.

```ts
import { addComponentsDir, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    const resolver = createResolver(import.meta.url)

    addComponentsDir({
      path: resolver.resolve('runtime/app/components'),
    })
  },
})
```

::tip{icon="i-lucide-lightbulb"}
사용자 코드나 다른 모듈과의 충돌을 피하기 위해 export에 접두사를 붙이는 것을 강력히 권장합니다.

:read-more{to="/docs/4.x/guide/modules/best-practices#prefix-your-exports"}
::

::note
보통 `app/` 폴더에 두는 모든 컴포넌트, 페이지, composable 및 기타 파일은 `runtime/app/` 안에 있어야 한다는 점에 유의하세요. 그래야 올바르게 타입 검사를 할 수 있습니다.
::

## Composable 추가하기 %{#add-composables}%

모듈이 composable을 제공해야 한다면 `addImports` 유틸리티를 사용해 Nuxt가 해석할 auto-import로 추가할 수 있습니다.

```ts
import { addImports, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    const resolver = createResolver(import.meta.url)

    addImports({
      name: 'useComposable', // 사용할 composable 이름
      as: 'useMyComposable', // 소비하는 앱에서 사용할 수 있는 선택적 별칭
      from: resolver.resolve('runtime/app/composables/useComposable'), // composable 경로
    })
  },
})
```

여러 항목을 배열로 전달할 수도 있습니다:

```ts
import { addImports, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    const resolver = createResolver(import.meta.url)

    addImports([
      { name: 'useFirstComposable', from: resolver.resolve('runtime/composables/useFirstComposable') },
      { name: 'useSecondComposable', from: resolver.resolve('runtime/composables/useSecondComposable') },
    ])
  },
})
```

또는 `addImportsDir`를 사용해 전체 디렉터리를 추가할 수 있습니다.

```ts
import { addImportsDir, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    const resolver = createResolver(import.meta.url)

    addImportsDir(resolver.resolve('runtime/composables'))
  },
})
```

::tip{icon="i-lucide-lightbulb"}
사용자 코드나 다른 모듈과의 충돌을 피하기 위해 export에 접두사를 붙이는 것을 강력히 권장합니다.

:read-more{to="/docs/4.x/guide/modules/best-practices#prefix-your-exports"}
::

::note
보통 `app/` 폴더에 두는 모든 컴포넌트, 페이지, composable 및 기타 파일은 `runtime/app/` 안에 있어야 한다는 점에 유의하세요. 그래야 올바르게 타입 검사를 할 수 있습니다.
::

### 키가 지정된 함수 추가하기 %{#add-keyed-functions}%

때로는 서버와 클라이언트 사이에서 상태 일관성을 유지해야 할 수 있습니다. 예를 들면 Nuxt의 내장 `useState`나 `useAsyncData` composable이 있습니다. Nuxt는 이러한 함수를 자동 키 주입 대상으로 등록하는 방법을 제공합니다.

함수가 등록되면 Nuxt의 컴파일러는 해당 함수가 지정된 인수 개수보다 적은 인수로 호출될 때 고유 키를 추가 인수로 자동 주입합니다. 이 키는 서버 사이드 렌더링과 클라이언트 hydration 사이에서 안정적으로 유지됩니다.

::tip
주입되는 키는 파일 경로와 호출 위치에서 파생된 해시입니다.
::

함수를 등록하려면 `keyedComposables` 옵션을 사용하세요:

```ts
import { createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    const resolver = createResolver(import.meta.url)

    nuxt.options.optimization.keyedComposables.push({
      name: 'useMyState',
      source: resolver.resolve('./runtime/composables/state'),
      argumentLength: 2,
    })
  },
})
```

`keyedComposables` 구성은 다음 속성을 가진 객체 배열을 받습니다:

| Property         | Type     | Description                                                                                                                |
|------------------|----------|----------------------------------------------------------------------------------------------------------------------------|
| `name`           | `string` | 함수 이름입니다. default export에는 `'default'`를 사용하세요. (호출 가능한 이름은 파일명에서 camelCase로 파생됩니다.)     |
| `source`         | `string` | 함수가 정의된 파일의 해석된 경로입니다. Nuxt alias(`~`, `@` 등)를 지원합니다.                                              |
| `argumentLength` | `number` | 함수가 받을 수 있는 최대 인수 개수입니다. 이보다 적은 인수로 호출되면 고유 키가 주입됩니다.                               |

예를 들어 `argumentLength: 2`인 경우:

```ts
useMyState() // useMyState('$HJiaryoL2y')
useMyState('myKey') // useMyState('myKey', '$HJiaryoL2y')
useMyState('a', 'b') // 변환되지 않음 (이미 인수가 2개 있음)
```

::warning
키 주입 플러그인은 각 함수 호출의 정확한 해석된 import source를 확인합니다. 배럴 export는 따라가지 않습니다. 함수는 `source` 속성에 지정한 정확한 소스 파일에서 export되어야 합니다.

```ts
// ✅ 동작함 - 직접 import가 구성된 source와 일치함
import { useMyState } from 'my-module/runtime/composables/state'

// ❌ 동작하지 않음 - 배럴 파일을 통해 다시 export됨
import { useMyState } from 'my-module/runtime/composables' // index.ts barrel
```
::

::warning
함수 호출은 정적으로 분석 가능해야 합니다. 컴파일러는 동적이거나 간접적인 함수 호출에는 키를 주입할 수 없습니다.

```ts
import { useMyState } from 'my-module/runtime/composables/state'
import * as composables from 'my-module/runtime/composables/state'

// ✅ 동작함 - 직접 함수 호출
useMyState()

// ✅ 동작함 - 네임스페이스 import에서 호출
composables.useMyState()

// ❌ 동작하지 않음 - 동적 속성 접근
const name = 'useMyState'
composables[name]()

// ❌ 동작하지 않음 - 변수에 다시 할당됨
const myFn = useMyState
myFn()

// ❌ 동작하지 않음 - 콜백으로 전달됨
someFunction(useMyState)

// ❌ 동작하지 않음 - 중첩 스코프에서 이름을 바꿔 구조 분해됨
function setup () {
  const { useMyState: localState } = composables
  localState() // 변환되지 않음
}

// ...
```
::

## 라우트 미들웨어 추가하기 %{#add-route-middleware}%

```ts
import { addRouteMiddleware, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    const resolver = createResolver(import.meta.url)

    // 전역 라우트 미들웨어를 추가하는 예시
    addRouteMiddleware({
      global: true,
      name: 'name-of-your-middleware',
      path: resolver.resolve('./runtime/middleware/name-of-your-middleware'),
    })
  },
})
```

## 서버 라우트 추가하기 %{#add-server-routes}%

```ts
import { addServerHandler, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    const resolver = createResolver(import.meta.url)

    addServerHandler({
      route: '/api/_my-module/hello',
      handler: resolver.resolve('./runtime/server/api/hello/index.get'),
    })
  },
})
```

동적 서버 라우트를 추가할 수도 있습니다:

```ts
import { addServerHandler, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    const resolver = createResolver(import.meta.url)

    addServerHandler({
      route: '/api/_my-module/hello/:name',
      handler: resolver.resolve('./runtime/server/api/hello/[name].get'),
    })

    // 또는 catch all 라우트 사용
    addServerHandler({
      route: '/api/_my-module/files/**:path',
      handler: resolver.resolve('./runtime/server/api/files/[...path].get'),
    })
  },
})
```

::tip{icon="i-lucide-lightbulb"}
사용자 정의 라우트와의 충돌을 피하기 위해 서버 라우트에 접두사를 붙이는 것을 강력히 권장합니다. `/api/auth`, `/api/login`, `/api/user`와 같은 일반적인 경로는 애플리케이션에서 이미 사용 중일 수 있습니다.

:read-more{to="/docs/4.x/guide/modules/best-practices#prefix-your-exports"}
::

## 다른 자산 추가하기 %{#add-other-assets}%

모듈이 다른 종류의 자산을 제공해야 한다면 이 역시 주입할 수 있습니다. 다음은 Nuxt의 `css` 배열을 통해 스타일시트를 주입하는 간단한 예시 모듈입니다.

```js
import { addPlugin, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    const resolver = createResolver(import.meta.url)

    nuxt.options.css.push(resolver.resolve('./runtime/style.css'))
  },
})
```

그리고 [Nitro](/docs/4.x/guide/concepts/server-engine)의 `publicAssets` 옵션을 통해 자산 폴더를 노출하는 좀 더 고급 예시입니다:

```js
import { createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    const resolver = createResolver(import.meta.url)

    nuxt.hook('nitro:config', (nitroConfig) => {
      nitroConfig.publicAssets ||= []
      nitroConfig.publicAssets.push({
        dir: resolver.resolve('./runtime/public'),
        maxAge: 60 * 60 * 24 * 365, // 1년
      })
    })
  },
})
```

## 다른 모듈 사용하기 %{#use-other-modules}%

모듈이 다른 모듈에 의존한다면 `moduleDependencies` 옵션을 사용해 이를 지정할 수 있습니다. 이렇게 하면 버전 제약과 구성 병합을 포함해 모듈 의존성을 더 견고하게 처리할 수 있습니다:

```ts
import { createResolver, defineNuxtModule } from '@nuxt/kit'

const resolver = createResolver(import.meta.url)

export default defineNuxtModule<ModuleOptions>({
  meta: {
    name: 'my-module',
  },
  moduleDependencies: {
    '@nuxtjs/tailwindcss': {
      // 모듈의 버전 제약을 지정할 수 있습니다
      version: '>=6',
      // `nuxt.options`를 덮어써야 하는 모든 구성
      overrides: {
        exposeConfig: true,
      },
      // 설정되어야 하는 모든 구성입니다. 모듈 기본값은 덮어쓰지만
      // `nuxt.options`에 설정된 구성은 덮어쓰지 않습니다
      defaults: {
        config: {
          darkMode: 'class',
          content: {
            files: [
              resolver.resolve('./runtime/components/**/*.{vue,mjs,ts}'),
              resolver.resolve('./runtime/*.{mjs,js,ts}'),
            ],
          },
        },
      },
    },
  },
  setup (options, nuxt) {
    // Tailwind 지시어를 포함한 CSS 파일을 주입할 수 있습니다
    nuxt.options.css.push(resolver.resolve('./runtime/assets/styles.css'))
  },
})
```

::callout{type="info"}
`moduleDependencies` 옵션은 더 이상 사용되지 않는 `installModule` 함수를 대체하며, 올바른 설정 순서와 구성 병합을 보장합니다.
::
